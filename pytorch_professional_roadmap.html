목표와 현실적인 기준

현재 개발 경험을 활용해 PyTorch 문법만 배우는 것이 아니라, 데이터부터 학습·평가·추론까지 연결할 수 있는 실무 기초를 만든다.

최종 목표
Transformer의 구조를 설명하고 구현하며, 머신러닝 문제를 올바르게 정의·평가하고, PyTorch로 모델을 학습·디버깅·추론할 수 있다. 어느 영역부터 배웠는지는 중요하지 않다.
범위
이 계획은 새로운 모델 구조를 연구하는 연구자 과정이 아니다. 모델을 이해하고, 학습시키고, 제품 코드에 연결하는 ML 엔지니어 실무 기초 과정이다.
1차 순환
표 데이터에서 데이터 → Baseline → PyTorch 학습 → 평가 → 저장·추론을 먼저 연결하고, 이어 Transformer 핵심 손코딩 → Tiny Decoder LM → 사전학습 텍스트 모델 적용까지 빠르게 한 번 완주한다. 각 단계는 실행만 하지 않고 Shape 예측·Baseline 비교·오류 확인·재실행 증거를 남긴다.
2차 깊이 선택
1차 순환을 마친 뒤 실제로 부족했던 역량이나 만들고 싶은 결과물에 따라 수학·최적화, 데이터 검증, LLM·NLP 응용, 컴퓨터 비전, 학습 성능, MLOps, Knowledge Graph·GraphRAG·Agent Harness 중 하나만 선택한다. 보유 커리큘럼에서 고른 목록은 이때 사용하는 후보이며 현재 순서에 자동으로 추가되지 않는다.

현재 학습 상태와 다음 방향

최근 구현·검증 기록과 남은 완료 증거를 함께 보고, 지금 이어갈 단계와 다음 트랙의 선택 이유를 결정한다.

교차 트랙 전환 실행
TransformerBlock.forward() 뒤 시작한 ML 회원 이탈 Baseline과 PyTorch Module·Optimizer, 작은 회귀 데이터의 Dataset·DataLoader Batch 학습을 검증했다. 이제 같은 회원 이탈 Split에 Train·Validation DataLoader와 MLP를 붙이고, 저장·복원·간단한 추론 API까지 검증해 작은 end-to-end 결과물을 닫은 뒤 Tiny Decoder LM → 사전학습 텍스트 모델 적용으로 이어간다.
통합 상태
전체 24개 완료 조건 중 13개를 검증했다. 단일 전체 퍼센트보다 각 하위 로드맵의 현재 위치와 다음 행동을 우선해서 본다.

전체 학습 방향 점검

확보한 연결: 실제 회원 이탈 데이터에서 품질 확인·분할·전처리·Baseline·분류 Metric을 검증했고, PyTorch에서는 Module·Gradient·Optimizer와 작은 Batch 학습을 확인했다. Transformer는 Embedding부터 TransformerBlock까지 구현·Shape 설명을 마쳤다.

현재 경계: 각 부품의 역할은 설명할 수 있지만, 새로운 요구사항에서 원본 데이터 → Pandas → NumPy/Tensor → DataLoader → 학습 → Validation → 저장·추론을 자료 없이 한 번에 연결하는 증거는 아직 부족하다.

판정: 한 분야에 잘못 치우친 상태가 아니라, 여러 트랙에서 배운 부품을 하나의 실제 결과물로 묶는 단계다. 새 주제를 늘리기보다 현재 회원 이탈 MLP의 end-to-end 완료를 우선한다.

보강 방식과 전환 조건

Pandas·NumPy: 별도 장기 기초 과정으로 돌아가지 않고 현재 MLP에서 열 선택·필터·집계·배열 인덱싱·reshape·axis와 Pandas → NumPy → Tensor의 Shape·dtype을 짧게 반복한다.

별도 보강 조건: 같은 자료 조작을 여러 번 사용한 뒤에도 작은 문제를 자료 없이 재현하지 못하면, 그때 짧은 집중 실습을 별도 관문으로 둔다.

즉시 완료 목표: 같은 Split로 MLP Train·Validation 루프와 Accuracy·Yes Recall을 계산하고 Logistic Baseline과 비교한 뒤, 과적합 판단·저장·복원·한 건 추론까지 확인한다.

다음 전환: 위 결과물을 닫으면 Tiny Decoder LM으로 복귀해 실제 데이터 학습에서 확인한 Batch·Validation·일반화 흐름을 Token shift·Causal Loss·생성에 적용한다. 이어 작은 공개 텍스트 데이터에서 사전학습 모델을 같은 Baseline·Split·Metric으로 평가하면 1차 순환을 닫는다.

누락을 막는 4개의 고정 산출물 관문

앞으로 새로운 라이브러리 이름을 떠올릴 때마다 로드맵에 붙이지 않는다. 모든 필수 역량을 아래 네 산출물의 입력·처리·검증에 배치한다. 어떤 기술이 빠졌는지도 이 네 관문으로 감사한다.

①데이터 관문

입력: CSV·JSON·Parquet 또는 SQL 결과. 처리: 행의 의미와 Key 확인 → Pandas 검사·정리 → 시각화 → 올바른 분할 → scikit-learn 전처리 Pipeline과 Baseline. 검증: 누수 없이 동일한 split과 Metric으로 비교한다.

산출물: 데이터 설명서, EDA 그래프, 분할된 데이터, 재현 가능한 Baseline 결과
②학습 관문

NumPy와 Tensor에서 안정적인 PyTorch 학습까지

입력: Feature·Label과 확정된 Metric. 처리: Tensor·Dataset·DataLoader → Module·Loss·Optimizer → train/eval. 검증: 한 Batch 과적합, Shape·dtype·device·Gradient·finite 여부를 확인한다.

산출물: 학습·검증 루프, Loss/Metric 곡선, Best checkpoint와 디버깅 기록
③Transformer 관문

핵심 손코딩에서 실제 사전학습 모델 적용까지

입력: Token batch와 Mask. 처리: Attention·MHA·FFN·Residual·Norm → Tiny Decoder LM 학습·생성 → 사전학습 모델 Fine-tuning. 검증: Shape·Mask와 공식 연산 결과를 비교하고 길이·클래스별 오류를 분석한다.

산출물: 테스트된 핵심 블록, 작은 생성 모델, Baseline과 비교된 텍스트 모델
④전달 관문

내 노트북에서 다른 환경의 실행 가능한 결과물까지

입력: 평가가 끝난 모델. 처리: 환경·의존성·설정·Git·Logging·Test → 저장·복원 → Batch/API/Docker. 검증: 새 프로세스에서 동일 전처리와 모델을 불러와 예측을 재현한다.

학습 시점
이 여섯 가지를 먼저 별도 강의로 완주하지 않는다. Python·NumPy는 현재 코드에서 막힐 때, Pandas·SQL·시각화·scikit-learn은 첫 실제 데이터 관문에서, 테스트·환경·배포는 결과물을 다른 환경으로 넘길 때 필요한 만큼 배운다.

이 문서가 전체 학습의 기준점이다

계획, 현재 위치, 이해한 개념, 발견된 기반 공백, 실습 코드와 학습 문서를 이곳에서 연결한다. 새 대화를 시작해도 이 파일을 먼저 읽으면 이전 흐름을 복원할 수 있다.

운영 원칙
새 개념을 배울 때마다 문서를 무작정 늘리지 않는다. 현재 구현 또는 질문과 연결하고, 실제로 이해한 내용은 관련 학습 문서에 기록한 뒤 이 허브에서 참조한다.

현재 학습 위치

구현 완료Single-head Scaled Dot-Product Attention
QKᵀ → Scaling → Mask → Softmax → attention_weights @ value를 연결하고 출력과 Attention weight를 반환했다.
검증한 개념[query, token] @ [token, value_dim] → [query, value_dim]에서 가운데 Token 축이 곱의 합으로 처리되고, 각 출력 행이 Value의 가중합임을 숫자로 확인했다.

순서대로 듣지 않고 필요한 것을 끌어온다

Transformer, Machine Learning, PyTorch를 별도 과목처럼 모두 끝낸 뒤 연결하지 않는다. 실제 구현을 중심에 두고, 막힌 원인을 찾아 필요한 영역만 짧게 보강한 뒤 즉시 구현으로 돌아온다.

기반 축 · Machine Learning + PyTorch

Loss, Gradient, 데이터 분할, 평가, Tensor, Autograd처럼 현재 구현을 이해하는 데 필요한 기반을 작은 실습으로 채운다.

가장 효율적인 두 경로를 왕복한다

내부 이해 경로

수동 선형회귀, Autograd, Attention과 Transformer 블록을 직접 구현한다. 라이브러리 호출 뒤에서 어떤 Tensor 연산이 일어나는지 확인하는 경로다.

실전 적용 경로

실제 데이터, DataLoader, nn.Module, 사전학습 모델, 평가와 추론을 사용해 동작하는 결과물을 만든다. 손코딩이 끝날 때까지 적용을 미루지 않는다.

예: Attention을 손코딩하다 Shape에서 막히면 Tensor 실습으로 이동한다. 다시 Attention에 적용한 뒤에는 작은 사전학습 텍스트 분류 모델에서 attention_mask가 어떻게 쓰이는지 확인한다.

선택 방식
현재 Transformer 또는 PyTorch 코드에서 막힌 원인을 기준으로 가장 가까운 실습을 가져온다. 실습으로 원인을 확인한 뒤 반드시 원래 코드에 다시 적용한다.

Tensor Shape · dtype · device 실험실

indexing, reduction, view/reshape, permute/transpose, contiguous, broadcasting, matmul, dtype/device 이동과 NumPy↔Tensor 변환을 실행 전에 예상한다.

수동 선형회귀 · Autograd

y=wx+b를 손계산, Tensor 연산, backward(), 수동 SGD, Optimizer 순으로 구현하고 Gradient를 비교한다.

비선형 이진 분류 · 두 개의 달 또는 XOR

선형 모델의 한계를 확인한 뒤 MLP, Logit, Sigmoid, BCE, Decision Boundary가 어떻게 연결되는지 실험한다.

다중 분류 · FashionMNIST

이미지 Batch를 MLP로 분류하며 Logit, Softmax, Cross Entropy, Accuracy와 Confusion Matrix를 연결한다.

표 데이터 · scikit-learn Baseline 대결

Dummy·Linear/Logistic·Tree와 PyTorch MLP를 같은 split·Metric으로 비교한다. StandardScaler·OneHotEncoder를 Pipeline/ColumnTransformer로 묶어 누수를 막는다.

파일/SQL → Pandas → EDA → DataLoader

행의 의미·Key·null·중복을 확인하고 filter·groupby·merge를 사용한다. 분포와 클래스 비율을 시각화한 뒤 Feature·Label을 Tensor·Dataset·DataLoader로 연결한다.

여러 테이블 · Grain과 집계 Feature

메인 엔터티와 1:N 이력 테이블의 Key·Grain을 정의한다. 이력을 엔터티별로 집계한 뒤 조인하고 행 수·Key 중복·결측·예측 시점 이후 정보로 인한 누수를 검사한다.

시계열 · 미래 정보 누수 없는 검증

예측 시점과 Target 시점을 정의하고 시간순 Split, Lag·Rolling Feature, Naive Baseline과 Walk-forward 평가를 연결한다. Random split·전체 기간 통계가 만드는 미래 정보 누수를 의도적으로 비교한다.

과적합 · 데이터 누수 탐지

Train 성능만 좋아지는 실험과 분할 전 전처리로 누수가 생기는 실험을 의도적으로 만들고 올바른 Validation 결과와 비교한다.

불균형 분류 · Accuracy의 함정

한 클래스가 매우 많은 데이터에서 Accuracy, Precision, Recall, F1, Confusion Matrix와 Threshold의 차이를 비교한다.

이상탐지 · Label과 Alert 예산

규칙 Baseline, Class weight 지도 분류와 비지도 모델 하나를 비교한다. Sampling은 Train fold 안에서만 적용하고 PR-AUC·Recall at fixed Precision·Precision@K로 운영 가능한 Threshold를 정한다.

Tiny Decoder-only Language Model

입력 Token과 한 칸 이동한 Target, Causal Mask, Vocabulary Logit과 Token Cross Entropy를 연결해 작은 데이터에 과적합시키고 Greedy generation을 실행한다.

저장 · 복원 · Batch 추론

전처리·Config·Label mapping과 state_dict를 저장해 새 프로세스에서 같은 예측을 재현한다. train(), eval(), inference_mode()의 차이도 확인한다.

Attention · MHA Shape · Mask · 공식 연산 비교

작은 Q·K·V로 Attention을 손계산한 뒤 Head split/merge, Padding/Causal Mask의 broadcast Shape을 테스트하고 공식 SDPA와 forward·Gradient를 비교한다.

사전학습 Transformer · 텍스트 분류

TF-IDF+Logistic Baseline을 만든다. Token 길이·Padding·Truncation·Attention Mask를 검사하고 Head-only와 Fine-tuning을 비교한 뒤 오류 분석·저장·Batch 추론까지 연결한다.

대표 실습의 공통 완료 기준
① 입력과 정답을 설명한다. ② 핵심 Shape·dtype·device를 예상한다. ③ 학습 모델은 한 Batch 과적합과 Gradient·finite 검사를 통과한다. ④ Train/Validation Metric과 오류 사례를 분석한다. ⑤ 조건 하나를 바꾸고 결과를 설명한다. ⑥ 핵심 부분을 빈 화면에서 다시 작성한다.

역량 영역별 완료 체크

각 영역의 결과물을 설명하고 다시 만드는 과정이 확인되면 내가 독립적으로 완료 체크한다. 앞 영역의 완료가 뒤 영역 학습의 필수 조건은 아니다.

1차 순환 이후에는 한 방향을 깊게 판다

Area A~G의 공통 코어와 두 기본 결과물을 한 번 연결한 뒤, 실제로 부족했던 역량이나 만들고 싶은 결과물에 필요한 확장 트랙 하나를 선택한다.

진행 원칙
아래 확장 트랙과 강의에서 고른 실습 후보는 1차 순환 진행률에 포함하지 않는다. 한 트랙의 작은 프로젝트를 학습·평가·추론·문서화까지 완성한 뒤에만 다음 깊이를 선택한다.

외부 커리큘럼에서 선별해 가져오는 기준

현재 코어에 이미 포함문제 정의, Train·Validation 분할, 전처리, Baseline, Metric, PyTorch 학습 루프, Transformer 손코딩, 사전학습 텍스트 모델, 저장·추론은 기존 1차 순환을 그대로 사용한다. 같은 내용을 과정별로 반복 추가하지 않는다.
기존 깊이 후보를 강화머신러닝에는 L1·L2 Regularization, Stratified Cross-validation, RandomForest 또는 Gradient Boosting 한 모델, 작은 하이퍼파라미터 탐색과 Feature Importance를 같은 평가 계약 안에서 선택한다. PyTorch에는 이미지 분류, RNN/LSTM 비교, AutoEncoder를 실제 문제의 필요가 있을 때만 연다.
텍스트 적용에서 선택Encoder 계열 분류와 Decoder 계열 생성의 문제 계약을 먼저 구분한다. Accuracy·F1 같은 분류 Metric, Perplexity와 생성 결과의 근거·오류 분석, BLEU·ROUGE 같은 참조 문장 Metric은 실제 과제가 요구할 때만 선택한다.
새 독립 확장으로 분리Artifact·Canary·Monitoring·Drift·재학습은 MLOps·모델 운영으로, Graph Schema·GraphRAG·Ontology 또는 Tool Loop·실패 복구·MCP·Agent 평가는 Knowledge Graph·Agent Harness로 분리했다.
목록만으로는 추가하지 않음모든 ML 알고리즘, 모든 CNN·RNN 구조, 여러 UI Framework, 여러 산업별 예제 프로젝트를 각각 챕터로 만들지 않는다. 현재 결과물의 오류나 요구사항이 선택 근거를 줄 때 하나만 구현한다.

Expansion B

컴퓨터 비전

이미지 데이터를 처음부터 모델 목록으로 배우지 않고, 사전학습 모델을 실제 데이터 계약·평가·오류 분석과 연결하는 방향이다.

  • 이미지 메타데이터와 Custom Dataset·DataLoader

지금 가장 효율적인 다음 관문

회원 이탈 Baseline과 PyTorch nn.Module·Optimizer, 작은 회귀 데이터의 Batch 학습까지 검증했다. 아래는 1차 순환을 닫기 위해 지금부터 이어갈 실제 순서다.

  1. 완료: 회원 이탈 Train·Validation Split을 각각 DataLoader로 만들고 입력 [batch,45]와 정답 Shape, MLP Forward와 SGD 한 Step을 확인했다.
  2. 작은 MLP의 Train Loss와 Validation Accuracy·Yes Recall을 Logistic·Tree와 같은 조건에서 비교한다.
  3. 과적합과 오류 사례를 확인한 뒤 Best checkpoint를 저장·복원하고 한 건 추론을 재현한다.
  4. Tiny Decoder LM에서 Target shift·Causal Mask·Token Loss·작은 생성을 연결한다.
  5. 작은 공개 텍스트 문제에서 단순 Baseline과 사전학습 Transformer를 같은 Split·Metric으로 비교해 1차 순환을 닫는다.

현재 관문과 그다음 전환
회원 이탈 scikit-learn Baseline과 PyTorch nn.Module·Optimizer, 작은 회귀 데이터의 Batch 학습을 검증했고 같은 회원 이탈 Split에 Train·Validation DataLoader·MLP Forward·SGD 한 Step까지 연결했다. 다음에는 Linear 파라미터·Shape를 재확인한 뒤 한 Batch 과적합과 Train·Validation Metric을 만들고, 저장·복원·간단한 추론 API를 마친다. 이후 Tiny Decoder LM과 사전학습 텍스트 모델 적용까지 연결해 1차 순환을 닫는다.
