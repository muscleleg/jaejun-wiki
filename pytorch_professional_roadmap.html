  6. 6KV Cache·Batch

    PyTorch 추론 Baseline

    현재

    성취 목표

  8. 8TP·NCCL

    Multi-GPU 분산 추론

    핵심 종착점

    성취 목표
    작은 Tensor로 AllReduce·AllGather·ReduceScatter의 입출력 Shape·값·통신 Byte를 먼저 검산합니다. 이어 Tensor Parallel 1·2·4 GPU를 같은 조건에서 실행하고 GPU 수가 늘 때 연산과 통신이 어떻게 나뉘는지 확인하며, nvidia-smi topo -m·nccl-tests·NVLink·PCIe를 실제 Scaling 결과에 연결합니다.

    완료 조건
    세 Collective 결과와 통신량을 직접 계산한 뒤 GPU 수별 Throughput·TTFT·TPOT·GPU당 VRAM과 Scaling Efficiency 표를 만들고, 선형 확장을 막는 통신 병목을 근거로 설명하면 핵심 여정이 완료됩니다. 이후 측정된 필요가 있을 때만 Prefill/Decode 분리·NIXL·RDMA로 확장합니다.

현재 코어에 이미 포함문제 정의, Train·Validation 분할, 전처리, Baseline, Metric, PyTorch 학습 루프, Transformer 손코딩, 사전학습 Causal LM Forward·수동 생성, 저장·추론은 기존 1차 순환을 그대로 사용한다. 같은 내용을 과정별로 반복 추가하지 않는다.
기존 깊이 후보를 강화머신러닝에는 L1·L2 Regularization, Stratified Cross-validation, RandomForest 또는 Gradient Boosting 한 모델, 작은 하이퍼파라미터 탐색과 Feature Importance를 같은 평가 계약 안에서 선택한다. PyTorch에는 이미지 분류, RNN/LSTM 비교, AutoEncoder를 실제 문제의 필요가 있을 때만 연다.
텍스트 적용에서 선택현재 코어는 Decoder-only 사전학습 Causal LM의 Forward·수동 생성이다. BERT 계열 Encoder-only 분류와 Marian 계열 Encoder-Decoder 번역·Cross-Attention은 첫 순환 뒤 선택 분기로만 두며 진행률 조건에 포함하지 않는다. Accuracy·F1, Perplexity와 생성 오류 분석, BLEU·ROUGE 같은 Metric은 실제 과제가 요구할 때 선택한다.
새 독립 확장으로 분리Artifact·Canary·Monitoring·Drift·재학습은 MLOps·모델 운영으로, Graph Schema·GraphRAG·Ontology 또는 Tool Loop·실패 복구·MCP·Agent 평가는 Knowledge Graph·Agent Harness로 분리했다.
목록만으로는 추가하지 않음모든 ML 알고리즘, 모든 CNN·RNN 구조, 여러 UI Framework, 여러 산업별 예제 프로젝트를 각각 챕터로 만들지 않는다. 현재 결과물의 오류나 요구사항이 선택 근거를 줄 때 하나만 구현한다.

지금 가장 효율적인 다음 관문

완료한 기반을 다시 반복하지 않고 학습 기록의 핵심 여정을 그대로 따른다. 아래 순서는 다른 프로젝트나 확장 후보가 자동으로 바꿀 수 없다.

  1. 현재 · 사전학습 Causal LM: Tokenizer·동적 Padding 첫 Batch → [B,S,V] Forward → 마지막 위치 Logit 기반 수동 생성 → 평가·저장·복원을 연결한다.
  2. 다음 · PyTorch 추론 Baseline: 같은 모델·Prompt에서 No-cache와 KV Cache, Batch 1과 Batch N을 비교하고 latency·memory·품질 기준선을 고정한다.
  3. 이후 · vLLM Benchmark·관측: 같은 Benchmark 계약으로 vLLM을 비교하고 TTFT·TPOT·throughput·peak VRAM과 GPU 상태를 함께 측정한다.
  4. 핵심 종착점 · Multi-GPU: Tensor Parallel 1·2·4 GPU의 Scaling과 NCCL·Topology·AllReduce 통신 병목을 수치로 설명한다.
