백엔드 경험 위에,

약 4년간 Kubernetes 클러스터 관리 솔루션의 백엔드와 배포·모니터링·로그·백업 기능을 개발했습니다.

현재는 이 경험을 LLM 기반 시스템으로 확장하고 있습니다. RAG 서비스와 파인튜닝 프로젝트를 구현하고, PyTorch로 모델의 추론 구조를 직접 확인하며 vLLM 서빙을 검증합니다. 기능 구현뿐 아니라 출력 정확성과 실행 비용을 측정하고, 차이가 생기는 원인을 추적합니다.

How I work

문제를 기능으로 만들고, 결과를 검증합니다.

백엔드 API, 프론트엔드와 Kubernetes 운영 기능을 함께 구현해 왔습니다. 개인 AI 프로젝트에서도 모델 호출에 그치지 않고 데이터 준비, 서비스 연결, 평가와 오류 분석까지 직접 다룹니다.

운영을 아는 구현자배포·모니터링·로그·백업처럼 실제 운영에 필요한 기능을 개발했습니다.
경계를 넘나드는 개발자백엔드뿐 아니라 프론트엔드, Kubernetes와 데이터 흐름까지 연결합니다.
검증하는 AI 개발자모델 호출에 그치지 않고 데이터셋·평가·오류 분석·서빙까지 확인합니다.

모델 이해부터 추론 서버 성능 분석까지

PyTorch와 Transformer의 동작 원리부터 단일 GPU 추론 서버의 성능 측정·병목 분석까지 학습하고 실험했습니다. 이를 바탕으로 Kubernetes 기반 GPU 클러스터 운영과 Multi-GPU 분산 추론으로 범위를 넓혀가고 있습니다.

Tensor와 계산 그래프부터 Autograd·Optimizer·DataLoader·학습 루프·저장 복원까지 구성요소의 책임을 익힌다.

Embedding·위치 정보·Attention·정규화를 연결해 Decoder를 구성하고, 사전학습 모델 적용과 오프라인 복원까지 확인한다.

Cache·Batch·장치 이동·동기화를 분리 측정하고, PyTorch와 vLLM을 비교할 모델·입력·생성·측정 조건을 정의한다.

GPU 한 장에서 vLLM 서버를 실행하고, 스케줄링·KV Cache·성능 측정을 통해 서비스 품질을 지킬 수 있는 부하와 병목을 확인한다.

원하는 상태를 실제 Pod 실행으로 만드는 컴포넌트의 책임부터 Linux 네트워크와 Service Data Plane을 거쳐 대상 Pod까지 요청이 전달되는 전체 흐름을 연결해 이해한다.

GPU 자원 할당과 노드 배치부터 요청 라우팅, 자동 확장, 장애 대응까지 Kubernetes에서 추론 서버를 운영하는 구조를 익힌다.

여러 GPU와 노드에 추론을 나누고, Tensor Parallel·GPU 간 통신·KV Cache 전송이 처리량과 지연에 미치는 영향을 확인한다.
