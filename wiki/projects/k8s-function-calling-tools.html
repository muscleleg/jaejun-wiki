모델에게 공개한 다섯 개의 조회 전용 도구와 각 인자 계약을 정리한다. 이 페이지의 도구는 실행 handler가 아니라 Function Calling 학습·평가에 사용한 Schema다.

프로젝트 구현 범위데이터셋 상세
도구5개
유형조회 전용
호출요청당 1개
출력tool_calls / no-call
책임 경계도구 목록인자 규칙출력 계약

1. 도구의 책임 경계

한국어 요청 + 전체 tools Schema
        ↓
Qwen3-1.7B Function Calling 라우터
        ↓
도구명 + arguments를 담은 tool_calls 후보
        ↓
서버가 allowlist·JSON·Schema·권한 검증
        ↓
실제 Kubernetes handler 실행(이번 프로젝트 범위 밖)

따라서 아래 다섯 도구의 이름을 학습했다고 해서 모델이 Kubernetes를 직접 조회한 것은 아니다. 모델의 책임은 어떤 도구를 선택하고 어떤 인자를 넣을지 제안하는 데서 끝난다.

2. 제공한 다섯 도구

원본 계약은 프로젝트의 schemas/kubernetes_tools.json 하나에서 관리하고, 데이터 생성·학습·평가가 같은 계약을 재사용했다.

도구역할인자정답 생성 원칙
list_pods네임스페이스의 파드 목록 조회namespace?, label_selector?말한 네임스페이스와 label만 포함
get_pod특정 파드의 상세 상태 조회pod_name, namespace?pod_name은 필수
get_pod_logs특정 파드 컨테이너 로그 조회pod_name, namespace?, container?, tail_lines?, previous?사용자가 말한 옵션만 포함
list_deployments네임스페이스의 Deployment 목록 조회namespace?, label_selector?Deployment와 selector 의미를 구분
get_eventsKubernetes 이벤트 조회namespace?, resource_kind?, resource_name?, event_type?Pod/Deployment, Normal/Warning enum 준수

3. 인자 계약이 막는 실수

필수 인자get_pod와 get_pod_logs는 pod_name이 없으면 유효하지 않다.
선택 인자물음표가 붙은 필드는 사용자가 말했을 때만 넣는다. 서버 실행기의 기본값과 모델 출력은 구분한다.
추가 키 금지additionalProperties: false로 Schema에 없는 인자를 거절한다.
enum 고정resource_kind와 event_type은 허용된 대소문자까지 정확히 맞춰야 한다.
strict exact match
실행 결과가 같아 보이는 호출도 정답에 없는 기본값을 임의로 추가하거나 enum의 대소문자를 바꾸면 이 프로젝트의 strict 평가에서는 실패한다.

4. 모델이 반환해야 한 출력

{
  "tool_calls": [{
    "type": "function",
    "function": {
      "name": "get_pod_logs",
      "arguments": {
        "namespace": "production",
        "pod_name": "payment-api",
        "tail_lines": 100
      }
    }
  }]
}

삭제·재시작·스케일 변경처럼 제공한 조회 도구로 처리할 수 없는 요청에는 tool_calls를 만들지 않는 no-call 응답이 정답이다. OpenAI-compatible 응답의 실제 추출 위치와 채점 순서는 구현 범위의 출력 계약에 연결해 두었다.
