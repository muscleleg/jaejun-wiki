1. 데이터의 목적

한 행은 한국어 사용자 요청과 전체 다섯 도구 목록, 정답 assistant 응답으로 이루어진 단일 턴 예제다. 조회 요청에는 정확한 도구 호출을 넣고, 삭제·재시작·일반 질문처럼 허용된 도구가 없는 요청에는 no-call 응답을 넣었다.

3. 한 행의 구조

{
  "id": "train-list-pods-0001",
  "category": "list_pods",
  "tools": ["list_pods", "get_pod", "get_pod_logs", "list_deployments", "get_events"],
  "messages": [
    {"role": "user", "content": "운영계 파드 목록을 보여줘"},
    {"role": "assistant", "tool_calls": [{
      "function": {"name": "list_pods", "arguments": {"namespace": "production"}}
    }]}
  ]
}

학습 데이터 안의 arguments는 객체로 보관한다. Qwen chat template이 이를 직렬화하고, API 평가 단계에서는 모델이 반환한 JSON 문자열을 다시 파싱해 Schema와 정답 인자를 검사한다.

4. 왜 학습 전에 Holdout을 고정했는가

파인튜닝 전 원본 모델과 파인튜닝 후 모델을 같은 100건에 보내야 모델 변화만 비교할 수 있다. 그래서 먼저 base BF16 모델을 평가하고, 학습·adapter 병합 뒤 같은 데이터와 같은 추론 조건으로 tuned 모델을 다시 평가했다.

5. 데이터셋의 한계

Holdout의 문장은 학습 문장과 겹치지 않지만, 모두 같은 템플릿과 분포에서 생성됐다. 따라서 96%라는 결과는 이 과제 분포에서의 일반화이며, 실제 운영자가 작성한 새로운 표현까지 잘 처리한다는 증거는 아니다.

다음 평가에서는 실제 사용자 표현, 오타, 생략, 여러 의도가 섞인 요청을 별도 수집해 외부 일반화 성능을 확인해야 한다.
