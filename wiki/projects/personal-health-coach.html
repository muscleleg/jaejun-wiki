개인화 헬스 기록 코치

코딩 에이전트와 자연어로 대화하면 운동·식사·체성분이 날짜별 구조화 기록으로 정리되고, 같은 데이터에서 통계·시각화·다음 행동을 만드는 개인 헬스 기록 하네스입니다. 한 번 입력한 기록을 월별 운동 빈도, 종목별 수행 이력, 근육 자극 분포, 영양 구성과 체성분 추세에 함께 사용합니다.

목적은 기록을 많이 모으는 것이 아니라, 제가 실제로 어떤 운동과 식사를 이어 가고 있는지 빠르게 확인하는 것입니다. 기록이 쌓이면 현재 루틴을 유지할지, 운동 강도를 조정할지, 다음 식사에서 무엇을 보완할지를 판단하는 근거로 사용합니다.

프로젝트 형태 코딩 에이전트가 자연어 입력을 기록으로 바꾸고, JSON 형태의 데이터를 정적 웹 대시보드와 연결하는 개인 시스템입니다. 사용자는 별도의 입력 양식을 채우지 않고 그날의 운동과 식사를 말하며, 에이전트는 기존 기록과 규칙을 읽어 같은 날짜의 데이터와 코칭 결과를 갱신합니다. 현재 에이전트가 맡는 자연어 해석과 기록 갱신을 Function Tool 기반 입력으로 분리하고 챗봇이 해당 도구를 호출하도록 연결하면, 기존 데이터 계약과 통계·시각화 로직을 활용하는 애플리케이션으로 확장할 수 있습니다.

실제 공개 화면 아래 대시보드에서 누적 기록이 홈 코칭 요약, 운동 캘린더, 수행 이력, 근육 자극 지도, 영양과 체성분 화면으로 다시 사용되는 모습을 직접 확인할 수 있습니다.

개발 배경

운동과 식사를 꾸준히 기록하더라도, 기억만으로는 한 달의 운동 빈도와 반복한 종목, 자극 부위와 영양 구성을 함께 파악하기 어렵습니다.

하루의 운동을 마친 직후에는 어떤 종목을 몇 세트 수행했는지 기억할 수 있습니다. 하지만 기록이 여러 주 쌓이면 한 달 동안 며칠을 운동했는지, 특정 운동을 얼마나 반복했는지, 어떤 부위에 자극이 집중되었는지를 다시 확인하기 위해 과거 메모를 하나씩 읽어야 합니다. 먹은 음식도 비슷합니다. 그날 먹은 메뉴는 기억할 수 있지만 열량과 단백질, 탄수화물, 지방과 같은 영양 구성이 어떤 흐름으로 누적되는지는 따로 정리하지 않으면 보이지 않습니다.

이러한 정보를 한곳에 계속 쌓고 필요할 때 바로 확인하기 위해 프로젝트를 시작했습니다. 첫 번째 목적은 조언을 받는 것이 아니라 제가 실제로 어떤 운동과 식사를 이어 가고 있는지 정확히 확인하는 것이었습니다. 이후 기록이 쌓이면서 운동 강도와 자극 분포, 영양 구성과 누락된 정보를 함께 해석하고 다음 행동을 제안하는 코칭 기능으로 확장했습니다.

기존 방식 기억과 흩어진 메모에 의존

월별 운동일과 종목별 변화, 영양 패턴을 확인할 때 과거 기록을 다시 읽어야 했습니다.

개선 방식 날짜별 원본에서 필요한 화면을 자동 구성

한 번 기록한 내용을 캘린더·수행 이력·자극 지도·영양 분석과 코칭에 다시 사용합니다.

핵심 목표

기록을 많이 보관하는 것보다, 시간이 지나도 원하는 정보를 빠르게 찾아 현재 패턴을 이해할 수 있도록 만드는 데 초점을 맞췄습니다.

  1. 01
    일일 기록의 지속적인 축적

    운동·식사·체성분을 같은 날짜의 기록으로 관리하고 과거 내용을 삭제하거나 최신 값으로 덮어쓰지 않습니다.

  2. 02
    월별 운동 빈도의 빠른 확인

    운동한 날짜를 캘린더에서 확인하고 월별 운동일과 기록된 종목 수를 별도 계산 없이 파악합니다.

  3. 03
    운동 자극과 영양 구성의 시각화

    어떤 운동을 반복했고 어느 부위가 자극되었는지, 먹은 음식에 어떤 영양 성분이 포함되었는지를 화면으로 확인합니다.

  4. 04
    누적 기록의 다음 행동 전환

    기록이 쌓인 뒤에는 현재 패턴과 빠진 정보를 분석해 다음 운동과 식사에서 필요한 행동을 제안합니다.

주요 기능

기능은 하루의 기록을 남기는 데서 시작해 월별 빈도와 수행 변화, 자극 부위와 영양·체성분 추세를 확인하고, 마지막에는 다음 운동과 식사에서 필요한 행동으로 연결됩니다.

  1. 01
    일일 기록 관리 대화로 남긴 운동·식사·체성분을 같은 날짜의 기록에 축적합니다.
  2. 02
    월별 운동 캘린더 실제로 운동한 날짜와 월별 운동 빈도를 한눈에 확인합니다.
  3. 03
    운동 수행 이력 종목별 중량·세트·반복 수와 수행 품질을 과거 기록과 비교합니다.
  4. 04
    근육 자극 시각화 최근 운동이 어느 부위에 집중되었는지 인체 도해로 확인합니다.
  5. 05
    식사·영양 성분 분석 불확실성을 포함한 섭취 범위와 주요 영양 구성을 확인합니다.
  6. 06
    체성분 변화 분석 지표별 실제 측정일을 보존하며 최신 상태와 장기 추세를 봅니다.
  7. 07
    기록 기반 코칭 누적 기록을 비교해 지금 유지할 것과 다음 행동을 제안합니다.
기능 01

일일 기록 관리

사용자는 정해진 입력 양식을 작성하지 않고 그날 수행한 운동과 먹은 음식, 체성분 측정 결과를 대화하듯 남길 수 있습니다. 시스템은 내용을 날짜·운동·식사·측정값과 수행 상태로 구분해 기존 기록에 추가합니다.

같은 날짜에 식사를 먼저 기록하고 나중에 운동을 추가하더라도 새로운 날짜를 중복 생성하지 않습니다. 이미 저장된 식사나 측정값을 유지하면서 새 정보만 합칩니다. 사용자가 말하지 않은 체성분 값이나 운동 여부는 이전 값으로 채우지 않으며, 확인되지 않은 항목은 미기록 상태로 남겨 이후 화면에서도 사실처럼 표시되지 않도록 합니다.

  1. 입력 자연어 기록 운동·식사·체성분과 컨디션을 전달합니다.
  2. 구분 사실과 누락 확인 제공된 값과 확인되지 않은 값을 나눕니다.
  3. 저장 같은 날짜에 병합 과거 기록을 보존하며 새 내용만 추가합니다.
  4. 반영 관련 화면 재계산 요약·캘린더·분석·코칭을 갱신합니다.

사용자가 얻는 변화 입력 양식을 채우는 수고 없이 대화에 집중하면서도, 말하지 않은 값이 임의로 채워지지 않는 신뢰 가능한 일일 기록을 남길 수 있습니다.

구현 상세 날짜별 단일 원본·병합·누락값 처리

날짜별 단일 원본

모든 기록은 날짜를 기준으로 하나의 항목에 보관합니다. 운동은 운동 사전의 안정적인 ID를 참조하고, 그날의 중량·세트·반복 수·난이도·자세만 날짜 기록에 저장합니다. 식사와 체성분도 같은 날짜 항목을 확장하는 방식으로 누적합니다.

누락값 처리

체중·골격근량·체지방량·체수분 중 제공되지 않은 값은 이전 측정값으로 채우지 않습니다. 식사나 체성분만 알려 주고 운동 여부를 말하지 않은 날은 휴식일로 추정하지 않고 운동 여부 미기록으로 구분합니다. 사용자가 운동하지 않았다고 명시한 경우에만 빈 운동 배열과 휴식 상태를 저장합니다.

기능 02

월별 운동 캘린더

운동 기록이 있는 날짜를 월별 캘린더에 표시합니다. 사용자는 기록 전체를 다시 세지 않아도 이번 달에 며칠 운동했고 각 날짜에 몇 종목을 수행했는지 한눈에 확인할 수 있습니다.

캘린더는 단순히 날짜 기록이 존재하는지를 기준으로 표시하지 않습니다. 실제 운동 항목이 있는 날짜만 운동일로 계산하며, 식사나 체성분만 기록한 날과 명시적인 휴식일은 운동일에서 제외합니다. 특정 날짜를 선택하면 해당 날짜의 운동 수행 기록을 확인할 수 있어 월별 빈도와 개별 수행 내용을 자연스럽게 이어서 볼 수 있습니다.

  1. 조회 선택한 월의 기록 확인 날짜별 원본에서 해당 월을 찾습니다.
  2. 판정 실제 운동일 구분 운동 항목이 있는 날짜만 표시합니다.
  3. 집계 운동일·종목 수 계산 월별 빈도와 기록 규모를 요약합니다.
  4. 탐색 날짜별 기록 연결 선택한 날의 수행 내용으로 이동합니다.

사용자가 얻는 변화 날짜별 원본을 다시 세지 않아도 이번 달의 실제 운동 빈도와 각 운동일의 기록 규모를 즉시 확인할 수 있습니다.

구현 상세 운동일 판정·월별 집계·휴식일 구분

운동일 판정

날짜 기록에 운동 배열이 존재하고 실제 운동 항목이 하나 이상 있을 때만 운동일로 처리합니다. 빈 운동 배열은 명시적인 휴식 상태로 보존하지만 캘린더의 운동일에는 포함하지 않습니다. 운동 필드가 없는 날짜는 운동 여부 미기록으로 남깁니다.

파생 집계

월별 운동일 수와 기록된 종목 수는 캘린더용 숫자를 따로 저장하지 않고 날짜별 기록에서 계산합니다. 새로운 운동 기록이 추가되면 별도의 월 목록을 수정하지 않아도 같은 계산을 통해 캘린더가 갱신됩니다.

기능 03

운동 수행 이력

종목별 중량·세트·반복 수와 수행 품질을 날짜 순서로 확인합니다. 같은 운동을 이전보다 안정적으로 수행했는지, 현재 강도를 유지할지 조정할지를 과거 기록과 함께 판단할 수 있습니다.

모든 세트를 완료했다는 사실만으로 중량을 올리지는 않습니다. 마지막 세트에서 몇 회를 더 수행할 수 있었는지를 나타내는 여유 반복 수(RIR), 자세 유지 여부, 통증이나 중단 기록을 함께 확인합니다. 세트별 반복 수가 다를 때는 하나의 평균값으로 뭉개지 않고 각 세트의 실제 반복 수를 보존합니다.

수행 조정

반복 미달·중단·통증 기록이 있으면 먼저 수행을 안정화합니다.

판단 보류

세트를 완료했어도 RIR이나 난이도가 없으면 증량을 단정하지 않습니다.

증량 후보

명시된 수행 품질 조건을 연속으로 충족했을 때만 최소 단위 증량을 제안합니다.

사용자가 얻는 변화 단순 완료 횟수가 아니라 실제 수행 품질을 과거와 비교해, 무리한 증량을 피하고 현재 강도를 유지하거나 조정할 근거를 얻습니다.

계산 및 판정 기준 세트별 반복·RIR·자세·통증·연속 성공

보수적인 증량 규칙

자세를 유지하며 목표 반복 수를 완료하고 마지막 세트에 정해진 여유가 있었다는 기록이 연속된 운동일에서 확인될 때만 증량 후보로 분류합니다. 수행 품질 정보가 부족하면 현재 설정을 유지하고 다음 판단에 필요한 입력을 요청합니다.

장비 해석

어시스트 머신처럼 화면의 숫자가 보조 중량인지 실제 저항인지 불분명한 장비는 확인 전까지 표시 중량으로 기록합니다. 불확실한 장비 수치를 다른 외부 중량과 같은 의미로 비교하지 않습니다.

기능 04

근육 자극 시각화

최근 운동에서 사용한 주동근과 보조근을 앞·뒤 인체 도해에 연결합니다. 어떤 부위를 충분히 사용했고 어느 부위의 직접 자극이 적었는지 운동 목록을 다시 읽지 않고 확인할 수 있습니다.

기본 화면은 최근 최대 3회의 운동 기록을 합산합니다. 사용자는 전체 기간뿐 아니라 특정 날짜 또는 특정 운동을 선택해 자극 분포를 다시 볼 수 있습니다. 운동을 선택하면 같은 종목의 과거 수행 이력도 함께 확인할 수 있어 자극 부위와 수행 변화를 연결해 살펴볼 수 있습니다.

사용자가 얻는 변화 운동 이름을 하나씩 되짚지 않아도 최근 루틴의 자극이 어디에 집중되었는지 확인하고, 다음 루틴에서 보완할 부위를 찾을 수 있습니다.

구현 상세 운동 사전·주동근·보조근·인체 영역 연결

근육 매핑

운동 사전에는 각 종목의 주동근과 보조근을 정의하고, 별도의 근육 지도 설정에서 근육 이름을 인체 도해 영역과 연결합니다. 운동 세트와 주동근·보조근 가중치를 합산해 부위별 상대 자극 단계를 계산합니다.

해석 범위

이 지도는 실제 근전도나 근활성도 측정 결과가 아닙니다. 기록된 운동 세트와 근육 분류를 바탕으로 만든 상대적인 운동 분포이므로, 운동 구성의 균형을 확인하는 참고 정보로 사용합니다.

기능 05

식사·영양 성분 분석

날짜별로 먹은 음식을 아침·점심·저녁·간식으로 나누어 보관하고, 열량과 단백질을 비롯한 주요 영양 성분의 추정 범위를 확인합니다.

음식의 제품명이나 양이 정확할 때는 확인 가능한 영양 정보를 사용합니다. 양을 알려 주지 않은 일반 음식은 기록을 포기하지 않고 보편적인 1인분을 가정해 최소·최대 범위로 추정합니다. 사용자가 제공한 사실, 외부에서 확인한 제품 정보, 표준 1인분을 바탕으로 한 추정치를 구분하고 어떤 음식 때문에 불확실성이 커졌는지도 함께 표시합니다.

식사 정보가 충분한 날에는 열량·단백질·탄수화물·지방·포화지방·유리당·식이섬유·나트륨을 확인할 수 있습니다. 단순 합계를 보여 주는 데서 끝나지 않고 목표 또는 상한과 비교해 부족·충족·초과 가능성을 표시하고 다음 식사에서 보완할 행동을 제안합니다.

사용자가 얻는 변화 음식의 양이 정확하지 않은 날도 기록을 포기하지 않고 추정 범위로 남기며, 다음 식사에서 부족한 영양소를 무엇으로 보완할지 판단할 수 있습니다.

구현 상세 범위 추정·출처·신뢰도·영양 기준

범위 추정

양이 불명확한 음식은 단일 숫자를 확정값처럼 저장하지 않습니다. 최소·최대 범위, 대표값, 가정과 신뢰도를 보존하고 일일 합계도 같은 범위로 계산합니다. 먹을 예정인 음식은 실제 섭취와 분리해 현재 합계에서 제외합니다.

기준 적용

에너지와 주요 영양소는 공개된 집단 참고치와 운동 목표를 함께 참고합니다. 단백질은 운동 목표에 맞춘 체중당 목표를 사용하고, 포화지방·유리당·나트륨은 상한 중심으로 비교합니다. 개인의 실제 필요량과 다를 수 있다는 조건을 화면에 함께 표시합니다.

기능 06

체성분 변화 분석

체중·골격근량·체지방량·체수분을 날짜별로 보존하고, 각 지표의 최신 상태와 누적 변화를 확인합니다. 한 번의 측정값보다 비슷한 조건에서 반복된 장기 추세를 중심으로 해석합니다.

모든 지표가 같은 날 측정된다고 가정하지 않습니다. 최신 기록에 체수분이 없더라도 이전 값을 최신 날짜의 원본으로 복사하지 않고, 체수분을 실제로 측정한 가장 최근 날짜와 함께 표시합니다. 체중과 체성분 값이 충분하면 BMI, 체지방률, FMI, FFMI, 체수분 비율과 같은 파생 지표를 다시 계산합니다.

사용자가 얻는 변화 한 번의 측정값에 흔들리지 않고 지표별 실제 측정일과 장기 추세를 함께 보며 몸의 변화를 더 보수적으로 해석할 수 있습니다.

계산 및 해석 기준 최신값 선택·파생 지표·장기 추세

지표별 최신값

체중·골격근량·체지방량·체수분은 각각 실제 값이 존재하는 가장 최근 기록을 선택합니다. 더 최신인 불완전한 기록이 과거의 유효한 측정 화면을 비우지 않도록 하면서도, 과거 값을 새 날짜의 사실로 복사하지는 않습니다.

해석 한계

체성분은 측정 기기와 시간, 수분 상태에 따라 달라질 수 있습니다. 서로 다른 조건의 단일 측정값으로 근육 증가나 체지방 감소를 단정하지 않으며, 의료 진단이나 치료 판단을 제공하지 않습니다.

기능 07

기록 기반 코칭

홈 화면은 기록을 시간순으로 나열하기보다 최근 기록에서 확인한 판단과 다음 행동을 먼저 보여 줍니다. 사용자는 전체 데이터를 다시 해석하지 않고 현재 유지할 것과 다음에 보완할 입력을 확인할 수 있습니다.

최근 7일 요약은 컴퓨터의 오늘이 아니라 실제 최신 원본 기록일을 기준으로 계산합니다. 데이터 입력이 잠시 멈추더라도 빈 기간 때문에 최근 코칭이 사라지지 않도록 하기 위한 기준입니다. 운동 빈도·총세트·자극 분포·식사 기록과 누락된 수행 품질을 함께 살펴보고, 현재 가장 중요한 행동을 우선순위로 제시합니다.

사용자가 얻는 변화 누적 기록을 매번 직접 해석하지 않아도 지금 유지할 것, 다음에 바꿀 것, 판단을 위해 추가로 기록할 것을 한 번에 확인할 수 있습니다.

판정 기준 최근 기록 기준일·우선순위·누락 입력

코칭 입력

운동 구성과 빈도, 종목별 수행 품질, 근육 자극 분포, 영양 추정과 체성분 추세를 함께 참고합니다. 동일한 기준으로 다시 계산할 수 있는 값과 AI가 작성한 해석을 분리해 저장합니다.

현재 입력부

사용자가 대화로 사실을 제공하면 코딩 에이전트가 저장소 규칙과 누적 기록을 읽고, 자연어를 날짜별 운동·식사·체성분 데이터로 바꾸어 새 코칭과 함께 갱신합니다.

기록이 다음 행동으로 이어지는 과정

이 프로젝트의 핵심은 기록을 쌓는 데서 끝나지 않고, 같은 기록을 여러 관점에서 확인한 뒤 다음 운동과 식사의 행동으로 되돌리는 데 있습니다.

1. 기록 입력 사용자가 그날의 운동·식사·체성분과 수행 상태를 대화로 전달합니다.

2. 날짜별 정리 제공된 사실과 누락된 값을 구분하고, JSON 형태의 날짜별 객체로 정리해 같은 날짜의 기존 기록에 병합합니다.

3. 파생 화면 갱신 월별 운동일, 수행 이력, 자극 분포, 영양 구성과 체성분 추세를 다시 계산합니다.

4. 현재 상태 해석 누적 기록과 명시된 기준을 비교해 유지할 내용과 보완할 정보를 정리합니다.

5. 다음 행동 연결 사용자는 제안된 항목을 다음 운동과 식사에서 실행하고 새로운 기록을 남깁니다.

순환의 결과 기록할수록 과거를 다시 세고 해석하는 시간은 줄어들고, 지금 유지할 행동과 다음에 바꿀 행동은 더 분명해집니다.

기록과 코칭의 역할과 경계

사용자가 실제 행동과 목표를 결정하고, AI가 기록 정리와 비교를 보조하며, 정적 대시보드는 저장된 결과를 다시 확인하는 화면이 됩니다.

자연어 입력과 JSON 기록, 정적 대시보드를 분리한 개인 시스템입력 채널을 Function Tool을 호출하는 챗봇으로 바꾸어도 같은 데이터 계약과 화면 계산을 재사용할 수 있습니다.
  1. 01
    기록사용자가 운동·식사·체성분과 컨디션을 전달합니다.

    통증과 회복 상태처럼 본인만 확인할 수 있는 정보도 판단 근거로 제공합니다.

  2. 02
    정리·비교AI가 날짜별 기록과 기준을 읽고 새 사실과 해석을 구분합니다.

    불확실한 영양 정보는 범위와 가정으로 표시하고, 누적 기록과 비교해 다음 행동을 제안합니다.

  3. 03
    확인정적 대시보드가 같은 원본에서 계산한 결과를 여러 화면으로 보여 줍니다.

    요약·캘린더·수행 이력·자극 지도·영양·체성분 화면에서 같은 기록을 다시 확인합니다.

데이터와 화면의 분리

공개 구현의 날짜별 원본은 date, workouts, meals, body, advice, actions 같은 필드를 가진 JSON 형태의 객체로 보존합니다. 월별 운동일과 최근 7일 통계, 영양 범위와 근육 자극 분포는 이 원본을 읽어 계산하므로 화면마다 같은 데이터를 다시 작성하지 않습니다.

현재 코딩 에이전트는 사용자의 문장에서 운동·식사·체성분 값을 꺼내고, 기존 날짜 기록과 합치는 입력부 역할을 합니다. 애플리케이션에서는 이 동작을 운동 기록, 식사 기록, 체성분 기록 같은 Function Tool로 나눌 수 있습니다. 챗봇이 자연어에서 필요한 도구와 인자를 선택하고, 도구 실행부가 값을 검증해 기존 JSON 데이터 구조에 저장하는 방식입니다.

이렇게 입력부를 교체해도 날짜별 데이터 계약, 월별·최근 통계 계산, 근육 자극과 영양 분석, 화면 렌더링은 그대로 재사용할 수 있습니다. 애플리케이션 전환 시 새로 구현할 영역은 챗봇 화면, Function Tool 실행 API와 영속 저장소이며, 현재 프로젝트는 그 전환에 사용할 기록 스키마와 계산·시각화 규칙을 이미 분리해 두었습니다.

역할의 경계

사용자 역할

운동과 체형의 목표를 정하고 실제 수행·식사·측정 결과를 제공합니다. 고정 루틴을 유지하거나 바꿀지 최종적으로 선택하며, 통증과 회복 상태처럼 본인만 확인할 수 있는 정보를 판단 입력으로 제공합니다. 공개할 정보의 범위와 화면의 우선순위도 사용자가 결정합니다.

AI 활용 범위

자연어 기록을 날짜별 구조로 정리하고 누적 기록과 명시된 정책을 비교합니다. 불확실한 영양 정보는 범위와 가정으로 표시하고, 현재 상태에 대한 설명과 다음 행동을 제안합니다. 데이터·링크·반응형 화면과 공개 안전 검증도 보조합니다.

자동화의 한계 AI는 사용자의 수행과 컨디션을 직접 관측하거나 장기 목표를 임의로 바꾸지 않습니다. 기록되지 않은 사실을 확정하지 않으며 의료 진단과 치료 판단을 제공하지 않습니다.

날짜별 기록

운동·식사·체성분과 날짜별 AI 분석 결과를 보존합니다. 화면별 요약 숫자와 날짜 목록은 별도 원본으로 만들지 않습니다.

도메인 기준

운동명과 주동근·보조근은 운동 사전, 고정 정보는 프로필, 참고 범위는 체성분 기준, 최근 집계와 증량·영양 규칙은 코칭 정책, 인체 영역 연결은 근육 매핑에서 관리합니다.

HTML은 화면 구조, CSS는 반응형 레이아웃과 인체 도해, JavaScript는 데이터 결합·파생 계산·렌더링과 화면 전환을 담당합니다. 현재는 저장소의 JSON 기록을 공개 화면으로 보여 줍니다.

애플리케이션 전환 지점

코딩 에이전트의 자연어 해석과 기록 병합을 Function Tool로 옮기고 챗봇이 도구를 호출하게 하면, 입력 방식만 대화형 애플리케이션으로 바꾸면서 날짜·운동·식사·측정·코칭 데이터 계약과 기존 화면을 유지할 수 있습니다.

사용자가 말한 사실, 같은 입력에서 다시 계산할 수 있는 값, AI가 작성한 해석을 분리하고 여러 화면이 같은 원본을 가리키는지 확인합니다.

사용자 사실
말한 내용만 원본 기록으로 보존합니다.

운동·식사·측정값과 컨디션을 날짜별로 남기며, 제공하지 않은 값은 이전 기록이나 추정치로 채우지 않습니다.

재현 가능한 계산
같은 기록과 기준에서 같은 결과가 나오도록 합니다.

월별 운동일, 최근 집계, BMI·FMI·FFMI, 영양 충족도와 자극 점수는 명시된 규칙으로 계산합니다.

AI 해석
판단과 추정은 사실과 다른 층에 남깁니다.

코칭 요약·다음 행동·영양 추정에는 판단 날짜, 가정, 범위와 신뢰도를 함께 기록합니다.

교차 확인
한 기록이 연결된 모든 화면에서 일치하는지 검사합니다.

요약·캘린더·수행 이력·자극 지도·영양·체성분 화면과 공개 범위를 함께 확인합니다.

현재는 한 사람의 목표와 기록 방식을 위한 개인 시스템이며, 입력은 코딩 에이전트와의 대화를 통해 갱신합니다. 영양값과 운동 자극은 실제 섭취량이나 근활성도 측정값이 아닌 근거가 표시된 추정치입니다.

검증 항목 데이터·계산·화면·공개 안전

데이터 검증

  • 같은 날짜가 한 번만 존재하는지 확인합니다.
  • 모든 운동 ID가 운동 사전에 등록되어 있는지 확인합니다.
  • 과거 기록이 보존되고 사용자 사실과 AI 추정 필드가 분리되어 있는지 확인합니다.
  • 최신값과 최근 7일 집계의 기준 날짜가 원본 기록과 일치하는지 확인합니다.

화면 검증

  • 홈·운동·신체·식사·원본 데이터 화면의 파생값이 같은 원본을 가리키는지 확인합니다.
  • 데스크톱 상단 탐색과 모바일 하단 탐색의 현재 화면 표시와 이동을 확인합니다.
  • 빈 값·부분 기록·불확실한 식사 입력이 확정값처럼 표시되지 않는지 확인합니다.
  • 콘솔 오류, 링크, 공개 페이지 응답과 시각 자료의 로딩을 확인합니다.

검증의 목적 기록 → 계산 → 해석 → 다음 행동의 각 단계가 추적 가능해야 하며, 체성분 분석과 코칭은 의료 진단이나 전문가의 판단을 대신하지 않습니다.
