목적
Transformer를 “Token끼리 정보를 섞는다”는 한 문장으로 외우지 않고, [B,S,D] Tensor가 어떤 코드와 Shape을 거쳐 위치별 문맥 벡터가 되는지 직접 확인하려고 했습니다. 각 연산은 왜 필요한지, 무엇을 보존하고 무엇을 바꾸는지, 작은 숫자로 검산할 수 있는지를 기준으로 한 Block을 조립했습니다.

질문 01

Token ID는 어떻게 의미 벡터와 위치 정보를 얻는가?

사용한 코드 nn.Embedding·torch.arange·학습형 Position Embedding·sin/cos div_term

확인할 이해 Token과 위치는 같은 [B,S,D] Shape에서 원소별로 더해지며, embedding_dim은 벡터 열 수이고 초기화 표준편차와는 다른 설정입니다.

질문 03

왜 Score를 √head_dim으로 나누고 미래 위치를 -inf로 바꾸는가?

질문 05

Attention 결과를 왜 Residual·LayerNorm·FFN에 다시 통과시키는가?

사용한 코드 x + attention_output·LayerNorm(D)·Linear(D,d_ff)·GELU·Linear(d_ff,D)

확인할 이해 Residual은 기존 정보를 보존한 채 새 문맥을 더하고, LayerNorm은 Token별 중심·규모를 정돈합니다. FFN은 Token을 서로 섞지 않고 각 위치의 특징 표현을 넓혔다 줄입니다.

1. 모든 계산은 [Batch, Token 위치, Feature]에서 시작했습니다

[B,S,D]=[1,3,2]를 “Batch 1개, 문장 3개, Token 2개”로 읽으면 뒤의 모든 Shape이 어긋납니다. 여기서는 문장 1개가 Batch에 들어 있고, 그 문장 안에 Token 위치가 3개 있으며, 각 Token을 길이 2인 벡터로 표현합니다.

B = Batch 안의 문장 수
S = 문장마다 정렬된 Token 위치 수
D = Token 하나를 표현하는 Feature 수

[1,3,2]
└ 문장 1개
  ├ 위치 0 → [특징 2개]
  ├ 위치 1 → [특징 2개]
  └ 위치 2 → [특징 2개]

Attention은 Token 위치끼리 정보를 주고받게 하지만 위치 축을 하나로 합치지 않습니다. 그래서 입력과 Block 출력은 모두 [B,S,D]이고, 각 위치는 자신이 참고할 수 있었던 Token들의 문맥이 반영된 벡터를 하나씩 유지합니다.

2. 한 Block의 실행 순서

Token IDs [B,S]
  ↓ Token Embedding + Position Embedding
Hidden [B,S,D]
  ↓ Q·K·V Linear, Head 분리
[B,H,S,head_dim]
  ↓ Q @ Kᵀ / √head_dim
Score [B,H,S,S]
  ↓ Causal Mask → Softmax → @ V
Head Output [B,H,S,head_dim]
  ↓ Token 축 기준 재정렬 → Head 병합 → W_O
Attention Output [B,S,D]
  ↓ Residual + LayerNorm
  ↓ FFN(D→d_ff→D) + Residual + LayerNorm
Block Output [B,S,D]

Attention은 Token 위치 사이의 정보를 섞지만 FFN은 이미 문맥이 들어간 각 Token의 마지막 Feature 축을 독립적으로 확장·GELU·축소합니다. 어느 단계도 Token 세 개를 하나의 Token으로 합치지 않습니다.

3. Token 의미와 위치 정보를 같은 Shape으로 더했습니다

nn.Embedding은 정수 ID를 행 번호로 받아 학습 가능한 벡터를 돌려주는 조회표입니다. Embedding(10,2)의 Weight는 [10,2]이고, Token ID 3,7,2를 넣으면 해당 세 행을 꺼내 [1,3,2]를 만듭니다. 같은 ID는 문맥 계산 전에는 항상 같은 Token Embedding 행을 조회합니다.

Token Embedding Weight [vocab_size=10, d_model=2]
Token IDs [1,3] → Token vectors [1,3,2]

Position Embedding Weight [max_seq_len=8, d_model=2]
Position IDs [1,3] → Position vectors [1,3,2]

Hidden = Token vectors + Position vectors
       = [1,3,2]

위치 정보는 고정 sin·cos 수식으로 만들 수도 있고 nn.Embedding(max_seq_len,d_model) 같은 학습형 표로 만들 수도 있습니다. 두 방식을 나중에 합치는 것이 아니라 위치 벡터를 만드는 서로 다른 선택지입니다. nn.Embedding 자체는 Token과 위치를 구분하지 않으며 어떤 ID를 넣고 어디에 더하는지가 역할을 정합니다.

# 고정 sin·cos 위치 벡터의 핵심 Shape
position = torch.arange(S).unsqueeze(1)       # [S,1]
div_term = torch.exp(
    torch.arange(0, D, 2) * (-math.log(10000.0) / D)
)                                             # [D/2]

pe[:, 0::2] = torch.sin(position * div_term) # 짝수 차원
pe[:, 1::2] = torch.cos(position * div_term) # 홀수 차원

torch.exp(x)는 자연상수 e의 x제곱을 원소별로 계산합니다. 차원 index가 커질수록 div_term이 작아져 위치에 따라 느리게 변하는 파형이 되고, 작은 index에서는 더 빠르게 변합니다. 짝수·홀수 차원에 sin·cos를 반씩 배치해 위치마다 여러 주기의 패턴을 갖게 합니다.

초기 Token 벡터의 전체 제곱합 기댓값을 약 1로 두려면 원소 분산은 약 1/D, 표준편차는 1/√D가 됩니다. 고전적인 Transformer에서는 이처럼 작은 Embedding에 √D를 곱해 위치 벡터와 더하기 전 크기를 끌어올립니다. 이것은 뒤에서 Attention Score를 √head_dim으로 나누는 연산과 목적이 다른 별도 Scaling입니다.

4. 같은 입력을 서로 다른 Linear로 보아 Q·K·V를 만들었습니다

Query·Key·Value는 입력 Tensor를 복사해 이름만 바꾼 것이 아닙니다. 각각 별도의 Linear(D,D) Weight를 통과하므로 Shape은 [B,S,D]로 같아도 값과 학습 역할이 다릅니다.

Q = x @ W_Qᵀ + b_Q  # 무엇을 찾는가
K = x @ W_Kᵀ + b_K  # 어떤 조건으로 발견되는가
V = x @ W_Vᵀ + b_V  # 발견됐을 때 가져올 내용

x [1,3,2]
Q [1,3,2]
K [1,3,2]
V [1,3,2]

nn.Linear는 입력의 마지막 축에만 같은 행렬을 적용하므로 Batch와 Token 위치 수는 보존됩니다. 실제로 한 Token 벡터에 대해 x @ weight.T를 직접 계산하고 Linear 결과와 torch.allclose()로 비교했습니다. Key 계산에서 Query Projection을 잘못 재사용한 오타도 이 별도 Weight 경계를 확인하며 발견했습니다.

5. QKᵀ의 합이 커지는 이유를 분산으로 따라갔습니다

한 Query와 한 Key의 Score는 같은 위치의 Feature끼리 곱한 뒤 모두 더한 숫자 하나입니다. head_dim=2이면 Score=A+B, head_dim=k이면 독립적인 항 k개의 합으로 봅니다.

Score = q₁k₁ + q₂k₂ + ... + qₖkₖ

각 항의 평균 ≈ 0, 분산 ≈ 1, 서로 독립이라고 단순화하면
Var(Score) ≈ 1 + 1 + ... + 1 = k
Std(Score) ≈ √k

Scaled Score = Score / √head_dim
→ 표준편차 규모를 다시 약 1로 완화

A,B∈{-1,1}인 작은 예에서 가능한 Score는 [2,0,0,-2]입니다. 평균은 0이고, 분산은 (2²+0²+0²+(-2)²)/4=2, 표준편차는 √2입니다. 중요한 것은 A와 B 두 숫자의 분산을 구하는 것이 아니라, 여러 입력에서 매번 A+B로 만든 Score 집단의 퍼짐을 보는 것입니다.

√head_dim은 현재 Q·K의 실제 표준편차를 측정한 정확한 정규화가 아닙니다. 중심 0·비슷한 분산·약한 상관이라는 초기화 근사 아래에서 차원이 커질수록 Softmax 입력이 과도하게 벌어지는 현상을 줄이는 고정 Scaling입니다.

6. Causal Mask는 Shape을 바꾸지 않고 선택 비중을 0으로 만듭니다

torch.tril()로 현재 위치와 과거 위치만 True인 하삼각 Boolean Mask를 만들었습니다. ~causal_mask는 이를 뒤집어 미래 위치가 True인 “금지 위치” Mask로 만들고, masked_fill(...,-inf)로 해당 Score를 음의 무한대로 바꿉니다.

허용 Mask
[[ True, False, False],
 [ True,  True, False],
 [ True,  True,  True]]

Softmax(zᵢ) = exp(zᵢ) / Σ exp(zⱼ)
exp(-inf) = 0
→ 미래 위치의 Attention Weight = 0

Softmax는 원래 점수의 단순 합 비율이 아니라 각 점수에 지수함수 exp를 적용한 양수들의 비율입니다. 첫 행에서 자기 자신만 허용된다면 나머지는 0이므로 허용 칸의 비율은 1이 됩니다. dim=-1은 각 Query 행에서 마지막 Key 축의 합이 1이 되도록 계산한다는 뜻입니다.

7. Attention Weight는 Value 벡터를 실제로 섞는 비율입니다

Q·K로 만든 Weight는 관계 점수이고, 그 자체가 Token의 새 내용은 아닙니다. 각 Query 행의 Weight를 대응하는 Value 벡터에 곱해 더해야 문맥이 반영된 출력이 됩니다.

Query 2의 Weight = [a₃, a₄]
Value 1 = V₁
Value 2 = V₂

Output 2 = a₃ × V₁ + a₄ × V₂

첫 번째 Query의 실제 Weight [0.5084,0.4916]에 두 Value를 곱해 더한 결과 [-0.0971,0.0557]이 코드의 output[0,0]과 일치함을 확인했습니다. 이 계산을 통해 “Token끼리 정보를 주고받는다”는 말은 다른 Token 자체를 복사하는 것이 아니라, 현재 Query가 정한 비율로 여러 Value의 특징을 가중합한다는 의미로 구체화됐습니다.

8. Head를 나눴다가 Token별로 다시 모았습니다

D를 여러 Head가 나눠 서로 다른 Projection 관점으로 관계를 계산합니다. D=2, Head 2개라면 head_dim=1입니다. Token을 둘로 늘리는 것이 아니라 Token마다 가진 Feature 축을 Head별로 분리합니다.

[B,S,D]
→ reshape [B,S,H,head_dim]
→ transpose [B,H,S,head_dim]
→ Head별 Attention
→ transpose [B,S,H,head_dim]
→ reshape [B,S,D]
→ Output Projection W_O [B,S,D]

transpose(1,2)로 Head A·B의 결과를 Token별로 다시 모은 뒤에야 reshape(B,S,D)로 합칠 수 있습니다. 이어 붙이기만 한 결과는 Head 특징이 나열된 상태이므로 W_O가 학습 가능한 비율로 다시 섞습니다. 한 Token의 multi_head_output @ W_O.T를 직접 계산해 nn.Linear의 Output Projection과 일치하는 것도 확인했습니다.

9. Causal Multi-Head Attention 핵심 코드

class CausalMultiHeadAttention(nn.Module):
    def __init__(self, d_model: int, num_heads: int) -> None:
        super().__init__()
        assert d_model % num_heads == 0
        self.d_model = d_model
        self.num_heads = num_heads
        self.head_dim = d_model // num_heads
        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model)
        self.v_proj = nn.Linear(d_model, d_model)
        self.out_proj = nn.Linear(d_model, d_model)

    def forward(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        batch_size, token_count, _ = x.shape
        query = self.q_proj(x)
        key = self.k_proj(x)
        value = self.v_proj(x)

        def split_heads(tensor: torch.Tensor) -> torch.Tensor:
            return tensor.reshape(
                batch_size, token_count, self.num_heads, self.head_dim
            ).transpose(1, 2)

        query_heads = split_heads(query)
        key_heads = split_heads(key)
        value_heads = split_heads(value)

        scores = query_heads @ key_heads.transpose(-2, -1)
        scores = scores / (self.head_dim ** 0.5)
        causal_mask = torch.tril(torch.ones(
            token_count, token_count, dtype=torch.bool, device=x.device
        ))
        scores = scores.masked_fill(~causal_mask, float("-inf"))
        attention_weights = torch.softmax(scores, dim=-1)
        head_outputs = attention_weights @ value_heads

        outputs_by_token = head_outputs.transpose(1, 2).contiguous()
        multi_head_output = outputs_by_token.reshape(
            batch_size, token_count, self.d_model
        )
        return self.out_proj(multi_head_output), attention_weights

10. Residual·LayerNorm·FFN 조립

class CausalTransformerBlock(nn.Module):
    def __init__(self, d_model: int, num_heads: int, d_ff: int) -> None:
        super().__init__()
        self.attention = CausalMultiHeadAttention(d_model, num_heads)
        self.norm1 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU(),
            nn.Linear(d_ff, d_model),
        )
        self.norm2 = nn.LayerNorm(d_model)

    def forward(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        attention_output, attention_weights = self.attention(x)
        after_attention = self.norm1(x + attention_output)
        ffn_output = self.ffn(after_attention)
        block_output = self.norm2(after_attention + ffn_output)
        return block_output, attention_weights

첫 Residual은 x + attention_output이고, FFN에는 이 합을 정리한 after_attention이 들어갑니다. 두 번째 Residual의 기준도 원래 최초 x가 아니라 after_attention + ffn_output입니다. FFN은 각 Token마다 D→d_ff→D로 특징을 넓혀 GELU로 반응을 조절하고 다시 줄입니다.

LayerNorm은 값을 0~1로 제한하거나 튀는 원소만 제거하는 연산이 아닙니다. 각 Token의 마지막 Feature 축 평균을 빼고 표준편차 규모로 나눈 뒤 학습 가능한 scale과 bias를 적용합니다. Residual과 Linear를 반복하며 값의 중심·크기가 흔들려도 다음 층이 다루기 쉬운 범위로 정돈합니다.

입력 Shape:              [1, 3, 2]

Attention Weight Shape: [1, 2, 3, 3]

Head 0 Attention 예:
[[1.0000, 0.0000, 0.0000],

첫 Token은 자기 자신만, 둘째 Token은 0·1번 위치만, 셋째 Token은 0·1·2번 위치를 봅니다. 이 병렬 계산 구조가 뒤의 LM Head에서 위치마다 “그 Prefix 다음 Token” 후보 점수를 만들 수 있는 기반입니다.

12. 오래 걸렸던 의문과 수정

왜 √head_dim으로 나누나독립적인 항의 합은 항 수만큼 분산이 커지고 표준편차는 √항 수만큼 커지므로, 나눠 Softmax 입력 규모가 차원과 함께 폭증하는 것을 줄였습니다.
~causal_mask허용 위치 True를 뒤집어 금지 위치 True로 만든 뒤 그 위치를 -inf로 채웠습니다. Softmax에서 exp(-inf)=0이 됩니다.
Value 수동 검산 실패둘째 출력에서 Weight만 더해 False가 남았고, 올바른 식은 a₃×V₁ + a₄×V₂처럼 각 Attention Weight에 대응 Value 벡터를 곱해 더하는 것입니다.
Projection 오타Key 계산에 Query Projection을 재사용한 코드를 key_projection(x)로 수정하고 두 Weight가 별도 학습 파라미터임을 확인했습니다.
Head 병합[B,H,S,head_dim]을 바로 reshape하지 않고 transpose(1,2)로 Token별 Head를 다시 모은 뒤 [B,S,D]로 합쳤습니다.
Embedding 차원 오해embedding_dim은 초기화 표준편차가 아니라 벡터 하나의 열 수입니다. 초기화 std는 별도 함수에서 정하고, num_embeddings는 조회 가능한 행 수입니다.
차원과 차수45개 입력 같은 “Feature 차원”과 수학식의 1차·2차를 구분했습니다. Linear는 여러 입력을 받더라도 제곱항이 없는 1차식의 묶음입니다.

13. 확인된 완료 증거

  • Token·Position Embedding에서 Block Output까지 핵심 Shape을 순서대로 예측했습니다.
  • Q·K·V와 Score가 Token별 문맥을 어떻게 만드는지 Shape과 미래 Mask 값으로 설명했습니다.
  • Score 항 두 개의 분산 2·표준편차 √2를 작은 경우로 계산하고 일반 √head_dim Scaling과 연결했습니다.
  • Attention Weight와 Value의 가중합을 실제 숫자로 계산해 출력과 비교했습니다.
  • Attention 뒤와 FFN 뒤에 각각 현재 입력을 Residual로 더하고 LayerNorm하는 순서를 재구성했습니다.
  • outputs_by_token.reshape(B,S,D)가 여러 Head를 원래 모델 차원으로 합치는 코드라고 설명했습니다.
