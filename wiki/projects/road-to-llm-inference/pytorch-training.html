1. 완성 결과 미리보기

고정 Batch를 10,000번 학습하면 Loss가 0.00069까지 내려가고 같은 Batch Accuracy는 1.0이 되었지만 Validation Accuracy는 71.19%였습니다. 이것을 과적합 진단으로 사용한 뒤 새 모델을 전체 Train DataLoader로 20 Epoch 학습해 Validation Accuracy 78.99%, 이탈 Label 1의 Recall 35.56%를 얻었습니다.

중요한 구분
Batch 64는 모델 입력 Feature 수가 아닙니다. Batch 크기는 한 번의 수정에 쓰는 행 수이고, Linear(45, 16)이 요구하는 마지막 축 45가 고정 Feature 수입니다.

2. Pandas에서 Tensor까지 정보의 역할이 바뀝니다

원본 X_train은 열 이름과 dtype을 가진 Pandas DataFrame입니다. ColumnTransformer를 거치면 모델 계산에 필요한 숫자만 남은 NumPy 배열이 되고, PyTorch 학습에는 다시 torch.float32 Tensor가 필요합니다. “같은 표의 다른 표현”이지만 각 단계가 제공하는 기능은 다릅니다.

Pandas DataFrame
열 이름·index·dtype을 보존하며 전처리 대상을 선택
        ↓ preprocessor
NumPy ndarray
전처리된 숫자 행렬과 Shape 중심
        ↓ torch.tensor(..., dtype=torch.float32)
PyTorch Tensor
Gradient·GPU·nn.Module 연산에 참여

Label y_train은 Pandas Series [5634]였습니다. to_numpy() 뒤 reshape(-1, 1)을 사용해 행 수는 전체 원소 수에 맞춰 자동 계산하고 열은 1개로 고정했습니다. 따라서 [5634]가 [5634,1]이 되어 모델 Logit [Batch,1]과 Shape이 맞습니다.

3. TensorDataset은 짝을 묶고 DataLoader는 Batch를 꺼냅니다

TensorDataset(X, y)은 같은 행 번호의 입력과 정답을 한 Sample로 묶습니다. 실제 행렬 계산을 수행하는 모델이 아니라, dataset[0]처럼 한 쌍을 꺼낼 수 있는 Dataset입니다. DataLoader는 이 Dataset의 index를 순회하며 여러 Sample을 한 Batch로 쌓습니다.

TensorDataset 길이 = 고객 수 5,634
한 Sample:
  x [45]
  y [1]

DataLoader(batch_size=64)의 한 Batch:
  batch_x [64,45]
  batch_y [64,1]

iter(train_loader) → Batch를 순서대로 꺼내는 iterator
next(...)          → 현재 iterator의 Batch 하나

마지막 Batch는 남은 행 수만큼만 나올 수 있습니다. Batch 64는 모델의 고정 입력 크기가 아니라 한 번의 Weight 수정에 사용하는 고객 수입니다. 그래서 추론 때는 고객 1명도 [1,45]로 넣을 수 있지만 Feature 마지막 축 45는 반드시 맞아야 합니다.

4. 데이터와 파라미터 Shape

Pandas X_train [5634, 19]
  ↓ preprocessor.fit_transform
NumPy X_train_processed [5634, 45]
  ↓ torch.tensor(dtype=torch.float32)
X_train_tensor [5634, 45]
y_train_tensor [5634, 1]
  ↓ TensorDataset → DataLoader(batch_size=64)
Batch X [64, 45] / Batch y [64, 1]
  ↓ Linear(45,16) → ReLU → Linear(16,1)
Logit [64, 1]

첫 Linear: Weight 16×45 = 720, Bias 16
둘째 Linear: Weight 1×16 = 16, Bias 1
총 학습 파라미터 = 720 + 16 + 16 + 1 = 753

Linear(45,16)은 Weight 45개짜리 1차식이 16개 있다는 뜻입니다. 각 식은 45개 입력을 서로 다른 Weight로 조합하고 자기 Bias 하나를 더해 출력 하나를 만듭니다. 따라서 첫 층은 Weight 16×45=720개와 Bias 16개를 학습합니다. “45차 함수”가 아니라 변수 45개를 사용하는 1차식 16개의 묶음입니다.

5. Logit을 Label에 맞춰 BCE로 채점합니다

마지막 Linear(16,1)은 음수·양수 제한이 없는 Logit을 냅니다. ReLU는 Hidden Layer에만 있으므로 최종 Logit은 -0.4도 100도 될 수 있습니다. sigmoid는 이를 0과 1 사이 출력으로 바꾸며 현재 Label 계약에서는 1인 이탈 쪽 점수로 읽습니다.

sigmoid(z) = 1 / (1 + exp(-z))

실제 Label y=1: Loss = -log(p)
실제 Label y=0: Loss = -log(1-p)

Batch BCE = 고객별 BCE를 모두 더한 뒤 고객 수로 나눈 값

예를 들어 실제 정답이 0이고 sigmoid 출력이 0.4352라면 맞힌 쪽의 크기는 1-0.4352=0.5648이고 Loss는 -log(0.5648)입니다. 정답이 1이면 -log(0.4352)를 사용합니다. 정답 쪽 출력이 1에 가까울수록 -log 값은 0에 가까워지고, 자신 있게 틀릴수록 크게 벌점이 납니다.

사용자가 처음 떠올린 (출력-정답)²의 평균도 가능한 Loss이며 이름은 MSE(평균제곱오차)입니다. 분산은 각 값에서 데이터 평균을 빼지만 MSE는 예측에서 정답을 뺍니다. 이진 분류에서는 정답 Label 쪽을 로그로 강하게 채점하는 BCE를 사용했고, BCEWithLogitsLoss는 sigmoid와 BCE를 수치적으로 안정적인 한 연산으로 계산합니다.

초기 Logit: [-0.2608, -0.2874, -0.4080]
sigmoid 출력: [0.4352, 0.4286, 0.3994]
실제 Label: [0, 0, 0]
초기 평균 Loss: 0.656400
한 번 수정 후 Loss: 0.651151

6. 한 Batch의 평균 Loss로 전체 파라미터를 한 번 수정합니다

optimizer.zero_grad()  # 이전 Batch의 Gradient 제거
logits = model(batch_x) # [64,45] → [64,1]
loss = loss_fn(logits, batch_y) # 고객 64명의 평균 BCE
loss.backward()        # 753개 파라미터의 Gradient 계산
optimizer.step()       # SGD가 lr만큼 Weight·Bias 수정

고객마다 따로 backward()하는 것이 아니라 Batch 전체를 한 번에 Forward하고, Batch 안 고객별 Loss의 평균 하나에서 Gradient를 구해 한 번 수정했습니다. SGD(확률적 경사 하강법)는 파라미터를 대략 parameter -= learning_rate × gradient 방향으로 움직입니다. zero_grad()를 빼면 PyTorch가 이전 Gradient를 누적하므로 매 Batch 시작에 초기화했습니다.

7. 같은 Batch 암기와 Validation 일반화를 분리했습니다

고정한 고객 64명만 1,000번 반복 학습했을 때 Loss는 0.6932 → 0.0228로 내려갔고 같은 Batch Accuracy는 1.0이 됐습니다. 그러나 Validation 전체 Accuracy는 약 69.77%였습니다. 이 실험은 “많이 학습하면 무조건 좋아진다”가 아니라, 본 데이터에 대한 성능과 보지 않은 데이터의 일반화가 다르다는 것을 보여줬습니다.

같은 64명: Accuracy 1.0
Validation 전체: Accuracy 약 0.6977

→ 64명을 잘 외웠다는 증거
→ 전체 고객에게 일반화됐다는 증거는 아님

이후 모델을 새로 초기화하고 전체 Train DataLoader를 20 Epoch 순회해 Validation Accuracy 78.99%를 얻었습니다. 고정 Batch 실험과 전체 학습 모델을 같은 객체의 연속 결과처럼 섞지 않고, 과적합 확인용과 최종 평가용으로 구분했습니다.

8. Batch별 평균이 아니라 전체 행 수를 누적했습니다

각 Batch에서 predictions == valid_y를 계산하면 고객별 True·False가 나옵니다. 이를 float()로 1·0으로 바꿔 같은 Batch 평균을 낼 수 있지만, Validation 전체는 마지막 Batch 크기가 다를 수 있으므로 Batch Accuracy의 단순 평균 대신 맞힌 고객 수와 전체 고객 수를 누적했습니다.

correct_count += (predictions == valid_y).sum().item()
total_count += valid_y.shape[0]
validation_accuracy = correct_count / total_count

true_positive_count += (
    (predictions == 1) & (valid_y == 1)
).sum().item()
actual_positive_count += (valid_y == 1).sum().item()
yes_recall = true_positive_count / actual_positive_count

numel()은 Tensor의 전체 원소 수이므로 Target이 [64,2]가 되면 128을 셉니다. 이번 Target은 고객당 하나인 [Batch,1]이므로 우연히 행 수와 같았습니다. “고객 수”를 뜻하려는 현재 Metric에서는 valid_y.shape[0]이 의도를 더 직접 드러냅니다.

9. 학습·평가·복원의 통합 코드

import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

X_train_tensor = torch.tensor(X_train_processed, dtype=torch.float32)
y_train_tensor = torch.tensor(y_train.to_numpy(), dtype=torch.float32).reshape(-1, 1)
X_valid_tensor = torch.tensor(X_valid_processed, dtype=torch.float32)
y_valid_tensor = torch.tensor(y_valid.to_numpy(), dtype=torch.float32).reshape(-1, 1)

train_loader = DataLoader(
    TensorDataset(X_train_tensor, y_train_tensor),
    batch_size=64,
    shuffle=True,
)
valid_loader = DataLoader(
    TensorDataset(X_valid_tensor, y_valid_tensor),
    batch_size=64,
)

class ChurnMLP(nn.Module):
    def __init__(self) -> None:
        super().__init__()
        self.network = nn.Sequential(
            nn.Linear(45, 16),
            nn.ReLU(),
            nn.Linear(16, 1),
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.network(x)

model = ChurnMLP()
loss_fn = nn.BCEWithLogitsLoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

for epoch in range(20):
    model.train()
    for batch_x, batch_y in train_loader:
        optimizer.zero_grad()
        logits = model(batch_x)
        loss = loss_fn(logits, batch_y)
        loss.backward()
        optimizer.step()

model.eval()
correct_count = 0
total_count = 0
true_positive_count = 0
actual_positive_count = 0
with torch.no_grad():
    for valid_x, valid_y in valid_loader:
        logits = model(valid_x)
        predictions = (torch.sigmoid(logits) >= 0.5).float()
        correct_count += (predictions == valid_y).sum().item()
        total_count += valid_y.shape[0]
        true_positive_count += ((predictions == 1) & (valid_y == 1)).sum().item()
        actual_positive_count += (valid_y == 1).sum().item()

10. Weight 복원과 원본 고객 한 명의 추론까지 이어졌습니다

state_dict에는 Linear 층의 학습된 Weight와 Bias가 이름별 Tensor로 저장됩니다. 모델 구조 자체를 새로 만드는 코드는 따로 필요하므로 같은 ChurnMLP 인스턴스를 만든 뒤 Weight를 로드했습니다. eval()은 평가 모드로 전환하고 torch.no_grad()는 추론 중 계산 그래프를 만들지 않게 합니다.

torch.save(model.state_dict(), "churn_mlp_state.pt")

restored_model = ChurnMLP()
restored_model.load_state_dict(
    torch.load("churn_mlp_state.pt", weights_only=True)
)
restored_model.eval()

with torch.no_grad():
    outputs_match = torch.allclose(
        model(X_valid_tensor[:3]),
        restored_model(X_valid_tensor[:3]),
    )

원본 고객 한 명은 X_valid.iloc[[0]]으로 가져왔습니다. iloc[[0]]은 0번째 행을 DataFrame [1,19]로 유지하지만 X_valid[0]은 0이라는 열 이름을 찾으려 하기 때문에 행 선택 문법이 아닙니다. 이 원본 행은 아직 19열이므로 반드시 학습 때 저장한 preprocessor.transform()을 거쳐 [1,45]로 만든 뒤 Tensor로 넣었습니다.

one_customer = X_valid.iloc[[0]]              # Pandas [1,19]
processed = preprocessor.transform(one_customer) # NumPy [1,45]
customer_tensor = torch.tensor(processed, dtype=torch.float32)

with torch.no_grad():
    customer_logit = restored_model(customer_tensor)
    customer_value = torch.sigmoid(customer_logit)

Train과 Validation에 같은 전처리 기준을 썼던 이유와 똑같이, 새 고객도 같은 범주 열 순서와 숫자 Scaling을 써야 학습된 Weight가 의미 있는 입력을 받습니다. 모델 Weight만 저장하면 이 전처리 계약까지 자동 보존되지는 않는다는 배포 한계도 확인했습니다.

11. 막혔던 지점과 수정

TensorDataset TypeErrorValidation에 NumPy 배열을 넣자 NumPy의 .size 정수 속성을 Tensor의 .size(0) 메서드처럼 호출해 오류가 났습니다. 모든 입력을 torch.Tensor로 통일했습니다.
.float.mean()float는 메서드이므로 .float().mean()으로 호출했습니다.
고정 Batch 1.0암기한 64행의 정확도만으로 일반화를 주장하지 않고 Validation 전체를 별도로 평가했습니다.
Batch와 Feature[64,45]에서 64는 바뀔 수 있는 고객 수, 45는 Linear(45,16) 때문에 고정되는 Feature 축으로 교정했습니다.
새 고객 추론원본 Pandas 한 행은 먼저 저장된 전처리 기준으로 19열에서 45열로 바꾼 뒤 Tensor [1,45]로 넣었습니다.
