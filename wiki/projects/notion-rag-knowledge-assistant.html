Notion RAG 개인 지식 비서

Notion에 쌓인 개인 문서를 서비스로 가져와 질문의 근거로 검색하고, 선택한 문서로 퀴즈를 만들어 결과와 오답까지 이어 가는 지식 활용 서비스입니다. 문서를 다시 읽는 데서 끝내지 않고 질문·확인·복습의 재료로 사용하도록 설계했습니다.

사용자는 Notion URL 또는 페이지 ID로 문서를 등록하고, 필요한 문서를 골라 질문하거나 퀴즈를 시작합니다. 답변에는 검색한 원문 링크가 남고, 퀴즈의 점수·오답·해설은 이후 복습과 통계에 다시 사용됩니다.

프로젝트 형태FastAPI와 Next.js로 구현한 1인 개발 웹 애플리케이션입니다. PostgreSQL에는 사용자·문서·대화·학습 이력을, Qdrant에는 문서 임베딩을 저장하고, OpenAI API를 문서 기반 답변과 퀴즈 생성에 사용했습니다.

개인 프로젝트 목록

개발 배경

Notion에는 다시 볼 가치가 있는 문서가 계속 쌓였지만, 필요한 내용을 찾으려면 문서를 하나씩 열어 읽어야 했고 읽은 내용을 실제로 기억하는지 확인할 방법은 따로 없었습니다.

검색만 추가하면 필요한 문서를 찾는 시간은 줄일 수 있지만, 질문에 대한 답이 어느 문서에서 왔는지 확인하기 어렵고 읽은 내용을 능동적으로 복습하기도 어렵습니다. 반대로 퀴즈만 만들면 어떤 문서를 기준으로 문제가 생성되었는지와 이후 오답이 어디에 남는지가 분리될 수 있습니다.

그래서 문서 수집, 검색을 근거로 한 질의응답, 선택 문서 기반 퀴즈, 채점과 오답·통계를 하나의 흐름으로 연결했습니다. 목적은 새로운 검색 알고리즘을 만드는 것이 아니라 이미 작성한 개인 문서를 질문과 복습에 계속 재사용할 수 있는 실제 애플리케이션을 만드는 것이었습니다.

기존 방식문서를 찾고 다시 읽는 데서 끝납니다.

답을 찾더라도 출처 확인, 이해 점검, 오답 복습과 학습 이력이 서로 분리됩니다.

개선 방식같은 문서가 질문과 복습의 공통 근거가 됩니다.

문서를 한 번 등록하면 근거 기반 채팅, 퀴즈, 결과와 통계에서 계속 사용할 수 있습니다.

핵심 목표

문서를 많이 저장하는 것보다, 이미 작성한 문서를 필요한 순간에 근거와 함께 꺼내고 실제 이해 여부까지 확인하는 데 초점을 맞췄습니다.

  1. 01
    개인 문서의 지속적인 재사용

    Notion 원문을 서비스로 가져와 검색·질문·퀴즈가 공유하는 데이터로 만듭니다.

  2. 02
    출처를 확인할 수 있는 답변

    질문과 관련된 문서를 먼저 찾고 답변 아래에 참고한 Notion 문서 링크를 남깁니다.

  3. 03
    읽기에서 능동적인 복습으로 전환

    선택한 문서의 핵심 내용을 객관식 문제와 해설로 바꾸어 실제로 기억하는지 확인합니다.

  4. 04
    결과와 오답의 누적

    점수·정오·해설과 문서별 풀이 기록을 저장해 이전 학습을 다시 확인합니다.

주요 기능

기능은 문서를 서비스에 가져오는 데서 시작해, 같은 문서를 질문의 근거와 퀴즈의 범위로 사용하고, 결과와 오답을 다음 복습에 남기는 순서로 이어집니다.

  1. 01
    Notion 문서 수집과 검색 준비URL 또는 페이지 ID로 원문을 가져와 본문·이미지·검색 벡터를 함께 준비합니다.
  2. 02
    근거 기반 실시간 질문관련 문서를 먼저 검색하고 출처 링크가 포함된 답변을 실시간으로 전달합니다.
  3. 03
    선택 문서 퀴즈와 즉시 채점사용자가 고른 문서의 핵심 내용을 문제로 만들고 정오와 해설을 바로 보여 줍니다.
  4. 04
    오답·통계·학습 이력점수와 틀린 문제를 저장해 이전 결과와 문서별 학습 상태를 다시 확인합니다.
기능 01

Notion 문서 수집과 검색 준비

Notion URL 또는 페이지 ID만 입력하면 원문을 서비스 안에서 읽고 검색할 수 있는 상태로 준비합니다.

간단한 등록문서를 다시 복사해 붙여 넣지 않습니다.

사용자가 문서 위치를 입력하면 백엔드가 본문과 이미지를 수집하고 원문의 구조를 가능한 한 유지한 Markdown으로 변환합니다.

공통 문서 원본한 번 수집한 문서를 질문과 퀴즈에서 함께 사용합니다.

문서 메타데이터와 변환한 본문은 PostgreSQL에, 본문을 검색하기 위한 임베딩은 Qdrant에 저장합니다. 사용자는 목록에서 문서를 골라 채팅하거나 퀴즈를 만들 수 있습니다.

사용자가 얻는 변화이미 작성한 Notion 문서를 새로운 서비스에 다시 정리하지 않고도 검색·질문·복습에 바로 재사용할 수 있습니다.

수집 파이프라인 보기수집·변환·이미지 보존·임베딩
  1. Frontend가 FastAPI /notion/fetch에 수집을 요청합니다.
  2. 백엔드가 Notion 문서를 조회하고 HTML을 파싱합니다.
  3. 문서 이미지를 별도로 저장하고 본문을 Markdown으로 변환합니다.
  4. PostgreSQL에 문서 메타데이터와 본문을 저장합니다.
  5. 임베딩을 생성해 Qdrant에 문서 벡터를 저장합니다.
기능 02

근거 기반 실시간 질문

질문과 관련된 문서를 먼저 찾고, 참고한 원문 링크가 포함된 답변을 실시간으로 전달합니다.

검색 후 답변생성 모델이 문서 없이 바로 답하지 않습니다.

질문과 의미가 가까운 문서를 Qdrant에서 찾은 뒤, 검색 결과를 답변에 사용할 문맥으로 구성합니다. OpenAI API가 이 문맥을 바탕으로 답변을 생성합니다.

출처 확인
사용자가 답변의 근거를 직접 열어 봅니다.

답변 아래의 Notion 링크를 통해 어떤 문서가 검색되었는지 확인할 수 있습니다.

대화 유지
채팅방과 메시지를 저장해 이전 질문에서 이어갑니다.

WebSocket으로 답변을 스트리밍하고, 대화 이력은 PostgreSQL에 보존합니다.

사용자가 얻는 변화긴 문서를 처음부터 다시 읽지 않고 필요한 내용을 질문으로 찾으면서도, 답변만 믿지 않고 원문 근거를 바로 확인할 수 있습니다.

RAG 처리 흐름 보기벡터 검색·답변 생성·WebSocket·대화 저장
  1. Frontend가 사용자 질문을 WebSocket으로 전송합니다.
  2. FastAPI Chat Handler가 질문과 유사한 문서를 검색합니다.
  3. Qdrant 검색 결과로 답변용 문맥을 구성합니다.
  4. OpenAI API가 문맥 기반 답변을 생성하고 스트리밍합니다.
  5. 답변에 참고한 Notion 문서 링크를 함께 제공합니다.
  6. 채팅방과 메시지를 PostgreSQL에 저장합니다.
기능 03

선택 문서 퀴즈와 즉시 채점

검색과 답변에서 끝내지 않고, 사용자가 고른 문서의 핵심 내용을 문제로 바꾸어 실제로 기억하는지 확인합니다.

범위 선택전체 문서가 아니라 지금 복습할 문서만 고릅니다.

특정 문서 여러 개 또는 최근 문서를 기준으로 퀴즈 생성을 요청할 수 있습니다. 선택한 문서 본문이 문제 생성의 범위가 됩니다.

즉시 확인정답 여부와 이유를 같은 화면에서 확인합니다.

OpenAI API가 선택 문서의 핵심 내용을 바탕으로 객관식 문제·정답·해설을 구성하고, 사용자가 답을 고르면 백엔드가 점수를 계산합니다.

사용자가 얻는 변화문서를 읽었다는 사실이 아니라 핵심 내용을 실제로 구분할 수 있는지 확인하고, 틀린 이유를 해설과 원문으로 바로 복습할 수 있습니다.

퀴즈 처리 흐름 보기문서 선택·문제 생성·채점·결과 저장
  1. 사용자가 특정 문서 또는 최근 문서를 선택합니다.
  2. FastAPI /quiz/generate가 PostgreSQL에서 대상 문서를 조회합니다.
  3. OpenAI API가 문서의 핵심 내용을 기반으로 객관식 문제·정답·해설을 생성합니다.
  4. Frontend가 문제를 표시하고 사용자가 답안을 제출합니다.
  5. 백엔드가 점수를 계산하고 PostgreSQL에 결과를 저장합니다.
  6. Statistics API가 문서별 정답률과 풀이 수를 조회합니다.
기능 04

오답·통계·학습 이력

퀴즈 결과를 단발성 응답으로 끝내지 않고, 틀린 문제와 이전 학습 상태를 다시 확인할 수 있도록 저장합니다.

결과 보존틀린 문제를 정답·해설과 함께 다시 봅니다.

제출한 답안과 점수, 문제별 정오와 해설을 저장합니다. 오답 노트에서는 사용자가 선택한 답과 정답을 비교하고 관련 문서 내용으로 돌아갈 수 있습니다.

Results
답안 채점과 점수 계산 결과를 보존합니다.

제출 결과와 문제별 정답 여부, 해설을 이후에도 확인할 수 있습니다.

History
이전 퀴즈 목록과 상세 결과를 다시 엽니다.

과거에 어떤 문서를 학습했고 어떤 문제에서 틀렸는지 확인합니다.

학습 통계
문서별 정답률과 풀이 수를 집계합니다.

저장된 결과를 바탕으로 어떤 문서를 더 복습해야 하는지 판단할 근거를 제공합니다.

사용자가 얻는 변화한 번 푼 문제를 잊어버리지 않고, 오답과 문서별 결과를 다음 복습의 출발점으로 사용할 수 있습니다.

문서가 학습으로 이어지는 과정

앞의 네 기능은 서로 다른 메뉴가 아니라 같은 문서가 질문의 근거, 퀴즈의 범위, 다음 복습의 기록으로 이어지는 하나의 순환입니다.

  1. 01
    Notion 문서를 등록합니다.

    본문과 이미지를 보존하고 검색에 사용할 임베딩을 함께 준비합니다.

  2. 02
    필요한 내용을 질문합니다.

    관련 문서를 검색한 뒤 출처 링크가 포함된 답변을 받습니다.

  3. 03
    선택한 문서로 이해를 확인합니다.

    문서의 핵심 내용으로 생성한 문제를 풀고 정오와 해설을 확인합니다.

  4. 04
    결과를 다음 복습에 사용합니다.

    점수·오답·해설과 문서별 통계를 다시 읽어 필요한 문서로 돌아갑니다.

↺같은 문서가 다시 다음 질문과 복습의 근거가 됩니다.새로운 문서를 추가하거나 오답이 쌓일수록 다음에 확인할 범위가 더 구체적으로 남습니다.

시스템 구성

화면, 애플리케이션 로직, 영속 데이터와 벡터 검색의 책임을 분리했습니다.Next.js가 문서·채팅·퀴즈·결과 화면을 제공하고, FastAPI가 수집·검색·생성·채점 흐름을 연결합니다.

Interface
Next.js·React

Google OAuth 로그인과 문서·채팅·퀴즈·결과·통계 화면을 제공합니다.

Application
FastAPI

Notion 수집, Qdrant 검색, OpenAI 답변·문제 생성, 채점과 이력 저장을 연결합니다.

Persistent data
PostgreSQL

사용자·문서 메타데이터와 본문, 채팅 메시지, 퀴즈 결과와 통계를 저장합니다.

Vector search
Qdrant

문서 임베딩을 보관하고 질문과 관련된 문서를 유사도 검색으로 찾습니다.

역할과 자동화 범위

문서 선택과 답변·해설의 최종 판단은 사용자에게 남기고, 반복되는 수집·검색·생성·저장은 애플리케이션이 처리합니다.

사용자가 결정하는 일

  • 서비스에 등록할 Notion 문서를 선택합니다.
  • 채팅과 퀴즈에서 사용할 문서 범위를 정합니다.
  • 답변의 출처와 퀴즈 해설이 원문에 맞는지 확인합니다.
  • 오답과 통계를 보고 다시 복습할 문서를 고릅니다.

애플리케이션이 처리하는 일

  • 문서 본문·이미지를 수집하고 검색 벡터를 생성합니다.
  • 관련 문서를 검색해 답변과 출처 링크를 제공합니다.
  • 선택 문서를 바탕으로 문제·정답·해설을 생성합니다.
  • 대화·점수·오답과 문서별 학습 통계를 저장합니다.

자동화의 경계검색 결과가 관련 문서를 찾았다는 사실과 생성된 답변·문제가 원문에 충실하다는 판단은 같지 않습니다. 현재 구현은 출처 링크와 이력을 제공하지만 검색 품질, 답변 충실도와 문제 품질을 자동으로 보증하지는 않습니다.
