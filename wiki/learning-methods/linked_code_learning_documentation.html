코드를 읽다가
설명으로 바로 이동하기

전체 구현 코드는 하나의 연속된 흐름으로 보존하고, 의미 단위별 코드 구간을 클릭하면 해당 코드만 자세히 설명하는 문서로 이동시키는 학습 문서화 패턴이다.

1. 왜 필요한가

코드 조각만 따로 복사하면 한 줄의 의미는 설명할 수 있어도, 그 코드가 전체 실행 흐름에서 어디에 놓였는지 잃어버리기 쉽다. 반대로 전체 파일만 보여주면 초보자는 어디를 먼저 읽어야 할지 모른다.

이 패턴은 두 요구를 분리한다.

읽고 싶은 것제공하는 화면
파일 전체의 실행 순서하나로 이어진 원본 코드 패널
특정 함수·설정의 의미해당 구간을 클릭해 여는 상세 설명
개념과 구현의 연결상세 설명 안의 관련 개념 링크
원본과 설명의 일치 여부상세 페이지의 원본 복귀 링크와 재구성 검증

2. 전체 구조

프로젝트 코드 파일
       ↓
원본 코드 페이지: 하나의 연속된 패널
       ↓ 의미 단위별 <a> 링크
상세 설명 페이지의 fragment
       ↓
코드 발췌 · 줄별 해설 · 관련 개념 · 원본 복귀

핵심은 코드를 문서에서 삭제하거나 요약하는 것이 아니다. 같은 원본을 두 방향으로 탐색할 수 있게 만드는 것이다.

구성 요소역할
Source page실행 가능한 전체 코드를 보존하고 의미 단위별 링크를 제공한다.
Code segment함수·설정·검증·저장처럼 하나의 질문으로 설명할 수 있는 구간이다.
Detail page해당 구간을 발췌해 동작·이유·개념을 설명한다.
Fragment클릭한 구간과 설명의 위치를 정확히 연결하는 HTML 앵커다.

3. 원본 코드 페이지를 만드는 법

코드는 의미 단위로 나누더라도 화면에서는 하나의 패널처럼 이어져야 한다. 카드 사이에 큰 여백을 넣으면 코드를 읽는 흐름이 끊기므로, 공통 배경과 얇은 경계선만 사용한다.

각 <a>가 코드 구간 전체를 감싸므로 사용자는 코드 위 어느 위치를 눌러도 설명으로 이동할 수 있다. CSS는 gap과 카드 여백을 없애고, hover 시 왼쪽 테두리만 강조해 “연속 코드”와 “클릭 구간”을 동시에 표현한다.

원본 보존
코드 구간을 보여주기 위해 내용을 축약하거나 설명용 코드로 바꾸지 않는다. 설명 페이지의 코드는 발췌일 수 있지만, 실행 가능한 전체 코드는 원본 페이지에 하나만 둔다.

4. 상세 설명 페이지를 만드는 법

상세 페이지는 클릭한 코드에만 집중한다. 한 페이지 안에서 여러 fragment를 사용할 수도 있고, 주제가 크면 여러 페이지로 나눌 수도 있다.

각 상세 절에는 최소한 다음 내용을 넣는다.

  1. 연결된 원본 줄 범위와 코드 발췌
  2. 코드가 실행되는 시점과 입력·출력
  3. 왜 필요한지와 생략했을 때의 문제
  4. 관련 개념 문서
  5. 원본 코드의 같은 위치로 돌아가는 링크

5. 반복 적용을 위한 작성 규칙

규칙기준
의미 단위로 자르기함수·설정·검증·저장처럼 하나의 질문으로 설명 가능한 크기로 묶는다.
원본 순서 유지페이지에 표시되는 블록 순서는 실제 파일의 줄 순서와 같게 한다.
코드와 설명 분리원본 페이지는 전체 흐름, 상세 페이지는 특정 부분의 이해에 집중한다.
양방향 링크원본에서 설명으로, 설명에서 원본의 같은 구간으로 모두 이동 가능해야 한다.
범용 개념 분리특정 프로젝트에만 해당하지 않는 개념은 별도 위키 문서로 만들고 프로젝트에서 참조한다.
검증 가능한 표현“코드가 알아서 처리한다” 대신 실제 함수·라이브러리·입출력 책임을 적는다.

6. 문서화 후 검증

각 코드 블록을 순서대로 합친 결과
  == 원본 파일 내용
모든 href 파일 존재
모든 fragment id 존재
공개 문서 안전성 검사 통과

코드를 여러 HTML 블록으로 나누면 줄이 누락되거나 순서가 바뀔 수 있다. 따라서 분할된 블록을 다시 합쳐 원본과 비교한다. 또한 모든 코드 박스 링크, 상세 페이지 fragment, 관련 개념 링크를 검사한다.

이 패턴을 실제로 적용한 예는 Kubernetes Function Calling 학습 코드 원본과 코드 블록별 해설에서 확인할 수 있다.
