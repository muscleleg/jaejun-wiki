DevOps

FLUX CD란

1. 개요

1-1. GitOps란?

GitOps는 워크플로우를 유도하고 클라우드 네이티브 애플리케이션에 대한 지속적 배포(CD)를 구현하도록 지원하는 원칙 세트. 이는 이전에 수동으로 이루어지던 프로세스에 자동화를 도입하여 클러스터 구성과 애플리케이션 배포를 관리하는 데 도움을 줌.

1-2. GitOps 특징

  1. Declarative configuration
  2. 모든 것이 configuration file에 선언됨
  3. Version Control
  4. 모든 confinguration이 깃 리포지토리에 저장됨
  5. 자동 동기화
  6. 실제 상태는 Git에 선언된 원하는 상태와 동기화되어야 함
  7. 관측성
  8. 변화와 현재상태는 쉽게 확인되어야함

1-3. Flux CD는 이에 어떻게 부합하는가?

  1. flux CD는 GitOps 원칙을 쿠버네티스에서 구현하기위해 도움을 주는 도구이다.
  2. git repository를 지켜보며 변화가 있을시 kubernetes에 적용함
  3. Flux CD는 GitOps와 일치하는 여러 기능을 제공함
  4. 깃 리포지토리에서 만든 changes를 자동으로 적용함
  5. 쉽게 이전 버전으로 롤백함
  6. 쉽게 다중 네임스페이스나 클러스터를 관리할 수 있음
  7. 자동화된 디플로이먼트를 위한 정책을 설정할 수 있음

1-4. Flux CD를 사용한 GitOps를 구현할 때 고려해야할것

  1. configuration을 단순화해라
  2. 풀리퀘스트를 항상해라
  3. synchronization 상태를 주시해라
  4. personal access token이나 SSH key를 사용하여 repository를 보호해라

1-5. Flux CD가 가지고 있는 훌륭한 관찰기능

  1. 빌트인 모니터링이나 디플로이먼트 트랙로깅을 사용할 수 있음
  2. 내장된 모니터링 및 로깅 기능을 사용하여 배포와 상태 변경을 추적하여, 언제나 애플리케이션 및 인프라 상태를 인식할 수 있도록 할 수 있음"

1-6. 요약

GitOps는 인프라와 애플리케이션을 관리하는 강력한 패러다임이며, Flux CD는 GitOps를 쉽게 구현할 수 있도록 도와주는 탁월한 도구.

2. Flux CD

2-1. Flux CD란?

Flux CD는 쿠버네티스를 위해 특별히 설계된 GitOps tool이다.

GitOps는 선언적 인프라 및 애플리케이션 관리에서 git을 단일 진실 공급원으로 활용하는 운영 모델이다.

→ 단일 진실 공급원 : https://ko.wikipedia.org/wiki/%EB%8B%A8%EC%9D%BC_%EC%A7%84%EC%8B%A4_%EA%B3%B5%EA%B8%89%EC%9B%90 : 모든 데이터 요소를 한 곳에서만 제어 또는 편집하도록 조직하는 관례를 이른다

Flux CD는 깃과 자동화된 동기화통해 이 모델을 수용하며 Kubernetes 애플리케이션의 지속적인 전달과 배포를 가능하게 한다.

2-2. 쿠버네티스 배포를 위한 Flux CD의 강력한 기능

  1. 자동화된 배포와 동기화를 제공하며 이는 깃리포지토리에 정의된 이상적인 kubernetes 클러스터 상태를 보장한다.
  2. 이는 수동 개입을 제거하고 일관된 신뢰할 수 있는 배포 프로세스를 유지하는 데 도움이 된다
  3. Flux CD는 하나의 컨트롤 플랜(마스터노드)에서 멀티 클러스터와 네임스페이스 관리를 가능하게 한다.
  4. 이것은 복잡한 인프라 구성을 가진 조직이나 많은 마이크로서비스를 다루는 조직에 특히 유용하다.
  5. Flux CD는 GitHub, GitLab, Bitbucket과 같은 인기있는 Git 제공 업체와의 통합을 지원함. 이 통합은 Flux CD가 귀하의 Git 저장소에서 변경 사항을 감시하고, 이러한 변경 사항에 따라 배포를 자동으로 트리거할 수 있도록 한다. 다시 말해, Flux CD는 소스 코드 저장소에서 변경 사항을 감지하여 자동으로 애플리케이션 배포를 관리할 수 있다. 이는 Git 저장소에 정의된 원하는 상태와 실제 상태를 조화시키는 GitOps 원칙을 따른다.

2-3. Flux CD 아키텍처

  1. Flux Operator
  2. Flux CD의 핵심은 Flux Operator이며 쿠버네티스 클러스터 안에서 작동한다.
  3. Flux Operator는 git Repository와 소통하며 지속적으로 정의된 워크로드를 모니터링한다.
  4. git repository에서 변화가 감지될 시 Flux operator는 쿠버네티스 자원에 변화를 적용시킴으로서 쿠버네티스 클러스터를 조정(동기화)한다.
  5. 이는 git repository에 정의된 이상적인 상태로 쿠버네티스 클러스터를 업데이트하도록 보증한다.
  6. Flux CD는 GitOps, Helm Controller를 지원한다.
  7. Helm Controller: Helm Release를 관리함
  8. 헬름 차트를 사용하여 보다 복잡한 응용 프로그램 배포와 버전 관리를 활용할 수 있도록 한다.
  9. Kustomiation Operator

2-4. Flux CD Workflow

  1. git repository에 있는 쿠버네티스의 이상적인 상태 정의
  2. 워크로드, configuration, dependencies 정의
  3. Flux operator는 변화감지를 위해 지속적으로 git repository 모니터링함
  4. 변화가 감지되면 kubernetes cluster에 적용함
  5. Flusx operator는 git repository에 정의된 상태와 동일하도록 보증해줌
  6. 생성,삭제,업데이트의 변화와 같은 변화의 상태를 일치시켜줌
  7. 사용자의 CLI를 통해 배포과정을 보여줌
  8. 배포, 롤백, 에러나 충돌과 같은 상태를 쉽게 추적할 수 있음

2-5. Flux CD 장점

  1. GitOps의 특징을 최대한 활용하여 Flux CD는 자동화와 쿠버네티스 배포의 일관성을 가져옴
  2. 예측가능하고 재생산가능한 배포과정을 가질 수 있고 사람의 실수를 줄여주며 항상 제어되고 효율적인 방식으로 애플리케이션이 배포되는 것을 보장한다.
  3. Flux CD는 높은 수준의 관찰성과 추적성을 가능하게 한다.
  4. git repository의 commit history를 통해 클러스터의 변화를 추적가능하게하며 이는 배포에 대한 철저한 감사 추적을 제공한다.
  5. Flux CD는 협업과 확장성을 촉진한다.
  6. 원하는 상태가 git 저장소에 정의되기 때문
  7. 여러 팀 멤버들은 표준 git 워크플로를 사용하여 변경 사항에 기여하고 검토할 수 있다.
  8. 이는 팀환경에서 배포 관리를 쉽게 만드며 이로 인해 팀 환경에서 배포를 관리하는 것이 더 쉬워지며 인프라의 원활한 확장이 용이해진다.

2-6. 요약

  1. Flux CD는 Git 저장소와 Kubernetes 클러스터 간의 동기화를 자동화함으로써 Kubernetes 배포에서 중요한 역할을 하는 강력한 GitOps 도구입니다.
  2. Flux CD는 이상적인 상태로 어플리케이션이 배포되는 것을 보장해준다.

helm Release

  • helm install 명령 실행 결과로 생성되며, helm chart의 인스턴스라고 볼 수 있다.
  • 하나의 helm chart 에
  • 서로 다른 values.yaml 을 적용해서 내용적으로 다른 여러 helm release 를 만들 수도 있고,
  • 동일한 values.yaml 을 적용하되 release 이름을 다르게 지정해서 내용적으로는 동일한 여러 helm release 를 만들 수도 있다.
  • helm chart 및 values.yaml 파일의 내용 변경을 k8s 자원에 반영해야 할 때 helm upgrade 명령을 통해 release 의 내용을 변경할 수 있다.

rollout

rollout은 여러개의 pod를 모두 죽이지않고 순차적으로 업데이트하는 방식을 말합니다.

rollout restart \{deployname\}등의 옵션은 deployment의 pod을 순차적으로 모두 재시작하고싶을떄 사용하기도 합니다.

편입 후 검증 메모

  • 렌더링 확인: Helm은 템플릿 도구이자 release manager다. 적용 전에 values 병합 결과와 렌더링된 manifest를 검사한다.
  • 업그레이드: chart version·app version·CRD·immutable field를 분리하고, backup과 rollback 가능성을 먼저 확인한다.
  • GitOps: Git이 원하는 상태의 원본이 되면 cluster에서 직접 수정한 값은 controller가 되돌릴 수 있다. 긴급 변경의 기록·동기화 절차가 필요하다.
  • 자격증명: repository·SCM·registry 자격증명은 manifest에 평문으로 넣지 않고 전용 Secret와 최소 권한을 사용한다.
