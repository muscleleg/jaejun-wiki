TensorDataset과 타입 오류

모델이 계산할 Tensor로 바꾸는 작업은 앞의 torch.tensor()에서 끝났다. 4. MLP(다층 퍼셉트론)는 각 고객의 45개 값을 16개 중간값과 Logit 하나로 바꾼다

ChurnMLP Forward
from torch import nn

class ChurnMLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.hidden = nn.Linear(45, 16)
        self.output = nn.Linear(16, 1)

    def forward(self, x):
        hidden = self.hidden(x)
        activated = torch.relu(hidden)
        logits = self.output(activated)
        return logits
[batch,45] → [batch,16] → [batch,1]

45 → 16은 고객 한 명의 Feature 45개를 학습 가능한 조합 16개로 바꾸고, 16 → 1은 그 16개를 고객별 Logit 하나로 합친다는 뜻이다. Batch가 64명이어서 출력이 [64,1]이지만 모델이 64명 전용이라는 뜻은 아니다. [1,45], [32,45], 마지막 [2,45]도 각각 앞 차원을 유지해 처리한다.

ReLU와 마지막 Linear 구분
ReLU는 음수를 0에 가깝게 만드는 것이 아니라 정확히 0으로 만들고, 양수에는 상한 1을 두지 않는다. ReLU(10)=10이다. ReLU는 중간값에만 적용되므로 마지막 Linear(16,1)의 가중치와 bias에 따라 Logit은 -100, -0.2608, 10처럼 어떤 실수도 될 수 있다.

5. Linear의 숫자와 파라미터 Shape

파라미터 수 설명은 검증됨
Linear(45,16)이 “입력 45개를 받는 서로 다른 1차식 16개”이며, Weight 45 × 16 = 720개와 Bias 16개가 조정된다는 것을 사용자가 자기 말로 설명했다. 두 Linear를 합친 753개와 Logistic Regression(로지스틱 회귀)의 46개도 비교했다.
3차원 입력 Shape 재예측은 아직 보강
Linear가 앞 차원은 유지하고 마지막 Feature 축만 바꾸는 기술 기준은 아래에 남겨 둔다. [32,10,45]의 출력 Shape을 자료 없이 다시 예측하는 확인은 완료 체크와 분리한다.

nn.Linear(45,16)의 두 숫자는 입력값 45개와 출력값 16개를 뜻한다. 실제 weight는 [out_features,in_features]=[16,45]인 2차원 행렬이고, 출력값마다 bias 하나가 있어 bias Shape은 [16]이다.

계층WeightBias파라미터 수
Linear(45,16)[16,45] · 45 × 16 = 720[16] · 16개736개
Linear(16,1)[1,16] · 16개[1] · 1개17개
전체ReLU에는 학습 파라미터가 없음753개
16개 출력을 16개의 서로 다른 식으로 보기
출력₁  = 첫 번째 Weight 45개로 계산     + Bias₁
출력₂  = 두 번째 Weight 45개로 계산   + Bias₂
⋯
출력₁₆ = 열여섯 번째 Weight 45개로 계산 + Bias₁₆

따라서 720은 출력 개수가 아니라 입력 45개와 출력식 16개 사이의 조정 가능한 Weight 연결 수다. 입력 고객 하나에서 실제로 나오는 중간 결과는 16개다.

모델구조학습 파라미터이번 Validation 결과
Logistic Regression(로지스틱 회귀)45 → 1Weight 45 + Bias 1 = 46개Accuracy 80.55% · Yes Recall 55.88%
MLP(다층 퍼셉트론)45 → 16 → 1736 + 17 = 753개Accuracy 78.99% · Yes Recall 35.56%

MLP(다층 퍼셉트론)는 더 많은 파라미터와 연산으로 더 복잡한 관계를 표현할 수 있지만, 그 자체가 더 좋은 일반화 성능을 보장하지는 않는다. 이번 설정에서는 연산과 조정값이 적은 Logistic Regression(로지스틱 회귀)이 두 지표 모두 더 높았다.

Linear의 weight는 2차원이지만 입력 Tensor는 3차원 이상일 수 있다. Linear는 앞 차원을 유지하고 마지막 Feature 축만 바꾼다.

[32,10,45] → Linear(45,16) → [32,10,16]

nn.Linear(45,33,16)은 45 → 33 → 16을 뜻하지 않는다. 세 번째 위치 인자는 새 출력 차원이 아니라 bias 자리다. 현재 PyTorch에서는 정수 16이 참으로 취급되어 Linear(45,33,bias=True)처럼 만들어질 수 있지만, 의도가 불분명하므로 쓰지 않는다. 45 → 33 → 16을 만들려면 Linear(45,33)과 Linear(33,16) 두 계층을 따로 선언해야 한다.

6. Sigmoid는 제한 없는 Logit을 0과 1 사이로 압축한다

첫 고객의 학습 전 Logit은 z=-0.2608이었다. Sigmoid 계산은 다음과 같다.

11 + e−z = 11 + e0.2608 ≈ 11 + 1.298 ≈ 0.4352

현재 단계에서는 이 값을 과하게 해석하지 않고 학습 전 sigmoid 출력값이라고 기록한다. Sigmoid 자체는 각 실수를 독립적으로 0~1 사이로 압축할 뿐이며, MinMaxScaler처럼 데이터 전체의 최솟값·최댓값을 사용하는 정규화는 아니다.

0.5 Threshold는 sigmoid 출력값을 최종 0/1 판정으로 바꿀 때 쓰는 별도 규칙이다. 현재 셀은 아직 Threshold로 판정하지 않았고, BCE가 연속적인 sigmoid 출력값을 채점하는 단계다.

표현상 주의
학습 전 출력에는 단순히 “확률”이라고 쓰지 않고 학습 전 sigmoid 출력값이라고 쓴다. BCE 학습 뒤에도 이는 모델이 추정한 값이며 현실의 빈도와 맞는지는 별도의 Calibration 검증이 필요하다.

7. BCE(이진 교차 엔트로피)는 실제 정답 쪽 sigmoid 출력값에 -log를 적용한다

p를 sigmoid 출력값, y를 실제 정답 0 또는 1이라고 두면 고객 한 명의 BCE(이진 교차 엔트로피)는 다음 두 경우로 읽을 수 있다.

실제 정답 y=1개별 Loss = -log(p)
실제 정답 y=0개별 Loss = -log(1-p)

두 경우를 한 식으로 합치면 다음과 같다.

L = -[y log(p) + (1-y) log(1-p)]

첫 고객 실제 숫자로 계산

z = -0.2608, p = 0.4352, y = 0
L
= -[0 × log(0.4352) + (1 - 0) × log(1 - 0.4352)]
= -log(0.5648)
≈ 0.571

첫 고객의 실제 정답이 0이므로 p가 아니라 1-p=0.5648을 선택해 벌점을 계산한다. 같은 출력에서 정답이 1이었다면 -log(0.4352) ≈ 0.832가 된다.

정답 방향 벌점의 크기는 별도 예제로도 예측했다. sigmoid 출력값이 0.8일 때 실제 정답이 1이면 -log(0.8), 실제 정답이 0이면 -log(0.2)이므로 두 번째 벌점이 더 크다. e-x가 0.8보다 작은 0.2가 되려면 x가 더 커야 한다는 관계로도 설명했다. 이는 같은 모델 출력이라도 실제 정답 쪽에 남긴 값이 0.8인지 0.2인지에 따라 BCE가 달라진다는 확인이다.

고객별 Loss 64개를 하나로 합치기

nn.BCEWithLogitsLoss()의 기본값은 reduction="mean"이다. 따라서 고객별 Loss 64개를 모두 더한 뒤 64로 나눈다.

Batch Loss = 고객 1 Loss + 고객 2 Loss + ⋯ + 고객 64 Loss64 = 0.6564000844955444

화면에는 logits[:3]으로 앞 3명만 출력했지만, 실제 Loss 계산에는 logits [64,1]과 batch_y [64,1] 전체가 들어갔다. 고객별 값을 보고 싶을 때만 reduction="none"을 사용한다.

MSE·분산·BCE 구분

계산비교 기준현재 의미
분산각 값 − 그 값들의 평균데이터가 평균에서 얼마나 퍼졌는지
MSE Loss예측값 − 실제 정답을 제곱한 평균앞선 선형회귀에서 사용한 Loss
BCE Loss정답 쪽 sigmoid 출력값에 -log현재 0/1 이진분류에서 선택한 Loss

(sigmoid 출력값 - 실제 정답)²을 평균내는 방식도 가능한 다른 Loss이며 MSE라고 부른다. 현재 코드는 이 방식 대신 BCE를 선택했다.

WithLogits의 뜻
개념상 Logit → Sigmoid → BCE지만 BCEWithLogitsLoss는 수치적으로 안전하게 계산하려고 원본 Logit에서 두 단계를 함께 처리한다. 따라서 Loss에는 loss_fn(logits, batch_y)를 넣고, torch.sigmoid(logits)를 다시 넣어 sigmoid를 중복 적용하지 않는다.

8. SGD(확률적 경사 하강법) 한 Step에서 고정 Batch 암기 진단까지

저장된 노트북의 한 Step
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

optimizer.zero_grad()
logits = model(batch_x)
loss_before = loss_fn(logits, batch_y)
loss_before.backward()
optimizer.step()

SGD(확률적 경사 하강법)는 model.parameters()에 등록된 753개 weight·bias 각각에 대해 새 값 = 기존 값 - learning rate × Gradient를 적용한다. 이번 저장된 실행에서는 같은 Batch의 Loss가 0.6564000844955444에서 0.6511512994766235로 내려갔다.

한 Step에서 확인한 것
사용자는 optimizer.step() 한 번마다 Gradient와 learning rate를 기준으로 weight·bias가 조금 조정되고, 그 결과 Loss가 0.6564000844955444 → 0.6511512994766235로 소폭 감소했다고 자기 말로 설명했다.

고정된 고객 64명을 의도적으로 암기시킨 진단

학습 파이프라인이 실제로 한 Batch를 학습할 수 있는지 확인하기 위해 새 ChurnMLP를 만들고, 고정된 입력 [64,45]와 정답 [64,1]만 반복해서 사용했다. 모델 구조는 Linear(45,16) → ReLU → Linear(16,1), Optimizer는 SGD(lr=0.1)였으며 총 10,000번 수정했다.

고정 Batch 진단의 핵심 반복

overfit_optimizer = torch.optim.SGD(
    overfit_model.parameters(),

for step in range(10_000):

최종 성능으로 해석하지 않는다.
같은 Batch 100%와 Validation 약 71.19% 사이에는 약 28.81%p 차이가 있다. Validation 결과는 정답의 다수 클래스만 고르는 Dummy 기준 약 73.46%보다도 낮고, 같은 Split의 Logistic Regression 기준 약 80.55%에도 미치지 못했다. 따라서 이 실험의 결론은 “좋은 이탈 예측 모델을 만들었다”가 아니라 “모델 → BCE Loss → Backward → SGD 연결이 작동하며, 64개를 암기한 결과는 일반화되지 않는다”이다.

전체 Train DataLoader의 한 Epoch 구조 확인

새 모델로 train_loader를 한 번 순회했을 때 optimizer.step()은 89번 실행됐다. 이는 Train 고객 5,634명을 Batch 64개씩 공급하면 64 × 88 + 2가 되어 마지막 Batch가 2명이기 때문이다. 이 구조 확인 뒤 같은 새 모델을 전체 데이터로 20 Epoch 학습하고 Validation Metric까지 계산했다.

9. 전체 Train 20 Epoch와 Validation 평가

고정된 64개만 반복한 진단 모델과 분리해 새 train_model을 만들었다. 한 Epoch마다 서로 다른 Train Batch 89개를 모두 순회했고, 각 Batch에서 고객별 BCE를 평균한 Scalar Loss 하나로 backward()와 optimizer.step()을 한 번 실행했다.

89 updates / epoch × 20 epochs = 1,780 updates
전체 Train DataLoader를 20 Epoch 학습
train_model = ChurnMLP()
train_optimizer = torch.optim.SGD(
    train_model.parameters(),
    lr=0.1,
)

train_model.train()
step_count = 0

for epoch in range(20):
    epoch_loss = 0

    for train_batch_x, train_batch_y in train_loader:
        train_optimizer.zero_grad()

        train_logits = train_model(train_batch_x)
        train_loss = loss_fn(train_logits, train_batch_y)

        train_loss.backward()
        train_optimizer.step()

        epoch_loss += train_loss.item()
        step_count += 1

    if (epoch + 1) % 5 == 0:
        average_loss = epoch_loss / len(train_loader)
        print(f"{epoch + 1} Epoch 평균 Loss:", average_loss)

print("전체 수정 횟수:", step_count)

Epoch Loss는 각 Batch에서 나온 평균 BCE를 89개 누적한 뒤 Batch 수 89로 나눈 값이다. 즉 현재 로그는 Batch 평균 Loss들의 평균이다. 마지막 Batch는 고객이 2명이라 고객별 가중 평균과 아주 조금 다를 수 있으며, 고객 전체를 정확히 같은 비중으로 계산하려면 각 Batch Loss에 train_batch_y.shape[0]을 곱해 누적한 뒤 고객 수로 나눈다.

Validation Accuracy와 Yes Recall

평가에서는 학습된 가중치를 바꾸지 않고 Validation 1,409명을 통과시켰다. Accuracy는 맞힌 고객 수를 전체 고객 수로 나누고, Yes Recall은 실제 이탈자 중 모델이 이탈이라고 맞힌 수를 계산한다.

가중치를 바꾸지 않고 Accuracy와 Yes Recall 누적
train_model.eval()

correct_count = 0
total_count = 0
true_positive_count = 0
actual_positive_count = 0

with torch.no_grad():
    for valid_batch_x, valid_batch_y in valid_loader:
        valid_logits = train_model(valid_batch_x)
        valid_values = torch.sigmoid(valid_logits)
        valid_predictions = (valid_values >= 0.5).float()

        correct_count += (
            valid_predictions == valid_batch_y
        ).sum().item()
        total_count += valid_batch_y.shape[0]

        true_positive_count += (
            (valid_predictions == 1)
            & (valid_batch_y == 1)
        ).sum().item()
        actual_positive_count += (
            valid_batch_y == 1
        ).sum().item()

validation_accuracy = correct_count / total_count
yes_recall = true_positive_count / actual_positive_count
eval()과 no_grad()는 다른 일을 한다.
train_model.eval()은 Dropout·BatchNorm 같은 계층을 평가 동작으로 바꾸지만 Gradient 기록을 끄지는 않는다. with torch.no_grad():는 계산 그래프와 Gradient 기록을 막아 평가·추론에 필요 없는 메모리와 계산을 줄인다. 현재 Linear·ReLU만 있는 모델은 eval() 전후 출력이 같지만 두 역할을 구분해 사용한다.
Accuracy = 1,1131,409 = 0.78992193 ≈ 78.99%
Yes Recall = TPTP + FN = 133374 = 0.35561497 ≈ 35.56%

Metric을 셀 때 고객 수를 분명히 한다

현재 정답 Shape이 [batch,1]이라 batch_y.numel()과 batch_y.shape[0]은 같은 수가 나온다. numel()은 Tensor의 모든 숫자 개수를 세고, shape[0]은 첫 번째 축인 고객 수만 센다. 현재는 고객당 정답이 하나라 두 값이 우연히 같다.

정답 Shape과 지표 의미분자분모
현재 이진 Label [batch,1](pred == y).sum()y.shape[0]
다중 출력을 각 원소별로 채점(pred == y).sum()y.numel()
다중 출력 n개를 모두 맞힌 고객만 정답 처리(pred == y).all(dim=1).sum()y.shape[0]
다중 출력에서 분모만 shape[0]으로 바꾸면 안 된다.
[batch,n]에서 현재의 .sum()은 맞은 원소를 총 batch × n개 중 세기 때문에, 고객 단위 정확도를 구하려면 분자도 .all(dim=1)로 바꿔야 한다.

10. state_dict 저장·복원과 동일 출력 확인

학습된 train_model의 파라미터 상태를 churn_mlp_state_dict.pt에 저장하고 파일 생성을 확인했다. 새 ChurnMLP 객체를 만든 뒤 weights_only=True로 상태를 읽어 load_state_dict()에 전달했다.

학습된 파라미터 저장과 새 모델 복원
checkpoint_path = "churn_mlp_state_dict.pt"
torch.save(train_model.state_dict(), checkpoint_path)

restored_model = ChurnMLP()

    checkpoint_path,
    weights_only=True,

restored_model.load_state_dict(restored_state)
restored_model.eval()

load_state_dict() 결과는 <All keys matched successfully>였다. 이는 새 모델이 기대하는 각 파라미터 이름과 저장된 Tensor 이름이 빠짐없이 일치했다는 뜻이다. 현재 MLP에서는 두 Linear 계층의 weight·bias, 총 753개 학습 파라미터 값이 동일하게 복원됐다.

동일한 Validation 입력 3명의 Logit 비교

기존 모델과 복원 모델을 eval() 상태로 두고 동일한 X_valid_tensor[:3], Shape [3,45]를 입력했다.

모델Logit 3개
기존 train_model[-2.6156, 0.5590, -3.0925]
새 restored_model[-2.6156, 0.5590, -3.0925]
torch.allclose(original_logits, restored_logits) → True

같은 구조에 동일한 weight·bias를 복원하고 같은 입력을 넣었기 때문에 두 모델의 Logit이 일치했다. torch.allclose()는 부동소수점 계산의 아주 작은 오차를 허용하면서 Tensor의 모든 원소가 같은지 확인한다. 단순 ==보다 저장 전·후 숫자 동일성 검증에 안전한 이유다.

eval()은 모델을 평가 모드로 바꾸며, 현재 MLP(다층 퍼셉트론)에는 Dropout·BatchNorm이 없어 출력 자체를 바꾸지는 않지만 추론 단계라는 상태를 명시한다. Gradient 기록은 별도의 torch.no_grad()로 끊는다.

state_dict에 포함state_dict에 미포함

state_dict만으로 원본 고객을 처리할 수는 없다.
복원하려면 먼저 같은 ChurnMLP 구조로 빈 모델을 만들고 Weight·Bias를 넣어야 한다. 원본 19개 열을 학습 때와 같은 45개 Feature로 바꾸려면 Train에서 학습한 전처리기와 Label 정의도 별도로 필요하다. 따라서 이번 저장·복원·한 명 추론은 학습 흐름을 연결한 관문이며, 모델·전처리기·Label 규약을 하나로 저장한 독립 배포 Artifact 완료를 뜻하지는 않는다.

11. 원본 고객 한 명을 전처리부터 Label까지 추론

one_customer = X_valid.iloc[[0]]으로 Validation 원본 DataFrame에서 고객 한 명을 꺼냈다. 대괄호를 두 겹으로 쓴 iloc[[0]]은 Series로 축소하지 않고 열 19개가 있는 2차원 DataFrame Shape (1,19)를 유지한다.

X_valid와 X_valid_tensor의 차이
X_valid는 범주 문자열과 숫자 열을 가진 원본 DataFrame이므로 모델에 바로 넣을 수 없고, Train에서 이미 fit한 preprocessor.transform()이 필요하다. 반면 X_valid_tensor는 같은 전처리를 거쳐 45개 숫자 Feature가 된 float32 Tensor이므로 바로 모델 입력으로 사용할 수 있다. 이 셀의 preprocessor는 현재 Notebook 메모리에 남아 있는 fitted 객체이며, state_dict 파일에서 복원한 것이 아니다.

12. 챕터 완료와 별도 보강

  • 고객별 BCE를 reduction="none"으로 출력하고 첫 값과 Batch 평균을 다시 계산한다.
  • 검증됨: Linear(45,16)·Linear(16,1)의 Weight·Bias를 736 + 17 = 753개로 계산하고, Logistic Regression(로지스틱 회귀) 46개와 비교했다.
  • 별도 보강: 3차원 입력 [32,10,45]에 Linear(45,16)을 적용한 출력 Shape을 자료 없이 다시 예측한다.
  • 검증됨: 한 번의 SGD Step을 반복해 고정 Batch 64개를 10,000회 수정하고, 같은 Batch Accuracy 1.0과 Validation Accuracy 약 71.19%의 차이를 해석한다.
  • 검증됨: 전체 Train DataLoader를 20 Epoch 순회해 1,780번 수정하고, 가중치를 바꾸지 않는 Validation 평가를 분리한다.
  • 검증됨: Validation Accuracy와 Yes Recall을 같은 Split의 Dummy·Logistic Regression Baseline과 비교한다.
  • 검증됨: 모델 state_dict를 저장하고 새 ChurnMLP에 복원해 동일 입력의 Logit이 일치하는지 확인한다.
  • 검증됨: 원본 고객 한 명을 Train 기준 전처리기로 [1,45] Tensor로 바꾸고, 복원 모델의 Logit → sigmoid 출력 → 0.5 Threshold → No/Yes Label까지 연결한다.

현재 회원 이탈 MLP(다층 퍼셉트론) 챕터 완료. Dataset·DataLoader 학습·Validation 평가·Baseline 비교·저장·복원·동일 출력·원본 고객 한 명 추론을 재현했다. 위 목록의 고객별 BCE(이진 교차 엔트로피) 출력과 3차원 Linear Shape 재설명은 별도 보강이며 이 학습 관문의 완료를 되돌리지 않는다. 다음 활성 구현은 기존 TransformerBlock을 Causal DecoderBlock으로 바꾸고, 그 블록을 입출력 구조와 연결해 Tiny Decoder LM(소형 디코더 언어 모델)을 만드는 순서다.
