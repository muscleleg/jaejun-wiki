8. nn.Linear와 Optimizer로 같은 학습을 다시 만든다

수동 실습에서는 w와 b를 직접 만들고 값을 수정했습니다. nn.Linear(1, 1)는 같은 선형식을 가진 nn.Module이며, 학습 대상인 weight와 bias를 내부 Parameter로 관리합니다.

model = nn.Linear(
    in_features=1,
    out_features=1,
)

print(model)
print(list(model.parameters()))
print(model)

입력 특징 1개를 출력 특징 1개로 바꾸고 bias를 사용하는 모델 구조를 보여 줍니다.

model.parameters()

Optimizer가 수정할 실제 weight와 bias Tensor를 제공합니다.

prediction = x × weight + bias

weight는 기울기이고 bias는 절편입니다. 초기값은 무작위이므로 실행마다 다를 수 있지만, y=3x+2 데이터를 학습하면 각각 3과 2에 가까워져야 합니다.

MSELoss는 틀린 정도를 한 숫자로 만든다

MSE = (prediction₁ − target₁)² + ⋯ + (predictionₙ − targetₙ)²n

nn.MSELoss()는 예측과 정답의 차이를 제곱해 평균냅니다. 제곱값의 평균이므로 음수가 될 수 없고, 예측이 정답에 가까워질수록 0에 가까워집니다.

SGD는 수정 대상과 학습률을 먼저 등록한다

optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.1,
)

이 선언만으로 파라미터가 바뀌지는 않습니다. model.parameters()로 수정할 대상을 알려 주고, lr=0.1로 계산된 Gradient의 10%만 실제 변화량에 반영하도록 정합니다.

new parameter = current parameter − learning rate × gradient

Gradient가 음수이면 음수를 빼므로 파라미터가 커지고, 양수이면 파라미터가 작아집니다. 학습률 0.1은 매번 0.1만큼 움직인다는 뜻이 아니라, 현재 Gradient 크기의 0.1배만 적용한다는 뜻입니다.

한 학습 Step의 정확한 역할 분담

optimizer.zero_grad()
predictions = model(x)
loss = loss_function(predictions, y)
loss.backward()
optimizer.step()
호출하는 일하지 않는 일
zero_grad()이전 backward()가 .grad에 남긴 Gradient를 지웁니다.파라미터 값과 계산 그래프를 지우지 않습니다.
model(x)현재 weight·bias로 예측하고 자동미분용 연산 경로를 만듭니다.Gradient를 아직 계산하지 않습니다.
loss.backward()현재 Loss에서 ∂L/∂weight와 ∂L/∂bias를 계산해 기존 .grad에 더합니다.weight와 bias를 수정하지 않습니다.
optimizer.step()두 .grad에 학습률을 적용해 weight와 bias를 함께 수정합니다.Gradient를 새로 계산하지 않습니다.
두 Gradient는 같은 수정 전 상태를 기준으로 합니다. weight의 순간변화율은 현재 bias를 고정한 관점에서, bias의 순간변화율은 현재 weight를 고정한 관점에서 계산합니다. 한쪽을 먼저 수정한 값을 다른 쪽 계산에 쓰지 않습니다. 두 Gradient를 모두 계산한 뒤 step()이 함께 적용하며, 수정된 값은 다음 Epoch의 forward부터 두 Gradient에 영향을 줍니다.

데이터 하나로 두 미지수를 유일하게 찾을 수는 없다

x=3, y=11 하나만 주어지면 조건은 3 × weight + bias = 11 하나입니다. 따라서 (weight, bias)=(3,2), (2,5), (1,8)처럼 Loss가 0인 조합이 여러 개 존재합니다.

x=0 → y=2

0 × weight + bias = 2이므로 bias가 2여야 한다는 정보를 줍니다.

x=3 → y=11

앞에서 찾은 bias 2와 함께 보면 weight가 3이어야 한다는 정보를 줍니다.

실제 학습에서는 값을 순서대로 직접 풀지 않습니다. 서로 다른 입력과 정답의 오차를 평균낸 Loss에서 두 Gradient를 계산하고, 여러 Epoch에 걸쳐 전체 Loss를 줄이는 방향으로 두 값을 동시에 이동시킵니다.

no_grad()는 추론용 자동미분 기록을 끈다

with torch.no_grad():
    test_prediction = model(test_x)

예측 숫자는 그대로 계산하지만, 그 숫자를 만든 연산 연결과 backward에 필요한 중간값은 저장하지 않습니다. 따라서 이 결과로는 나중에 backward()할 수 없습니다. 큰 모델의 추론에서 사용하지 않을 자동미분 기록이 차지하는 메모리를 줄일 수 있습니다.

no_grad()와 zero_grad()는 다릅니다. no_grad()는 그 안의 새 연산 경로를 기록하지 않을 뿐 기존 .grad를 지우지 않습니다. 다음 backward에서 현재 Gradient만 얻고 싶을 때 이전 누적값을 지우는 기능은 optimizer.zero_grad()입니다.

반복해서 헷갈린 지점을 다시 확인하는 FAQ

Q1. print(model), model.parameters(), model(x)는 모두 출력처럼 보이는데 무엇이 다른가?

print(model)은 Linear(in_features=1, out_features=1, bias=True)처럼 모델의 구조 설명을 보여 줍니다. model.parameters()는 그 구조 안에서 학습으로 바뀔 실제 weight·bias Tensor를 제공합니다. model(x)가 입력 x를 계산식에 넣어 만드는 진짜 예측 출력입니다.

Q2. x=3도 학습을 통해 3으로 맞추는 값인가?

아닙니다. x는 데이터에서 주어진 고정 입력입니다. 이 선형 모델에서 Optimizer가 학습으로 바꾸는 값은 model.parameters()에 등록된 weight와 bias입니다. x=3을 넣었을 때 학습된 weight≈3, bias≈2를 사용해 예측 3×3+2≈11을 만드는 것입니다.

Q3. MSE는 각 값에서 평균을 빼는 공식인가?

아닙니다. 분산은 value − mean을 제곱해 값들이 자기 평균에서 얼마나 퍼졌는지 측정합니다. MSE는 prediction − target을 제곱해 모델 예측이 정답에서 얼마나 벗어났는지 측정합니다. 둘 다 제곱의 평균이라는 모양은 같지만 비교 기준이 다릅니다.

분산 = Σ(value − mean)²n · MSE = Σ(prediction − target)²n
Q4. Loss를 계산할 때마다 Gradient가 쌓이는가?

아닙니다. Forward와 Loss 계산은 숫자와 자동미분 경로를 만들 뿐 .grad를 채우지 않습니다. loss.backward()를 실행하는 순간 Gradient를 계산하고, 새 값으로 덮어쓰지 않고 기존 .grad에 더합니다. 따라서 매 Step의 현재 Gradient만 사용할 때는 backward 전에 optimizer.zero_grad()로 이전 누적값을 지웁니다.

Q5. lr=0.1이면 weight와 bias가 매번 0.1씩 움직이는가?

아닙니다. 각 파라미터가 움직이는 양은 자기 Gradient에 따라 다릅니다. 예를 들어 weight.grad=-17.0394이면 변화량은 −0.1×(−17.0394)=+1.70394입니다. lr=0.1은 Gradient 크기의 10%를 이번 업데이트에 적용한다는 뜻입니다.

Q6. 한 Step에서 weight와 bias를 번갈아 수정하는가?

Gradient를 해석할 때는 ∂L/∂weight를 현재 bias가 고정된 관점에서, ∂L/∂bias를 현재 weight가 고정된 관점에서 봅니다. 하지만 한쪽을 실제로 먼저 수정한 뒤 다른 Gradient를 구하는 것은 아닙니다. 두 Gradient 모두 같은 수정 전 (weight, bias) 스냅샷에서 계산되고, optimizer.step()이 둘을 함께 적용합니다. 새 weight가 bias Gradient에 영향을 주고 새 bias가 weight Gradient에 영향을 주는 시점은 다음 Epoch의 forward와 backward부터입니다.

Q7. 데이터 하나만으로 weight와 bias를 함께 학습할 수 없는 이유는 무엇인가?

x=3, y=11 하나는 3×weight+bias=11이라는 식 하나만 제공합니다. 미지수는 두 개이므로 이 식을 만족하는 조합이 여러 개입니다. 서로 다른 x를 가진 데이터가 더 필요합니다. 특히 x=0 데이터는 예측에서 weight 항이 사라져 bias에 직접적인 정보를 주고, 다른 x들은 기울기를 구분할 정보를 줍니다. 학습은 이 식들을 순서대로 푸는 대신 모든 데이터의 평균 Loss를 줄이는 두 Gradient를 반복 적용합니다.

Q8. no_grad()는 기존 Gradient를 지우고 다음 backward를 깨끗하게 만드는 기능인가?

아닙니다. no_grad() 안에서도 Forward와 Loss 숫자는 계산할 수 있지만, 그 결과에서 backward할 때 필요한 Autograd 연산 경로와 중간값은 저장하지 않습니다. 일반 Forward만 실행해도 Gradient는 쌓이지 않으며, 실제 누적은 backward() 때 일어납니다. no_grad()는 기존 .grad를 지우지 않으므로 다음 backward 전에 이전 Gradient를 정리하는 역할은 zero_grad()가 맡습니다.

Q9. Epoch 20 이후 Loss가 거의 0이면 나머지 Epoch는 의미가 없는가?

이 작은 문제에서는 Epoch 20의 Loss가 약 0.0009219였고, 그 제곱근인 RMSE도 약 0.030이라 예측과 정답의 오차 규모가 이미 작았습니다. 이후에도 Loss는 수학적으로 계속 감소하지만 개선 폭이 작습니다. 실제 모델은 학습 Loss가 0이 될 때까지 기다리기보다 Validation 성능이 더 좋아지는지 확인하고, 개선이 멈추면 Early Stopping으로 종료하는 방식을 사용합니다.

9. Dataset은 입력과 정답을 한 샘플로 묶는다

x=[0,1,2], y=[2,5,8]처럼 입력과 정답의 순서가 대응할 때, TensorDataset(x, y)는 같은 인덱스의 값을 한 쌍으로 관리합니다. 예를 들어 dataset[1]은 입력 x=1과 정답 y=5를 함께 꺼내고, dataset[2]는 (2, 8)을 꺼냅니다.

DataLoader는 Dataset 항목을 정한 개수씩 꺼낸다

샘플 3개를 batch_size=2, shuffle=False인 DataLoader로 순회했습니다. 첫 반복에서는 입력 [[0],[1]]과 정답 [[2],[5]]가 각각 2개씩 나왔고, 마지막 반복에서는 남은 입력 [[2]]와 정답 [[8]]가 각각 1개씩 나왔습니다. 따라서 반복 횟수는 총 2번이었습니다.

Batch 학습 뒤 전체 Loss를 같은 데이터로 비교한다

각 Batch에서 zero_grad() → 예측 → MSELoss → backward() → step()을 실행했습니다. 한 Epoch에는 Batch가 2개이므로 optimizer.step()도 2번 실행됩니다. 학습 전 전체 Loss는 38.047859였고, 첫 Epoch 종료 뒤 0.188768, Epoch 100 종료 뒤 1.64 × 10⁻¹⁰까지 줄었습니다. 최종 예측은 [1.99998, 4.99999, 8.0]으로 정답 [2, 5, 8]에 가까웠습니다.

학습과 확인의 구분 — no_grad()는 학습 전·후 전체 Loss를 측정할 때만 사용했습니다. 각 Batch를 학습할 때는 Gradient 기록이 필요하므로 no_grad()를 쓰지 않고, 대신 zero_grad()로 이전 Batch의 Gradient를 비운 뒤 현재 Batch의 Gradient만 적용했습니다.
현재 확인한 범위 — Dataset이 입력·정답을 짝짓고 DataLoader가 2개 + 남은 1개 Batch를 공급하며, Batch 학습 뒤 전체 Loss가 줄어드는 기본 학습 루프를 검증했습니다. 실제 회원 이탈 Train·Validation DataLoader와 MLP의 Validation Metric은 다음 단계에서 확인합니다.
