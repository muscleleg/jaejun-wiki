PyTorch · Tensor Shape

크기가 다른 Tensor끼리 계산할 수 있는 이유: Broadcasting

서로 다른 Shape의 Tensor가 어떤 조건에서 덧셈·뺄셈·곱셈을 수행할 수 있는지, LayerNorm 복습에서 사용한 [1,2,4] - [1,2,1] 계산으로 따라갑니다.

PyTorch에서는 두 Tensor의 Shape이 완전히 같지 않아도 특정 조건을 만족하면 덧셈·뺄셈·곱셈 같은 원소별 연산을 수행할 수 있습니다.

이 동작을 Broadcasting(브로드캐스팅)이라고 합니다.

이번 LayerNorm 복습에서는 다음 두 Tensor를 뺐습니다.

hidden_states  [1,2,4]
feature_mean   [1,2,1]

두 Tensor의 차원 수는 모두 3개이지만 마지막 축의 길이는 4와 1로 다릅니다. 그런데도 뺄셈이 가능했습니다.

그 이유는 크기가 1인 축이 상대 Tensor의 축 크기에 맞춰 반복 적용될 수 있기 때문입니다.

1. Token별 Feature 평균을 구했습니다

먼저 두 Token의 Hidden State를 다음과 같이 만들었습니다.

import torch

from torch import Tensor
from jaxtyping import Float

hidden_states: Float[
    Tensor,
    "batch token feature",
] = torch.tensor(
    [
        [
            [1.0, 2.0, 3.0, 4.0],
            [10.0, 20.0, 30.0, 40.0],
        ]
    ]
)

Shape은 다음과 같습니다.

[Batch=1, Token=2, Feature=4]

각 Token은 네 개의 Feature를 가집니다.

첫 번째 Token: [1, 2, 3, 4]
두 번째 Token: [10, 20, 30, 40]

마지막 Feature 축의 평균을 구합니다.

feature_mean: Float[
    Tensor,
    "batch token 1",
] = hidden_states.mean(
    dim=-1,
    keepdim=True,
)

결과는 다음과 같습니다.

tensor([
    [
        [ 2.5],
        [25.0],
    ]
])

Shape은 [1,2,1]입니다.

hidden_states  [1,2,4]
feature_mean   [1,2,1]

keepdim=True를 사용했기 때문에 평균을 계산한 마지막 축이 사라지지 않고 길이 1로 유지됐습니다.

2. 마지막 축의 길이가 다른데도 뺄셈이 됩니다

이제 원래 Hidden State에서 평균을 뺍니다.

centered_hidden_states: Float[
    Tensor,
    "batch token feature",
] = hidden_states - feature_mean

두 Tensor의 Shape은 완전히 같지 않습니다.

hidden_states  [1,2,4]
feature_mean   [1,2,1]
                         ↑
                  4와 1로 다름

그런데 PyTorch는 크기가 1인 마지막 축을 상대 Tensor의 크기 4에 맞춰 사용할 수 있습니다.

개념적으로 첫 번째 Token의 평균은 다음처럼 확장됩니다.

[2.5]
  ↓ Broadcasting
[2.5, 2.5, 2.5, 2.5]

두 번째 Token도 마찬가지입니다.

[25.0]
  ↓ Broadcasting
[25.0, 25.0, 25.0, 25.0]

따라서 실제 연산은 다음처럼 이해할 수 있습니다.

첫 번째 Token

[1.0, 2.0, 3.0, 4.0]
-
[2.5, 2.5, 2.5, 2.5]
=
[-1.5, -0.5, 0.5, 1.5]
두 번째 Token

[10.0, 20.0, 30.0, 40.0]
-
[25.0, 25.0, 25.0, 25.0]
=
[-15.0, -5.0, 5.0, 15.0]

최종 결과의 Shape은 원래 Hidden State와 같은 [1,2,4]입니다.

3. Broadcasting이 가능한 조건

PyTorch는 두 Tensor의 축을 오른쪽부터 비교합니다.

각 축이 다음 조건 중 하나를 만족하면 Broadcasting할 수 있습니다.

1. 두 축의 크기가 같다
2. 한쪽 축의 크기가 1이다
3. 차원이 더 적은 Tensor에는 대응하는 왼쪽 축이 없다

첫 번째와 두 번째 조건은 비교적 직관적입니다.

4와 4 → 크기가 같으므로 가능
4와 1 → 한쪽이 1이므로 가능

세 번째 조건은 두 Tensor의 차원 수가 다를 때 적용됩니다.

[1,2,4]
[    4]

짧은 Tensor의 왼쪽에 대응할 축이 없더라도, 오른쪽 축부터 맞출 수 있다면 Broadcasting이 가능합니다.

4. “한쪽 Tensor에는 비교할 축이 없다”는 의미

다음 두 Tensor를 생각해 보겠습니다.

A Shape: [1,2,4]
B Shape:     [4]

PyTorch는 오른쪽부터 축을 맞춥니다.

A: [1, 2, 4]
B: [      4]
           ↑
        여기부터 비교

마지막 축은 모두 4입니다.

A의 마지막 축: 4
B의 마지막 축: 4

따라서 마지막 축끼리는 계산할 수 있습니다.

그런데 B에는 그보다 왼쪽의 Token 축과 Batch 축이 없습니다.

A: Batch 1, Token 2, Feature 4
B:                    Feature 4

이것이 “한쪽 Tensor에는 비교할 축이 없다”는 의미입니다.

개념적으로는 B의 왼쪽에 크기 1인 축이 생략되어 있다고 생각하면 이해하기 쉽습니다.

실제 B Shape

[4]
Broadcasting을 이해하기 위한 개념적 Shape

[1,1,4]

그다음 Token 축이 상대 Tensor의 크기에 맞춰 확장됩니다.

[1,1,4]
   ↓
[1,2,4]

예를 들어 다음과 같이 계산할 수 있습니다.

import torch

from torch import Tensor
from jaxtyping import Float

hidden_states: Float[
    Tensor,
    "batch token feature",
] = torch.tensor(
    [
        [
            [1.0, 2.0, 3.0, 4.0],
            [10.0, 20.0, 30.0, 40.0],
        ]
    ]
)

feature_bias: Float[
    Tensor,
    "feature",
] = torch.tensor(
    [100.0, 200.0, 300.0, 400.0]
)

result: Float[
    Tensor,
    "batch token feature",
] = hidden_states + feature_bias

feature_bias의 Shape은 [4]입니다.

hidden_states  [1,2,4]
feature_bias       [4]

개념적으로 feature_bias가 모든 Token에 적용됩니다.

첫 번째 Token

[1, 2, 3, 4]
+
[100, 200, 300, 400]
=
[101, 202, 303, 404]
두 번째 Token

[10, 20, 30, 40]
+
[100, 200, 300, 400]
=
[110, 220, 330, 440]

최종 결과는 다음과 같습니다.

tensor([
    [
        [101, 202, 303, 404],
        [110, 220, 330, 440]
    ]
])

즉 [4]의 Feature 값이 모든 Batch와 Token에 동일하게 적용된 것입니다.

다만 PyTorch가 없는 축을 아무 위치에나 마음대로 끼워 넣는 것은 아닙니다.

항상 오른쪽부터 축을 맞추며, 부족한 축은 왼쪽에 생략된 것으로 처리합니다.

[1,2,4]
[    4]  → 오른쪽 Feature 축끼리 대응

5. Broadcasting은 크기가 다르면 항상 적용되는 것이 아닙니다

다음 연산은 불가능합니다.

[1,2,4] - [1,2,2]

오른쪽부터 축을 비교하면 마지막 축의 크기가 4와 2입니다.

4와 2
├─ 서로 같지 않음
└─ 어느 쪽도 1이 아님

따라서 PyTorch는 어느 값을 어떻게 반복해야 하는지 결정할 수 없습니다.

[1,2,4] - [1,2,3]  → 불가능
[1,2,4] - [1,2,2]  → 불가능
[1,2,4] - [1,2,1]  → 가능
[1,2,4] - [1,2,4]  → 가능

Broadcasting은 크기가 다른 Tensor를 무조건 계산해 주는 기능이 아닙니다.

각 축이 Broadcasting 조건을 만족할 때만 가능합니다.

6. 차원 수와 축의 길이는 다른 개념입니다

이번에 헷갈릴 수 있었던 부분은 두 Tensor의 차원 수는 같지만 마지막 축의 길이가 다르다는 점입니다.

[1,2,4] → 차원 수 3
[1,2,1] → 차원 수 3

둘 다 세 개의 축을 가지므로 3차원 Tensor입니다.

하지만 마지막 축의 길이는 다릅니다.

첫 번째 Tensor의 마지막 축 길이: 4
두 번째 Tensor의 마지막 축 길이: 1

따라서 다음 두 개념을 구분해야 합니다.

차원 수 또는 Rank
= Tensor가 몇 개의 축을 가지는가

축의 길이
= 특정 축에 몇 개의 원소가 있는가

이번 연산은 차원 수가 같아서 가능한 것이 아닙니다.

마지막 축의 길이가 4와 1이고, 한쪽이 1이라는 Broadcasting 조건을 만족해서 가능합니다.

7. 크기가 1인 축은 다른 위치에서도 확장될 수 있습니다

Broadcasting은 마지막 축에만 적용되는 기능이 아닙니다.

예를 들어 다음 두 Shape도 계산할 수 있습니다.

[1,2,4]
[1,1,4]

오른쪽부터 비교하면 다음과 같습니다.

Feature 축: 4와 4 → 같음
Token 축:   2와 1 → 한쪽이 1
Batch 축:   1과 1 → 같음

두 번째 Tensor의 Token 축 1이 2에 맞춰 사용됩니다.

[1,1,4]
   ↓ Token 축 Broadcasting
[1,2,4]

따라서 [1,1,4]의 Feature 값이 두 Token에 동일하게 적용됩니다.

8. 차원 수가 다른 Tensor는 오른쪽부터 맞춥니다

다음 Shape들을 비교해 보겠습니다.

A [2,3,4]
B     [3,4]
C       [4]
D       [1]

PyTorch는 오른쪽부터 축을 맞춥니다.

A [2,3,4]
B [  3,4]
C [    4]
D [    1]

각 관계는 다음과 같습니다.

A와 B
[2,3,4]
[  3,4]

오른쪽 3과 3이 같음
오른쪽 4와 4가 같음
B에 왼쪽 Batch 축이 없음
→ 가능
A와 C
[2,3,4]
[    4]

마지막 4가 같음
C에는 왼쪽 두 축이 없음
→ 가능
A와 D
[2,3,4]
[    1]

마지막 축에서 4와 1
한쪽이 1
D에는 왼쪽 두 축이 없음
→ 가능

짧은 Tensor의 부족한 축은 항상 왼쪽에 생략된 것으로 봅니다.

9. keepdim=True가 필요한 이유

평균을 다음처럼 구하면 마지막 Feature 축이 제거됩니다.

feature_mean = hidden_states.mean(
    dim=-1,
    keepdim=False,
)

Shape은 다음처럼 됩니다.

hidden_states  [1,2,4]
feature_mean     [1,2]

PyTorch는 오른쪽부터 비교하므로 실제 대응은 다음과 같습니다.

hidden_states  [1,2,4]
feature_mean   [  1,2]

오른쪽 축부터 비교하면:

hidden_states의 마지막 축: 4
feature_mean의 마지막 축:  2

4와 2는 같지 않고 어느 쪽도 1이 아니므로 바로 뺄 수 없습니다.

반면 keepdim=True를 사용하면:

hidden_states  [1,2,4]
feature_mean   [1,2,1]

평균을 구한 Feature 축이 길이 1로 유지됩니다.

Feature 축: 4와 1 → Broadcasting 가능
Token 축:   2와 2 → 같음
Batch 축:   1과 1 → 같음

따라서 다음처럼 사용할 수 있습니다.

[1,2,1]
   ↓
[1,2,4]

keepdim=True는 단순히 Shape을 보기 좋게 유지하는 옵션이 아닙니다.

이후 원래 Tensor와 Broadcasting 연산을 할 수 있도록 평균을 계산한 축의 위치를 보존하는 역할을 합니다.

10. Broadcasting은 개념적 반복입니다

Broadcasting을 설명할 때는 다음처럼 값이 반복된다고 표현합니다.

[2.5]
  ↓
[2.5, 2.5, 2.5, 2.5]

하지만 이 설명은 연산을 이해하기 위한 개념적 표현입니다.

PyTorch가 항상 실제로 같은 값을 여러 번 복사해서 새로운 큰 Tensor를 먼저 만든다는 뜻은 아닙니다. 내부적으로는 크기가 1인 축의 값을 반복해서 참조하는 방식으로 연산을 처리할 수 있습니다.

따라서 다음 두 문장은 구분해야 합니다.

개념적으로:
크기 1의 값이 상대 축만큼 반복 적용됩니다.

구현상:
반드시 큰 Tensor를 실제 메모리에 복제한 뒤 계산하는 것은 아닙니다.

결론

PyTorch에서는 두 Tensor의 Shape이 완전히 같지 않아도 Broadcasting 조건을 만족하면 원소별 연산을 수행할 수 있습니다.

PyTorch는 오른쪽 축부터 비교하며 다음 조건을 확인합니다.

1. 두 축의 크기가 같다
2. 한쪽 축의 크기가 1이다
3. 차원이 더 적은 Tensor에는 대응하는 왼쪽 축이 없다

이번 LayerNorm 복습에서는 다음 Shape을 계산했습니다.

hidden_states  [1,2,4]
feature_mean   [1,2,1]

feature_mean의 마지막 축 크기가 1이므로 각 Token의 평균이 네 Feature에 반복 적용됐습니다.

[2.5]  → [2.5, 2.5, 2.5, 2.5]
[25.0] → [25.0, 25.0, 25.0, 25.0]

그 결과 각 Token의 Feature에서 자신의 평균을 뺄 수 있었고, 결과 Shape은 원래 Hidden State와 같은 [1,2,4]로 유지됐습니다.

차원 수가 더 적은 Tensor도 오른쪽부터 축을 맞출 수 있습니다.

[1,2,4]
[    4]

여기서 [4]는 Feature 축에 대응하며, 부족한 Batch·Token 축은 왼쪽에 생략된 것으로 이해할 수 있습니다.

Broadcasting은 크기가 다른 Tensor를 무조건 계산하는 기능이 아닙니다. 오른쪽부터 축을 비교하여 크기가 같거나 한쪽이 1인 경우, 또는 짧은 Tensor의 왼쪽 축이 생략된 경우에만 서로 호환되는 원소별 연산을 가능하게 하는 규칙입니다.
