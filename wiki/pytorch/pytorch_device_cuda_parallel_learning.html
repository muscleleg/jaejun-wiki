.to(device)로 옮긴 Tensor는 어떻게 GPU 병렬 연산으로 이어지는가

모델과 Tensor를 장치로 옮기는 코드가 어떻게 PyTorch의 장치 디스패치, CUDA Kernel, GPU 병렬 실행으로 이어지는지 한 흐름으로 연결합니다.

1. 시작한 의문

우리가 작성한 코드는 생각보다 단순합니다.

device: torch.device = torch.device(
    "cuda" if torch.cuda.is_available() else "cpu"
)

model = model.to(device)
input_ids: torch.Tensor = input_ids.to(device)

outputs = model(
    input_ids=input_ids,
)

직접 한 것은 모델과 입력 Tensor를 device로 옮긴 뒤 입력 Tensor를 모델에 넣은 것뿐입니다. 그런데 이 코드만으로 어떻게 GPU 병렬 처리가 실행되는 걸까요?

GPU가 “이 Tensor의 첫 번째 축은 문장들이니 문장별로 병렬 처리해야겠다”고 알아내는 것은 아닙니다.

PyTorch는 Tensor가 저장된 장치를 보고 CPU용 연산과 CUDA용 연산 중 무엇을 실행할지 선택하고, CUDA용 연산은 큰 Tensor 계산을 수많은 작은 계산으로 나눠 GPU에서 동시에 실행합니다.

2. device는 계산할 장치를 표현한다

device: torch.device = torch.device(
    "cuda" if torch.cuda.is_available() else "cpu"
)

CUDA를 사용할 수 있다면 device는 cuda, 그렇지 않다면 cpu가 됩니다. 하지만 변수를 선언했다고 바로 계산 장치가 바뀌지는 않습니다. 이 변수는 앞으로 사용할 장치를 나타낼 뿐입니다.

3. .to(device)는 해당 장치의 메모리로 옮긴다

input_ids = input_ids.to(device)
model = model.to(device)

GPU를 사용하는 경우 입력 Tensor와 모델의 Weight·Bias가 CPU 메모리에서 GPU 메모리로 이동합니다.

input_ids
CPU 메모리 → GPU 메모리

model의 Weight와 Bias
CPU 메모리 → GPU 메모리

.to(device) 자체가 Attention이나 행렬곱을 실행하는 코드는 아닙니다.

.to(device)
→ 계산할 데이터를 해당 장치의 메모리로 이동

model(...)
→ 실제 모델 계산 시작

모델과 입력 Tensor는 같은 장치에 있어야 합니다. 모델은 GPU에 있는데 입력 Tensor가 CPU에 있으면 두 장치의 데이터를 바로 행렬곱할 수 없으므로 오류가 발생합니다.

4. 실제 계산은 model(...)에서 시작된다

outputs = model(
    input_ids=input_ids,
)

이 호출이 실행되면 모델 내부에서 다음 연산들이 시작됩니다.

Token Embedding
→ Q·K·V Projection
→ Attention Score
→ Softmax
→ Value 결합
→ FFN
→ LM Head

각 단계의 실제 작업은 Embedding 조회, 행렬곱, 덧셈, Softmax, 정규화 같은 Tensor 연산입니다.

5. PyTorch는 Tensor의 장치를 확인한다

같은 행렬곱 코드라도 Tensor의 장치에 따라 실행되는 내부 구현이 달라집니다.

result = input_tensor @ weight
입력과 Weight가 CPU에 있음
→ PyTorch가 CPU용 행렬곱 구현 선택
→ CPU에서 실행

입력과 Weight가 CUDA 장치에 있음
→ PyTorch가 CUDA용 행렬곱 구현 선택
→ GPU에서 실행

따라서 사용자가 CPU용 함수와 GPU용 함수를 직접 나눠 호출할 필요가 없습니다. PyTorch가 Tensor에 기록된 장치 정보를 보고 적절한 연산 구현을 선택합니다. 이를 장치에 따른 연산 Dispatch(디스패치)라고 볼 수 있습니다.

6. CUDA는 PyTorch 연산을 GPU 작업으로 연결한다

PyTorch가 CUDA용 연산을 선택하면 CUDA Kernel이 실행됩니다. CUDA Kernel은 GPU에서 실행되는 계산 함수입니다.

예를 들어 큰 행렬곱 X @ W가 있다면, 그 행렬의 각 출력 원소를 만드는 수많은 곱셈과 덧셈을 많은 GPU Thread가 나눠 처리할 수 있습니다.

큰 행렬곱 하나
→ 출력 원소를 계산하는 작은 작업들로 분할
→ 작업들을 여러 GPU Thread에 배정
→ 많은 작업을 동시에 실행

우리가 CUDA Thread를 직접 생성하거나 계산 위치를 배정하는 것은 아닙니다. PyTorch와 CUDA 라이브러리가 Tensor의 Shape에 맞는 Kernel을 실행하고 계산 작업을 분할합니다.

7. GPU는 문장을 이해하지 않고 Tensor Shape을 처리한다

길이가 같은 문장 네 개가 Token ID로 변환되었다고 해보겠습니다.

input_ids Shape = [4, 6]

사람이 해석하면 문장 네 개와 각 문장의 Token 여섯 개입니다. Embedding을 통과하면 다음 Shape이 됩니다.

hidden_states Shape = [4, 6, D]

[문장 수, 문장마다 Token 수, Token 하나의 정보 차원]

GPU는 4가 문장 수라는 의미를 알지 못합니다. GPU가 보는 것은 계산할 값이 많이 들어 있는 Tensor입니다.

[4, 6, D] 크기의 Tensor
→ 각 위치에 필요한 계산이 존재함
→ 가능한 계산을 여러 Thread에 분배함

따라서 GPU 병렬 처리의 직접적인 원인은 “첫 번째 축이 Batch이기 때문”이라기보다, 큰 Tensor 연산 안에 동시에 수행할 수 있는 계산이 많이 존재하기 때문입니다.

8. 여러 문장을 하나의 Batch Tensor로 구성하는 이유

서로 다른 문장을 완전히 따로 모델에 호출하면 각각 별개의 연산으로 실행됩니다.

model(sentence_1)
model(sentence_2)
model(sentence_3)
model(sentence_4)

반면 문장들을 하나의 Tensor로 묶으면 PyTorch는 한 번의 모델 호출에서 더 큰 Tensor 연산으로 처리할 수 있습니다.

input_ids.shape == [4, 6]

outputs = model(
    input_ids=input_ids,
)
문장 네 개를 하나의 Batch Tensor로 구성
→ 모델에 한 번 전달
→ 큰 행렬 연산 생성
→ CUDA가 작은 계산들로 분할
→ GPU에서 병렬 실행

사용자 코드는 여러 입력을 하나의 Batch Tensor로 구성하고 모델과 Tensor를 GPU로 옮긴 뒤 모델을 호출합니다. PyTorch와 CUDA는 CUDA용 연산을 선택하고 Tensor Shape에 맞는 GPU Kernel을 실행해 계산을 여러 Thread에 분배합니다.

9. 생성에서는 무엇이 병렬이고 무엇이 순차적인가

Autoregressive Generation(자기회귀 생성)은 다음 Token을 하나씩 생성합니다.

첫 번째 새 Token 생성
→ 그 결과를 사용해 두 번째 새 Token 생성
→ 그 결과를 사용해 세 번째 새 Token 생성

두 번째 Token을 만들려면 첫 번째 Token 결과가 필요하므로 생성 Step 사이는 순차적입니다. 하지만 하나의 Step 안에서는 Batch의 여러 문장과 대규모 Tensor 연산을 함께 처리할 수 있습니다.

생성 Step 사이
→ 순차적

한 생성 Step 내부
→ 여러 문장의 행렬 연산을 병렬 처리 가능

11. 결론

.to(device)가 직접 병렬 처리를 실행하는 것은 아닙니다. .to("cuda")는 모델과 Tensor를 GPU 메모리로 옮기고, 이후 model(...)에서 PyTorch가 Tensor의 장치를 보고 CUDA용 연산을 선택합니다. CUDA는 큰 Batch Tensor의 행렬 계산을 수많은 작은 작업으로 나눠 GPU Thread에서 동시에 실행합니다.

CPU에서도 여러 Core·Thread와 최적화된 행렬곱 구현을 사용할 수 있으므로 CPU가 반드시 모든 원소를 하나씩 순서대로 처리하는 것은 아닙니다. 다만 GPU는 같은 종류의 계산을 많은 데이터에 반복하는 Tensor 연산에 훨씬 많은 연산 장치를 사용할 수 있습니다.

현재는 이 연결을 코드와 Shape을 통해 설명한 단계입니다. 다음 검증은 CUDA GPU에서 같은 Batch 생성 실험을 실행하고, GPU 작업을 동기화한 상태에서 처리 시간과 Token 처리량을 비교하는 것입니다.
