PyTorch · CPU, GPU & Tensor Transfer

Tokenizer가 만든 Tensor는 언제 CPU에 있고, .to("cuda")는 무엇을 옮기는가

Tokenizer가 만든 입력 Tensor의 최초 장치부터 H2D·D2H 이동, GPU에서 다음 Token 선택과 후속 Forward를 유지하는 실제 추론 흐름까지 연결합니다.

← PyTorch 학습 경로Device·CUDA·병렬 연산
실습 목적 Tokenizer와 CPU CUDA로 이동 같은 장치 GPU Logit CPU로 이동 불필요한 왕복 줄이기 전체 흐름 결론

1. 이번 실습에서 확인하려던 것

RunPod의 GPU 환경에서 모델과 입력 Tensor를 CUDA 장치로 옮긴 뒤 다음 항목을 직접 확인했습니다.

모델은 어느 장치에 있는가?
Tokenizer가 만든 input_ids는 어디에 있는가?
.to("cuda") 이후에는 어디로 이동하는가?
모델이 반환한 Logit은 어디에 있는가?
GPU 결과를 CPU로 가져오면 무엇이 달라지는가?

실행 결과는 다음과 같았습니다.

Model Device: cuda:0
이동 전 Input Device: cpu
이동 후 Input Device: cuda:0
GPU Logits Device: cuda:0
D2H 후 Logits Device: cpu
Logits Shape: torch.Size([1, 3, 50257])

이 결과를 통해 CPU와 GPU 사이에서 Tensor가 어떻게 이동하는지 확인할 수 있었습니다.

2. Tokenizer가 만든 Tensor는 이미 CPU에 있습니다

입력 Token ID는 다음 코드로 만들었습니다.

cpu_input_ids: Int64[
    Tensor,
    "batch token",
] = tokenizer(
    "I study.",
    return_tensors="pt",
).input_ids

처음에는 이 코드에 .to("cpu")가 없기 때문에 아직 CPU나 GPU 어느 쪽에도 들어가지 않은 중간 상태처럼 보일 수 있습니다.

하지만 Tensor에는 장치가 정해지지 않은 상태가 없습니다. PyTorch Tensor는 생성되는 순간 반드시 어떤 장치의 메모리에 존재합니다.

Tokenizer는 별도의 장치를 지정하지 않으면 PyTorch Tensor를 CPU 메모리에 생성합니다.

print(cpu_input_ids.device)
# cpu

따라서 다음 두 코드는 장치 관점에서 같은 결과를 만듭니다.

input_ids = tokenizer(
    "I study.",
    return_tensors="pt",
).input_ids
input_ids = tokenizer(
    "I study.",
    return_tensors="pt",
).input_ids.to("cpu")

두 번째 코드는 이미 CPU에 있는 Tensor를 다시 CPU로 지정하므로 .to("cpu")가 불필요합니다.

3. .to(cuda_device)는 CPU Tensor를 GPU로 옮깁니다

Tokenizer가 만든 CPU Tensor를 GPU에서 계산하려면 CUDA 장치로 이동시켜야 합니다.

gpu_input_ids: Int64[
    Tensor,
    "batch token",
] = cpu_input_ids.to(cuda_device)

이때 일어나는 일은 다음과 같습니다.

CPU 메모리의 input_ids
→ H2D 복사
→ GPU 메모리의 input_ids

H2D는 Host to Device의 약자입니다.

  • Host: CPU와 CPU 메모리
  • Device: GPU와 GPU 메모리

이동 전후의 Tensor는 같은 Token ID를 가지지만 저장된 장치가 다릅니다.

print(cpu_input_ids.device)
# cpu

print(gpu_input_ids.device)
# cuda:0

학습을 위해 변수를 나누지 않아도 됩니다. 실제 코드에서는 다음처럼 Tokenizer 결과에 바로 .to(cuda_device)를 연결할 수 있습니다.

gpu_input_ids: Int64[
    Tensor,
    "batch token",
] = tokenizer(
    "I study.",
    return_tensors="pt",
).input_ids.to(cuda_device)

이번 실습에서는 이동 전후의 장치를 비교하기 위해 cpu_input_ids와 gpu_input_ids를 일부러 분리했습니다.

4. 모델과 입력 Tensor는 같은 장치에 있어야 합니다

모델도 GPU로 이동시켰습니다.

gpu_model: GPT2LMHeadModel = (
    GPT2LMHeadModel
    .from_pretrained(model_name)
    .to(cuda_device)
)

모델이 사용하는 Weight와 입력 Tensor가 모두 cuda:0에 있어야 GPU에서 계산할 수 있습니다.

모델 Weight: cuda:0
입력 Tensor: cuda:0
→ GPU 연산 가능

반대로 모델만 GPU에 있고 입력 Tensor는 CPU에 남아 있으면 서로 다른 장치의 값을 직접 계산할 수 없으므로 오류가 발생합니다.

모델 Weight: cuda:0
입력 Tensor: cpu
→ 장치 불일치 오류

모델의 장치는 첫 번째 Parameter를 통해 확인할 수 있습니다.

print(
    next(gpu_model.parameters()).device
)
# cuda:0

5. GPU 모델이 만든 Logit도 GPU에 있습니다

GPU 모델에 GPU 입력을 넣어 Forward를 실행했습니다.

with torch.inference_mode():
    gpu_outputs: CausalLMOutputWithCrossAttentions = (
        gpu_model(
            input_ids=gpu_input_ids,
            use_cache=False,
        )
    )

반환된 Logit도 GPU 메모리에 있습니다.

gpu_logits: Float[
    Tensor,
    "batch token vocabulary",
] = gpu_outputs.logits

print(gpu_logits.device)
# cuda:0

이번 입력의 Shape은 다음과 같습니다.

input_ids  [1,3]
logits     [1,3,50257]

각 축은 다음 의미입니다.

[Batch, Token 위치, Vocabulary 후보 점수]

즉 한 문장의 세 Token 위치마다 Vocabulary 50,257개에 대한 다음 Token 점수가 만들어졌습니다.

6. .to("cpu")를 호출해야 GPU 결과가 CPU로 돌아옵니다

GPU Logit을 CPU 메모리로 옮기기 위해 다음 코드를 실행했습니다.

cpu_logits: Float[
    Tensor,
    "batch token vocabulary",
] = gpu_logits.to("cpu")

이 이동은 D2H 복사입니다.

GPU 메모리의 Logit
→ D2H 복사
→ CPU 메모리의 Logit

D2H는 Device to Host의 약자입니다.

print(gpu_logits.device)
# cuda:0

print(cpu_logits.device)
# cpu

이번 실습에서는 GPU 결과를 CPU로 옮길 수 있다는 사실을 확인하기 위해 전체 Logit을 이동시켰습니다.

하지만 실제 Token 생성에서 매번 전체 Logit을 CPU로 옮길 필요는 없습니다.

7. 실제 추론에서는 불필요한 왕복을 줄입니다

이번 실습의 흐름만 보면 데이터가 다음처럼 계속 왕복하는 것처럼 보일 수 있습니다.

CPU input_ids
→ GPU input_ids
→ GPU logits
→ CPU logits

그러나 이것은 장치 이동을 확인하기 위한 실습 구조입니다.

실제 GPU Token 생성에서는 보통 Logit과 다음 Token 선택을 GPU에서 계속 처리합니다.

Tokenizer가 CPU에 input_ids 생성
→ input_ids를 GPU로 한 번 이동
→ GPU에서 Forward
→ GPU에서 argmax 또는 Sampling
→ 선택한 next_token_ids를 GPU에 유지
→ 다음 Forward에 다시 사용

예를 들면 다음과 같습니다.

next_token_ids: Int64[
    Tensor,
    "batch 1",
] = gpu_logits[:, -1, :].argmax(
    dim=-1,
    keepdim=True,
)

gpu_logits가 GPU Tensor이므로 argmax() 결과인 next_token_ids도 GPU에 남습니다.

따라서 다음 Forward에 다시 넣기 위해 CPU로 내렸다가 GPU로 올릴 필요가 없습니다.

최종 문자열 Decode나 CPU 기반 분석에 필요한 작은 결과만 마지막에 CPU로 가져오면 됩니다.

8. 전체 흐름

문자열 "I study."
        ↓
Tokenizer
        ↓
CPU input_ids [1,3]
        ↓ .to("cuda")
H2D 복사
        ↓
GPU input_ids [1,3]
        ↓
GPU Model Forward
        ↓
GPU logits [1,3,50257]
        ↓
GPU에서 argmax 또는 Sampling
        ↓
GPU next_token_ids [1,1]
        ↓
다음 GPU Forward에 그대로 사용

전체 Logit을 CPU에서 확인해야 할 때만 다음 이동이 추가됩니다.

GPU logits
    ↓ .to("cpu")
D2H 복사
    ↓
CPU logits

9. 결론

Tokenizer가 return_tensors="pt"로 만든 Tensor는 장치 미지정 상태가 아니라 이미 CPU 메모리에 존재합니다.

Tensor 생성 시 장치 미지정
→ 기본적으로 CPU Tensor 생성

.to("cuda")는 그 CPU Tensor를 GPU 메모리로 옮깁니다. GPU 모델에 GPU 입력을 전달하면 결과 Logit도 GPU에 생성됩니다.

CPU input_ids
→ H2D
→ GPU input_ids
→ GPU Model
→ GPU logits

이번 실습에서는 장치 이동을 확인하기 위해 GPU Logit을 다시 CPU로 옮겼지만, 실제 추론에서는 전체 Logit을 매번 CPU로 가져오지 않습니다. 다음 Token 선택과 후속 Forward를 GPU에서 계속 처리하고, 최종적으로 필요한 결과만 CPU로 가져오는 것이 일반적인 흐름입니다.
