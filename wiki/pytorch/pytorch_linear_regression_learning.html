2. 현재까지 작성한 전체 코드

원문의 마지막 b.grad글은 실행할 수 없는 오타이므로 b.grad로 수정했습니다.

linear_regression_step.py학습 1회
import torch

x = torch.tensor([
    [0.0],
    [1.0],
    [2.0],
    [3.0],
])

y = torch.tensor([
    [2.0],
    [5.0],
    [8.0],
    [11.0],
])

w = torch.randn(1, requires_grad=True)
b = torch.randn(1, requires_grad=True)

y_pred = x * w + b

print("w:", w)
print("b:", b)
print("예측값:", y_pred)
print("실제 정답:", y)

errors = y_pred - y
print("예측 오차:", errors)

squared_errors = errors ** 2
loss = squared_errors.mean()

print("오차의 제곱:", squared_errors)
print("평균 오차 loss:", loss)

loss.backward()

print("w의 gradient:", w.grad)
print("b의 gradient:", b.grad)

learning_rate = 0.01

with torch.no_grad():
    w -= learning_rate * w.grad
    b -= learning_rate * b.grad

print("수정된 w:", w)
print("수정된 b:", b)
현재 코드는 학습을 한 번만 수행합니다. 정답에 가까워지려면 이후 이 과정을 반복하고, 매 반복마다 이전 Gradient를 0으로 초기화해야 합니다. 반복 학습은 다음 단계에서 구현합니다.

3. 랜덤한 w와 b에서 시작한다

w = torch.randn(1, requires_grad=True)
b = torch.randn(1, requires_grad=True)

torch.randn(1)의 숫자 1은 초기값 1이 아니라, 랜덤한 숫자를 한 개 만들라는 뜻입니다.

부분뜻
w학습하면서 바꿀 기울기
b학습하면서 바꿀 시작점
requires_grad=True이 값이 Loss에 어떤 영향을 주었는지 추적하고 Gradient를 계산할 대상으로 표시
requires_grad=True가 값을 자동으로 바꾸지는 않습니다. 계산 기록을 남겨 두었다가 loss.backward()가 수정 방향을 계산할 수 있게 합니다. 실제 수정은 뒤의 Update 코드가 수행합니다.

첫 번째 예측

y_pred = x * w + b

같은 w와 b를 데이터 네 개에 각각 적용합니다.

x=0 → 0×w+b
x=1 → 1×w+b
x=2 → 2×w+b
x=3 → 3×w+b

4. 예측이 얼마나 틀렸는지 측정한다

errors = y_pred - y

오차가 양수면 예측이 정답보다 크고, 음수면 작으며, 0이면 정확합니다.

왜 오차를 제곱하는가?

오차를 그대로 더하면 음수와 양수가 서로 지워질 수 있습니다.

−2 + 22 = 0

두 예측 모두 2만큼 틀렸는데도 오차가 0처럼 보입니다. 제곱하면 모든 값이 양수가 됩니다.

(−2)² + 2²2 = 4 + 42 = 4
squared_errors = errors ** 2
loss = squared_errors.mean()

이 Loss를 평균제곱오차(MSE)라고 합니다.

분산

각 값이 평균에서 얼마나 떨어졌는지 제곱한 뒤 평균냅니다.

MSE

각 예측값이 정답에서 얼마나 떨어졌는지 제곱한 뒤 평균냅니다.

둘 다 차이 → 제곱 → 평균 구조를 사용하지만, 분산은 평균과 비교하고 MSE는 정답과 비교합니다.

별도의 Loss 함수에 넣지 않았는데 왜 이것이 함수인가?

일반 애플리케이션 개발에 익숙하면 “특정 함수에 값을 전달해야 Loss가 계산된다”고 생각하기 쉽습니다. 하지만 아래에 순서대로 작성한 Tensor 연산 전체가 이미 하나의 Loss 함수를 구성합니다.

y_pred = x * w + b
errors = y_pred - y
squared_errors = errors ** 2
loss = squared_errors.mean()

이 코드를 하나의 수학식으로 합치면 다음과 같습니다.

Loss(w,b) = mean((xw + b − y)²)

명시적인 Python 함수로 감싸도 의미는 같습니다.

def calculate_loss(x, y, w, b):
    y_pred = x * w + b
    errors = y_pred - y
    squared_errors = errors ** 2

    return squared_errors.mean()


loss = calculate_loss(x, y, w, b)

계산이 끝나면 보통 최종 숫자만 남습니다. double loss = 7.5만으로는 그 숫자가 어떤 연산을 거쳐 만들어졌는지 거슬러 올라갈 수 없습니다.

자동미분을 추적하는 Tensor

최종 숫자뿐 아니라 자신을 만든 연산과 이전 Tensor의 연결 관계도 가지고 있습니다. 이 관계를 계산 그래프라고 합니다.

w,b → xw+b → 예측−정답 → 제곱 → 평균 → loss

출력에서 보이는 grad_fn=<MeanBackward0>는 이 Loss Tensor가 평균 연산으로 만들어졌고, 이전 계산으로 거슬러 올라갈 기록을 가지고 있다는 표시입니다.

개발자 관점의 핵심 전환 — PyTorch에서는 미리 정의된 특별한 Loss 함수만 역전파할 수 있는 것이 아닙니다. requires_grad=True인 Tensor들로 수행한 연산 자체가 동적으로 함수와 계산 그래프를 만들고, 최종 스칼라 Tensor의 backward()가 그 그래프를 사용합니다.

5. 평균변화율에서 순간변화율로

Gradient를 이해하려면 먼저 두 점 사이의 평균변화율과 한 점에서의 순간변화율을 구분해야 합니다.

두 점 사이의 평균변화율

다음과 같이 단순한 Loss 함수 하나를 생각합니다.

Loss(w) = (w − 3)²

w=1일 때 Loss는 4이고, w=2일 때 Loss는 1입니다.

대상처음나중변화량
w12+1
Loss41−3
평균변화율 = Loss 변화량w 변화량 = −31 = −3

−3은 이 구간에서 w가 증가할 때 Loss가 감소했다는 뜻입니다.

두 번째 점을 기준점에 점점 가깝게 가져온다

기준점 w=1은 그대로 두고, 비교할 두 번째 점을 점점 가까이 가져옵니다.

비교 구간평균변화율
1 → 2−3
1 → 1.1−3.9
1 → 1.01−3.99
1 → 1.001−3.999

두 점의 간격을 0에 한없이 가깝게 줄이면 변화율은 −4에 가까워집니다. 이것을 w=1이라는 한 점에서의 순간변화율 또는 미분값이라고 합니다.

w=1에서 dLossdw = −4

왼쪽에서 접근해도 같은가?

w=0.9999처럼 기준점의 왼쪽에서도 접근할 수 있습니다.

왼쪽에서 접근

w 변화량은 음수, Loss 변화량은 양수이므로 변화율은 음수이며 약 −4.0001이 됩니다.

오른쪽에서 접근

w 변화량은 양수, Loss 변화량은 음수이므로 변화율은 음수이며 약 −3.9999가 됩니다.

양쪽에서 같은 값 −4에 가까워지므로 이 점에서 미분할 수 있습니다. 접근하는 쪽은 달라도 변화량의 부호까지 함께 나누기 때문에 같은 순간변화율을 얻습니다.

PyTorch가 실제로 w를 조금씩 움직여 보는 것은 아닙니다. 작은 간격으로 접근하는 설명은 순간변화율의 의미를 이해하기 위한 것입니다. PyTorch의 자동미분은 저장된 계산식에 미분 규칙을 적용해 현재 순간변화율을 바로 계산합니다.

실제 실습 데이터에서 평균변화율과 w.grad 구분하기

실제 데이터 네 개를 사용하고 현재 값을 w=1, b=1로 놓으면 예측, 오차, Loss는 다음과 같습니다.

y_pred = [1, 2, 3, 4]
y      = [2, 5, 8, 11]
errors = [-1, -3, -5, -7]

loss = (1² + 3² + 5² + 7²) / 4
     = 21

b=1은 고정하고 w만 1 → 1.1로 움직이면 새로운 Loss는 19.335가 됩니다.

평균변화율 = 19.335 − 211.1 − 1 = −16.65

하지만 −16.65는 0.1이라는 구간에서 계산한 평균변화율이지, 정확한 w.grad는 아닙니다. 움직이는 크기를 바꾸면 평균변화율도 달라집니다.

w의 비교 구간w 변화량평균변화율

이동량을 0에 한없이 가깝게 줄이면 평균변화율은 −17에 가까워집니다. 이 극한값이 현재 w=1, b=1에서의 순간변화율입니다.

w.grad = ∂Loss∂w = lim(Δw→0) Loss(w+Δw,b) − Loss(w,b)Δw = −17

실제로 선택한 이동 구간에 따라 값이 달라집니다.

순간변화율 · w.grad

이동량을 0에 가깝게 보냈을 때 수렴하는 현재 한 점의 변화율입니다.

학습할 값이 여러 개라면 각각 구한다

실제 Loss는 w와 b 두 값에 의해 결정됩니다.

Loss(w, b)
w에 대한 순간변화율

b는 고정하고 w만 아주 조금 변한다고 보았을 때 Loss가 변하는 비율입니다. PyTorch는 이를 w.grad에 저장합니다.

b에 대한 순간변화율

w는 고정하고 b만 아주 조금 변한다고 보았을 때 Loss가 변하는 비율입니다. PyTorch는 이를 b.grad에 저장합니다.

Gradient = [w에 대한 순간변화율, b에 대한 순간변화율]

즉 Gradient는 특별한 별개의 숫자가 아니라, 학습할 값 각각의 순간변화율을 모아 놓은 것입니다.

6. backward()가 Gradient를 계산한다

loss.backward()

print(w.grad)
print(b.grad)

backward()는 어떤 외부 함수에 Loss를 다시 전달하는 호출이 아닙니다. 현재 loss Tensor 자신이 기억하고 있는 계산 그래프에서 출발해 앞의 계산을 거꾸로 따라가며, w와 b 각각에 대한 Loss의 순간변화율을 계산합니다.

loss평균 오차
squared_errors오차 제곱
errors예측−정답
y_predxw+b
w, b조절 대상
backward()는 w와 b를 움직이지 않습니다. 실행 전후의 w와 b는 그대로이고, 계산 결과인 w.grad와 b.grad만 채워집니다.
반환값이 아니라 .grad에 저장합니다. result = loss.backward()의 result는 None입니다. 계산된 변화율은 requires_grad=True로 표시한 학습 대상의 w.grad, b.grad에 각각 저장됩니다.

부호는 어느 방향으로 움직일지 알려준다

GradientLoss를 줄이는 방향
음수해당 값을 증가시킵니다.
양수해당 값을 감소시킵니다.
0현재 위치에서 기울기가 평평합니다.

예를 들어 w.grad=-31.4925라면, 현재 위치에서 w를 조금 증가시킬 때 Loss가 감소한다는 뜻입니다.

w와 w.grad는 다릅니다.
w는 예측 직선의 기울기이고, w.grad는 그 기울기 w를 바꿀 때 Loss가 변하는 방향과 정도입니다.

7. 학습률만큼 w와 b를 수정한다

learning_rate = 0.01

with torch.no_grad():
    w -= learning_rate * w.grad
    b -= learning_rate * b.grad
새 값 = 현재 값 − 학습률 × Gradient

Gradient는 현재 위치에서의 경사를 계산하고, learning_rate는 그 방향으로 실제로 얼마나 이동할지 사람이 정한 값입니다.

w.grad=-31.4925, 학습률이 0.01이라면:

w의 변화량 = −0.01 × (−31.4925) = +0.314925

Gradient가 음수이므로 빼기와 만나 양수가 되고, w는 약 0.315 증가합니다.

Gradient가 음수면 왜 w가 증가하는가?

업데이트 식을 그대로 펼치면 부호의 의미가 보입니다.

새 w = 현재 w − learning_rate × w.grad

w.grad가 음수이면 음수를 빼게 되므로 실제 계산은 더하기가 됩니다.

현재 w = 1
learning_rate = 0.1
w.grad = -4

새 w = 1 - 0.1 * (-4)
     = 1 + 0.4
     = 1.4
w.grad업데이트 결과Loss를 줄이기 위한 움직임
음수음수를 빼므로 w가 증가오른쪽으로 이동
양수양수를 빼므로 w가 감소왼쪽으로 이동
0에 가까움w가 거의 변하지 않음현재 지점 주변에 머묾

최적점에 가까워지면 이동량도 작아진다

학습률이 같더라도 Gradient의 크기가 작아지면 실제 업데이트 크기도 작아집니다.

w.grad = -4.0  → w 변화량 = +0.4
w.grad = -2.0  → w 변화량 = +0.2
w.grad = -0.2  → w 변화량 = +0.02
w.grad ≈  0    → w가 거의 움직이지 않음

현재 선형회귀 MSE는 아래로 볼록한 그릇 모양이므로 최솟값에 가까워질수록 Gradient가 0에 가까워집니다. 만약 한 번에 너무 멀리 이동해 최적점을 지나치면 Gradient의 부호가 양수로 바뀌고, 다음 업데이트에서 w를 다시 감소시키는 방향으로 움직입니다.

Gradient 0이 언제나 낮은 Loss를 보장하는 것은 아닙니다. 일반적인 복잡한 함수에서는 Gradient가 0인 곳이 최솟값, 최댓값 또는 안장점일 수 있습니다. 지금의 단순한 선형회귀 MSE에서는 Loss가 볼록하므로 Gradient가 0인 지점이 전체 최솟값입니다.

왜 torch.no_grad()를 사용하는가?

w와 b를 수정하는 행위 자체는 학습할 계산식에 포함할 필요가 없습니다. torch.no_grad()는 이 수정 구간을 자동미분 기록에서 제외합니다.

w.grad는 w의 변화율이 아니다

w.grad = w를 바꿀 때 Loss가 변하는 순간변화율

w는 모델이 조정할 값이고, w.grad는 현재 w 위치에서 Loss 그래프가 어느 방향으로 얼마나 가파른지를 나타냅니다. 정답 y, 예측값 y_pred, 현재 Loss 값과도 서로 다른 숫자입니다.

y=2는 계산 결과가 아니라 맞혀야 하는 정답 데이터입니다.
w=1, x=1이면 현재 예측은 y_pred=wx=1입니다. 학습 전부터 y_pred=y인 것이 아니며, 두 값의 차이로 Loss를 만든 뒤 w를 조정해 예측을 정답에 가까이 보냅니다.

Loss=(wx-y)²의 Gradient를 문자로 유도한다

임의의 숫자를 대입해 맞는지 확인하는 데서 멈추지 않고, 문자 그대로 전개해 공식을 유도합니다. 시작점은 w를 정확히 0이 아니라 0에 가까워지는 값 h만큼 움직였을 때의 변화율입니다.

lim(h→0) ((w+h)x-y)² − (wx-y)²h

1단계 · 움직인 뒤의 오차를 정리한다

첫 번째 괄호에서 분배법칙을 적용합니다.

(w + h)x - y
= wx + hx - y
= (wx - y) + hx

따라서 전체 변화율은 다음과 같습니다.

lim(h→0) ((wx-y)+hx)² − (wx-y)²h

2단계 · 반복되는 기존 오차를 A로 치환한다

식을 보기 쉽게 만들기 위해 기존 오차인 wx-y를 잠시 A라고 둡니다.

A = wx − y

그러면 식은 다음처럼 단순해집니다.

lim(h→0) (A+hx)² − A²h

3단계 · 제곱 공식을 사용해 전개한다

(A+hx)² = A² + 2Ahx + h²x²

이를 원래 식에 넣습니다.

lim(h→0) A² + 2Ahx + h²x² − A²h

앞의 A²와 뒤의 −A²가 서로 사라집니다.

lim(h→0) 2Ahx + h²x²h

4단계 · h를 약분한 뒤 0으로 보낸다

분자의 각 항과 분모에 공통으로 들어 있는 h를 약분합니다.

lim(h→0) (2Ax + hx²)
이때 h는 아직 정확히 0이 아닙니다.
0이 아닌 h로 먼저 약분한 뒤, 약분이 끝난 식에서 h가 0에 한없이 가까워질 때의 값을 구합니다. 따라서 0으로 나누는 계산이 아닙니다.

이제 h→0이면 hx²→0이므로 다음만 남습니다.

2Ax + 0x² = 2Ax

5단계 · A를 원래 오차로 되돌린다

A=wx-y였으므로 다시 대입합니다.

2Ax = 2(wx-y)x
ddw(wx-y)² = 2(wx-y)x
Gradient = 2 × error × x = 2(wx-y)x

이 공식은 특정 숫자에서만 성립하는 것이 아니라, 모델이 y_pred=wx이고 Loss가 제곱오차일 때 임의의 w, x, y에 적용됩니다. 모델이나 Loss가 달라지면 Gradient 식도 달라집니다.

학습률은 Loss의 일부가 아니라 Gradient의 반영 비율이다

w의 이동량 = −learning_rate × w.grad

learning_rate=0.1은 현재 Loss의 10%를 더한다는 뜻이 아닙니다. Loss 변화율의 반대 방향으로, 그 크기의 0.1배만큼 w를 이동한다는 뜻입니다.

w = 1.2
w.grad = -1.6
learning_rate = 0.1

이동량 = -0.1 * (-1.6) = +0.16
새 w = 1.2 + 0.16 = 1.36

왜 Gradient를 0으로 지우고 다시 계산하는가?

PyTorch의 backward()는 새 Gradient로 교체하지 않고 기존 .grad에 더합니다.

w.grad += 이번 backward가 계산한 Gradient
기존 w.grad = -2.0
현재 위치의 새 Gradient = -1.6

초기화 없이 backward → -3.6
zero_() 뒤 backward → -1.6

여러 계산이나 여러 미니배치의 영향을 의도적으로 합칠 때 누적이 필요합니다. 매 학습 단계에서 현재 Gradient만 사용할 때는 업데이트 전후의 적절한 위치에서 zero_() 또는 Optimizer의 zero_grad()로 지웁니다.

w -= ...와 w = w - ...의 차이

torch.no_grad() 안에서 w = w - ...를 실행하면 오른쪽 계산으로 새 Tensor를 만들고 이름 w가 그 Tensor를 가리키게 됩니다. 새 Tensor는 자동미분 추적이 꺼져 있어 다음의 w.grad가 None이 될 수 있습니다.

w = w - ...

새 Tensor로 이름을 다시 연결합니다.

w -= ...

기존 leaf Tensor의 값을 in-place로 수정해 requires_grad=True 상태를 유지합니다.

반복문 출력의 시점을 구분한다

Loss를 계산한 뒤 w를 업데이트하고 둘을 함께 출력하면, 수정 전 Loss와 수정 후 w가 같은 줄에 표시됩니다.

y_pred = w * x
loss = (y_pred - y) ** 2  # 현재 w로 계산한 수정 전 Loss
loss.backward()

with torch.no_grad():
    w -= learning_rate * w.grad  # 이제 w는 수정 후 값

print(w, loss)  # 수정 후 w, 수정 전 Loss

예를 들어 첫 반복의 출력이 w=1.2, loss=1.0이라면 Loss 1.0은 w=1.0에서 계산된 값입니다. w=1.2의 Loss 0.64는 다음 forward에서 계산됩니다.
