JavaScript·Vue 브라우저 실행 흐름

화면 code를 문법 조각으로 외우지 않고, browser가 event를 전달하고 task를 예약하며 component state와 route를 바꾸는 순서로 이해합니다.

브라우저 경계EventEvent loopTimerPromiseVue templateprops·emitlifecycleRouter결론

1. HTML, CSS, JavaScript는 역할이 다르다

  • HTML(HyperText Markup Language: 하이퍼텍스트 마크업 언어)은 문서의 구조와 의미를 표현합니다.
  • CSS(Cascading Style Sheets: 종속형 스타일 시트)는 cascade와 selector를 통해 표현을 결정합니다.
  • JavaScript는 DOM(Document Object Model: 문서 객체 모델), browser API(응용 프로그램 인터페이스), network 요청과 application state를 조작합니다.

화면에 보인다는 이유만으로 div와 button을 바꿔 써도 되는 것은 아닙니다. Semantic element는 keyboard 기본 동작, 접근성 tree, form 제출 같은 browser behavior를 함께 갖습니다.

2. Event는 target에서 전달되고 기본 동작을 가질 수 있다

<form id="search-form">
  <input name="query">
  <button type="submit">검색</button>
</form>
form.addEventListener("submit", (event) => {
  event.preventDefault();
  runSearch(new FormData(form).get("query"));
});

form 안의 button은 type을 생략하면 기본 submit button입니다. 제출 의도가 없는 control은 type="button"을 명시합니다. preventDefault()는 browser의 기본 동작을 취소하며 event propagation(전파)을 멈추지는 않습니다. 전파를 막는 stopPropagation()과 구분합니다.

Event delegation은 부모에 listener 하나를 두고 event.target이나 closest()로 실제 항목을 찾는 방식입니다. 동적으로 추가되는 list와 많은 항목에 유용하지만, target이 예상 element인지 검증해야 합니다.

3. Event loop는 완료된 callback을 실행 순서에 올린다

간단한 흐름
현재 call stack 실행 → microtask queue 비우기 → render 기회 → 다음 task
console.log("A");
setTimeout(() => console.log("timer"), 0);
Promise.resolve().then(() => console.log("promise"));
console.log("B");
// A, B, promise, timer

setTimeout(..., 0)은 즉시 실행이 아니라 최소 지연 뒤 task queue에 callback을 넣을 수 있다는 뜻입니다. Promise reaction은 microtask이므로 현재 stack이 끝난 뒤 일반 timer task보다 먼저 처리됩니다. 긴 synchronous loop는 queue뿐 아니라 render와 입력 처리도 막습니다.

4. Timer는 생성한 scope에서 해제한다

const timerId = setInterval(refreshStatus, 5000);
// 더는 필요하지 않을 때
clearInterval(timerId);

Interval callback이 이전 network 요청보다 빨리 반복되면 요청이 겹칠 수 있습니다. 완료 뒤 다음 setTimeout을 예약하거나 in-flight guard를 두어 중첩을 막습니다. Component가 사라지거나 route가 바뀔 때 timer, event listener, subscription을 정리하지 않으면 보이지 않는 작업과 memory reference가 남습니다.

5. Promise 조합은 실패 계약이 다르다

const [profile, orders] = await Promise.all([
  fetchProfile(),
  fetchOrders(),
]);
조합완료 조건적합한 상황
Promise.all하나라도 reject하면 전체 reject모든 결과가 있어야 다음 단계 가능
Promise.allSettled모든 작업이 settled될 때까지 대기부분 성공을 각각 표시
Promise.race가장 먼저 settled된 결과timeout 경쟁 등
Promise.any첫 fulfilled 결과여러 대안 중 하나 성공

Promise.all이 reject돼도 다른 underlying 작업이 자동 취소되는 것은 아닙니다. 취소가 필요하면 AbortController 같은 API와 작업별 정리 전략을 사용합니다.

6. Vue template은 state를 DOM으로 선언하는 문법이다

<ul>
  <li v-for="item in items" :key="item.id">
    <button type="button" @click="select(item.id)">
      {{ item.name }}
    </button>
  </li>
</ul>
  • {{ expression }}: text interpolation
  • v-bind 또는 :: attribute·prop binding
  • v-on 또는 @: event listener
  • v-for: collection rendering
  • :key: 항목 identity를 알려 DOM 재사용을 안정화

Index를 key로 쓰면 삽입·정렬 때 다른 항목의 DOM state가 재사용될 수 있습니다. Data가 가진 안정적인 고유 ID를 사용합니다.

7. Data는 props down, events up으로 흐른다

Parent가 child에 props를 전달하고, child는 props를 직접 변경하지 않고 event를 emit해 parent에 변경 의도를 알립니다.

<script setup>
const props = defineProps({ count: Number })
const emit = defineEmits(["increment"])
</script>

<template>
  <button type="button" @click="emit('increment')">
    {{ props.count }}
  </button>
</template>

양방향 binding처럼 보이는 v-model도 component contract에서는 prop과 update event의 조합입니다. 누가 state를 소유하는지 명확히 해야 여러 component가 같은 값을 덮어쓰는 문제를 피할 수 있습니다.

8. Lifecycle hook은 외부 자원의 시작과 정리 지점이다

onMounted(() => {
  window.addEventListener("resize", updateLayout);
});

onUnmounted(() => {
  window.removeEventListener("resize", updateLayout);
});

DOM이 필요하지 않은 순수 계산을 무조건 mounted hook으로 미루지 않습니다. 반대로 DOM, timer, observer, socket처럼 component 생명주기 밖의 자원은 생성한 hook과 대응하는 cleanup을 둡니다. Reactive data 변화를 관찰할 때는 computed value로 표현 가능한지 먼저 보고, side effect가 필요할 때 watch를 사용합니다.

9. Client router는 URL과 component tree를 동기화한다

SPA(Single-Page Application: 단일 페이지 응용 프로그램)의 router는 full page reload 없이 history와 화면을 바꿉니다. Route guard는 navigation 전후 조건을 처리하고, analytics처럼 완료된 route를 기록하는 작업은 afterEach 같은 완료 hook에 둡니다.

Vue Router와 React Router는 major version마다 API와 권장 구성이 크게 달랐습니다. 과거 예제의 constructor, hook, route declaration을 그대로 섞지 말고 설치된 version의 공식 문서에서 확인합니다. Direct URL 새로고침이 server 404가 되지 않도록 hosting server의 fallback routing도 필요합니다.

10. 결론

Frontend 오류는 HTML 기본 동작 → event 전달 → synchronous stack → microtask/task → component state 소유권 → lifecycle 정리 → route 변경 순서로 추적합니다. Framework 문법은 이 browser 실행 모델 위에 있으므로, 둘을 함께 보면 timer 중복, form reload, stale request, prop 변경과 listener leak을 같은 흐름으로 설명할 수 있습니다.
