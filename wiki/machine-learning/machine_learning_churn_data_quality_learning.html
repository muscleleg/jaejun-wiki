회원 이탈 데이터 품질 점검

모델을 만들기 전에 한 행의 의미, 자료형, 숨은 공백, 결측값, 중복과 Label 비율을 실제 데이터로 확인한 과정이다.

구조 숨은 공백 불리언 인덱싱 변환과 대체 중복과 Label normalize 구분 완료와 다음 단계 Feature·Label과 분할 Contract One-Hot StandardScaler

1. 원본 데이터의 모양과 자료형을 확인한다

행·열 수, 열 이름, dtype을 먼저 보면 어떤 Feature를 바로 사용할 수 있고 어떤 값에 전처리가 필요한지 알 수 있다. 모델을 만들기 전에 데이터 계약부터 확인하는 단계다.

2. isna()가 0이어도 빈 정보가 있을 수 있다

문자열 열에는 NaN이 아니라 공백 문자열이 들어 있을 수 있다. 공백 제거 후 길이가 0인 행을 찾아 실제 데이터를 직접 확인하고, 근거가 있을 때만 결측값으로 바꿔 처리한다.

3. 중복과 Label 분포를 확인한다

완전히 같은 행은 중복 수를 확인하고, Churn의 개수와 비율을 함께 본다. normalize=True는 평균이 아니라 각 Label의 비율을 반환한다.

중복·Label 분포·품질 확인 결과 보기 →

4. Feature·Label을 나누고 Train·Validation을 분리한다

Feature는 모델이 입력으로 보는 열이고 Label은 맞힐 정답이다. stratify=y는 Train과 Validation의 Label 비율을 비슷하게 유지해 평가 조건이 한쪽으로 치우치지 않게 한다.

5. 범주형 Feature는 One-Hot Encoding한다

문자열 범주는 순서가 없는 별도 열로 펼친다. 전처리기는 Train에서 출력 열 계약을 학습하고 Validation에는 같은 계약을 적용해야 데이터 누수를 막을 수 있다.

분할·One-Hot·fit/transform 계약 자세히 보기 →

6. 숫자형 Feature는 StandardScaler로 크기를 맞춘다

Train 데이터의 평균과 표준편차로 숫자형 Feature를 변환하고, Validation에는 그 값을 그대로 사용한다. One-Hot과 숫자형 변환은 하나의 ColumnTransformer로 합쳐 같은 입력 계약을 유지한다.
