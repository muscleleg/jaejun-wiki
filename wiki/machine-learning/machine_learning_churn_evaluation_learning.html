회원 이탈 예측으로 이해하는 머신러닝 실무 기초

회사 동료와의 대화에서 나온 Loss, Precision, Recall, AUC를 출발점으로 머신러닝 실무가 문제 정의·데이터·학습·평가·반복 실험으로 연결되는 과정을 정리한다.

회원 이탈을 예측 문제로 바꾼다

고객 정보를 Feature로, 이탈 여부를 Label로 정하고 “어떤 오류를 더 줄여야 하는가”를 먼저 결정한다. 같은 확률 출력도 Threshold와 업무 비용에 따라 최종 판단이 달라진다.

확률을 Label로 바꾸고 Metric으로 평가한다

Accuracy는 전체 정답 비율이고, Precision은 Yes 예측의 신뢰도, Recall은 실제 Yes를 놓치지 않은 비율이다. F1은 Precision과 Recall이 한쪽만 높은 경우를 그대로 좋다고 보지 않는다.

Dummy Baseline으로 최소 기준을 만든다

패턴을 학습하지 않는 most_frequent와 stratified 결과를 먼저 측정하면 실제 모델이 단순한 정답 분포보다 나은지 판단할 수 있다.

Logistic Regression의 점수·확률·Label을 구분한다

학습된 선형 점수는 확률로 변환되고, Threshold를 기준으로 최종 Label이 된다. Confusion Matrix와 Classification Report는 이 최종 Label의 오류를 클래스별로 보여 준다.

Decision Tree는 질문으로 데이터를 나눈다

Tree는 현재 고객 묶음에서 Label이 덜 섞이게 만드는 Feature와 Threshold를 선택한다. 깊이를 무제한으로 늘리면 Train을 더 맞추면서 Validation 성능이 나빠질 수 있어 복잡도 제한을 함께 비교한다.

모델 선택은 지표와 오류 비용을 근거로 한다

Logistic과 Tree 중 어느 모델이 맞는지는 이름으로 정하지 않는다. 같은 분할과 전처리 조건에서 Baseline을 비교하고, 이탈자 Yes를 놓치는 비용과 잘못 붙잡는 비용을 함께 판단한다.
