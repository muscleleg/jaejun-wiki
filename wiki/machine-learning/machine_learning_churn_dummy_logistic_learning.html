Dummy Baseline과 Logistic Regression

상위 학습 흐름에서 Dummy Baseline과 Logistic Regression에 필요한 계산·코드·검증 내용을 자세히 정리한다.

4. 아무 패턴도 배우지 않는 Dummy Baseline

일반적인 모델은 X를 예측으로 바꾸는 계산 구조를 가진다. 학습할 때는 X_train으로 만든 예측과 정답지 y_train의 오차가 줄어들도록 그 구조 안의 가중치를 조절한다. 모델마다 표현할 수 있는 패턴의 형태가 다르며, y는 입력이 아니라 예측과 비교할 정답이다.

DummyClassifier는 예외적인 기준 모델입니다.
Feature X의 패턴을 학습하거나 일반 모델처럼 Feature 가중치를 맞추지 않습니다. y_train의 정답 분포만 사용해, 실제 모델이 최소한 넘어야 할 기준을 만듭니다.

most_frequent와 stratified

전략동작
most_frequenty_train에서 가장 많은 클래스 하나로 모든 예측을 고정한다.
stratifiedy_train의 클래스 비율을 확률로 사용해 무작위로 예측한다. 매번 클래스 개수를 정확히 같은 비율로 보장한다는 뜻은 아니다.

학습 데이터에서 선택하고 Validation에서 평가한다

from sklearn.dummy import DummyClassifier

dummy_model = DummyClassifier(
    strategy="most_frequent"
)

dummy_model.fit(
    X_train,
    y_train,
)
확인 항목실제 결과해석

y_train에서 No가 가장 많았으므로 most_frequent는 X_valid 1,409개를 모두 No로 예측했다.

dummy_predictions = dummy_model.predict(
    X_valid
)

pd.Series(dummy_predictions).value_counts()
# No    1409
Train과 Validation의 역할 구분
가장 많은 정답이 No라는 선택은 y_train에서 한다. 그렇게 정한 규칙을 X_valid에 적용한 뒤, 실제 정답 y_valid와 비교해 성능을 평가한다.

predict() 결과가 1차원인 이유

scikit-learn의 단일 Target 분류에서 predict()는 보통 NumPy ndarray를 반환하며 Shape은 (n_samples,)다. Feature가 19개여도 고객 한 명마다 최종 정답 하나를 예측하므로 입력 Feature 수와 예측 출력 차원은 별개다.

출력일반적인 Shape
단일 Target predict()(n_samples,)
여러 Target을 동시에 예측하는 Multi-output(n_samples, n_outputs)
이진 분류 predict_proba()보통 (n_samples, 2)

Pandas Series는 1차원 값에 Label Index와 이름을 함께 가진다. pd.Series(dummy_predictions).value_counts()는 NumPy 배열을 Series로 감싼 뒤 값별 개수를 세기 위한 코드다. NumPy만 사용한다면 np.unique(dummy_predictions, return_counts=True)로도 확인할 수 있다.

Accuracy를 직접 계산해 기준을 재현한다

correct_predictions = (
    dummy_predictions == y_valid.to_numpy()
)

dummy_accuracy = correct_predictions.mean()

비교 결과는 예측이 맞으면 True, 틀리면 False인 Boolean 배열이다. 평균을 구할 때 True=1, False=0으로 계산되므로 전체 중 맞힌 비율이 Accuracy가 된다.

Dummy Accuracy = 0.7345635202271115 = 73.45635202271114%
사용자의 말로 해석
y_train에서 No가 가장 많아 most_frequent가 모든 예측을 No로 고정했다. 그래서 Validation에서는 실제 No인 비율만큼 맞았고 Accuracy가 약 73.456%가 나왔다.
Dummy 챕터 완료
무조건 다수 클래스만 예측해도 얻는 Accuracy를 실제로 재현했다. 이 값은 새 모델이 넘어야 할 최소 비교 기준이지, 회원 이탈 패턴을 학습한 결과가 아니다.
다음 단계
문자형 Feature와 숫자형 Feature를 서로 다르게 처리하는 전처리 Pipeline을 이해한 뒤 Logistic Regression을 같은 Train/Validation Split에서 학습한다. Accuracy뿐 아니라 Precision과 Recall도 Dummy와 비교한다.

4-1. Logistic Regression 결과를 표로 읽기

같은 Train/Validation 분할에서 전처리된 Feature를 Logistic Regression에 학습시킨 뒤, Validation 예측을 실제 정답과 비교했다. Accuracy는 80.55%로 Dummy Baseline 73.46%보다 약 7.10%p 높다. 다만 Accuracy 하나로는 실제 이탈자를 얼마나 놓쳤는지 알 수 없으므로, 혼동 행렬을 함께 읽는다.

학습된 점수 · 확률 · 최종 Label은 서로 다른 출력이다

LogisticRegression.fit(X_train_processed, y_train)은 Train Feature에서 y_train의 No·Yes를 구분하도록 가중치를 학습한다. 같은 Validation 입력이라도 어떤 메서드를 호출하느냐에 따라 출력의 뜻이 다르다.

메서드무엇을 돌려주는가
decision_function(X_valid_processed)제한 없는 원시 점수. 음수·양수 모두 될 수 있으며 아직 확률이나 Label이 아니다.
predict_proba(X_valid_processed)클래스별 확률. 이 실습의 클래스 순서는 ['No', 'Yes']이므로 두 번째 열이 Yes 확률이다.
predict(X_valid_processed)확률을 판정 기준과 비교한 최종 No 또는 Yes Label이다.

이진 분류에서 Yes 확률은 원시 점수 s에 sigmoid를 적용해 만든다.

Yes 확률 = sigmoid(s) = 11 + exp(−s)

첫 다섯 검증 입력에서 실제로 확인한 원시 점수 [-3.0338, 0.7709, -2.7705, -0.3978, -3.8216]에 sigmoid를 적용하면 Yes 확률 [0.04592, 0.68371, 0.05894, 0.40184, 0.02142]가 나온다. 이 값은 predict_proba(...)의 Yes 열과 np.allclose로 같음을 확인했다.

같은 입력을 세 단계로 읽는다.
decision_function은 “Yes 쪽으로 얼마나 기울었는가”라는 원시 점수, predict_proba는 이를 0과 1 사이의 Yes 확률로 바꾼 값, predict는 그 확률을 기준으로 고른 최종 클래스다. 그래서 Threshold를 바꾸는 실습에서는 먼저 확률 열을 보고, 최종 Label이 어떻게 달라지는지 확인한다.

confusion_matrix를 DataFrame 표로 만든 이유

from sklearn.metrics import confusion_matrix

confusion = pd.DataFrame(
    confusion_matrix(
        y_valid,
        logistic_predictions,
        labels=["No", "Yes"],
    ),
    index=["실제 No", "실제 Yes"],
    columns=["예측 No", "예측 Yes"],
)

confusion_matrix(y_valid, logistic_predictions)에서 첫 번째 입력 y_valid는 실제 정답이므로 행이 되고, 두 번째 입력 logistic_predictions는 모델 예측이므로 열이 된다. labels=["No", "Yes"]는 두 클래스의 행·열 순서를 No, Yes로 고정한다. index와 columns는 계산을 바꾸지 않고 사람이 읽을 표의 행·열 제목을 붙인다.

예측 No예측 Yes
실제 No926109
실제 Yes165209
  • 926: 실제 No를 No로 맞춘 수
  • 109: 실제 No를 Yes로 잘못 경고한 수 (FP)
  • 165: 실제 Yes를 No로 놓친 수 (FN)
  • 209: 실제 Yes를 Yes로 찾아낸 수 (TP)

Accuracy는 전체 네 칸 중 정답인 대각선 두 칸을 더한 비율이다.

Accuracy = 926 + 209926 + 109 + 165 + 209 = 1,1351,409 ≈ 80.55%

Yes를 기준으로 행과 열을 다르게 읽는다

실제 Yes 행은 실제 이탈자 전체 165 + 209 = 374명이다. 이 행에서 예측 Yes 209명을 고르면 “실제 이탈자 중 찾아낸 비율”이 된다.

Yes Recall = 209165 + 209 ≈ 55.88%

반대로 예측 Yes 열은 모델이 이탈이라고 경고한 전체 109 + 209 = 318명이다. 이 열에서 실제 Yes 209명을 고르면 “이탈이라고 한 예측을 얼마나 믿을 수 있는가”가 된다.

Yes Precision = 209109 + 209 ≈ 65.72%
행 하나나 열 하나는 전체 모집단이 아니다.
실제 Yes 행은 실제 Yes라는 조건으로 자른 374명이고, 예측 Yes 열은 모델이 Yes라고 한 조건으로 자른 318명이다. 네 칸을 모두 더한 1,409명이 전체 Validation 모집단이다.

F1은 한쪽만 높은 상태를 그대로 좋다고 보지 않는다

이번 Yes Precision과 Recall의 단순 평균은 약 60.80%이고, F1은 약 60.40%다.

Yes F1 = 2 × 65.72 × 55.8865.72 + 55.88 ≈ 60.40%

F1은 Precision과 Recall의 조화평균이다. 한쪽만 높고 다른 쪽이 낮으면 단순 평균보다 낮은 쪽의 문제를 더 반영한다. 따라서 단순 평균과 F1이 비슷하면서 둘 다 높다면, Precision과 Recall이 모두 높고 균형도 비교적 맞는 상태다. 반대로 둘이 비슷해도 값 자체가 낮으면 좋은 모델이라는 뜻은 아니다.

classification_report는 클래스별 표를 한 번에 보여 준다

from sklearn.metrics import classification_report

print(
    classification_report(
        y_valid,
        logistic_predictions,
        labels=["No", "Yes"],
        digits=3,
    )
)

  • support: 각 행의 실제 정답 개수다. No는 1,035명, Yes는 374명이다.
  • accuracy: 클래스 구분 없이 전체 1,409명 중 맞춘 비율이다.
  • macro avg: No와 Yes를 같은 비중으로 단순 평균한다. 예를 들어 Precision은 (0.849 + 0.657) / 2 = 0.753이다.
  • weighted avg: 실제 정답 수(support)가 많은 클래스에 더 큰 비중을 준다. 이번 Precision은 0.849 × (1035 / 1409) + 0.657 × (374 / 1409) ≈ 0.798이다.
어떤 평균이 “더 좋은가”는 고정되어 있지 않다.
클래스 수가 적은 Yes도 No와 똑같이 중요하면 macro average가 그 차이를 더 잘 드러낸다. 실제 고객 수 비중대로 전체 성능을 요약하고 싶다면 weighted average가 맞는다. 이탈자를 놓치거나 잘못 경고하는 비용을 판단할 때는 평균 하나만 보지 말고 Yes Precision·Recall과 혼동 행렬도 함께 본다.
