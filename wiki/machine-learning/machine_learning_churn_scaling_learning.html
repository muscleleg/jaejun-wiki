10. 숫자형 Feature의 크기를 맞추는 StandardScaler

현재 숫자형 Feature 네 개는 값이 움직이는 범위와 표준편차가 서로 크게 달랐다.

Feature평균표준편차최솟값 ~ 최댓값
SeniorCitizen0.1632940.3696670 ~ 1
tenure32.48509124.5687440 ~ 72
MonthlyCharges64.92996130.13810518.4 ~ 118.75
TotalCharges2299.3346822279.2042780 ~ 8684.8

예를 들어 SeniorCitizen은 0과 1 사이인데 TotalCharges는 수천까지 간다. 이 값들을 그대로 사용하면 단위와 크기가 다른 숫자들이 한 모델 안에 함께 들어간다. 이번 실습에서는 각 숫자형 열을 자신의 평균과 표준편차 기준으로 바꾸는 StandardScaler를 확인했다.

fit과 transform

from sklearn.preprocessing import StandardScaler

numeric_scaler = StandardScaler()

scaled_numeric_train = numeric_scaler.fit_transform(
    X_train[numeric_features]
)
fitTrain의 숫자형 열마다 평균과 표준편차를 계산해 저장한다.
transform저장한 Train 평균과 표준편차로 각 값을 변환한다.
변환값 = 원래 값 − Train 열 평균Train 열 표준편차

Validation에도 Validation 자체의 평균과 표준편차를 새로 fit하지 않는다. Train에서 저장한 기준으로 transform해야 학습할 때와 같은 좌표계를 유지할 수 있다.

실제 변환 결과

scaled_numeric_train.mean(axis=0)
# [ 7.44089837e-17, -1.00893537e-17,
#  -2.40252735e-16,  2.52233843e-17]

scaled_numeric_train.std(axis=0)
# [1., 1., 1., 1.]

e-17과 e-16 수준의 평균은 부동소수점 계산 오차 때문에 생긴 매우 작은 값이므로 사실상 0이다. 출력으로는 네 열 모두 평균이 사실상 0, 표준편차가 1이 된 것을 확인했다.

One-Hot과 StandardScaler를 한 전처리기에 함께 넣기

preprocessor_scaled = ColumnTransformer(
    transformers=[
        (
            "categorical",
            OneHotEncoder(
                sparse_output=False,
                handle_unknown="ignore",
            ),
            categorical_features,
        ),
        (
            "numeric",
            StandardScaler(),
            numeric_features,
        ),
    ],
)

X_train_processed = preprocessor_scaled.fit_transform(
    X_train
)

X_valid_processed = preprocessor_scaled.transform(
    X_valid
)

print(X_train_processed.shape)  # (5634, 45)
print(X_valid_processed.shape)  # (1409, 45)

범주형 열은 One-Hot 결과로 옆으로 펼쳐지고, 숫자형 네 열은 Train 기준 StandardScaler 결과로 바뀐다. 따라서 최종 입력은 범주형 One-Hot 41열과 숫자형 4열을 이어 붙인 45열이다. 숫자형 열의 개수는 StandardScaler 때문에 늘지 않는다.

합쳐진 2차원 배열에서 마지막 숫자형 4열 꺼내기

processed_numeric_train = X_train_processed[
    :,
    -len(numeric_features):,
]

print(processed_numeric_train.shape)  # (5634, 4)
print(processed_numeric_train.mean(axis=0))
print(processed_numeric_train.std(axis=0))

NumPy의 2차원 슬라이싱은 배열[행 선택, 열 선택]으로 읽는다.

첫 번째 :모든 행을 선택한다.
-len(numeric_features):뒤에서 숫자형 열 개수만큼의 시작 위치부터 끝 열까지 선택한다.

현재 len(numeric_features) = 4이므로 위 선택은 X_train_processed[:, -4:]와 같다. 최종 전처리기에서 categorical 작업을 먼저, numeric 작업을 뒤에 적었기 때문에 이 실습에서는 마지막 네 열이 숫자형 StandardScaler 결과다.

전체 [5634, 45] → 모든 행 : + 마지막 4열 -4: → 숫자형 부분 [5634, 4]

작은 1차원 예시에서 values[-2:]가 마지막 두 값을 뜻하듯, 음수 인덱스는 뒤에서부터 위치를 세고 뒤의 :는 그 위치부터 끝까지를 뜻한다.

통합 전처리 검증 완료

X_train_processed[:, -len(numeric_features):]를 실제로 꺼내 확인했다. Shape은 [5634, 4]였고, 네 숫자형 열의 평균은 부동소수점 오차 수준으로 0, 표준편차는 모두 1이었다.

이번에 확인한 전처리 계약
Train은 fit_transform으로 범주형 41열과 StandardScaler 숫자형 4열을 합쳐 [5634, 45]가 된다. Validation은 Train에서 정한 One-Hot 칸과 평균·표준편차를 그대로 쓰는 transform으로 [1409, 45]가 된다. 다음 단계에서는 이 두 배열을 Logistic Regression에 넣어 Dummy Baseline과 비교한다.
아직 이해 완료로 처리하지 않은 수학 질문
코드 출력이 평균 0·표준편차 1이 되는 것은 확인했지만, “왜 평균을 빼도 표준편차는 원래의 σ로 남고, 다시 σ로 나누면 표준편차가 정확히 1이 되는가?”를 분산 공식에서 형식적으로 연결하는 과정은 아직 납득하지 못했다.
생략 없는 증명 초안
평균의 정의부터 z의 평균·표준편차를 직접 전개한 StandardScaler 평균 0·표준편차 1 증명을 추가했다. 이 문서는 다음 복습용 참조이며, 읽었다는 이유만으로 이해 완료 처리하지 않는다.

다음 복습에서 증명할 두 단계

1. 중심 이동y = x − μ일 때 새 평균은 0이고 표준편차는 왜 여전히 σ인가?
2. 크기 조절z = y / σ일 때 분산이 왜 1이고 표준편차도 왜 1인가?

이 증명은 다음 복습에서 작은 숫자 집합 하나에 평균·분산·표준편차 공식을 직접 대입해 두 단계를 설명할 수 있을 때 이해 완료로 표시한다. 전처리 통합과 출력 검증은 이미 끝났으므로, 현재 모델 실습의 다음 행동은 Logistic Regression 생성·학습·Dummy 비교다.
