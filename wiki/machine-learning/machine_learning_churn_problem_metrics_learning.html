이 문서의 출발점

머신러닝 실무는 논문과 수식을 완전히 이해한 뒤 새로운 알고리즘을 직접 구현하는 일만을 뜻하지 않는다. 이미 알려진 방법을 조사하고 현재 문제에 적용한 뒤, 동일한 조건에서 지표와 오류를 비교해 개선하는 작업도 큰 비중을 차지한다.

대화의 위치
동료 한 명의 경험은 머신러닝 직무 전체를 대표하는 객관적 근거가 아닙니다. 여기서는 그 대화를 학습 질문을 발견한 계기로 사용하며, 개별 업무 설명을 일반 법칙으로 단정하지 않습니다.
현재 바뀐 관점
실무의 핵심은 모든 이론을 먼저 완주하는 것이 아니라, 문제를 정확히 정의하고 검증 가능한 Baseline을 만든 뒤 지표와 오류 사례에 근거해 다음 실험을 선택하는 것입니다.

1. 회원 이탈을 머신러닝 문제로 바꾼다

Feature와 Label

구분회원 이탈 예시역할
Feature X최근 접속 이후 일수, 로그인 횟수, 가입 기간, 결제 금액, 문의 횟수예측에 사용하는 입력 정보
Label y이탈 1, 비이탈 0모델이 맞혀야 하는 실제 정답
Feature(X) → Model → Prediction → Label(y)과 비교

Feature와 Label만 정하면 끝나는 것이 아니다

예측 대상어떤 회원을 대상으로 하는가?
기준 시점언제까지의 정보만 Feature로 쓰는가?
예측 기간앞으로 며칠 이내의 이탈을 예측하는가?
업무 조치예측 후 쿠폰·상담 등 무엇을 실행하는가?
오류 비용FP와 FN 중 어느 실수가 더 비싼가?

예를 들어 이탈을 “향후 30일 동안 접속하지 않음”으로 정의한다면 예측 시점 이후의 30일은 Label을 만드는 데 사용해야 합니다. 이 미래 정보를 Feature에 섞으면 모델이 실제 예측 시점에 알 수 없는 정보를 본 것이므로 데이터 누수가 됩니다.

2. Weight와 Loss로 모델을 학습한다

사람이 Feature별 Weight를 일일이 정하는 것이 아니라, 모델이 학습 과정에서 Loss를 줄이는 방향으로 Weight를 조정합니다.

예측값 = Feature₁ × Weight₁ + Feature₂ × Weight₂ + ···
1. 입력Feature를 모델에 넣는다.
2. 예측현재 Weight로 결과를 계산한다.
3. LossPrediction과 Label의 차이를 수치화한다.
4. 학습Loss가 감소하는 방향으로 Weight를 수정한다.
5. 반복새 Weight로 다시 예측하고 평가한다.
실무자가 직접 조절하는 것
학습된 Weight 자체를 한 칸씩 손으로 바꾸기보다 Feature, 데이터 구성, 모델 종류, Hyperparameter, Loss, Class weight와 Threshold 등을 선택하고 실험합니다.

학습을 오래 한다고 무조건 좋아지지 않는다

분할역할
TrainWeight를 실제로 학습시키는 데이터
Validation학습 중 일반화 성능, Hyperparameter와 Threshold를 선택하는 데이터
Test선택을 모두 끝낸 뒤 마지막 성능을 평가하는 데이터

Train 성능만 계속 좋아지고 Validation 성능이 나빠지면 학습 데이터를 외우는 Overfitting을 의심합니다. Test 결과를 보면서 Threshold나 모델을 반복 선택하면 Test도 선택 과정에 오염됩니다.

3. 확률을 Threshold로 판정하고 결과를 평가한다

이진 분류기는 이탈 여부를 바로 출력하기보다 이탈 점수 또는 확률을 만들 수 있습니다. Threshold가 0.5라면 그 이상을 이탈로 판정합니다.

실제 이탈실제 비이탈
이탈로 예측TP · 정확히 발견FP · 잘못 경보
비이탈로 예측FN · 이탈을 놓침TN · 정확히 제외
TP·FP·TN·FN을 읽는 고정 규칙
P / N = 모델이 Positive / Negative 중 무엇으로 예측했는가
T / F = 그 예측이 실제 정답과 같았는가

Positive는 좋다는 뜻이 아니라 이 문제에서 찾아내기로 정한 대상입니다. 스팸 탐지에서는 스팸, 질병 검사에서는 질병 있음, 불량품 검사에서는 불량품을 Positive로 정할 수 있습니다.

이름모델의 예측예측이 맞았는가?
TPPositive맞음 · 실제도 Positive
FPPositive틀림 · 실제는 Negative
TNNegative맞음 · 실제도 Negative
FNNegative틀림 · 실제는 Positive

문제가 바뀌어도 같은 규칙을 적용하는 샘플

회원 이탈

TP 이탈로 예측 → 실제 이탈
FP 이탈로 예측 → 실제 비이탈
TN 비이탈로 예측 → 실제 비이탈
FN 비이탈로 예측 → 실제 이탈

스팸 탐지

TP 스팸으로 예측 → 실제 스팸
FP 스팸으로 예측 → 실제 정상
TN 정상으로 예측 → 실제 정상
FN 정상으로 예측 → 실제 스팸

질병 검사

TP 질병 있음으로 예측 → 실제 질병 있음
FP 질병 있음으로 예측 → 실제 질병 없음
TN 질병 없음으로 예측 → 실제 질병 없음
FN 질병 없음으로 예측 → 실제 질병 있음

불량품 검사

TP 불량품으로 예측 → 실제 불량품
FP 불량품으로 예측 → 실제 정상 제품
TN 정상 제품으로 예측 → 실제 정상 제품
FN 정상 제품으로 예측 → 실제 불량품

Precision · Recall · Accuracy · F1

Precision = TPTP + FP = 이탈이라고 예측한 사람 중 실제 이탈자 비율
Recall = TPTP + FN = 실제 이탈자 중 찾아낸 비율
Accuracy = TP + TN전체 데이터
F1 = 2 × Precision × RecallPrecision + Recall

실제 이탈자가 10명, 비이탈자가 90명일 때 전부 비이탈이라고 예측해도 Accuracy는 90%입니다. 그러므로 Positive가 적은 문제에서는 Accuracy만으로 모델을 평가하면 안 됩니다.

같은 모델도 Yes 기준으로 무엇을 묻느냐가 다르다

이탈을 Yes로 정하면, Recall은 실제로 이탈한 Yes 고객들 중 모델이 Yes로 찾아낸 비율이다. 따라서 실제 Yes인데 예측 No로 나온 FN이 많으면 Recall이 낮아진다. 이 지표는 “이탈자를 얼마나 놓치지 않았는가?”를 묻는다.

Precision은 모델이 Yes라고 예측한 고객들 중 실제로 Yes였던 비율이다. 따라서 실제 No인데 예측 Yes로 나온 FP이 많으면 Precision이 낮아진다. 이 지표는 “이탈이라고 경고한 대상이 얼마나 믿을 만한가?”를 묻는다.

무엇을 우선할지는 오류의 비용으로 정한다.
실제 이탈자를 놓치는 손해가 크면 Recall을 우선한다. 실제로 이탈하지 않을 고객에게 할인·상담 같은 유지 조치를 잘못 주는 비용이 크면 Precision을 우선한다. 두 오류의 비용이 비슷하면 Precision과 Recall이 모두 높고 서로 한쪽만 낮지 않게 보는 F1을 중심 지표로 둘 수 있다.

Threshold를 바꾸면 무엇이 달라지는가?

변경일반적인 영향비즈니스 의미
Threshold를 높임Precision 상승 가능, Recall 하락 가능확실한 대상만 조치하지만 실제 이탈자를 더 놓칠 수 있음
Threshold를 낮춤Recall 상승 가능, Precision 하락 가능더 많은 이탈자를 찾지만 불필요한 조치가 늘 수 있음
지표는 업무 비용과 연결해야 합니다.
쿠폰 비용이 매우 크면 FP를 줄이는 Precision이 중요할 수 있고, 고가 고객의 이탈을 놓치는 손해가 크면 FN을 줄이는 Recall이 중요할 수 있습니다.
