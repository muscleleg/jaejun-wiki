상위 학습 흐름에서 실험 판단과 다음 검증에 필요한 계산·코드·검증 내용을 자세히 정리한다.

5. 실제 업무는 지표를 근거로 한 반복 실험에 가깝다

1. 현재 평가Baseline과 오류를 확인한다.
2. 문제 발견어떤 집단에서 무엇을 틀리는지 찾는다.
3. 가설성능 저하의 원인을 하나 정한다.
4. 조사·변경Feature·알고리즘·설정을 하나 바꾼다.
5. 비교같은 Split과 Metric에서 다시 평가한다.

비교 가능한 실험을 위해 데이터 Split, Seed, Metric을 고정하고 한 번에 한 요인을 바꿉니다. “새 알고리즘을 사용했더니 좋아졌다”가 아니라 어떤 조건에서 어떤 지표가 얼마나 변했고 어떤 오류가 남았는지 기록해야 합니다.

문제 정의 → 데이터 준비 → Baseline → 학습 → 평가 → 오류 분석 → 가설 → 실험 → 비교

6. 오늘 내용에서 정확히 구분할 부분

Loss와 Metric

Loss는 Weight 학습에 사용하는 목적함수이고, Metric은 모델을 업무 관점에서 평가하는 수치입니다. 둘이 같을 필요는 없습니다.

Weight와 Hyperparameter

Weight는 모델이 학습하고, Learning rate·Tree depth·Threshold 같은 Hyperparameter나 운영 기준은 사람이 실험으로 선택합니다.

F1과 조화평균

같은 거리의 평균속도 예시는 조화평균이 등장하는 사례이지 F1 공식의 직접적인 증명은 아닙니다. F1은 Precision과 Recall 중 하나만 낮아도 점수가 크게 낮아지도록 조화평균을 사용합니다.

AUC와 Threshold

AUC가 높다고 특정 Threshold의 실제 업무 성과가 자동으로 좋다는 뜻은 아닙니다. 순위 능력과 최종 판정 성능을 구분해야 합니다.

대표 실습의 비교 순서

Dummy → Logistic Regression → Decision Tree → Random Forest 또는 Gradient Boosting

모든 알고리즘을 각각 별도 챕터로 외우지 않습니다. 동일한 Split과 Metric에서 대표 Baseline을 비교하고, Threshold와 불균형 처리 방법을 하나씩 바꾸면서 결과를 설명합니다.

실제 데이터 점검으로 연결
회원 이탈 공개 데이터의 구조·자료형·숨은 공백·결측·중복·Label 비율을 직접 확인했습니다. 회원 이탈 데이터 품질 점검 문서에서 isna(), 공백 문자열, 불리언 인덱싱, fillna()와 value_counts(normalize=True)의 실제 검증 과정을 이어서 봅니다.
