LLM 정밀도 형식과 양자화

모델의 계산식을 바꾸지 않고도 왜 FP32, BF16, FP8, INT4 같은 숫자 형식을 선택하는지, 메모리·표현 범위·반올림 오차의 trade-off로 연결한다.

원문과 읽는 위치

이 문서는 Avi Chawla의 LinkedIn 글 “8 LLM precision formats, clearly explained”을 읽으며 만든 학습 노트다.

원문의 한 문장 주장
더 적은 비트로 Tensor를 저장하면 메모리를 절약하고 계산을 빠르게 할 수 있지만, 그 비트는 숫자 범위 또는 세밀함 중 한쪽에서 줄어든다.
현재 이해 상태
7B 모델의 FP32 가중치가 약 28GB이고 4-bit 모델은 훨씬 작아진다는 큰 흐름은 이해했다. 다만 exponent·mantissa, scale, activation outlier, FP8의 두 형식을 아직 각각 계산으로 검증하지 않았다.

먼저 잡을 핵심

같은 Transformer 계산식 + 다른 숫자 저장·연산 형식 = 메모리·속도·수치오차의 trade-off

예를 들어 현재 손코딩한 아래 식은 그대로다.

scores = query @ key.transpose(-2, -1)
attention_weights = softmax(scores)
output = attention_weights @ value

달라지는 것은 query, key, value, 가중치와 gradient를 FP32로 둘지 BF16·FP8·INT4처럼 더 작은 형식으로 둘지다.

왜 7B 모델이 12GB GPU에 안 들어가는가?

가중치 저장 형식원소당 저장량70억 개 가중치만 대략 저장하면
FP324 bytes약 28GB
FP16 / BF162 bytes약 14GB
FP8 / INT81 byte약 7GB
INT4 / NF40.5 byte약 3.5GB

실제 모델 파일에는 scale, metadata, 일부 높은 정밀도 Tensor 등이 들어갈 수 있으므로 정확한 파일 크기는 다르다. 표는 왜 4-bit 추론 모델이 소비자 GPU에 들어갈 수 있는지 보여 주는 근사치다.

Float에서 무엇을 포기하는가?

[부호 sign] [지수 exponent] [가수 mantissa]
비트 영역하는 일줄이면 생기는 문제
sign양수·음수 표시보통 여기서는 줄이지 않는다.
exponent아주 큰 값과 아주 작은 값까지의 표현 범위큰 값 overflow, 작은 값 underflow 위험이 커진다.
mantissa서로 가까운 값을 얼마나 세밀하게 구분할지가까운 값이 같은 값으로 반올림될 수 있다.
아직 외울 공식은 아니다. 현재 필요한 구분은 exponent = 범위, mantissa = 세밀함이다. FP16과 BF16의 차이는 이 두 비트를 서로 다르게 배분한다는 데서 시작한다.

8개 형식의 역할 지도

형식한 줄 역할기억할 점
FP32기준이 되는 32-bit Float무겁지만 넓은 범위와 높은 정밀도를 제공한다.
BF16범위를 유지한 16-bit FloatFP32와 같은 8 exponent bit를 유지하고 mantissa를 줄인다. 현대 학습에서 자주 쓰인다.
FP16더 세밀하지만 범위가 좁은 16-bit Float작은 gradient가 0으로 사라질 수 있어 loss scaling을 사용하기도 한다.
TF32FP32 저장을 유지한 빠른 Tensor Core 행렬곱모델 메모리를 줄이는 형식이 아니라 계산 내부의 정밀도·속도 선택이다.
FP88-bit Float 저정밀 학습·추론E4M3은 forward의 weight·activation, E5M2는 넓은 범위가 필요한 gradient에 쓰는 hybrid 방식이 대표적이다.
INT8256개 정수 단계로 실수를 근사scale을 따로 두고 실수 범위를 정수로 대응한다.
INT416개 정수 단계로 더 강하게 압축메모리는 작지만 근사 오차와 outlier 문제가 더 커질 수 있다.
NF4LLM 가중치 분포에 맞춘 4-bit 형식16 단계를 균등하게 두지 않고 0 근처를 더 잘 표현하도록 설계되어 QLoRA에서 자주 등장한다.

INT4·INT8에서 outlier가 왜 문제인가?

INT4는 실수값을 16개 단계 중 하나에 대응한다. 그런데 대부분 값이 -1과 1 사이인데 값 하나만 100이면, 16개 단계를 넓은 범위에 배치해야 한다.

평범한 작은 값들이 같은 단계에 몰림 → 서로 다른 값이 같은 정수값으로 양자화됨

이런 큰 값 하나를 outlier라고 한다. 특히 activation에서 이런 현상이 문제가 될 수 있으며, LLM.int8과 SmoothQuant 같은 방법은 이 손실을 줄이는 방향을 다룬다. 이 문서에서는 이름만 연결해 두고, scale과 quantization 식을 먼저 작은 숫자로 실습한 뒤 돌아온다.
