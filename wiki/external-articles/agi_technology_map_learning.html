AGI를 시스템의 결합으로 보기

이 문서에서 사용하는 관점은 “AGI를 위한 단 하나의 정답 알고리즘”보다, 여러 능력을 하나의 반복 루프로 연결하는 쪽이다.

Foundation Model
      │
      ├─ Transformer / SSM / MoE
      ├─ Multimodal
      ├─ Reasoning
      ├─ Memory
      ├─ Planning
      ├─ Tool Use
      ├─ Agent
      ├─ World Model
      ├─ Robotics
      └─ Continual Learning
능력의 반복 루프
관찰 → 이해 → 기억 → 추론 → 계획 → 행동 → 결과 확인 → 학습 → 다음 행동
범위 주의 — 아래 상용화 분류는 이 대화에서 만든 학습용 잠정 지도다. “상용화”는 제품·구현 범위·시점에 따라 의미가 달라지므로, 각 항목을 완성된 AGI의 증거로 읽지 않는다.

핵심 기술을 기능별로 보기

1. Foundation Model과 Transformer

Transformer는 입력 Token 사이의 관계를 Self-Attention으로 계산하고, FFN과 여러 Layer를 통해 다음 표현이나 다음 Token을 만든다. 현재 주요 LLM의 핵심 Backbone으로 널리 사용된다.

입력 Token → Self-Attention → FFN → 여러 Layer → 출력

긴 Context에서는 Attention 계산량과 KV 메모리가 커지므로, 효율적인 Attention·KV Cache·다른 Sequence Architecture를 함께 연구한다.

2. SSM·Mamba

Transformer가 Token 간 관계를 넓게 비교하는 구조라면, SSM 계열은 이전 상태를 갱신하며 긴 Sequence를 처리하는 방향이다.

x₁ → state₁
      ↓
x₂ → state₂
      ↓
x₃ → state₃

현재는 Transformer를 완전히 대체한다기보다, Attention이 필요한 부분과 효율적인 상태 갱신을 조합하는 Hybrid 가능성까지 함께 본다.

3. MoE

여러 Expert를 두고 Router가 Token마다 일부 Expert를 선택한다. 전체 Parameter 수는 크게 유지하면서 한 Token의 활성 계산량을 줄일 수 있다.

입력 → Router → Expert 일부만 실행

4. Multimodal

Text만이 아니라 Image·Audio·Video·Code·Sensor 등을 하나의 Foundation Model 흐름으로 다루려는 방향이다. 현실을 이해하려면 여러 입력 양식을 연결해야 한다는 관점과 이어진다.

5. Reasoning과 Test-Time Compute

단순히 다음 Token을 한 번 예측하는 것에서 문제 분해·가설·검증·수정 같은 중간 과정을 활용하는 방향이다.

문제 → 문제 분해 → 추론 → 가설 → 검증 → 수정 → 답

같은 모델에 더 많은 추론 시간, Search, Verifier, Self-Correction을 허용해 결과를 개선하는 Test-Time Compute도 이 범주에 들어간다.

6. Tool Use와 Agent

Tool Use는 검색·Python·Database·API 같은 외부 도구를 호출해 모델 내부 지식만으로 해결하지 않는 방식이다. Agent는 여기서 더 나아가 목표를 여러 단계로 나누고, 행동 결과를 확인한 뒤 다음 행동을 정하는 Loop를 갖는다.

목표 → 계획 → 행동 → 결과 확인 → 다음 행동
                 ↖ 실패하면 계획 수정

7. Memory

현재 서비스는 외부 DB·RAG·Conversation Memory를 통해 과거 정보를 다시 검색해 넣는 방식을 주로 사용한다.

기억 구분학습 메모에서의 의미
Working Memory현재 Context에서 작업 중인 정보
Episodic Memory과거에 경험한 사건·작업 기록
Semantic Memory세상에 대한 일반 지식

8. World Model과 Planning

Language Model이 다음 Token을 예측한다면, World Model은 행동을 했을 때 다음 상태가 어떻게 될지 예측하려 한다.

두 예측의 차이
P(tokenₜ₊₁ | token₁:ₜ)는 다음 언어 단위를, P(stateₜ₊₁ | stateₜ, actionₜ)는 행동 이후의 상태를 모델링하려는 표현이다.

Planning은 목표를 달성하기 위한 행동 순서를 만드는 능력이다. 긴 작업에서는 초기 목표를 잊거나 잘못된 계획을 고집하거나 실패 복구를 못하는 문제가 남아 있다.

9. Robotics·VLA

현실 세계에서 행동하려면 Vision·Language·Action을 연결해야 한다. VLA는 “빨간 컵을 싱크대로 가져가” 같은 명령을 관찰·경로 계획·로봇 행동으로 연결하는 방향이다.

10. Continual Learning

현재 많은 모델은 학습을 끝낸 뒤 서비스되며, 서비스 중 얻은 경험으로 Model 자체가 자동 변화하지 않는다. 새로운 것을 배우면서 기존 능력을 잊지 않는 것, 즉 Catastrophic Forgetting을 피하는 것이 핵심 과제다.

학습용 상용화 수준 지도

아래 표는 기능의 존재와 범용성·자율성·안정성을 구분하기 위한 요약이다. “상용화”라고 해서 인간 수준의 일반성이 해결됐다는 뜻은 아니다.

현재 AI와 AGI 사이의 경계

현재 시스템은 대체로 다음 조합까지는 실제 서비스로 제공된다.

고정된 Foundation Model
      + Context
      + 외부 Memory
      + Agent
      + Tools

아직 핵심적으로 어려운 부분은 행동에서 얻은 경험이 장기적으로 쌓이고, 모델 또는 시스템이 스스로 더 나은 행동을 하도록 안정적으로 변하는 루프다.

현재의 빈칸
행동 → 경험 → 스스로 학습 → 모델·정책 변화 → 다음 행동 개선

여기에 World Model·장기 Memory·장기 Planning·Continual Learning이 안정적으로 결합되면 현재의 도구형 Agent와는 다른 시스템이 될 가능성이 있다. 이것은 가능성에 대한 학습 가설이지, AGI 도달 시점을 예측하는 문장이 아니다.

내 학습 로드맵과 연결하기

지금 공부한 Transformer·Attention·KV Cache는 AGI와 떨어진 옛 기초가 아니라, 현재 Foundation Model 시스템의 계산 기반이다. 이후에는 다음처럼 확장하면 된다.

다음 관심사현재 위키의 연결
Transformer 핵심Transformer 상위 문서와 Multi-Head Attention
효율적인 추론GLM GPU 최적화와 MTP, LLM 정밀도 형식
Memory와 Agent이 문서를 선수지식 지도 삼아 Tool Use·RAG·Agent Loop를 별도 실습으로 확장
World Model·Robotics현재는 개념 지도 단계이며 작은 상태 전이·계획 실험부터 추가
한 문장 결론 — 현재 AGI 연구는 Transformer 하나가 갑자기 AGI가 되는 흐름보다, 강력한 Foundation Model에 Reasoning·Memory·Planning·Tool Use·Agent·World Model·Continual Learning을 하나씩 연결해 범용 시스템으로 확장하는 흐름으로 이해하는 편이 자연스럽다.
