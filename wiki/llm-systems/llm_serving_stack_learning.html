1. BF16과 INT4는 같은 종류의 선택이 아니다

항목BF16INT4
표현부동소수점 16-bit16개 단계로 실수를 근사하는 4-bit 정수
목적학습·추론에서 범위와 메모리의 절충추론 메모리 절약
일반적인 사용학습·추론추론 중심

비트 형식의 수학은 LLM 정밀도 형식과 양자화에서, 7B weight 메모리는 7B 파라미터 문서에서 이어 본다.

2. 모델·엔진·서버의 계층

모델 weight / format
  ├─ Hugging Face safetensors (BF16 등)
  └─ GGUF
        ↓
추론 엔진
  ├─ llama.cpp
  └─ vLLM
        ↓
API 서버
  ├─ llama-server
  ├─ Ollama API
  └─ vLLM OpenAI-compatible API
        ↓
클라이언트
  └─ curl / OpenAI SDK / 애플리케이션

llama.cpp는 C/C++ 기반 추론 엔진이고, llama-server는 그 엔진을 HTTP 서버로 노출하는 실행 방식이다. Ollama는 모델 관리와 API 경험을 감싼 별도 런타임이다. 어떤 엔진과 서버를 선택할지는 모델 형식·GPU·지연시간·운영 방식에 따라 달라진다.

3. OpenAI-compatible API의 의미

OpenAI SDK를 사용한다는 말은 OpenAI의 모델을 사용한다는 뜻이 아니다. vLLM이 같은 요청·응답 모양을 제공하므로 클라이언트 코드를 재사용한다는 뜻이다.

client = OpenAI(base_url="http://server:8000/v1", api_key="local")
response = client.chat.completions.create(
    model="local-model",
    messages=[...], tools=available_tools,
    tool_choice="auto", temperature=0,
)

Qwen의 도구 호출 텍스트를 API 객체로 변환하려면 vLLM의 auto tool choice와 적절한 tool-call parser가 필요하다.

5. 적용 사례로 이동하기

특정 GPU 환경과 모델 alias를 포함한 실행 기록은 범용 개념 문서에 넣지 않는다. 실제 환경에서의 서빙·평가 순서는 프로젝트 평가 단계에서 확인한다.
