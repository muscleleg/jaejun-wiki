Tensor 원소·차원·bytes와 메모리

“FP32는 4 bytes”가 Token 하나, 차원 하나, 가중치 하나 중 무엇을 뜻하는지 Shape부터 구분한다.

토큰 벡터Attention Tensor계산과 bytes정밀도 아티클로 돌아가기

핵심 결론

FP32 Tensor 원소 숫자 1개 = 4 bytes

여기서 “원소 하나”는 Tensor 안의 숫자 하나다. Token 자체가 4 bytes라는 뜻은 아니다.

Token1의 x / Q / K / V 벡터
= [차원1, 차원2, 차원3]
= [FP32 숫자, FP32 숫자, FP32 숫자]
= [4 bytes, 4 bytes, 4 bytes]

Embedding을 거친 Token1의 벡터가 3차원이라면 숫자 원소가 3개이고, 각 원소를 FP32로 저장하면 총 12 bytes다.

Shape으로 보는 저장량

입력이나 Hidden State, Q·K·V는 보통 다음 Shape을 가진다.

[batch, token, dimension]
Shape 축의미메모리 계산에서 하는 일
batch문장을 몇 개 동시에 계산하는가문장 수만큼 Tensor 원소가 늘어난다.
token문장 안 Token 개수Token마다 벡터 하나가 생긴다.
dimension벡터 안 숫자 원소 개수각 숫자가 FP32라면 각각 4 bytes를 쓴다.

x.shape = [1, 2, 4096]이라면 FP32 숫자가 1 × 2 × 4096개다. 따라서 전체 x Tensor는 약 1 × 2 × 4096 × 4 bytes를 사용한다.

Token ID는 별개다.
입력 Token ID는 정수 하나다. Token ID를 Embedding으로 조회한 다음에야 여러 차원 숫자로 된 x 벡터가 생긴다. “차원 하나당 4 bytes”라는 설명은 이 벡터 원소를 FP32로 저장할 때의 이야기다.

가중치 7B와 Token 벡터는 다른 메모리다

7B 모델의 7B는 Token 수가 아니라, 모델 내부의 모든 학습된 가중치 행렬과 그 밖의 파라미터에 저장된 숫자를 합쳐 약 70억 개라는 뜻이다.

대상무엇이 몇 개 있는가?FP32일 때
가중치 7B모델 내부의 학습된 숫자 약 70억 개약 70억 × 4 bytes = 약 28GB
Token 하나의 4096차원 Q 벡터숫자 4096개약 4096 × 4 bytes = 약 16KB
Token 하나의 K와 V 벡터각각 숫자 4096개라고 단순화약 2 × 4096 × 4 bytes = 약 32KB
가중치 숫자란 무엇인가?
W_Q, W_K, W_V와 FFN의 W₁, W₂ 같은 행렬의 각 칸에 저장된 숫자다. 7B 모델의 파라미터와 가중치 숫자표에서 입력·중간 결과와 구분한다.

실제 Multi-Head Attention에서는 Head 수와 head_dim으로 나뉘지만, 한 Layer에서 모든 Head의 차원을 합치면 보통 이 단순화와 같은 방식으로 원소 수를 셀 수 있다. GQA/MQA 같은 구조에서는 K·V 원소 수가 더 줄어들 수 있다.

Attention 중간 결과도 각 칸이 숫자 하나다

FP32로 계산 결과를 저장한다고 가정하면, Attention에서 새로 나오는 Tensor의 각 칸도 FP32 숫자 하나이므로 4 bytes다.

계산결과 Shape한 칸의 의미FP32 저장량
Q @ Kᵀ[token, token]한 Query가 한 Key를 얼마나 맞는지 나타내는 Score 숫자 하나4 bytes
softmax(scores)[token, token]한 Query가 한 Key를 참고하는 비율 숫자 하나4 bytes
attention_weights @ V[token, value dimension]참고한 뒤 만들어진 Output 벡터의 차원값 하나4 bytes
 
scores            = [토큰 수, 토큰 수]
attention_weights = [토큰 수, 토큰 수]
output            = [토큰 수, value 차원]

예를 들어 Token이 2개이고 Value 차원이 1024라면 scores와 attention_weights는 각각 [2, 2], output은 [2, 1024]다. 이 Tensor들 안의 각 칸이 FP32라면 각각 4 bytes를 사용한다.

이름을 구분한다.
Q @ Kᵀ의 결과가 scores다. 마지막 attention_weights @ V의 결과는 Score가 아니라 새 output 벡터다.

BF16·FP16으로 저장하면 같은 Shape이라도 각 칸은 보통 2 bytes가 된다. 따라서 Tensor의 메모리는 원소 개수 × 원소당 bytes로 생각하면 된다.

4 bytes는 곱셈 단위가 아니다

Q Projection의 한 출력 차원은 다음처럼 숫자를 곱하고 더해 만든다.

q₁ = x₁w₁₁ + x₂w₂₁ + ··· + xdwd1

x1과 w11이 FP32라면 각각 메모리에서 4 bytes를 차지한다. GPU는 두 숫자를 읽어 산술 곱셈을 수행하고, 결과는 보통 다시 FP32 숫자 하나로 계산·저장한다.

따라서 4 bytes × 4 bytes = 16 bytes가 되는 것은 아니다. bytes는 숫자를 담는 저장 단위이고, 곱셈은 그 숫자값으로 하는 산술 연산이다.

다만 FP32도 표현 가능한 숫자 범위가 유한하다. 곱셈·합산 결과가 너무 크면 inf가 되고, 너무 작으면 0으로 사라질 수 있다. 정밀도 형식이 낮아질수록 이 overflow·underflow·반올림 오차를 더 신경 써야 한다.
