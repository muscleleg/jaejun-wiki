#15.5 HD Thumbnail Generation (08:31)

## 수정 목적

- 사람이 선택한 썸네일 후보를 그대로 끝내지 않고, 피드백을 반영한 최종 고해상도 썸네일로 다시 생성합니다.
- `interrupt` 이후 받은 `chosen_prompt`, `user_feedback`를 실제 후속 생성 단계에 연결합니다.
- 후보 탐색 단계와 최종 렌더링 단계를 분리해 비용과 품질을 다르게 운영하는 구조를 만듭니다.

## 핵심 개념

- `chosen_prompt`
  - 한 줄 정의: 사람이 고른 썸네일 후보의 원본 프롬프트입니다.
  - 필요한 상황: 여러 후보 중 하나를 최종본의 기반으로 삼아야 할 때 필요합니다.
  - 코드에서 맡는 역할: `generate_hd_thumbnail`의 입력 프롬프트 원본이 됩니다.
- `user_feedback`
  - 한 줄 정의: 사람이 추가로 반영해달라고 요청한 수정사항입니다.
  - 필요한 상황: 자동 생성 결과를 사람 취향과 목적에 맞게 다듬을 때 필요합니다.
  - 코드에서 맡는 역할: 원본 프롬프트를 보강하는 지시문으로 사용됩니다.
- `generate_hd_thumbnail`
  - 한 줄 정의: 선택된 후보와 피드백을 반영해 최종 고품질 썸네일을 다시 생성하는 노드입니다.
  - 필요한 상황: 저해상도 초안 탐색 후 최종본만 높은 품질로 뽑고 싶을 때 필요합니다.
  - 코드에서 맡는 역할: 개선 프롬프트 생성과 `gpt-image-1` 고품질 이미지 생성을 담당합니다.
- `quality="high"`
  - 한 줄 정의: 최종 렌더링 단계에서 더 높은 품질의 이미지를 생성하도록 지정하는 옵션입니다.
  - 필요한 상황: 초안 후보보다 선명하고 완성도 높은 최종 이미지를 만들고 싶을 때 필요합니다.
  - 코드에서 맡는 역할: 탐색 단계의 `low` 품질과 구분되는 최종 렌더링 품질 제어값입니다.

## 동작 흐름

- `generate_thumbnails x 5`로 후보를 먼저 생성합니다.
- `human_feedback`가 사용자에게 후보 선택과 수정 요청을 받습니다.
- `chosen_prompt`와 `user_feedback`가 상태에 저장됩니다.
- `generate_hd_thumbnail`이 두 값을 합쳐 개선 프롬프트를 만듭니다.
- 최종적으로 `thumbnail_final.jpg`를 생성하고 그래프가 종료됩니다.

## 사용 이유

- 처음부터 모든 썸네일을 고품질로 만들면 비용이 커지고 탐색 속도가 느려집니다.
- 먼저 여러 초안을 저비용으로 만든 뒤, 사람이 고른 한 장만 고품질로 다시 생성하는 구조가 더 실무적입니다.
- 사용자 피드백을 프롬프트 재작성 단계에 넣으면 자동 생성 결과를 사람이 원하는 방향으로 더 정확히 보정할 수 있습니다.

def generate_hd_thumbnail(state: State):

chosen_prompt = state["chosen_prompt"]

user_feedback = state["user_feedback"]

prompt = f"""

You are a professional YouTube thumbnail designer. Take this original thumbnail prompt and create an enhanced version that incorporates the user's specific feedback.

ORIGINAL PROMPT:

{chosen_prompt}

USER FEEDBACK TO INCORPORATE:

{user_feedback}

Create an enhanced prompt that:

  1. Maintains the core concept from the original prompt
  2. Specifically addresses and implements the user's feedback requests
  3. Adds professional YouTube thumbnail specifications:
  • High contrast and bold visual elements
  • Clear focal points that draw the eye
  • Professional lighting and composi

tion

  • Optimal text placement and readability with generous padding from edges
  • Colors that pop and grab attention
  • Elements that work well at small thumbnail sizes
  • IMPORTANT: Always ensure adequate white space/padding between any text and the image borders

"""

response = llm.invoke(prompt)

final_thumbnail_prompt = response.content

client = OpenAI()

result = client.images.generate(

model="gpt-image-1",

prompt = final_thumbnail_prompt,

quality = "high",

moderation="low",

size="auto",

)

image_bytes = base64.b64decode(result.data[0].b64_json)

filename = f"thumbnail_final.jpg"

with open(filename,"wb") as file:

file.write(image_bytes)

- 무엇인가

- 어떻게 동작하는가

- 실제 사용 방식

- 왜 필요한가

from langgraph.graph import END, START, StateGraph
from typing import TypedDict
import subprocess
from openai import OpenAI

class State(TypedDict):
    video_file: str
    audio_file: str
    transcription: str

def extract_audio(state: State):
    output_file = state["video_file"].replace("mp4", "mp3")
    commmand = [
        "ffmpeg", "-i", state["video_file"], "-filter:a", "atempo=2.0", output_file
    ]
    subprocess.run(commmand)
    return {"audio_file": output_file}

def transcribe_audio(state: State):
    client = OpenAI()
    with open(state["audio_file"], "rb") as audio_file:
        transcription = client.audio.transcriptions.create(
            model="whisper-1", response_format="text", file=audio_file, language="ko"
        )
        return {"transcription": transcription}

15.3 썸네일 생성 파이프라인 확장

이 단계는 청크별 요약을 하나의 최종 요약으로 합친 뒤, 같은 요약을 여러 이미지 생성 작업에 나누어 보내 썸네일 후보를 병렬 생성한다.

왜 add_edge가 아니라 Send인가

add_edge는 미리 정한 다음 노드를 한 번 실행한다. 반면 청크나 이미지 후보의 수는 실행 중에 결정되므로, 런타임에 작업 수만큼 노드 호출을 만드는 동적 fan-out이 필요하다.

add_edge:  transcribe → summarize_chunk 1회
Send:      transcribe → dispatch → summarize_chunk × N회

Send("summarize_chunk", payload)는 공유 State 전체가 아니라 해당 작업에 필요한 payload를 노드에 전달한다. 단순한 for 루프도 같은 결과를 만들 수 있지만 외부 호출을 순차 처리한다는 차이가 있다.

방식실행노드 입력용도
add_edge고정 1회공유 State고정된 다음 단계
add_conditional_edges + Send런타임 N회작업별 payload동적 병렬 fan-out

add_conditional_edges의 역할

graph_builder.add_conditional_edges(
    "transcribe_audio",
    dispatch_summarizers,
    ["summarize_chunk"],
)
  • 첫 번째 인자: 분기를 시작할 source 노드
  • 두 번째 인자: State를 읽고 Send 목록을 만드는 라우팅 함수
  • 세 번째 인자: 라우팅 함수가 선택할 수 있는 목적지 노드

확장된 흐름

video.mp4
  ↓
extract_audio
  ↓
transcribe_audio
  ↓
dispatch_summarizers
  ↓
summarize_chunk × N
  ↓
mega_summary
  ↓
dispatch_artists
  ↓
generate_thumbnails × 5
  ↓
thumbnail_prompts + thumbnail_1~5.jpg

상태와 핵심 노드

import base64
import operator
from typing_extensions import Annotated, TypedDict
from langgraph.types import Send
from openai import OpenAI

class State(TypedDict):
    video_file: str
    audio_file: str
    transcription: str
    summaries: Annotated[list[str], operator.add]
    final_summary: str
    thumbnail_prompts: Annotated[list[str], operator.add]
    thumbnail_sketches: Annotated[list[str], operator.add]

def mega_summary(state: State):
    all_summaries = "\n".join(state["summaries"])
    response = llm.invoke(
        "Create a comprehensive final summary from these chunk summaries:\n"
        + all_summaries
    )
    return {"final_summary": response.content}

def dispatch_artists(state: State):
    return [
        Send(
            "generate_thumbnails",
            {"id": concept_id, "summary": state["final_summary"]},
        )
        for concept_id in range(1, 6)
    ]

def generate_thumbnails(args):
    concept_id = args["id"]
    summary = args["summary"]
    prompt_response = llm.invoke(
        "Create a detailed YouTube thumbnail prompt. "
        "Include the main visual elements, color scheme, text overlay, "
        f"and composition.\n\nSummary: {summary}"
    )
    thumbnail_prompt = prompt_response.content

    result = OpenAI().images.generate(
        model="gpt-image-1",
        prompt=thumbnail_prompt,
        quality="low",
        size="auto",
    )
    filename = f"thumbnail_{concept_id}.jpg"
    with open(filename, "wb") as image_file:
        image_file.write(base64.b64decode(result.data[0].b64_json))

    return {
        "thumbnail_prompts": [thumbnail_prompt],
        "thumbnail_sketches": [filename],
    }

그래프 연결

graph_builder.add_node("mega_summary", mega_summary)
graph_builder.add_node("generate_thumbnails", generate_thumbnails)

graph_builder.add_edge("summarize_chunk", "mega_summary")
graph_builder.add_conditional_edges(
    "mega_summary",
    dispatch_artists,
    ["generate_thumbnails"],
)
graph_builder.add_edge("generate_thumbnails", END)

  • State의 키와 각 노드의 반환 키는 thumbnail_prompts, thumbnail_sketches처럼 정확히 일치해야 한다.
  • 병렬 분기 결과를 모으는 목록 필드에는 reducer가 필요하다.
  • 이미지 파일은 재생성 가능한 산출물이므로 Git 제외 목록에 두되, 환경 변수 파일과 비밀값도 함께 공개 저장소에서 제외한다.
  • 원문에 반복되던 동일한 ⑤·⑥ 설명과 코드 블록 경계에서 잘린 단어는 하나의 실행 가능한 예제로 합쳤다.

2️⃣ MCP(Model Context Protocol) 개념

MCP는 AI Agent가 외부 Tool 서버와 표준 방식으로 통신하는 프로토콜이다.

Agent는 다음과 같은 흐름으로 MCP Tool을 사용한다.

User 질문
    ↓
Agent 판단
    ↓
MCP 서버 Tool 목록 조회
    ↓
mcp_list_tools
    ↓
Agent Tool 선택
    ↓
mcp_call
    ↓
Context7 서버 실행
    ↓
결과 반환
    ↓
Agent 응답 생성

즉 Agent가 직접 Tool을 구현하는 것이 아니라

외부 MCP 서버가 제공하는 Tool을 사용할 수 있다.

import time
from crewai.tools import tool
from playwright.sync_api import sync_playwright
from bs4 import BeautifulSoup


@tool
def scrape_tool(url: str):
    """
    Use this when you need to read the content of a website.
    Returns the content of a website.
    If the website is not available, it returns 'No content'.
    Input should be a `url` string.
    """

    print(f"Scraping URL: {url}")

    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        page.goto(url)

        # 동적 로딩 대기
        time.sleep(5)

        html = page.content()
        browser.close()

        soup = BeautifulSoup(html, "html.parser")

        # 제거할 태그 목록
        unwanted_tags = [
            "header",
            "footer",
            "nav",
            "aside",
            "script",
            "style",
            "noscript",
            "iframe",
            "form",
            "button",
            "input",
            "select",
            "textarea",
            "img",
            "svg",
            "canvas",
            "audio",
            "video",
            "embed",
            "object",
        ]

        # 불필요한 태그 제거
        for tag in soup.find_all():
            if tag.name in unwanted_tags:
                tag.decompose()

        # 텍스트만 추출
        content = soup.get_text(separator=" ")

        return content if content.strip() != "" else "No content"

scrape_tool 동작 단계 정리

  1. Playwright로 실제 브라우저 실행
  2. URL 접속
  3. 5초 대기 (동적 JS 로딩 대비)
  4. HTML 전체 가져오기
  5. BeautifulSoup 파싱
  6. 불필요한 태그 제거
  7. 순수 텍스트 추출
  8. 비어 있으면 "No content" 반환

2. Streamlit의 동작 원리

2.1 Streamlit은 인터랙션이 발생하면 전체 스크립트를 재실행한다

Streamlit은 버튼 클릭, 입력 변경 등의 사용자 인터랙션이 발생하면

스크립트를 위에서 아래까지 처음부터 다시 실행한다.

즉, 다음과 같은 일이 발생한다:

  • st.text_input() 값이 변경됨
  • Streamlit이 스크립트 전체를 다시 실행
  • 모든 일반 변수는 다시 초기화됨

2.2 일반 변수는 상태를 유지하지 못한다

예를 들어 아래와 같이 작성하면:

is_admin = False

사용자가 이름을 입력하여 True로 바꿔도

스크립트가 재실행되면서 다시 False로 초기화된다.

즉,

  • 일반 변수는 요청 단위로만 존재
  • 재실행 시 값이 유지되지 않음

3. 상태를 유지하는 방법:

st.session_state

3.1 session_state란?

st.session_state는

사용자 세션 단위로 값을 저장할 수 있는 저장소다.

  • 브라우저 사용자마다 독립적인 상태 유지
  • 스크립트가 재실행되어도 값이 유지됨

3.2 초기값 설정 방식

if "is_admin" not in st.session_state:
    st.session_state["is_admin"] = False

이 코드는 다음을 의미한다:

  • 처음 실행될 때만 is_admin을 False로 초기화
  • 이후에는 기존 값을 유지

3.3 상태 변경

if name:
    st.session_state["is_admin"] = True

사용자가 이름을 입력하면:

  • is_admin이 True로 변경
  • 이후 재실행되어도 True 유지

초기 실행

  1. is_admin이 없으므로 False로 초기화

3) placeholder의 역할

3-1) placeholder란?

text_placeholder = st.empty()
image_placeholder = st.empty()

st.empty()는 “아직 비어있는 UI 슬롯(자리)”을 하나 만들어 두는 것이다.

이 슬롯은 나중에 같은 위치에서 내용을 계속 바꿔치기(update)할 수 있다.

3-2) 왜 placeholder가 필요하냐?

스트리밍에서는 모델이 텍스트를 여러 조각(delta)으로 보내온다.

만약 매번 st.write()로 찍으면 줄이 계속 늘어나서

  • 안
  • 안녕
  • 안녕하세요

처럼 화면에 쌓인다.

하지만 placeholder를 쓰면 같은 슬롯에 계속 덮어쓰므로

“한 줄이 점점 길어지는 것처럼” 보이게 만들 수 있다.

3-3) 이미지도 같은 이유로 placeholder를 분리했다

이미지 생성도 partial 이미지가 여러 번 올 수 있다.

image_placeholder.image(image)

이 방식이면 같은 위치에 이미지가 계속 교체되면서

“점점 그려지는 것처럼” 보인다.

4) response.completed에서 empty() 하면 화면이 다 사라지지 않나?

겉으로 보면 지워지는 것처럼 보이지만, 구조적으로는 다음 흐름이다.

4-1) 스트리밍 중

  • placeholder가 “임시 실시간 렌더링”을 담당한다.

4-2) 스트리밍 완료(response.completed)

image_placeholder.empty()
text_placeholder.empty()
  • 임시 렌더링 공간을 정리한다.
  • 이 단계는 “최종 메시지를 지우는 것”이 아니라 “임시 UI를 지우는 것”이다.

4-3) 왜 최종 결과가 유지되나?

Runner.run_streamed(..., session=session) 때문에,

스트리밍이 끝나면 최종 결과가 SQLiteSession에 저장된다.

그리고 Streamlit은 입력/상태 변화가 있으면 스크립트를 다시 실행(rerun)한다.

rerun 시점에:

asyncio.run(paint_history())

가 실행되면서

세션에 저장된 “최종 메시지”가 다시 그려진다.

즉,

  • placeholder: 스트리밍 동안만 보이는 임시 출력
  • session + paint_history: 최종 결과 재생(영구 출력)

4-4) empty()를 안 하면 생길 수 있는 문제

  • 스트리밍 중 placeholder에 보인 내용
  • rerun 후 paint_history가 다시 그린 내용

이 둘이 겹치면서 “중복 출력”이 생길 수 있다.

그래서 empty()는 “중복 방지용 정리” 역할이다.

5) 최종 정리

placeholder는

  • 스트리밍을 자연스럽게 보이게 만드는 “교체용 UI 슬롯”
  • 텍스트/이미지를 같은 자리에서 계속 업데이트하는 용도
  • 완료 후에는 세션에 저장된 최종 결과가 다시 그려지므로

placeholder는 비워도 결과가 사라지지 않는다

  • empty()는 “최종 삭제”가 아니라 “임시 렌더링 정리(중복 방지)”다

3️⃣st.text() vs st.write()

st.text("Hello")
  • Plain text 그대로 출력
  • Markdown 해석하지 않음

반면 st.write()는:

  • Markdown 해석
  • DataFrame, dict 등 자동 렌더링

4️⃣ st.status()의 상태 머신 구조

이 코드의 핵심은 여기다:

with st.status("Agent is using tool") as status:

✔ 기본 상태는

"running"

  • 아이콘: 🔄 spinner
  • 기본 state = "running"

✔ update() 동작 방식

label만 변경

status.update(label="Agent is searching the web...")
  • 텍스트만 변경
  • state는 그대로 "running"
  • spinner 유지

state를 명시적으로 running으로 지정

status.update(state="running", label="Agent is reading the page...")
  • 여전히 spinner 유지

complete로 변경

status.update(state="complete", label="Agent is done!")
  • 아이콘이 ✅ 체크로 변경

5️⃣ 자동 complete 동작

중요한 점:

with st.status(...) 블록이 종료되면

Streamlit은 자동으로 state를 "complete"로 변경한다.

즉:

with 블록 종료 → 자동 complete

그래서 명시적으로 지정하지 않아도

마지막에는 체크 표시가 될 수 있다.

6️⃣ state 값 종류

허용되는 state 값은 다음뿐이다:

  • "running" → 🔄
  • "complete" → ✅
  • "error" → ❌

임의 문자열은 사용할 수 없다.

import asyncio
import time  # ⭐ NEW: 상태 표시/확장 대비
import streamlit as st
import dotenv

dotenv.load_dotenv()

from agents import Agent , Runner, SQLiteSession, WebSearchTool  # ⭐ NEW: WebSearchTool 추가


# ⭐ MODIFIED: Agent에 WebSearchTool 연결
if "agent" not in st.session_state:
    st.session_state["agent"] = Agent(
        name="ChatGPT Clone",
        instructions="""
        You are a helpful assistant.

        You have access to the following tools:
            - Web Search Tool: Use this when the user asks a questions that isn't in your training data. Use this to learn about current events.

        """,
        tools=[  # ⭐ NEW
            WebSearchTool(),
        ]
    )
agent = st.session_state["agent"]


if "session" not in st.session_state:
    st.session_state["session"] = SQLiteSession("chat-history", "chat-gpt-clone-memory.db")
session = st.session_state["session"]


# ⭐ MODIFIED: tool 이벤트까지 히스토리에 안전하게 대응
async def paint_history():
    messages = await session.get_items()

    for message in messages:
        # ⭐ NEW: role이 없는 메시지(web_search_call 등) 대비
        if "role" in message:
            with st.chat_message(message["role"]):
                if message["role"] == "user":
                    st.write(message["content"])
                else:
                    # AI 응답에는 tool call 등 다양한 타입이 섞일 수 있으므로 message만 렌더링
                    if message["type"] == "message":
                        st.write(message["content"][0]["text"])

        # ⭐ NEW: tool 호출 자체도 히스토리에 표시
        if "type" in message and message["type"] == "web_search_call":
            with st.chat_message("ai"):
                st.write("Searched the web for information...")


# ⭐ NEW: 상태 업데이트 로직 중앙화 (중복 제거 목적)
def update_status(status_container, event):
    status_messages = {
        "response.web_search_call.completed": ("✅ Web Search Completed", "complete"),
        "response.web_search_call.in_progress": ("🔍 Starting Web Search", "running"),
        "response.web_search_call.searching": ("🔍 Web Search in Progress", "running"),
        "response.completed": ("✅", "complete")
    }

    if event in status_messages:
        label, state = status_messages[event]
        status_container.update(label=label, state=state)


asyncio.run(paint_history())


async def run_agent(message):
    # 하나의 AI 말풍선 안에서 스트리밍
    with st.chat_message("ai"):
        status_container = st.status("🔍", expanded=False)  # ⭐ NEW: 상태 UI 컨테이너
        text_placeholder = st.empty()
        response = ""

        # session을 전달하면 Runner가 자동으로 user/assistant 기록을 SQLite에 저장
        stream = Runner.run_streamed(
            agent,
            message,
            session=session,
        )

        async for event in stream.stream_events():
            if event.type == "raw_response_event":
                update_status(status_container, event.data.type)  # ⭐ NEW: 상태 업데이트 호출(중복 제거)

                if event.data.type == "response.output_text.delta":
                    response += event.data.delta
                    text_placeholder.markdown(response)


prompt = st.chat_input("Write a message for your assistant")

if prompt:
    with st.chat_message("human"):
        st.write(prompt)
    asyncio.run(run_agent(prompt))


with st.sidebar:
    reset = st.button("Reset memory")
    if reset:
        asyncio.run(session.clear_session())
    st.write(asyncio.run(session.get_items()))

🧠 왜 필요한가?

  "type": "web_search_call",

}

이 메시지에는 role이 없다.

def update_status(status_container, event):
    status_messages = {
        "response.web_search_call.completed": ("✅ Web Search Completed", "complete"),
        "response.web_search_call.in_progress": ("🔍 Starting Web Search", "running"),

어디까지 파볼까?

편입 후 검증 메모

  • 업로드 안전성: 파일명·MIME·크기·내용을 검증하고 임시 파일 수명과 삭제를 관리한다. 업로드 파일을 그대로 tool 명령이나 검색 색인에 신뢰하지 않는다.
  • Streaming: delta는 화면을 점진 갱신하는 조각이고 최종 output item은 완성된 의미 단위다. 같은 내용을 두 경로에서 중복 렌더링하지 않는다.
  • MCP·외부 Tool: 연결 성공과 도구 신뢰는 다르다. 서버 권한·명령 범위·데이터 유출·prompt injection 경계를 검토한다.
  • 멀티 Agent: 역할을 많이 나눈다고 자동으로 좋아지지 않는다. routing 비용·context 손실·오류 전파를 단일 Agent baseline과 비교한다.
