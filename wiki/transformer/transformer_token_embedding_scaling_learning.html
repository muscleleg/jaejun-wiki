어차피 키울 거라면 처음부터 크게 초기화하면 안 될까?

초기 순전파의 값만 비교하면 가능합니다. 다음 두 방식은 출력의 초기 표준편차가 모두 약 1입니다.

작게 저장하고 입력에서 확대

W ~ N(0, 1/d_model)
Embedding = W[token] × √d_model

≈
처음부터 크게 저장

W ~ N(0, 1)
Embedding = W[token]

하지만 원형 Transformer는 임베딩 행렬을 마지막 단어 예측층과 공유합니다. 하나의 작은 가중치 W를 두 경로가 서로 다르게 사용하는 구조입니다.

입력 경로 token_id → W에서 조회 → × √d_model → 토큰 표현
출력 경로 hidden_state → hidden_state @ Wᵀ → vocabulary logits

입력에서는 작은 임베딩이 Positional Encoding에 묻히지 않도록 확대합니다. 출력에서는 작은 공유 가중치를 그대로 사용하여 초기 logits가 지나치게 커지고 softmax가 포화되는 것을 피할 수 있습니다.

weight_tying.py뒤에서 구현할 연결
# 입력: 공유 가중치를 조회한 뒤 확대
x = token_embedding(token_ids)  # 내부에서 × √d_model

# 출력: 같은 가중치를 확대하지 않고 사용
output_projection.weight = token_embedding.embedding.weight
logits = output_projection(hidden_states)

학습 과정도 완전히 같지는 않습니다. 스케일링이 있으면 임베딩 가중치에 전달되는 gradient에도 √d_model이 곱해집니다. 따라서 초기 출력 분포가 같더라도 optimizer, 학습률, weight decay가 만드는 학습 경로는 달라집니다.

정확성 메모 — 원 논문은 가중치 공유와 √d_model 스케일링을 모두 명시하지만, “가중치를 공유하기 때문에 스케일링한다”는 인과관계를 직접 설명하지는 않습니다. 스케일링의 직접적인 역할은 입력 임베딩의 크기를 보정하는 것이며, 가중치 공유는 왜 작은 가중치를 저장한 채 입력 경로에서만 확대하는지가 설계상 자연스러운 이유를 보여줍니다.
