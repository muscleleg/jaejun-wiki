Query와 모든 Key의 관련도

Score 분포의 규모 안정화

기본 ShapeQ: [batch, query_token, d_k] · K: [batch, key_token, d_k] · V: [batch, key_token, d_v]Score: [batch, query_token, key_token] · Output: [batch, query_token, d_v]

Q·K 내적과 Scaling

Score 한 칸은 하나의 Query와 하나의 Key 벡터를 내적한 값이다.

한 칸의 ScoreSᵢⱼ = qᵢ₁kⱼ₁ + qᵢ₂kⱼ₂ + ··· + qᵢdₖkⱼdₖ

초기 상태에서 각 곱의 평균이 0에 가깝고 분산이 약 1이며 서로 독립이라고 단순화하면, d_k개를 더한 Score의 분산은 약 d_k, 표준편차는 약 √d_k 규모가 된다.

Scalingscaled_scores = scores / math.sqrt(d_k)임베딩에서 했던 스케일을 취소하는 것이 아니라, Q·K 곱을 여러 개 합쳐 커진 Score 분포를 안정화하는 연산이다.

Multi-Head에서는 전체 d_model이 아니라 Head 하나의 마지막 차원인 head_dim을 사용한다.

Mask와 Softmax

Mask는 Q나 K를 지우는 것이 아니라, 이미 계산된 Score 행렬에서 볼 수 없는 칸을 숨긴다.

scores = scores.masked_fill(
    mask == 0,
    float("-inf"),
)
attention_weights = torch.softmax(scores, dim=-1)
Padding Mask길이를 맞추려고 넣은 PAD Token을 참고하지 않게 한다.
Causal Mask현재 Query가 미래의 Key Token을 보지 못하게 한다.

dim=-1은 마지막 축인 Key 방향이다. 각 Query가 모든 Key에 배정한 비율을 따로 계산하므로 행별 합이 1이 된다.

[0.3, 0.7] → 1
[0.4, 0.6] → 1

e-∞는 0에 가까우므로 Mask된 칸의 Softmax 비율은 0이 된다.

Attention Weight와 Value

Attention Weight는 Query가 각 Key를 얼마나 참고할지 나타내는 비율이다. 이 비율을 Value 벡터에 곱해 더한다.

첫 번째 Query의 출력Output₁ = a₁₁ × Value₁ + a₁₂ × Value₂ + ···

따라서 Output은 “관련도 숫자” 자체가 아니라, 관련도를 가중치로 사용해 Value 벡터를 섞은 새로운 벡터다.

여기까지의 핵심 — Score는 Query-Key 관련도, Softmax 결과는 Key별 참고 비율, Value 가중합 결과는 그 비율을 반영한 새로운 Token 표현이다.
