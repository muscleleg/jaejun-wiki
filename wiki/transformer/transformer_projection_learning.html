Q·K·V Projection과
Linear 가중치

같은 입력을 서로 다른 가중치 표에 통과시켜 Query·Key·Value 관점의 중간 표현을 만드는 과정을 정리한다.

같은 입력, 서로 다른 Projection

입력 x 하나를 세 개의 서로 다른 학습 가능한 가중치 표에 통과시킨다.

Q = x @ W_Q
K = x @ W_K
V = x @ W_V
Query현재 Token이 어떤 정보를 찾는지 나타내는 표현
Key각 Token이 어떤 정보인지 비교에 사용할 표현
Value관련도가 높을 때 실제로 가져올 표현

같은 x를 넣어도 W_Q, W_K, W_V가 다르므로 Q·K·V의 숫자는 서로 다르게 나온다.

nn.Linear가 만드는 새로운 특징

PyTorch의 Linear는 입력 특징들을 서로 다른 비율로 조합해 새로운 출력 특징을 만든다.

x = [x₁, x₂]

y₁ = x₁ × w₁₁ + x₂ × w₁₂
y₂ = x₁ × w₂₁ + x₂ × w₂₂
PyTorch Shapenn.Linear(in_features, out_features)weight.shape = [out_features, in_features]

가중치 행에 사람이 미리 “문법”, “위치” 같은 의미를 지정하는 것은 아니다. 학습을 통해 유용한 조합이 생기고, 나중에 그 표현을 사람이 해석할 수 있게 된다.

Projection 결과는 최종 예측값이 아니다

Q·K·V는 단어를 바로 예측하는 결과가 아니라 Attention 계산에 사용할 중간 표현이다.

x
→ Q, K, V Projection
→ Attention
→ multi_head_output
→ W_O Output Projection
→ 다음 Transformer 층
→ hidden state
→ vocabulary logits

따라서 Q·K·V의 숫자가 정답 Token과 직접 같아질 필요는 없다. 이 값들은 최종 예측을 잘 만들기 위한 내부 표현이다.

Q·K·V 가중치는 어떻게 학습되는가?

Q·K·V의 가중치를 각각 정답에 직접 맞추는 것이 아니다. 최종 예측 Loss가 전체 계산 그래프를 거꾸로 통과하면서 모든 가중치에 Gradient를 전달한다.

최종 logits
→ Loss
→ loss.backward()
→ W_Q, W_K, W_V의 Gradient 계산
→ Optimizer가 가중치 업데이트

따라서 Q·K·V Projection은 Transformer의 Attention 구조 안에서 최종 Loss를 줄이는 방향으로 함께 조정된다.

초기 상태 주의 — 실습에서 Linear 가중치가 랜덤으로 초기화되어 있으면 Q·K·V 출력도 임의의 숫자다. 아직 학습되지 않았으므로 그 숫자에 완성된 의미가 있다고 해석하면 안 된다.

Q·K·V Projection과 Score 계산

이전 실습에서는 query, key, value를 직접 만들었다. 이번에는 하나의 입력 x를 서로 다른 nn.Linear에 통과시켜 Query, Key, Value 역할의 벡터를 만들었다.

Q Projection입력과 출력 Shape 확인
import torch
from torch import nn

x = torch.tensor([[
    [1.0, 0.0],
    [0.0, 1.0],
]])

query_projection = nn.Linear(
    in_features=2,
    out_features=2,
    bias=False,
)

query = query_projection(x)

print("query", query)
print("query shape", query.shape)
입력 x[1, 2, 2]
차원의 의미[문장 수, 토큰 수, 토큰 벡터 차원]
Q Projectionnn.Linear(2, 2)
출력 query[1, 2, 2]

nn.Linear(2, 2)는 마지막 차원의 2차원 벡터를 새로운 2차원 벡터로 변환한다. 따라서 입력과 출력의 Shape은 같지만, 가중치 행렬이 곱해졌으므로 원소 값과 역할은 달라진다.

nn.Linear의 계산을 직접 행렬곱과 비교

동일성 확인bias=False인 경우
manual_query = torch.matmul(
    x,
    query_projection.weight.T,
)

print(torch.allclose(query, manual_query))
# True

bias=False일 때 이번 실습의 계산은 다음과 같다.

query_projection(x) = x @ query_projection.weight.T

torch.allclose()는 부동소수점의 미세한 계산 오차를 허용하면서 두 Tensor의 값이 거의 같은지 검사한다. PyTorch 연산을 직접 구현한 결과와 비교할 때 사용할 수 있다.

같은 입력에서 Q·K·V가 서로 달라지는 이유

Q·K·V Projection각자 별도의 가중치 사용
query_projection = nn.Linear(2, 2, bias=False)
key_projection = nn.Linear(2, 2, bias=False)
value_projection = nn.Linear(2, 2, bias=False)

query = query_projection(x)
key = key_projection(x)
value = value_projection(x)
Q = XW_Qᵀ · K = XW_Kᵀ · V = XW_Vᵀ 입력과 출력 Shape은 모두 [1,2,2]지만 서로 다른 가중치 행렬을 사용하므로 값과 역할이 달라집니다.

초기에는 세 가중치가 각각 무작위로 초기화되고, 학습 중에는 Loss를 줄이는 방향으로 서로 다르게 조정됩니다. 따라서 같은 입력을 사용한다는 사실이 같은 출력값을 의미하지 않습니다.

Projection 결과로 Score를 직접 계산

QKᵀ와 Scaling현재 d_k=2
scores = torch.matmul(

    key.transpose(-2, -1),
)

d_k = query.size(-1)
scaled_scores = scores / math.sqrt(d_k)
query[1, 2, 2]
key.transpose(-2, -1)[1, 2, 2]

현재는 토큰 수와 차원 수가 모두 2라서 전치 전후 Shape이 우연히 같습니다. 그러나 전치의 의미는 [token, dimension] → [dimension, token]으로 바뀌어 각 Query와 모든 Key가 비교될 수 있게 하는 것입니다.

실행 결과무작위 가중치에 따라 값은 달라질 수 있음

오늘 확인한 결론 — 원본 x는 서로 다른 학습 가능한 가중치와 곱해져 Q·K·V 관점의 벡터가 됩니다. QKᵀ의 한 칸은 d_k개 곱의 합이고, 현재는 d_k=2이므로 Score를 √2로 나눕니다. 이 나눗셈은 실제 Score를 1로 만드는 것이 아니라 Score 분포의 표준편차를 약 1 규모로 맞추기 위한 것입니다.
