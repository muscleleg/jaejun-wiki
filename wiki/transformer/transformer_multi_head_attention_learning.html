Multi-Head Attention
분리하고 다시 합치기

Token을 늘리는 것이 아니라 특징 차원을 Head별로 나누고, 각 Head에서 Attention을 계산한 뒤 다시 공통 표현으로 합치는 흐름을 정리한다.

← Attention 학습 경로Shape 계산 상세 →QKV Projection →

무엇을 나누는가?

Multi-Head Attention은 Token 자체를 여러 Token으로 쪼개지 않는다. 각 Token의 특징 벡터 차원을 여러 Head 조각으로 나눈다.

기본 관계d_model = num_heads × head_dim
Token 1 = [0, 1, 2, 3]

num_heads = 2
head_dim = 2

Head 1 조각 = [0, 1]
Head 2 조각 = [2, 3]

Token 수는 그대로이고, 계산할 Token × Head 조각의 수만 늘어난다.

view()·transpose()·reshape()

원래[batch, token, d_model]
Head 분리[batch, token, head, head_dim]
계산용 축[batch, head, token, head_dim]
병합 후[batch, token, d_model]

view()와 reshape()는 숫자에 새로운 값을 계산하는 연산이 아니라 Shape을 다시 해석하는 연산이다. transpose(1, 2)는 Token 축과 Head 축의 위치를 바꿔 같은 Head의 모든 Token을 모아준다.

Head 1 결과 = [a, b]
Head 2 결과 = [c, d]

다시 병합 → [a, b, c, d]
순서 유지 — Token 축은 계속 유지되고, Head 결과를 다시 축으로 되돌린 뒤 reshape()하면 원래 특징 차원 순서대로 이어진다. Head 분리는 Token 순서를 없애는 연산이 아니다.

Head별 Attention과 multi_head_output

각 Head는 담당 특징 조각으로 독립적인 Attention을 계산한다.

Q @ Kᵀ
→ √head_dim Scaling
→ Softmax
→ Attention Weight @ V
Head별 결과Head 1 → [a, b] · Head 2 → [c, d]multi_head_output → [a, b, c, d]

multi_head_output은 여러 Head의 결과를 단순히 이어 붙인 중간 표현이다. 아직 최종 단어 예측값이 아니고, 다음 Transformer 층으로 넘어가기 전의 Attention 출력이다.

왜 Output Projection (W_O)를 또 적용하는가?

단순 병합은 Head 결과를 나열할 뿐이다. (W_O)는 나열된 특징들을 학습된 가중치로 다시 조합한다.

multi_head_output → W_O → projected_output
reshape값을 바꾸지 않고 Head 결과를 이어 붙인다.
W_O Linear여러 Head의 정보를 섞어 공통 모델 표현으로 바꾼다.

보통 Shape은 유지된다.

[batch, token, d_model] → W_O → [batch, token, d_model]

Shape이 같아도 표현의 의미는 다를 수 있다. 병합 직후에는 Head별 결과가 나란히 있고, (W_O) 이후에는 여러 Head의 정보가 조합된 표현이 된다.

직접 검증: nn.Linear와 수동 행렬곱

bias=False인 Output Projection은 각 Token 벡터에 W_O를 곱하는 연산이다. 따라서 같은 Token을 수동으로 계산한 값과 nn.Linear의 결과를 비교할 수 있다.

projected_output = output_projection(multi_head_output)

manual_output = (
    multi_head_output[0, 0]
    @ output_projection.weight.T
)

torch.allclose(
    manual_output,
    projected_output[0, 0],
)
# True
이번에 확인한 것 — multi_head_output[0, 0]은 [batch, token, :]에서 0번째 Batch의 0번째 Token 벡터다. 이 벡터를 W_O.T와 직접 곱한 결과가 projected_output[0, 0]과 같으므로, Output Projection이 단순 병합 뒤에 실제로 적용된다는 것을 확인했다.

nn.Module 안에 Projection 등록하기

수동으로 따로 만들었던 Q·K·V Projection과 Output Projection을 하나의 모듈 안에 등록하면, Transformer의 한 Attention 객체로 묶어 관리할 수 있다.

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()

        assert d_model % num_heads == 0

        self.d_model = d_model
        self.num_heads = num_heads
        self.head_dim = d_model // num_heads

        self.query_projection = nn.Linear(
            d_model, d_model, bias=False
        )
        self.key_projection = nn.Linear(
            d_model, d_model, bias=False
        )
        self.value_projection = nn.Linear(
            d_model, d_model, bias=False
        )
        self.output_projection = nn.Linear(
            d_model, d_model, bias=False
        )
assert d_model % num_heads == 0특징 차원을 Head 수로 똑같이 나눌 수 있는지 먼저 검증한다.
nn.Linear(d_model, d_model)각 Token의 d_model개 특징을 받아 다시 d_model개 특징을 출력한다. Token 개수를 바꾸는 층은 아니다.

예를 들어 d_model=2, num_heads=2이면:

head_dim = d_model // num_heads
         = 2 // 2
         = 1

여기서 head_dim=1은 각 Head가 각 Token에서 담당하는 특징 차원 수가 1이라는 뜻이다. Token이 1개로 줄어든다는 뜻은 아니다.

첫 forward() 실행 검증

실제 입력 x를 모듈에 넣으면 Q·K·V를 Projection한 뒤 Head 축까지 분리한다.

query_heads, key_heads, value_heads = attention(x)

print(query_heads.shape)
print(key_heads.shape)
print(value_heads.shape)

# 모두 torch.Size([1, 2, 2, 1])
이번 실행에서 확인한 것 — Projection 결과는 먼저 [batch, token, d_model]이고, view()와 transpose()를 거치면 세 Tensor 모두 [batch, head, token, head_dim]이 된다. 현재 숫자에서는 [1, 2, 2, 1]이며 Token 수는 그대로 2개다.

Head별 Score 계산

분리된 Query와 Key에서 마지막 특징 차원을 내적하도록 key_heads의 마지막 두 축을 전치한 뒤 행렬곱한다.

scores_heads = torch.matmul(
    query_heads,
    key_heads.transpose(-2, -1),
)

# [batch, head, query_token, key_token]
# torch.Size([1, 2, 2, 2])
이번 실행에서 확인한 것 — Score의 마지막 두 축은 [query_token, key_token]이다. 따라서 각 Head마다 각 Query Token이 각 Key Token과 얼마나 관련되는지 나타내는 2×2 행렬이 생긴다.

head_dim=1일 때 Scaling 숫자가 같은 이유

scaled_scores_heads = scores_heads / math.sqrt(self.head_dim)

self.head_dim = 1
math.sqrt(1) = 1

scaled_scores_heads = scores_heads / 1

현재 실습은 d_model=2, num_heads=2이므로 head_dim=1이다. 따라서 Scaling 코드는 실행되지만 숫자에는 변화가 보이지 않는다. Scaling 연산이 잘못된 것이 아니라, 나눌 기준값이 1인 작은 예시를 사용한 것이다.

Head별 Softmax와 Key 방향 합

attention_weights_heads = torch.softmax(
    scaled_scores_heads,
    dim=-1,
)

# Shape: [batch, head, query_token, key_token]
#        [1,     2,    2,           2]

print(attention_weights_heads.sum(dim=-1))
# tensor([[[1., 1.],
#          [1., 1.]]])

여기서 Head 축이 서로 다른 계산 관점이고, Head 안의 각 행은 하나의 Query Token이다. 한 행 안의 값들은 그 Query가 Key Token들에 각각 얼마나 비중을 두는지를 나타낸다.

Head 1
Query 1 → [Key 1 비중 0.3783, Key 2 비중 0.6217]
Query 2 → [Key 1 비중 0.6100, Key 2 비중 0.3900]

Head 2
Query 1 → [Key 1 비중 0.5386, Key 2 비중 0.4614]
Query 2 → [Key 1 비중 0.4220, Key 2 비중 0.5780]
왜 합이 1인지 확인하는가? — dim=-1은 마지막 축인 Key 방향에 Softmax를 적용한다. 따라서 각 Head의 각 Query 행에서 Key 비중을 모두 더하면 1이어야 한다. 이는 “각 관점에서 한 Query가 어느 Key에 얼마나 비중을 배분했는가”가 정상적인 비율로 만들어졌는지 확인하는 검사다.

Value 가중합부터 W_O까지 모듈 안에서 완성

head_outputs = torch.matmul(
    attention_weights_heads,
    value_heads,
)
# [batch, head, token, head_dim]
# [1, 2, 2, 1]

outputs_by_token = head_outputs.transpose(1, 2)
# [batch, token, head, head_dim]
# [1, 2, 2, 1]

multi_head_output = outputs_by_token.reshape(
    batch_size,
    token_count,
    self.d_model,
)
# [batch, token, d_model]
# [1, 2, 2]

projected_output = self.output_projection(
    multi_head_output
)
# [batch, token, d_model]
# [1, 2, 2]

head_outputs.transpose(1, 2)는 Head별로 모여 있던 결과를 같은 Token의 Head 결과끼리 이웃하도록 다시 정렬한다. 그다음 reshape()가 head × head_dim을 d_model로 병합하고, W_O가 나란히 붙은 Head 정보를 학습된 비율로 다시 조합한다.

multi_head_output:
tensor([[[-0.1418, -0.0712],
         [-0.2561, -0.0701]]])
shape: [1, 2, 2]

projected_output:
tensor([[[-0.0200,  0.0252],
         [-0.0737,  0.0376]]])
shape: [1, 2, 2]
완료 검증 — W_O를 통과하면서 값은 달라졌지만 d_model → d_model Linear이므로 Shape은 [batch, token, d_model]=[1,2,2]로 유지됐다. 이 결과로 Multi-Head Attention의 전체 계산을 하나의 nn.Module.forward() 안에서 연결했다.

포지셔널 인코딩은 사라지지 않는다

포지셔널 인코딩은 Head 분리 때 다시 넣는 값이 아니다. Attention보다 앞에서 이미 Token Embedding에 더해져 x가 된다.

x = token_embedding + positional_encoding

Q = x @ W_Q
K = x @ W_K
V = x @ W_V

따라서 Q·K·V와 Head 결과에는 Token의 의미와 문장 속 위치 정보가 함께 반영되어 있다.

한 줄 요약 — Head는 위치 정보를 버리는 별도 공간이 아니라, 위치 정보가 이미 섞인 x의 특징 차원을 나눠 보는 여러 계산 관점이다.

모든 가중치는 최종 Loss로 함께 학습된다

최종 logits
→ Loss
→ loss.backward()
→ W_Q, W_K, W_V, W_O 모두 Gradient 계산
→ Optimizer 업데이트

Q·K·V와 (W_O)가 각자 정답을 따로 맞추는 것이 아니다. 전체 Transformer가 최종 예측을 잘하도록 모든 가중치가 함께 조정된다.
