LayerNorm은 무엇을 정리하는가?

입력 Shape이 [batch, token, d_model]이면 LayerNorm은 보통 마지막 d_model 차원에 적용된다.

Token 1의 차원값들끼리 평균·분산 계산
Token 2의 차원값들끼리 평균·분산 계산

Batch 전체를 한 번에 정규화하지 않음
문장의 모든 Token을 한 번에 정규화하지 않음

Attention과 Residual을 여러 층 거치면서 Token 벡터의 값 규모가 달라질 수 있다. LayerNorm은 각 Token을 다음 층이 다루기 쉬운 규모로 정리한다.

[batch,token,1]인 평균을 원래 [batch,token,d_model] Tensor의 마지막 축에서 빼는 Shape 규칙은 Tensor Broadcasting 문서에서 이어서 볼 수 있다.

정규화의 두 단계1. 각 값에서 Token 평균을 뺀다 → 평균을 0으로2. Token 표준편차로 나눈다 → 표준편차를 1로

현재 Token 1 숫자로 시작

Residual 뒤 첫 번째 Token은 다음과 같다.

Token 1 = [0.9800, 0.0252]

두 차원의 평균은:

(0.9800 + 0.0252) / 2
= 0.5026

각 값에서 평균을 뺀다.

0.9800 - 0.5026 =  0.4774
0.0252 - 0.5026 = -0.4774

평균을 뺀 결과 = [0.4774, -0.4774]

두 값의 새 평균은 0이다.

(0.4774 + -0.4774) / 2 = 0

왜 표준편차가 0.4774인가?

평균을 뺀 두 값을 제곱한다.

 0.4774² = 0.22791076
-0.4774² = 0.22791076

두 제곱값의 평균이 분산이다. LayerNorm은 여기서 원소 개수로 나누는 분산을 사용한다.

분산
= (0.22791076 + 0.22791076) / 2
= 0.22791076

표준편차는 분산의 제곱근이다.

표준편차
= √0.22791076
= 0.4774

표준편차로 나누면 왜 [1, -1]인가?

평균을 뺀 각 값을 방금 구한 표준편차 0.4774로 나눈다.

첫 번째 값
=  0.4774 / 0.4774
= 1

두 번째 값
= -0.4774 / 0.4774
= -1

따라서:

[0.4774, -0.4774]
→ 표준편차 0.4774로 나눔
→ [1, -1]

표준편차로 나누는 이유는 나눈 결과의 표준편차를 1로 만들기 위해서다.

[1, -1]의 평균 = 0

분산
= (1² + (-1)²) / 2
= 1

표준편차
= √1
= 1
현재 작은 예제의 특징 — 차원이 두 개이고 두 값이 평균을 기준으로 정확히 대칭이므로 결과가 깔끔하게 [1,-1]이 된다. 더 많은 차원에서는 각 값이 반드시 ±1이 되는 것이 아니라, Token 전체 차원값의 평균이 0, 분산이 1에 가까워진다.

LayerNorm은 이상치를 잘라내는 연산이 아니다

LayerNorm이 정리하는 것은 개별 값 하나의 튐을 찾아 제거하거나 일정 범위로 잘라내는 것이 아니다. 한 Token 안에서 값 전체가 위아래로 이동한 정도는 평균을 빼서 상쇄하고, 값 전체가 함께 커지거나 작아진 정도는 표준편차로 나누어 상쇄한다.

예를 들어 같은 상대적 모양을 가진 두 Token을 비교하면, eps를 무시한 정규화 직후 결과는 같다.

[10, 20]
평균 = 15
평균을 뺀 값 = [-5, 5]
표준편차 = 5
정규화 직후 = [-5 / 5, 5 / 5] = [-1, 1]

[1000, 2000]
평균 = 1500
평균을 뺀 값 = [-500, 500]
표준편차 = 500
정규화 직후 = [-500 / 500, 500 / 500] = [-1, 1]

두 번째 Token의 원래 값은 첫 번째보다 100배 크지만, 평균에서 얼마나 떨어져 있는지와 표준편차도 함께 100배 커진다. 따라서 나눗셈에서 전체 배율이 사라지고, 다음 층에는 비슷한 규모의 표현이 전달된다.

하지만 한 차원만 상대적으로 튀는 모양까지 지우지는 않는다.

[0, 0, 100]
평균 ≈ 33.333
평균을 뺀 값 ≈ [-33.333, -33.333, 66.667]
표준편차 ≈ 47.140
정규화 직후 ≈ [-0.707, -0.707, 1.414]

전체 평균과 표준편차는 정돈됐지만 세 번째 값이 다른 두 값보다 상대적으로 큰 관계는 남아 있다. 즉 LayerNorm은 이상치를 제거하는 클리핑이 아니라, Token 내부 특징들의 상대적 모양을 남긴 채 중심과 전체 규모를 정돈하는 연산이다.

왜 전체 이동과 배율이 상쇄되는가?

한 Token의 모든 값에 같은 변환 y = cx + b를 적용했다고 하자. c가 양수이고 eps를 무시하면 평균과 표준편차도 함께 다음처럼 변한다.

mean(y) = c × mean(x) + b
std(y) = c × std(x)

(y - mean(y)) / std(y)
= (cx + b - (c × mean(x) + b)) / (c × std(x))
= c × (x - mean(x)) / (c × std(x))
= (x - mean(x)) / std(x)

b는 평균을 뺄 때 사라지고, 양의 배율 c는 분자와 분모에 함께 생겨 약분된다. 이것이 Linear나 Residual 뒤 값의 중심과 전체 배율이 달라져도 LayerNorm의 정규화 단계가 규모를 다시 정돈할 수 있는 이유다.

정규화 직후와 최종 출력을 구분한다 — 위 계산은 γ와 β를 적용하기 전 정규화 값에 대한 설명이다. 실제 LayerNorm은 그 뒤 output = γ × normalized + β를 적용하므로, 학습된 최종 출력이 반드시 평균 0·분산 1인 것은 아니다.

실제 PyTorch에서 달라지는 작은 부분

nn.LayerNorm은 표준편차가 0일 때 나눗셈이 깨지는 것을 막기 위해 아주 작은 eps를 분산에 더한다. 따라서 출력은 정확한 1이 아니라 1에 매우 가까운 값일 수 있다.

또한 정규화 뒤에는 학습 가능한 γ와 β로 크기와 위치를 다시 조정한다. 기본 초기값에서는 보통 γ=1, β=0에서 시작한다.

normalized = (x - mean) / sqrt(variance + eps)
output = γ × normalized + β

실제 출력의 2.9802e-08은 무엇인가?

Token별 평균:
tensor([[0.0000e+00, 2.9802e-08]],
       grad_fn=<MeanBackward1>)

2.9802e-08은 과학적 표기법이다.

2.9802e-08
= 2.9802 × 10⁻⁸
= 0.000000029802
≈ 0

따라서 첫 번째 Token의 평균은 정확히 표시된 0이고, 두 번째 Token의 평균도 사실상 0이다. PyTorch의 기본 float32가 모든 실수를 무한히 정확하게 저장하지 못하므로 평균·분산·제곱근·나눗셈 과정에서 아주 작은 반올림 오차가 남은 것이다.

token_means = normalized_output.mean(dim=-1)

torch.allclose(
    token_means,
    torch.zeros_like(token_means),
)
# True

torch.allclose()는 두 Tensor가 완전히 같은 비트인지가 아니라, 허용 가능한 작은 오차 범위에서 같은지 검사한다.

grad_fn은 오차 표시가 아니다 — grad_fn=<MeanBackward1>은 평균 계산이 Autograd 계산 그래프에 연결되어 역전파할 수 있다는 뜻이다. 평균값이 잘못됐다는 경고가 아니다.

이번 실습에서 실제로 확인한 전체 결과

normalized_output:
tensor([[[ 1.0000, -1.0000],
         [-1.0000,  1.0000]]],
       grad_fn=<NativeLayerNormBackward0>)

shape: torch.Size([1, 2, 2])

Token별 평균:
tensor([[0.0000e+00, 2.9802e-08]],
       grad_fn=<MeanBackward1>)

Token별 분산:
tensor([[1.0000, 1.0000]],
       grad_fn=<VarBackward0>)

사용자가 직접 해석한 흐름은 다음과 같다. 첫 번째 Token이 [1,-1]이고 평균이 0이므로:

분산
= ((1 - 0)² + (-1 - 0)²) / 2
= (1 + 1) / 2
= 1

두 번째 Token은 [-1,1]로 순서만 반대이므로 같은 계산에서 분산 1이 나온다. 즉 Shape은 [1,2,2]로 유지됐고, 각 Token의 마지막 차원에서 평균은 사실상 0, 분산은 1에 가까워졌다.

eps와 출력 표시를 구분한다 — 실제 계산에는 variance + eps가 들어가므로 내부 값이 수학적인 1과 아주 조금 다를 수 있다. 이번 출력의 1.0000은 소수 넷째 자리까지 반올림해 표시된 값이다.
현재 검증 완료 — LayerNorm 출력의 Token별 평균이 [0, 0.000000029802]로 나와 둘 다 사실상 0임을 확인했고, unbiased=False로 구한 Token별 분산도 [1.0000, 1.0000]임을 계산과 출력으로 확인했다.

FFN 뒤 두 번째 LayerNorm도 같은 원리다

FFN의 두 번째 Residual 결과에도 새 LayerNorm 모듈을 만들고 실제 값을 넣었다.

layer_norm_2 = nn.LayerNorm(d_model)
block_output = layer_norm_2(ffn_residual_output)

입력:
[[[ 0.4207, -0.5063],
  [-1.4502,  1.3765]]]

출력:
[[[ 1.0000, -1.0000],
  [-1.0000,  1.0000]]]
shape: [1, 2, 2]
Token별 평균: [0, -2.9802e-08] ≈ [0, 0]
Token별 분산 (unbiased=False): [1, 1]

첫 번째 LayerNorm과 마찬가지로 각 Token의 마지막 차원을 따로 정돈했고 Shape은 유지됐다. 사용자는 LayerNorm 모듈을 만드는 코드와 실제 Tensor를 넣어 호출하는 코드를 구분하고, 내부에서 평균을 0에 가깝게 만들고 표준편차를 1에 가깝게 맞추는 흐름을 연결했다.

과대 해석하지 않는다 — 현재 출력은 LayerNorm의 기본 γ=1, β=0 상태에서 확인한 결과다. 학습으로 γ와 β가 바뀐 뒤 최종 출력이 반드시 평균 0·분산 1이어야 하는 것은 아니라는 설명은 아직 재검증 전이다.
