Residual은 원본을 보존하는 지름길이다

Multi-Head Attention과 Output Projection을 통과하면 입력 x에서 새로운 projected_output이 만들어진다. 이 결과만 다음 단계로 보내면 원래 Token 정보는 Attention 결과로 교체된다.

Residual 연결은 원본을 버리지 않고 같은 위치끼리 더한다.

첫 번째 Residual 연결residual_output = x + projected_output
원본 Token 정보
+ Attention이 새로 알아낸 정보
= 원본을 유지하면서 Attention 정보가 반영된 결과
현재 이해한 표현 — Attention 결과는 원본에 가할 수정량처럼 붙는다. 즉, Attention 결과로 원본을 갈아 끼우는 것이 아니라 원래 입력에 새 정보를 더해 원본 정보가 계속 흐르게 만든다.

현재 실습 숫자로 보기

x:
Token 1 = [1.0, 0.0]
Token 2 = [0.0, 1.0]

projected_output:
Token 1 = [-0.0200, 0.0252]
Token 2 = [-0.0737, 0.0376]

Residual은 같은 Token의 같은 차원끼리 더한다.

Token 1
[1.0, 0.0] + [-0.0200, 0.0252]

Token 2
[0.0, 1.0] + [-0.0737, 0.0376]

이 단계에서는 새로운 행렬곱이나 가중치가 생기는 것이 아니다. 두 Tensor의 대응하는 원소를 그대로 더한다.

왜 W_O 뒤에 바로 더할 수 있는가?

원소별 덧셈을 하려면 원래 입력과 Attention 출력의 Shape이 맞아야 한다.

원래 입력x: [batch, token, d_model]
Attention 출력projected_output: [batch, token, d_model]

W_O는 여러 Head의 결과를 다시 조합하면서 출력의 마지막 차원을 d_model로 맞춘다. 그래서 원래 입력 x와 같은 Shape으로 더할 수 있다.

구분 — Head를 합치는 reshape()와 Residual은 다른 작업이다. reshape()는 Head 결과의 모양을 합치고, Residual은 그 Attention 결과에 원래 입력을 다시 더한다.

실제 덧셈 결과 검증

residual_output = x + projected_output

residual_output:
tensor([[[ 0.9800,  0.0252],
         [-0.0737,  1.0376]]])

shape: [1, 2, 2]

원래 입력과 Attention 출력의 대응 원소가 더해졌고 Shape은 [batch, token, d_model]=[1,2,2]로 유지됐다.

직접 설명한 결론 — “기존 Multi-Head Attention을 통해 얻은 값에 자기 자신도 더한다.” 여기서 자기 자신은 Attention 출력이 아니라, 그 Attention Sub-layer로 들어왔던 원래 입력 x를 뜻한다.

완성한 Block에서 두 Residual의 역할

완성한 Post-LN Block에는 서로 다른 두 Residual이 있다. 첫 번째는 원래 입력 x를 보존하면서 Attention이 만든 관계 정보를 더하고, 두 번째는 첫 LayerNorm까지 지난 현재 표현을 보존하면서 FFN이 만든 수정값을 더한다.

first_residual
= x + attention_dropout(Attention(x))

second_residual
= normalized_output + ffn_dropout(FFN(normalized_output))
자기 말로 검증한 구분 — 첫 Residual은 기존 의미와 Attention 관계 정보를 함께 유지한다. 두 번째 Residual은 정규화된 현재 표현을 유지하면서 FFN이 각 Token에 제안한 수정값을 반영한다.
