Cell 01

토큰 번호를 의미 벡터로 바꾸기

TokenEmbedding은 정수 토큰 ID를 d_model차원의 연속 벡터로 변환합니다. Transformer가 단어 사이의 관계를 계산하기 전에 반드시 거쳐야 하는 첫 번째 표현 변환입니다.

token_embedding.pyPyTorch
import math

import torch
from torch import nn


class TokenEmbedding(nn.Module):
    def __init__(self, vocab_size, d_model):
        super().__init__()

        self.d_model = d_model
        self.embedding = nn.Embedding(
            num_embeddings=vocab_size,
            embedding_dim=d_model,
        )
        nn.init.normal_(
            self.embedding.weight,
            mean=0.0,
            std=d_model ** -0.5,
        )

    def forward(self, token_ids):
        embeddings = self.embedding(token_ids)
        embeddings = embeddings * math.sqrt(self.d_model)

        return embeddings

먼저 바로잡을 부분: 원문에 표시된 **init**은 Markdown 강조가 섞인 형태입니다. 실제 Python 코드는 앞뒤에 밑줄이 두 개씩 있는 __init__이어야 합니다.

한눈에 보는 데이터 흐름

1. Token IDs 토크나이저가 만든 정수 번호
[B, S]
2. Lookup 임베딩 테이블에서 각 행 조회
vocab × d_model
3. Scale 모든 벡터에 √d_model 곱하기
× √d_model
4. Embeddings Transformer가 처리할 연속 표현
[B, S, D]

줄별로 이해하기

01 class TokenEmbedding(nn.Module)

PyTorch 모델의 기본 단위인 nn.Module을 상속합니다. 덕분에 파라미터 추적, 장치 이동, 저장과 로딩이 가능해집니다.

02 super().__init__()

부모 클래스인 nn.Module을 초기화합니다. 이 호출이 빠지면 내부 모듈과 파라미터 등록이 정상적으로 동작하지 않습니다.

03 nn.Embedding(vocab_size, d_model)

vocab_size × d_model 크기의 학습 가능한 표를 만듭니다. 각 토큰 ID는 이 표에서 하나의 행을 선택합니다.

04 nn.init.normal_(..., std=d_model ** -0.5)

임베딩을 표준편차 1/√d_model인 정규분포로 초기화합니다. 이후 √d_model을 곱하면 초기 표준편차가 약 1이 됩니다.

05 self.embedding(token_ids)

정수 ID마다 대응하는 벡터를 조회합니다. 계산상 행렬곱처럼 볼 수도 있지만, 실제 역할은 인덱스를 이용한 lookup입니다.

06 math.sqrt(self.d_model)

작게 초기화된 임베딩을 키워 이후 더해질 Positional Encoding에 토큰 의미가 묻히지 않도록 상대적인 스케일을 맞춥니다.

07 return embeddings

토큰마다 하나의 벡터가 생기므로 마지막 축이 추가됩니다. 이 결과가 다음 셀의 Positional Encoding 입력이 됩니다.

E = Embedding(token_ids) × √dmodel std = 1/√d_model로 초기화한 뒤 √d_model을 곱하므로, 초기 출력의 표준편차는 약 1이 됩니다.

임베딩 행렬은 실제로 어떻게 초기화될까?

학습 전 임베딩은 작은 랜덤값에서 시작한다. 핵심은 평균 0만 정하는 것이 아니라, d_model개의 원소를 가진 벡터 전체가 지나치게 크거나 작아지지 않도록 분산과 표준편차를 정하는 것이다.

벡터 제곱합의 기대값, 1 / √d_model 표준편차와 PyTorch 초기화 코드는 별도 설명에서 단계별로 전개한다.

왜 √d_model을 곱하는가?

Embedding 초기화와 입력 스케일링은 같은 연산이 아니다. 초기화는 학습 시작점의 벡터 크기를 정하고, √d_model 곱셈은 Positional Encoding과 더해질 때 Token 신호의 크기를 맞춘다.

텐서 Shape 정리

대상Shape의미
token_ids[batch_size, seq_len]문장마다 나열된 토큰 번호
Embedding weight[vocab_size, d_model]학습 가능한 전체 토큰 벡터 표

shape_check.py실행 예시
layer = TokenEmbedding(vocab_size=10_000, d_model=512)
token_ids = torch.tensor([
    [12, 51, 203, 7],
    [91, 18, 42, 0],
])

output = layer(token_ids)
print(output.shape)  # torch.Size([2, 4, 512])

이 셀을 이해했는지 확인하기

vocab_size가 10,000이면 출력 벡터도 10,000차원일까?

아닙니다. vocab_size는 임베딩 표의 행 개수이고, 출력 벡터 차원은 d_model이 결정합니다.

nn.Embedding의 값은 고정되어 있을까?

아닙니다. 임베딩 표는 학습 가능한 파라미터이며, 역전파를 통해 각 토큰 벡터가 업데이트됩니다.

입력이 [2, 4]이고 d_model=512라면 출력 shape은?

[2, 4, 512]입니다. 배치와 시퀀스 축은 유지되고 각 토큰에 벡터 축이 추가됩니다.
