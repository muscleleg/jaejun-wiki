Transformer의 Batch 문장들은 서로 문맥을 공유하지 않습니다

Batch는 여러 문장을 하나의 문맥으로 합치는 구조가 아니라, 서로 독립적인 여러 Sequence를 한 번에 계산하기 위한 구조입니다.

Transformer에 여러 문장을 한 번에 넣으면 GPU가 이 문장들을 함께 처리합니다.

이때 한 가지 의문이 생깁니다.

Batch에 여러 문장이 들어 있다면 서로 다른 문장의 Token도 Attention할까요?

결론부터 말하면 일반적인 Transformer에서는 Batch에 들어 있는 서로 다른 문장끼리 Attention하지 않습니다.

Batch는 여러 문장을 하나의 문맥으로 합치는 구조가 아니라, 서로 독립적인 여러 Sequence를 한 번에 계산하기 위한 구조입니다.

1. 하나의 Batch에는 여러 개의 독립적인 Sequence가 들어갑니다

Tokenizer에 여러 문장을 전달하면 다음과 같은 Tensor가 만들어집니다.

prompts: list[str] = [
    "I study",
    "Machine learning is interesting",
    "Today is sunny",
]

Padding을 적용한 input_ids의 Shape이 다음과 같다고 가정하겠습니다.

[Batch, Token]
[3, 5]

이를 실제 내용으로 표현하면 다음과 같습니다.

Batch
[
    [I, study, PAD, PAD, PAD],
    [Machine, learning, is, interesting, PAD],
    [Today, is, sunny, PAD, PAD],
]

여기서 Batch 크기 3은 서로 독립적인 Sequence가 3개 있다는 뜻입니다.

Batch[0] → "I study"
Batch[1] → "Machine learning is interesting"
Batch[2] → "Today is sunny"

이 세 문장은 GPU에서 함께 처리되지만 하나의 문맥으로 결합되지는 않습니다.

2. Self-Attention은 같은 Batch 행 안에서만 계산됩니다

각 문장의 Token은 자신과 같은 Batch 행에 있는 Token만 참조합니다.

Batch[0]의 Token ↔ Batch[0]의 Token
Batch[1]의 Token ↔ Batch[1]의 Token
Batch[2]의 Token ↔ Batch[2]의 Token

반면 다음과 같은 Attention은 발생하지 않습니다.

Batch[0]의 Token ↔ Batch[1]의 Token  ❌

첫 번째 문장의 study가 두 번째 문장의 Machine이나 세 번째 문장의 sunny를 참조하지 않습니다.

GPU가 문장들을 동시에 처리한다는 말은 문장들이 서로 정보를 교환한다는 뜻이 아닙니다.

서로 독립적인 같은 종류의 연산을 GPU가 한꺼번에 수행한다는 뜻입니다.

3. Attention Score의 Shape에서도 분리를 확인할 수 있습니다

Multi-Head Attention(멀티헤드 어텐션)의 Attention Score는 개념적으로 다음 Shape을 가집니다.

[Batch, Head, Query Token, Key Token]

Batch가 3이고 각 문장의 길이가 5라면 다음과 같습니다.

[3, Head, 5, 5]

이 구조에는 문장별 5 × 5 Attention 행렬이 각각 존재합니다.

Batch[0] → [Head, 5, 5]
Batch[1] → [Head, 5, 5]
Batch[2] → [Head, 5, 5]

다음처럼 세 문장의 Token을 모두 합친 하나의 Attention 행렬을 만드는 것이 아닙니다.

[Head, 15, 15]  ❌

따라서 Batch 크기를 늘려도 한 문장이 참조할 수 있는 문맥이 길어지는 것은 아닙니다. 동시에 처리하는 독립적인 문장의 수만 늘어납니다.

4. 문장끼리 문맥을 공유하려면 하나의 Sequence로 넣어야 합니다

다음 두 문장이 서로 이어지는 문맥이라고 가정하겠습니다.

나는 학교에 갔습니다.
수업이 끝난 뒤 집에 왔습니다.

두 문장을 서로 다른 Batch 행에 넣으면 다음과 같습니다.

Batch[0] → 나는 학교에 갔습니다.
Batch[1] → 수업이 끝난 뒤 집에 왔습니다.

이 경우 두 번째 문장은 첫 번째 문장을 참조할 수 없습니다. 두 문장은 서로 독립적인 입력이기 때문입니다.

두 번째 문장이 첫 번째 문장을 문맥으로 사용해야 한다면 하나의 Sequence로 연결해야 합니다.

Batch[0]
→ 나는 학교에 갔습니다. 수업이 끝난 뒤 집에 왔습니다.

Tensor 구조로 보면 [Batch=1, 전체 Token 수]입니다. 이제 두 번째 문장의 Token은 같은 Sequence 앞부분에 있는 첫 번째 문장의 Token을 Attention할 수 있습니다.

Causal LM(인과적 언어 모델)에서는 미래 Token을 볼 수 없도록 Causal Mask가 적용됩니다. 따라서 뒤에 있는 두 번째 문장은 앞의 첫 번째 문장을 참조할 수 있지만, 앞의 첫 번째 문장이 뒤의 두 번째 문장을 미리 참조하지는 않습니다.

첫 번째 문장 → 두 번째 문장 참조 불가
두 번째 문장 → 첫 번째 문장 참조 가능

5. Batch를 늘리는 것과 Sequence를 늘리는 것은 다릅니다

Batch 크기를 늘린 경우

[
    [I, study],
    [I, study],
    [I, study],
    [I, study],
]

Shape은 [4,2]입니다. 독립적인 I study 문장 4개를 함께 처리하며, 각 문장의 문맥 길이는 여전히 2 Token입니다.

Sequence 길이를 늘린 경우

[
    [I, study, I, study, I, study, I, study]
]

Shape은 [1,8]입니다. 하나의 Sequence 안에 Token 8개가 들어 있으며, 뒤쪽 Token은 같은 행의 앞쪽 Token을 문맥으로 참조할 수 있습니다.

두 입력은 전체 Token 수가 8개로 같지만 의미가 다릅니다.

[4, 2] → 독립적인 짧은 문장 4개
[1, 8] → 문맥을 공유하는 긴 Sequence 1개

6. KV Cache도 Batch 행마다 독립적입니다

KV Cache는 각 Layer에서 과거 Token의 Key와 Value를 보관합니다.

[Batch, KV Head, 과거 Token, Head Dimension]

Batch 크기가 3이라면 하나의 Cache Tensor 안에 세 문장의 정보가 함께 들어 있지만, 각 행의 Cache는 서로 독립적입니다.

Cache[0] → Batch[0] 문장의 과거 문맥
Cache[1] → Batch[1] 문장의 과거 문맥
Cache[2] → Batch[2] 문장의 과거 문맥

새 Token을 생성할 때도 각 문장은 자신의 Cache만 사용합니다.

Batch[0]의 새 Token → Cache[0] 참조
Batch[1]의 새 Token → Cache[1] 참조
Batch[2]의 새 Token → Cache[2] 참조

따라서 여러 문장을 Batch로 함께 생성하더라도 문장들의 생성 결과가 서로의 문맥에 직접 영향을 주지는 않습니다.

7. Batch의 각 행은 독립적인 클라이언트 요청처럼 볼 수 있습니다

LLM 추론 환경에서는 Batch의 각 행을 서로 다른 클라이언트 요청처럼 이해할 수 있습니다.

Batch[0] → 클라이언트 A의 요청
Batch[1] → 클라이언트 B의 요청
Batch[2] → 클라이언트 C의 요청

GPU는 이 요청들을 하나의 Batch로 묶어 함께 처리하지만 요청들의 문맥은 섞이지 않습니다.

다만 엄밀하게는 Batch 행을 클라이언트 자체보다 독립적인 요청 또는 Sequence라고 표현하는 것이 정확합니다. 한 클라이언트가 여러 요청을 보낼 수도 있고, 하나의 요청에서 여러 후보 Sequence를 생성할 수도 있기 때문입니다.

Batch의 한 행 ≈ 독립적으로 처리할 하나의 Sequence

8. 이전 KV Cache Benchmark에서는 어떻게 처리되었을까요?

이전 실험에서는 먼저 I study라는 문장 1,000개를 만들었습니다.

tokenizer(
    ["I study"] * 1000,
    return_tensors="pt",
).input_ids

이때 Shape은 [1000,2]였으므로 독립적인 짧은 문장 1,000개였습니다.

Batch[0] → I study
Batch[1] → I study
...
Batch[999] → I study

이후 .repeat(1,64)를 적용했습니다. 이 연산은 Batch 크기 1,000을 늘리지 않고 각 Batch 행의 Token을 오른쪽으로 반복했습니다.

Batch[0] → I study I study I study ... I study
Batch[1] → I study I study I study ... I study
...
Batch[999] → I study I study I study ... I study

최종 Shape은 [1000,128]이었습니다.

독립적인 Sequence: 1000개
각 Sequence의 문맥 길이: 128 Token

각 Sequence 내부에서는 128개의 Token이 서로 Attention할 수 있지만, 1,000개의 Sequence끼리는 서로 Attention하지 않았습니다. KV Cache 역시 각 Sequence마다 독립적으로 유지되었습니다.

9. 입력을 구성하는 기준

여러 문장을 모델에 넣을 때는 먼저 다음 질문을 해야 합니다.

이 문장들이 하나의 문맥으로 연결되어야 하는가?

문장들이 서로 이어지는 내용이라면 하나의 Sequence로 연결합니다.

앞 문장을 뒤 문장이 참고해야 함
→ 같은 Batch 행의 하나의 긴 Sequence

문장들이 서로 독립적인 요청이라면 Batch의 서로 다른 행에 넣습니다.

각 문장을 독립적으로 처리해야 함
→ 하나의 Batch 안의 서로 다른 행
문맥을 공유해야 하는 여러 문장
→ 한 행에 이어 붙임
→ [1, 긴 Token 수]

서로 독립적인 여러 문장
→ Batch의 여러 행으로 구성
→ [문장 수, 각 문장의 Token 수]

결론

Batch는 여러 문장을 하나의 문맥으로 합치는 구조가 아닙니다.

일반적인 Transformer에서 Batch의 각 행은 서로 독립적인 Sequence입니다. GPU는 여러 행의 연산을 함께 처리하지만, 서로 다른 행의 Token끼리 Attention하지 않습니다.

같은 Batch 행의 Token → 서로 Attention 가능
서로 다른 Batch 행의 Token → 서로 Attention하지 않음

KV Cache도 Batch 행마다 독립적입니다. 각 Sequence가 생성한 과거 K·V는 해당 Sequence의 다음 Token을 계산할 때만 사용됩니다.

따라서 Batch의 각 행을 독립적인 클라이언트 요청처럼 이해할 수 있습니다. 더 정확하게는 독립적으로 처리되는 하나의 Sequence입니다.

문장들이 서로 문맥을 공유해야 한다면 서로 다른 Batch 행으로 분리하지 않고 하나의 긴 Sequence로 연결해야 합니다.

Batch 크기는 동시에 처리하는 독립적인 Sequence의 수를 결정하고, Sequence 길이는 한 입력 안에서 서로 문맥을 공유하는 Token의 범위를 결정합니다.
