FFN · 실행 검증 상세

Residual·LayerNorm·Dropout을
실제 Tensor로 검증하기

FFN의 핵심 흐름을 이해한 뒤, 두 번째 Residual과 LayerNorm의 숫자·Shape, Dropout의 훈련·평가 모드, 전체 TransformerBlock 출력을 단계별로 확인한다.

← FFN 학습 경로LayerNorm 복습

두 번째 Residual 실제 결과

normalized_output:
tensor([[[ 1.0000, -1.0000],
         [-1.0000,  1.0000]]])

contracted_output:
tensor([[[-0.5793,  0.4936],
         [-0.4502,  0.3765]]])

같은 Token의 같은 차원끼리 더했다.

ffn_residual_output
= normalized_output + contracted_output

tensor([[[ 0.4207, -0.5063],
         [-1.4502,  1.3765]]])

shape:
torch.Size([1, 2, 2])

normalized_output과 contracted_output이 모두 [batch, token, d_model]=[1,2,2]이므로 원소별로 더할 수 있었고, 결과 Shape도 [1,2,2]로 유지됐다.

실행 검증 완료 — 원래 정돈된 표현 normalized_output에 FFN이 만든 수정값 contracted_output을 더한다는 설명이 실제 숫자와 Shape에서도 확인됐다.

결과를 본 뒤 사용자는 “그럼 또 normalized 진행하겠네?”라고 다음 단계를 예측했다. Transformer Block의 현재 흐름에서 이 예측은 맞다. 두 번째 Residual 결과를 다시 LayerNorm에 넣어 Token별 마지막 차원의 평균과 퍼짐을 정돈한다.

당시 다음 검증 — 두 번째 nn.LayerNorm(d_model)을 ffn_residual_output에 적용하고, Shape 유지와 Token별 평균·분산을 확인하는 것이 다음 질문이었다.

두 번째 LayerNorm 실제 결과

layer_norm_2 = nn.LayerNorm(d_model)
block_output = layer_norm_2(ffn_residual_output)

nn.LayerNorm(d_model)로 두 번째 LayerNorm 모듈을 만들고, layer_norm_2(ffn_residual_output)으로 실제 Residual 결과를 넣어 실행했다.

입력 ffn_residual_output:
tensor([[[ 0.4207, -0.5063],
         [-1.4502,  1.3765]]])

출력 block_output:
tensor([[[ 1.0000, -1.0000],
         [-1.0000,  1.0000]]])

shape:
torch.Size([1, 2, 2])

Token별 평균:
tensor([[0.0000e+00, -2.9802e-08]])

Token별 분산 (unbiased=False):
tensor([[1.0000, 1.0000]])

Shape은 [batch, token, d_model]=[1,2,2]로 유지됐고, 각 Token의 마지막 차원에서 평균은 사실상 0, 분산은 1이 됐다. -2.9802e-08도 -0.000000029802이므로 float32 반올림 오차 수준의 0이다.

당시 Post-LN 흐름 연결 — 이 단계에서는 Attention → Residual → LayerNorm → FFN → Residual → LayerNorm을 실제 Tensor로 연결했다. Dropout 통합 전이었으므로 당시에는 Transformer Block 전체를 완료 처리하지 않았다.
아직 남은 설명 검증 — 현재 기본 초기값의 LayerNorm 출력에서 평균 0·분산 1을 확인했다. 학습 후 γ와 β가 조정되면 최종 출력의 평균과 분산이 정확히 0과 1일 필요는 없다는 점은 아직 자기 말로 다시 설명하는 검증이 남아 있다.

Dropout의 훈련·평가 모드 비교

현재 FFN 분기에서는 두 번째 Linear가 만든 contracted_output에 Dropout을 적용한 뒤 Residual로 더한다.

ffn_residual_output
= normalized_output + dropout(contracted_output)

train()에서는 일부 원소를 무작위로 끈다

p = 0.5
torch.manual_seed(0)

contracted_output:
tensor([[[-0.5793,  0.4936],
         [-0.4502,  0.3765]]])

dropped_output:
tensor([[[-0.0000,  0.0000],
         [-0.9004,  0.0000]]])

shape:
torch.Size([1, 2, 2])

p=0.5는 전체 네 원소 중 정확히 두 개를 반드시 끈다는 뜻이 아니다. 각 원소를 서로 독립적으로 50% 확률로 끄므로, 이번처럼 네 개 중 세 개가 0이 될 수도 있다.

살아남은 값은 평균적인 출력 크기를 유지하도록 1 / (1-p)배 된다.

p = 0.5
1 / (1 - 0.5) = 2

-0.4502 × 2 = -0.9004

eval()에서는 Dropout 동작을 끈다

eval_output == contracted_output
torch.allclose(eval_output, contracted_output)
# True
직접 설명한 결론 — “똑같게 나오네. Dropout이 꺼져 있어서 그런가 보네.” 정확한 해석이다. eval()은 Dropout 모듈을 삭제하는 것이 아니라 무작위로 원소를 끄는 동작을 비활성화한다. 다시 train()을 호출하면 Dropout 동작이 재활성화된다.
당시 검증 범위 — Dropout의 Shape 유지, 독립적인 확률적 제거, 살아남은 값의 보정, train()/eval() 차이를 먼저 확인했다. 이 시점에는 낱개 연산을 Dropout 위치까지 포함한 하나의 TransformerBlock.forward()로 묶는 작업이 남아 있었다.

TransformerBlock 통합 검증 완료

낱개로 확인한 Attention, 두 Dropout, 두 Residual, 두 LayerNorm과 FFN을 하나의 forward()로 연결했다.

Attention
→ Attention Dropout
→ x + Attention 출력
→ LayerNorm 1
→ Linear(d_model, d_ff)
→ GELU
→ Linear(d_ff, d_model)
→ FFN Dropout
→ normalized_output + FFN 수정값
→ LayerNorm 2

입력과 출력 Shape은 모두 [batch, token, d_model]=[1,2,2]였다. 최종 출력의 Token별 평균 [2.98e-08, 2.98e-08]은 사실상 0이고, unbiased=False 분산은 [1,1]이었다.

FFN 역할 설명 완료 — 첫 Linear는 d_model → d_ff로 중간 특징 공간을 만들고, GELU는 그 중간 반응의 전달 정도를 부드럽게 조절하며, 두 번째 Linear는 d_ff → d_model의 수정값을 만든다. 양수는 관련 있고 음수는 무관하다고 고정해서 해석하지 않는다.
앞선 열린 질문의 후속 결과 — Dropout 위치까지 포함한 통합 구현, 입력·출력 Shape 검증과 두 Residual의 역할 설명을 마쳐 Transformer Block 완료 관문을 닫았다.
