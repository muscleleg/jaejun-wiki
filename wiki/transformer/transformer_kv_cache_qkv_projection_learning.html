KV Cache는 무엇을 저장하고
GPT-2는 Q·K·V를 어떻게 만드는가

개념적인 Q·K·V Projection과 GPT-2의 합쳐진 구현을 연결하고, 그 결과 중 어떤 Tensor가 KV Cache에 남아 다음 Token 생성에 재사용되는지 정리합니다.

← Q·K·V Projection 학습 경로과거 input_ids 없이 Cache 전달하기Layer·Head별 Cache Shape실제 Cache Shape 기록
별도 Projection Cache의 저장 대상 GPT-2 합성 QKV 구간별 Gradient 저장 Shape 생성 중 재사용 Q를 저장하지 않는 이유 한 줄 결론

1. 개념적으로는 Q·K·V Projection이 따로 있습니다

한 Transformer Layer에 들어온 Hidden State를 X [B,S,D]라고 두면, 같은 입력 X에 서로 다른 Projection Weight를 적용해 Query·Key·Value를 만듭니다. B는 Batch, S는 Token 수, D는 Hidden Feature 차원입니다.

Q = XW_Q + b_Q
K = XW_K + b_K
V = XW_V + b_V

X, Q, K, V Shape = [B,S,D]

Q·K·V가 같은 Shape을 가진다는 사실은 같은 값이나 같은 Weight를 사용한다는 뜻이 아닙니다. 각각 다른 Weight가 같은 Hidden State를 서로 다른 역할의 표현으로 바꿉니다.

2. KV Cache는 K·V Projection의 출력 Tensor를 저장합니다

KV Cache의 첫 정의는 “이미 처리한 Token의 K·V Projection 결과값을 저장하는 것”입니다. Projection Module, Projection Weight, 행렬곱 연산 자체를 저장하는 것이 아닙니다.

저장하지 않는 것
× QKV Projection Module
× W_Q, W_K, W_V Weight
× Projection 행렬곱 연산

저장하는 것
○ 각 Layer의 Hidden State에 Projection을 적용해 얻은 과거 Token의 K·V 출력 Tensor

같은 Token이라도 Layer마다 입력 Hidden State와 Projection Weight가 다르므로 K·V 결과도 다릅니다. 따라서 KV Cache는 Layer별로 따로 보관합니다.

3. GPT-2는 합쳐진 QKV Projection 한 번으로 계산합니다

개념은 세 Projection이지만 실제 GPT-2는 c_attn이라는 Conv1D-style Affine Projection 한 번으로 마지막 차원을 D → 3D로 늘린 뒤, 출력을 Q·K·V 구간으로 나눕니다. 이름은 Conv1D이지만 여기서는 Token별 Hidden State의 마지막 차원에 적용되는 Linear와 같은 종류의 행렬곱입니다.

d_model = 2

X [B,S,2]
  ↓ c_attn: 2 → 6
[q1,q2,k1,k2,v1,v2] [B,S,6]
  ↓ split
Q [q1,q2] | K [k1,k2] | V [v1,v2]

합쳐진 Weight Tensor 안에도 Q·K·V 출력을 만드는 구간이 나란히 들어 있습니다. 한 번 계산한다는 것은 같은 Weight를 공유한다는 뜻이 아니라, 개념적인 세 Weight를 한 Tensor에 붙여 행렬곱을 한 번에 수행한다는 뜻입니다.

W_QKV = [W_Q | W_K | W_V]
XW_QKV = [XW_Q | XW_K | XW_V]

4. 합쳐진 Projection도 구간별 Gradient가 다릅니다

Split 뒤에는 Q·K·V 구간이 서로 다른 계산 경로에 들어갑니다. Q와 K는 Score = QKᵀ / √d와 Softmax를 거쳐 Attention Weight A를 만들고, V는 A × V에서 그 비율로 섞일 정보를 제공합니다.

Q 구간 ─┐
        ├─ QKᵀ / √d → Softmax → A ─┐
K 구간 ─┘                            ├─ A × V → Attention 출력 → 최종 Loss
V 구간 ──────────────────────────────┘

최종 Loss는 하나지만 Loss까지 거치는 계산 경로가 다르므로, 역전파로 돌아오는 Gradient도 다릅니다. Q 경로의 Gradient는 합쳐진 Weight의 Q 구간에, K 경로의 Gradient는 K 구간에, V 경로의 Gradient는 V 구간에 기록됩니다.

Optimizer는 합쳐진 Weight Tensor 전체를 한 Step에 업데이트하지만 각 원소에 계산된 Gradient가 다르므로 세 구간은 각 역할에 맞게 서로 다르게 조정됩니다. 즉 출력은 Q·K·V로 잘라서 사용하고, 전체 Weight는 한 번에 업데이트하되 원소별 Gradient는 다릅니다.

5. Head 분리 후 past_key_values에 저장합니다

합쳐진 Projection 출력을 Q·K·V로 Split한 뒤 각 Tensor를 Head별로 다시 나눕니다. 그중 K와 V가 Layer별 past_key_values에 들어갑니다.

past_key_values[layer][0]  # 해당 Layer의 Key Tensor
past_key_values[layer][1]  # 해당 Layer의 Value Tensor

Prompt "I study."의 Token ID [40,2050,13]을 tiny GPT-2의 첫 Forward에 넣어 실제로 확인한 Layer 0의 K·V Shape은 다음과 같습니다.

Layer 0 Key   Shape = [1,2,3,1]
Layer 0 Value Shape = [1,2,3,1]

[Batch, Head, Token, Head dim]
[     1,    2,     3,        1]

예를 들어 past_key_values[0][0][0,0,1,:]은 Layer 0·Batch 0·Head 0에서 Token 1의 Key 벡터입니다. Value도 같은 위치 규칙을 사용합니다.

6. Prompt를 처음 계산한 뒤 새 Token의 K·V만 추가합니다

첫 Forward에서는 Prompt 전체의 Q·K·V를 계산하고 Layer별 K·V를 Cache로 반환합니다. 다음 생성 Step부터는 새 Token 하나의 Q·K·V만 계산합니다. 새 Query는 과거 K Cache와 새 K를 함께 조회하고, 그 Attention 비율로 과거 V Cache와 새 V를 함께 섞습니다.

첫 Forward
Prompt 전체 → Q·K·V 계산 → Prompt의 K·V Cache 저장

다음 Step
새 Token 하나 → 새 Q·K·V 계산
새 Q × [과거 K Cache + 새 K] → Attention Weight
Attention Weight × [과거 V Cache + 새 V] → 새 Token 출력
새 K·V → Cache의 Token 축 뒤에 append
실행 검증 경계 — 새 Token 하나와 첫 past_key_values를 다음 Forward에 전달해 Cache의 Token 축이 S → S+1로 늘어나는 한 Step을 확인한 뒤, 5개 Token 반복 생성에서 모델 입력 [1,2] → [1,1] → …과 Key Cache Token 축 2 → 6을 확인했습니다. 같은 Prompt·Greedy·생성 길이의 No-cache와 KV Cache 출력 Token ID도 일치했습니다. 과거 input_ids를 다시 넣지 않아도 전체 문맥을 사용하는 흐름은 KV Cache와 input_ids 전달 문서, 실제 Shape은 PyTorch 추론 Baseline 실습에서 이어 봅니다. 로컬 CPU의 Latency·Batch 처리량까지 검증했으며, GPU 메모리·CUDA 동기화 측정은 아직 남아 있습니다.

7. 과거 Q는 Cache하지 않습니다

과거 Token의 Query는 그 Token의 출력을 만들 때 이미 역할을 마쳤습니다. 다음 Step에서는 새 Token의 Query만 있으면 과거 Token의 K를 조회하고 V를 가져올 수 있습니다.

예를 들어 Prompt가 [A,B,C]라면 첫 Forward에서 Q_A·Q_B·Q_C는 각각 A·B·C 위치의 출력을 만드는 데 사용되고, 마지막 C 위치의 Logit으로 다음 Token D를 선택합니다. D를 붙인 뒤 E를 예측할 때는 과거 위치 전체를 다시 계산하는 대신 새 위치의 Q_D·K_D·V_D만 계산합니다. Q_D가 Cache에 있던 [K_A,K_B,K_C]와 새 K_D를 함께 조회하고, 그 결과로 [V_A,V_B,V_C]와 새 V_D를 섞어 D 위치의 출력을 만듭니다. 이때 Q_A·Q_B·Q_C가 만들 과거 위치 출력은 첫 Forward에서 이미 완성되었으므로 다시 사용할 필요가 없습니다.

새 Token 한 위치만 계산하는 목적

new Q [B,H,1,d]
  × all Kᵀ [B,H,d,S+1]
  → score [B,H,1,S+1]

Q_D × [K_A,K_B,K_C,K_D]ᵀ
  → D 위치가 A부터 D까지 조회하는 점수 한 행

Token 축이 1인 새 Query만 계산해도, 모든 과거 K를 Token 축 S+1에 이어 붙여 조회할 수 있습니다. 이것이 과거 Query 계산을 반복하지 않고도 새 Token 한 위치의 출력을 만드는 KV Cache의 목적입니다.

Attention Score·Weight·최종 출력도 현재 Query와 K·V로 다시 만들어지는 중간 결과이므로 저장하지 않습니다. 다음 Token 생성에서 다시 필요한 과거 정보인 K와 V만 보존합니다.

8. 한 줄 결론

GPT-2는 한 번의 합쳐진 QKV Projection 결과를 역할별로 나누고, 그중 이미 처리한 Token의 K·V 결과값만 Head로 분리해 Layer·Head·Token별 KV Cache에 저장합니다.
  • KV Cache 저장부터 Token 생성·검증·성능 비교까지 전체 흐름
  • KV Cache가 Layer별·Head별 형태로 저장되는 이유
  • Q·K·V Projection과 Linear 가중치
  • Multi-Head Attention 분리와 병합
