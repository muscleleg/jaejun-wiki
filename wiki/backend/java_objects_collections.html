Java 객체·동등성·제네릭·Collection

메서드를 누가 실행하는지에서 시작해 객체 동일성, 논리적 동등성, Hash 자료구조의 계약, 제네릭과 정렬 기준까지 하나의 객체 사용 흐름으로 연결합니다.

1. 인스턴스 메서드는 객체 참조를 통해 실행된다

class Counter {
    private int value;

    void increment() {
        value += 1;
    }

    int value() {
        return value;
    }
}

Counter first = new Counter();
Counter second = new Counter();
first.increment();

System.out.println(first.value());  // 1
System.out.println(second.value()); // 0

increment()는 static 메서드가 아니므로 특정 Counter 인스턴스가 필요합니다. first.increment()를 호출하면 메서드 안의 this가 first를 가리키고, 그 객체의 필드만 바뀝니다.

구분
클래스는 객체가 가질 상태와 동작의 설계이고, 인스턴스는 new로 만들어진 실제 객체입니다. 참조 변수는 객체 자체가 아니라 객체를 가리키는 값을 보관합니다.

2. static은 인스턴스가 아니라 클래스에 속한다

static 필드와 메서드는 특정 객체가 없어도 클래스 이름으로 접근합니다. 모든 인스턴스가 공유해야 하는 상수·순수 유틸리티에는 적합하지만, 사용자마다 다른 상태를 static 필드에 넣으면 모든 요청이 같은 값을 공유하게 됩니다.

class Temperature {
    static final double FREEZING_POINT = 0.0;

    static double celsiusToFahrenheit(double celsius) {
        return celsius * 9 / 5 + 32;
    }
}

double result = Temperature.celsiusToFahrenheit(20);

3. ==, equals, hashCode는 서로 다른 질문이다

도구질문대표 사용
==primitive 값이 같은가, 또는 두 참조가 같은 객체를 가리키는가?숫자·boolean·객체 identity
equals두 객체를 도메인 규칙상 같은 값으로 볼 것인가?문자열·값 객체
hashCodeHash bucket 후보를 고를 정수는 무엇인가?HashMap·HashSet
record MemberId(long value) {}

MemberId a = new MemberId(10);
MemberId b = new MemberId(10);

System.out.println(a == b);      // false: 서로 다른 객체
System.out.println(a.equals(b)); // true: record component 값이 같음

equals가 true인 두 객체는 반드시 같은 hashCode를 반환해야 합니다. 반대로 hashCode가 같다고 equals가 true인 것은 아닙니다. Hash 충돌이 가능하기 때문에 Hash 자료구조는 bucket을 찾은 뒤 equals로 최종 비교합니다.

Entity 주의
데이터베이스 Entity의 동등성은 생성 전·저장 후 식별자 변화와 프록시를 고려해야 하므로 값 객체와 같은 방식으로 무조건 모든 필드를 equals에 넣지 않습니다.

4. 배열 비교는 깊이에 따라 API가 다르다

int[] left = {1, 2};
int[] right = {1, 2};

left == right                       // false
Arrays.equals(left, right)          // true

int[][] a = {{1, 2}, {3, 4}};
int[][] b = {{1, 2}, {3, 4}};
Arrays.equals(a, b)                 // false: 내부 배열 참조 비교
Arrays.deepEquals(a, b)             // true: 중첩 내용 비교

배열은 Object.equals를 내용 비교로 재정의하지 않았습니다. 1차원은 Arrays.equals, 중첩 배열은 Arrays.deepEquals를 사용합니다.

5. 제네릭은 실행 전 타입 관계를 검사한다

static <T> T first(List<T> values) {
    if (values.isEmpty()) {
        throw new IllegalArgumentException("빈 목록");
    }
    return values.get(0);
}

String name = first(List.of("A", "B"));

<T>는 호출할 때 결정되는 타입 매개변수입니다. 반환값을 Object로 두고 매번 형 변환하는 대신 입력과 출력이 같은 타입이라는 계약을 컴파일 시점에 검사합니다.

? extends Number는 Number의 하위 타입을 읽는 생산자에, ? super Integer는 Integer를 넣는 소비자에 적합합니다. 흔히 PECS(Producer Extends, Consumer Super: 생산자는 extends, 소비자는 super)로 기억합니다.

6. 함수형 인터페이스는 동작을 값처럼 전달하는 계약이다

@FunctionalInterface
interface Formatter<T> {
    String format(T value);
}

Formatter<Integer> formatter = value -> "score=" + value;
System.out.println(formatter.format(80));

함수형 인터페이스는 추상 메서드가 하나입니다. default·static 메서드는 추가할 수 있습니다. 람다는 새로운 문법 종류의 함수가 아니라 그 인터페이스의 한 구현으로 변환됩니다.

표준 함수형 인터페이스인 Function<T,R>, Predicate<T>, Consumer<T>, Supplier<T>를 먼저 검토하면 사용자 정의 인터페이스 수를 줄일 수 있습니다.

7. Collection 선택은 필요한 연산에서 시작한다

구조강점대표 주의
ArrayList인덱스 접근, 끝 추가중간 삽입·삭제 시 이동
HashSet중복 제거, 평균 빠른 membership순서 계약 없음, equals/hashCode 필요
HashMapkey로 값 찾기평균 O(1)이지 항상 O(1)은 아님
TreeMapkey 정렬·범위 탐색일반적으로 O(log n)

정렬 기준

record Member(String name, int score) {}

List<Member> members = new ArrayList<>(List.of(
    new Member("B", 90),
    new Member("A", 90),
    new Member("C", 70)
));

members.sort(
    Comparator.comparingInt(Member::score).reversed()
        .thenComparing(Member::name)
);

Comparable은 타입 자체의 자연 순서를, Comparator는 상황별 외부 정렬 기준을 정의합니다. 점수가 같을 때 이름으로 비교하는 것처럼 동점 규칙을 끝까지 선언해야 결과가 안정적입니다.

8. 복잡도는 자료구조 이름이 아니라 구체 연산과 조건을 말한다

배열 인덱스 접근은 O(1), 값이 어디 있는지 모르는 배열 검색은 O(n)입니다. HashMap 조회는 좋은 hash 분포와 일반적인 구현에서 평균 O(1)이지만 충돌·크기 조정·최악 조건을 포함하면 “항상 O(1)”이라고 할 수 없습니다. 정렬된 TreeMap 조회는 O(log n)입니다.

실제 성능에는 입력 크기뿐 아니라 객체 할당, cache locality, boxing, I/O(입출력)도 영향을 줍니다. Big-O는 증가율을 비교하는 도구이지 실행 시간을 대신하는 숫자가 아닙니다.

9. 결론

Java 객체를 사용할 때는 누가 상태를 소유하는가, 같다는 뜻을 어떻게 정의하는가, 필요한 연산에 맞는 Collection은 무엇인가를 순서대로 결정합니다. 이 세 질문이 static 오용, HashSet 중복, 정렬 오류를 함께 줄입니다.
