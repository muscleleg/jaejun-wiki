입국심사

사람을 직접 배치하는 대신 시간 후보가 가능한지를 판정하고, 불가능과 가능이 갈리는 최초 경계를 이분 탐색으로 찾은 과정을 기록한다.

사람 배치에서 시간 판정으로 바꾼다

처음에는 심사관에게 사람을 한 명씩 나누는 방식으로 생각했지만, 후보 시간 T가 주어졌다고 가정하면 각 심사관이 처리할 수 있는 사람 수를 바로 계산할 수 있다.

available = sum(T // time for time in times)

available >= n이면 가능한 시간이고, 작으면 불가능한 시간이다. 시간이 늘어날수록 처리 인원은 줄지 않으므로 판정은 불가능 → 가능 순서로 한 번만 바뀐다.

최댓값은 안전한 시간 상한이다

left = 1
right = min(times) * n

가장 빠른 심사관 한 명이 모든 사람을 처리해도 끝나는 시간이므로 right는 정답이 넘지 않는 안전한 상한이다. 심사관 수로 나눈 시작점이 아니라, 정답 후보 전체 범위를 먼저 정한 것이다.

중간값은 사람 수가 아니라 시간 범위를 나눈다

mid = (left + right) // 2

//를 사용한 이유는 시간 후보를 정수로 탐색하기 위해서다. 중간값은 심사관 수에 따라 2등분·3등분하는 값이 아니라, 현재 남은 시간 후보 구간을 두 선택지로 나누는 기준이다.

검사한 중간값을 제외하고 경계를 옮긴다

if available >= n:
    right = mid - 1
else:
    left = mid + 1

가능하면 더 작은 시간에도 가능한지 확인해야 하므로 왼쪽 구간을 남긴다. 불가능하면 더 큰 시간이 필요하므로 오른쪽 구간을 남긴다. -1과 +1은 정수 후보 목록에서 이미 검사한 mid를 다음 후보 구간에서 제외하고, 바로 이전 또는 다음 정수부터 남긴다는 뜻이다.

available == n이어도 바로 종료하지 않는다. 예제에서 29분과 28분은 모두 6명을 처리하지만 최초 가능 시간은 28분이기 때문이다.

범위가 교차하면 최초 가능 시간이 남는다

반복 중에는 left보다 작은 값이 모두 불가능하고, right보다 큰 값이 모두 가능하도록 경계를 갱신한다. 마지막에 left > right가 되면 미확정 후보가 사라진다.

right = 마지막 불가능한 시간
left  = 최초로 가능한 시간

예제에서는 right = 27, left = 28로 갈리므로 답은 left다.

실제로 막혔던 지점

  • n과 심사관별 시간이 무엇을 뜻하는지 설명 없이 식부터 보면 문제를 따라가기 어려웠다.
  • right = min(times) * n을 최소 정답이 아니라 정답이 넘지 않는 안전한 상한으로 구분해야 했다.
  • 중간값을 심사관 수로 나눈 시작점으로 오해했지만, 실제로는 후보 범위에 대한 양자택일 기준이었다.
  • half 하나를 반복해서 나누는 것이 아니라 left와 right를 보관하고 매번 새 mid를 계산해야 했다.
  • 가능할 때 어느 경계를 움직이는지 처음에는 반대로 작성했다.
  • mid - 1은 답에서 1을 빼는 연산이 아니라, 이미 검사한 정수 후보를 폐구간에서 제외하는 표현이었다.
  • left > right는 오류가 아니라 미확정 후보가 모두 사라진 종료 조건이었다.

제출에 통과한 코드

def solution(n, times):
    left = 1
    right = min(times) * n

    while left <= right:
        mid = (left + right) // 2
        available = sum([mid // time for time in times])

        if available >= n:
            right = mid - 1
        else:
            left = mid + 1

    return left

첫 구현에서는 answer를 선언했지만 사용하지 않았고, 심사관 두 명만 직접 더하던 식은 sum()으로 일반화했다.

복잡도

심사관 수를 m, 시간 후보 상한을 R = min(times) × n이라고 두면, 후보 한 번의 가능 여부 계산은 모든 심사관을 보므로 O(m)이다. 시간 범위를 절반씩 줄이는 횟수는 O(log R)이므로 전체 시간 복잡도는 O(m log R)이다. Generator 표현을 바로 sum()에 넘기면 추가 공간은 O(1)이고, 제출 코드처럼 중간 List를 만들면 O(m)의 임시 공간이 필요하다.

지연 복습 완료

2026년 8월 31일에 기존 코드와 학습 기록을 보지 않고 다시 구현해 프로그래머스 전체 테스트에 통과했다. right=27은 불가능, left=28은 최초 가능인 경계에서 후보가 모두 소진되어 교차한다는 점을 설명했고, 이분 탐색의 O(log R)회마다 심사관 m명을 확인하므로 전체 시간 복잡도가 O(m log R)임을 교정했다. 이 증거로 이분 탐색 경계 설계 관문을 완료했다.
