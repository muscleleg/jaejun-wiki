프로세스

Queue에서 순서가 계속 바뀌는 동안에도 처음 선택한 프로세스를 추적하고, 꺼낸 횟수와 실제 실행 횟수를 구분하는 과정을 기록한다.

처음 생각

맨 앞 프로세스를 꺼낸다.
→ 뒤에 더 높은 우선순위가 있는지 찾는다.
→ 있으면 다시 뒤로 보낸다.
→ 없으면 실행한다.

전체 Simulation(시뮬레이션)은 이해했지만, 찾는 location 프로세스가 Queue 안에서 이동하면서 원래 위치를 잃는 문제가 생겼다.

핵심 해결 · 값과 원래 인덱스를 같이 저장한다

queue = [
    (priority, original_index)
    for original_index, priority in enumerate(priorities)
]

Queue에서 현재 위치가 바뀌더라도 original_index == location으로 처음 선택한 항목을 계속 식별할 수 있다.

재사용할 패턴
정렬이나 Queue 이동으로 순서는 바뀌지만 원래 항목의 정체성이 필요하면 (value, original_index)를 함께 들고 다닌다.

실수 1 · enumerate() 순서를 반대로 생각했다

for index, value in enumerate(items):
    ...

enumerate()가 만드는 쌍은 첫 번째가 index, 두 번째가 value다. 저장할 tuple의 순서를 (priority, original_index)로 정했다면 컴프리헨션 안에서 의도한 순서로 다시 배치해야 한다.

실수 2 · pop()을 Queue의 앞 제거로 생각했다

list.pop()마지막 값을 꺼낸다.
list.pop(0)리스트의 맨 앞 값을 꺼내지만 뒤 원소 이동 비용이 든다.
deque.popleft()Queue의 맨 앞 값을 꺼내는 데 적합하다.
from collections import deque

queue = deque(...)
priority, original_index = queue.popleft()

실수 3 · pop 횟수와 실행 횟수를 섞었다

높은 우선순위가 뒤에 있으면 현재 프로세스는 Queue에서 꺼내졌더라도 실행되지 않고 뒤로 돌아간다. 따라서 꺼낼 때마다 answer += 1을 하면 안 된다.

Queue에서 pop한 횟수
≠
프로세스가 실제 실행된 횟수

실행이 확정된 분기에서만 answer를 증가시킨다.

실수 4 · continue가 바깥 while로 간다고 생각했다

for other_priority, _ in queue:
    if other_priority > priority:
        queue.append((priority, original_index))
        continue

이 continue는 가장 가까운 for의 다음 반복으로 이동한다. 더 높은 값이 여러 개라면 같은 프로세스를 여러 번 append할 수도 있다.

이 문제는 더 높은 우선순위가 하나라도 발견되면 현재 프로세스를 실행할 수 없다는 판단이 확정된다. 따라서 다시 넣고 break한다.

is_pushed = False

for other_priority, _ in queue:
    if other_priority > priority:
        queue.append((priority, original_index))
        is_pushed = True
        break
판단 기준
하나라도 발견하면 조건이 확정되는 문제라면 발견 즉시 break할 수 있다.

실수 5 · 찾는 프로세스를 꺼낸 순간 종료했다

original_index == location이어도 뒤에 더 높은 우선순위가 있으면 다시 Queue로 돌아간다.

내 프로세스를 꺼냈다
≠
내 프로세스가 실행됐다

실행이 확정되어 answer를 증가시킨 뒤에만 원래 인덱스를 검사한다.

최종적으로 통과시킨 사고 흐름

맨 앞 프로세스를 꺼냄

→ 나보다 높은 우선순위가 하나라도 있는가?

YES
→ 현재 프로세스를 Queue 뒤로 보냄
→ 실행 횟수 증가 안 함

NO
→ 실제 실행
→ answer += 1

→ 실행한 프로세스의 원래 index가 location인가?

YES
→ answer 반환

이 흐름을 Python으로 옮기면 다음처럼 현재 프로세스의 정체성과 실행 시점을 분리할 수 있다.

from collections import deque

def solution(priorities, location):
    queue = deque(
        (priority, index)
        for index, priority in enumerate(priorities)
    )
    answer = 0

    while queue:
        priority, original_index = queue.popleft()

        if any(other_priority > priority for other_priority, _ in queue):
            queue.append((priority, original_index))
            continue

        answer += 1

        if original_index == location:
            return answer

Queue의 앞뒤 이동은 효율적이지만, 현재 구현은 각 단계에서 남은 우선순위를 훑으므로 최악의 경우 시간 복잡도는 O(n²)이다.
