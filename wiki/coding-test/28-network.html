네트워크

인접 행렬의 한 행을 현재 컴퓨터의 이웃 목록으로 읽고, 아직 방문하지 않은 시작점마다 DFS를 수행해 연결 요소 수를 셌다.

제출 통과DFSadjacency matrixconnected component
프로그래머스 문제 열기 ↗
이 문제 복습그래프 해석DFS 흐름연결 요소복잡도검증 증거← 전체 문제

인접 행렬의 행은 현재 정점의 이웃을 나타낸다

computers[current]의 각 열 next_node는 현재 컴퓨터와 다음 컴퓨터가 연결되어 있는지를 나타낸다. 값이 1이고 아직 방문하지 않았다면 같은 네트워크 안의 다음 정점이다.

computers[current][next_node] == 1
→ current와 next_node가 연결됨

한 번의 DFS가 하나의 네트워크를 모두 방문한다

DFS에 들어온 현재 컴퓨터를 방문 처리한 뒤 연결된 모든 이웃을 확인한다. 아직 방문하지 않은 이웃에 다시 DFS를 적용하면 직접 연결뿐 아니라 여러 간선을 거쳐 이어진 컴퓨터까지 같은 탐색에서 방문된다.

현재 정점 방문 처리
→ 현재 행의 모든 이웃 확인
→ 연결됐고 미방문이면 DFS
→ 연결된 전체 영역 방문 완료

DFS 시작 횟수가 연결 요소 개수다

바깥 반복에서 이미 방문한 컴퓨터는 이전 DFS가 속한 네트워크의 일부이므로 건너뛴다. 아직 방문하지 않은 컴퓨터를 만났다는 것은 새로운 네트워크의 시작점을 찾았다는 뜻이므로 그때만 개수를 하나 늘리고 DFS를 시작한다.

for node in 모든 컴퓨터:
    if node가 미방문:
        네트워크 수 += 1
        DFS(node)

인접 행렬에서는 시간 복잡도가 O(n²)이다

각 컴퓨터는 DFS에 한 번만 들어가지만, 들어갈 때마다 길이 n인 연결 행 전체를 확인한다. 따라서 컴퓨터 n개에 대해 n개의 열을 확인해 전체 시간 복잡도는 O(n²)이다. 방문 배열과 재귀 호출이 사용하는 추가 공간은 O(n)이다.

확인한 완료 증거

  • 인접 행렬의 행과 열을 현재 정점과 이웃 후보로 설명했다.
  • 바깥 반복에서 미방문 정점을 만날 때만 개수를 늘리는 이유를 연결 요소와 연결했다.
  • 각 정점은 한 번 방문해도 매번 행 전체를 읽으므로 O(n²)임을 설명했다.
  • 직접 구현한 뒤 프로그래머스 전체 테스트에 통과했다.
