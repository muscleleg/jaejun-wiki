로드맵 운영 원칙

문제 출처대표 문제, 복습 문제, 실전 문제는 모두 프로그래머스 코딩테스트 연습에서 고른다. 다른 플랫폼의 문제는 이 로드맵에 넣지 않는다.
완료 기준정답 제출 한 번으로 완료하지 않는다. 선택 이유·핵심 상태·시간과 공간 복잡도·예외 입력을 설명하고, 풀이를 보지 않은 재구현까지 확인한다.
진행 방식아래 순서는 현재 증거에서 출발하는 첫 순환의 기본 경로다. 한 관문을 마칠 때 드러난 blocker가 있으면 그 blocker를 검증하는 가장 작은 프로그래머스 문제로 먼저 이동한다.
시작 조건AI·ML 학습보다 우선하는 자동 순환 트랙으로 운영하지 않는다. 사용자가 해당 세션에서 코딩 테스트를 하겠다고 명시했을 때만 현재 관문에서 이어간다.
시간 사용처음부터 걸린 시간은 기록하지만 기초체력 단계의 시간은 합격·실패 판정에 쓰지 않는다. 막힌 위치가 문제 해석·상태 설계·구현·검증 중 어디인지 찾고, 같은 패턴의 전이 문제부터 도움을 줄인 뒤 제한시간을 완료 기준으로 올린다.
기록 방식문제마다 독립 문서에 입력·출력, 풀이 흐름, 기억할 코드, 실제로 헷갈린 지점과 재풀이 결과를 남긴다. 체크는 대화와 실행 증거를 확인한 뒤 갱신한다.

기초체력에서 제한시간 실력으로 가는 3단계

주차나 누적 문제 수로 단계를 올리지 않는다. 같은 역량을 도움 있는 대표 문제에서 익힌 뒤 새 조건으로 옮기고, 마지막에 실제 시험 시간으로 검증한다.

1단계 · 기초체력

대표 문제를 충분히 이해한다

문제 해석, 가장 단순한 풀이, 핵심 상태, 실제 값의 변화를 먼저 확인한다. 걸린 시간은 기록하지만 아직 통과 기준으로 사용하지 않는다. 막히면 문제 전체 답 대신 현재 막힌 지점을 넘는 가장 작은 힌트만 사용한다.

완료 증거
작은 입력의 결과를 코드 전에 예측하고, 핵심 상태를 실제 값으로 추적하며, 완성한 풀이의 선택 이유와 복잡도를 설명한다.

2단계 · 전이

같은 패턴을 새 조건에 적용한다

대표 문제를 닫은 뒤 같은 핵심 패턴의 처음 보는 문제에서 도움을 줄인다. 이전 정답 코드는 보지 않고 필요하면 개념 힌트 한 번만 사용하며, 문제 해석·설계·구현·검증에 걸린 시간을 나누어 기록한다.

완료 증거
유형 이름이 없어도 같은 패턴을 선택하고 경계 입력을 스스로 만들어 제출한 뒤, 시간이 지난 후 자료 없이 다시 구현한다.

3단계 · 실전

제한시간 혼합 세트로 검증한다

첫 순환의 핵심 관문을 닫은 뒤 유형을 가린 2~3문제 혼합 세트를 실제 지원 기업과 같은 시간·도움 없는 조건으로 푼다. 실패하면 더 많은 문제를 무작정 추가하지 않고 원인을 문제 해석·알고리즘 선택·구현·디버깅으로 분류한다.

완료 증거
목표 기업의 예상 통과 문제 수를 세 번 연속 넘기고, 실패 문제를 보완한 뒤 다시 풀 수 있을 때 제한시간 실력이 안정됐다고 판단한다.

한 세션은 한 문제를 끝내는 숙제가 아니다.
문제 해석, 작은 입력 예측, 상태 설계, 구현, 예외 검증, 재풀이 중 하나의 작은 관문만 닫아도 된다. 세션 마지막에는 다음에 시작할 질문 하나를 남겨 다시 시작할 때의 선택 부담을 줄인다.

문제 제시 → 풀이·질문 → 기록 → 다음 처방

미리 정한 문제 수를 소화하는 방식이 아니라, 한 문제에서 확인된 시간·막힘·힌트 의존도·재풀이 결과를 다음 문제 선택에 사용한다.

1 · 문제 제시사용자가 코딩 테스트를 시작한다고 말하면 에이전트가 현재 완료 증거와 blocker에 맞는 프로그래머스 공식 문제 하나만 고른다. 기초체력 단계에서는 필요한 패턴을 밝힐 수 있고, 전이·실전 단계에서는 유형을 가린다.
2 · 풀이 또는 막힘 보고풀었다면 코드·제출 결과·걸린 시간·어려웠던 부분을 가져온다. 막혔다면 지금까지 확실히 아는 것, 막힌 코드나 판단, 경과 시간을 가져온다. 시간은 사용자가 실제 측정한 값만 기록한다.
3 · 증거 확인문제 해석, 알고리즘 선택, 상태 설계, 구현, 예외 검증, 복잡도 설명과 힌트 사용 단계를 확인한다. 정답 제출만으로 완료하거나 다음 단계로 올리지 않는다.
4 · 다음 처방확인된 약점에 따라 다음 알고리즘 관문, 같은 패턴의 전이 문제, 더 작은 대표 문제, 구현 보강 문제 또는 자료 없는 재풀이 중 하나만 선택한다.
확인된 결과판정다음 처방
도움 없이 풀고 선택 이유·복잡도까지 설명함대표 문제 이해 확인같은 패턴의 처음 보는 전이 문제
정답이지만 시간이 오래 걸리거나 구현을 여러 번 되돌림개념보다 숙련도 보강 필요같은 패턴의 유사 문제에서 시간 구간을 다시 측정
큰 힌트나 정답 코드를 본 뒤 완성함아직 독립 풀이 증거 없음다음 코딩 테스트 세션에 자료 없이 같은 문제 재풀이
알고리즘 선택이나 상태 정의에서 막힘개념·모델링 blocker더 작은 대표 문제 또는 작은 입력 상태 추적
알고리즘은 맞지만 문법·인덱스·자료구조 구현에서 반복해 막힘구현 blocker같은 코드 구조를 쓰는 더 쉬운 구현 보강 문제
유형이 가려진 새 조건에서도 독립적으로 해결함전이 확인다음 알고리즘 관문 또는 제한시간 혼합 세트

힌트 사다리

질문으로 막힌 위치 확인 → 핵심 상태·자료구조 → 작은 입력 한 단계 추적 → 의사코드 → 전체 풀이 순서로 올린다. 처음부터 완성 코드를 주지 않고 필요한 최소 단계에서 멈춘다.

문제별 기록

첫 시도 시간, 제출 결과, 막힌 단계, 힌트 수준, 몰랐던 개념·문법, 예외 입력, 복잡도 설명, 재풀이 시간과 결과, 다음 처방과 이유를 같은 문제 문서에 누적한다.

첫 순환 · 다음 필수 관문

각 관문은 왼쪽부터 무조건 밀어붙이는 고정 진도가 아니다. 이분 탐색과 일반 그래프 관문을 완료했으며, 다음 코딩 테스트 세션에서는 가중치 최단경로로 이동한다.

1 · 이분 탐색 · 완료입국심사 학습 기록 → · 자료 없이 코드를 다시 구현해 전체 테스트에 통과하고, 최초 가능 경계와 O(m log R) 복잡도를 설명했다.
2 · Heap(힙) · 적용 완료더 맵게 학습 기록 → · heap[0]만 최솟값을 보장한다는 성질, heappop()·heappush()의 역할과 마지막 원소 예외를 확인했다. 가중치 최단경로에서의 Priority Queue 전이는 아직 남아 있다.
3 · 일반 그래프 탐색 · 완료네트워크 학습 기록 → · 단어 변환 학습 기록 → · 연결 요소 개수에는 DFS를, 무가중치 최소 단계에는 BFS를 선택해 구현하고 제출에 통과했다.
4 · 가중치 최단 경로 · 현재배달 ↗ · BFS만으로 해결되지 않는 이유를 설명하고 거리 갱신과 우선순위 큐의 역할을 연결한다.
5 · DP 상태 설계정수 삼각형 ↗ → 등굣길 ↗ · dp[i] 또는 dp[r][c]가 무엇을 뜻하는지 먼저 한 문장으로 정의하고 점화식·초깃값·순서를 구현한다.
6 · 최소 연결섬 연결하기 ↗ · 가장 싼 간선만 고르면 생기는 문제를 확인하고, 모든 정점을 연결하면서 Cycle(순환)을 막는 기준을 설명한다.

전이 확인 · 이미 본 패턴을 새 조건에 적용

Hash(해시)

의상 ↗에서 종류별 개수를 세고, 베스트앨범 ↗에서 집계와 정렬 기준을 함께 다룬다.

Stack·Queue

프로세스 학습 기록 →에서 원래 인덱스를 함께 저장하고, Queue에서 꺼낸 횟수와 실제 실행 횟수 및 Queue 회전을 분리했다.

정렬

가장 큰 수 ↗에서 숫자 크기가 아니라 이어 붙인 문자열의 순서를 비교하는 이유를 설명한다.

완전탐색·백트래킹

소수 찾기 ↗와 피로도 ↗에서 후보 생성, 중복 제거, 가지 상태 복원을 확인한다.

구현·Simulation(시뮬레이션)

주차 요금 계산 ↗에서 문자열 Parsing(파싱), 시간 계산, 누락된 출차 처리와 정렬된 출력을 하나의 흐름으로 연결한다.

언제 수행할까

첫 순환을 방해하며 전부 선행하지 않는다. 이미 배운 패턴인데 새 문제에서 선택하지 못했거나 구현이 흔들렸을 때 해당 카드의 문제로 전이 능력을 확인한다.

문제 하나를 완료하는 6개 관문

1 · 문제 모델링
입력·출력·제약을 자기 말로 바꾸고 작은 예제의 결과를 코드 전에 예측한다.
2 · Baseline(기준 풀이)
가장 단순한 풀이를 먼저 말하고, 입력 크기에서 충분한지 연산 수로 판단한다.
3 · 선택 근거
왜 이 자료구조와 알고리즘인지, 다른 후보는 왜 불리한지 설명한다.
4 · 구현과 상태 추적
핵심 변수·Queue·Stack·방문 배열·DP Table이 한 단계마다 어떻게 바뀌는지 실제 값으로 추적한다.
5 · 검증과 복잡도
빈 경계, 최소·최대, 중복, 도달 불가 같은 입력을 만들고 시간·공간 복잡도를 설명한다.
6 · 재풀이
정답이나 이전 코드를 보지 않고 다시 구현한 뒤, 핵심 선택 이유까지 말한다.

실전 전환과 로드맵 완료 조건

혼합 세트유형을 미리 보지 않은 프로그래머스 문제들을 묶어 풀고, 문제마다 해시·탐색·정렬·그래프·DP 같은 후보를 비교한 기록을 남긴다.
시간 제한읽기, 설계, 구현, 테스트 시간을 나눠 관찰한다. 막히면 무작정 오래 붙들지 않고 실패 지점을 문제 해석·알고리즘 선택·구현·디버깅 중 하나로 분류한다.
설명핵심 invariant(반복 중 계속 참이어야 하는 조건), 자료구조, 복잡도와 예외 처리를 코드 없이 먼저 설명한다.

문제를 풀며 확인한 Python 문법

dict와 set

d.get(key, default)로 기본값을 정하고, set.add(value)는 원본을 수정하지만 반환값은 None이다.

삭제와 Queue

remove(value)는 값을, pop(index)는 위치를 삭제하고 값을 반환한다. Queue 앞 삭제는 deque.popleft()를 사용한다.

순회와 문자열

enumerate()로 위치와 값을 함께 받고, split()과 split(" ")의 연속 공백 처리 차이를 구분한다. join()으로 다시 연결한다.

문자 검사와 변경

isalpha(), isdigit(), isalnum(), upper(), lower()를 사용한다. 문자열은 immutable이라 새 문자열을 만든다.

변환과 정렬

map 또는 리스트 컴프리헨션으로 문자열을 숫자로 바꾸고, key=lambda x: (-x[1], x[0])처럼 여러 정렬 조건을 표현한다.

재귀와 nonlocal

종료 조건 뒤 다음 상태를 호출한다. 중첩 함수가 바깥 함수의 지역변수를 수정할 때는 nonlocal을 사용한다.

지금까지 연결한 알고리즘 사고

조합·완전탐색j=i+1, k=j+1로 중복 선택을 없애고 가능한 후보를 모두 검사했다.
그리디예산처럼 정확한 합이 아니라 선택 개수를 최대화할 때 작은 값부터 고르는 이유를 확인했다.
정렬·Queue여러 정렬 조건과 앞 작업을 기준으로 묶이는 배포 순서를 다뤘다.
DP피보나치에서 같은 계산을 반복하는 재귀 대신 이전 값을 보관했다.
DFS타겟 넘버를 선택 두 갈래의 이진트리로 보고 리프의 결과를 부모에서 합산했다.
BFS게임 맵 최단거리에서 FIFO Queue로 같은 거리의 칸을 먼저 탐색하고, 격자에 부모 거리 + 1을 기록했다.
Heap·Priority Queue더 맵게에서 전체 정렬과 최소 힙의 차이를 확인하고, 최솟값 두 개를 꺼내 다시 넣는 연산과 원소 부족 예외를 처리했다.
Queue 우선순위 Simulation프로세스에서 값과 원래 인덱스를 함께 저장하고, Queue 회전과 실제 실행을 분리했다.
