로드맵 운영 원칙

문제 출처대표 문제, 복습 문제, 실전 문제는 모두 프로그래머스 코딩테스트 연습에서 고른다. 다른 플랫폼의 문제는 이 로드맵에 넣지 않는다.
완료 기준정답 제출 한 번으로 완료하지 않는다. 선택 이유·핵심 상태·시간과 공간 복잡도·예외 입력을 설명하고, 풀이를 보지 않은 재구현까지 확인한다.
진행 방식아래 순서는 현재 증거에서 출발하는 첫 순환의 기본 경로다. 한 관문을 마칠 때 드러난 blocker가 있으면 그 blocker를 검증하는 가장 작은 프로그래머스 문제로 먼저 이동한다.
기록 방식문제마다 독립 문서에 입력·출력, 풀이 흐름, 기억할 코드, 실제로 헷갈린 지점과 재풀이 결과를 남긴다. 체크는 대화와 실행 증거를 확인한 뒤 갱신한다.

첫 순환 · 다음 필수 관문

각 관문은 왼쪽부터 무조건 밀어붙이는 고정 진도가 아니다. 현재는 1번부터 시작하고, 완료 증거를 확인할 때마다 다음 blocker에 맞춰 조정한다.

1 · 이분 탐색입국심사 ↗ · 답이 될 수 있는 시간 범위와 가능/불가능 경계를 정의하고, 종료 뒤 어느 값이 최소 정답인지 설명한다.
2 · Heap(힙) · 적용 완료더 맵게 학습 기록 → · heap[0]만 최솟값을 보장한다는 성질, heappop()·heappush()의 역할과 마지막 원소 예외를 확인했다. 가중치 최단경로에서의 Priority Queue 전이는 아직 남아 있다.
3 · 일반 그래프 탐색네트워크 ↗ → 단어 변환 ↗ · 격자가 아닌 연결 관계를 만들고, 연결 요소 개수와 최소 단계라는 서로 다른 목표에 DFS/BFS를 선택한다.
4 · 가중치 최단 경로배달 ↗ · BFS만으로 해결되지 않는 이유를 설명하고 거리 갱신과 우선순위 큐의 역할을 연결한다.
5 · DP 상태 설계정수 삼각형 ↗ → 등굣길 ↗ · dp[i] 또는 dp[r][c]가 무엇을 뜻하는지 먼저 한 문장으로 정의하고 점화식·초깃값·순서를 구현한다.
6 · 최소 연결섬 연결하기 ↗ · 가장 싼 간선만 고르면 생기는 문제를 확인하고, 모든 정점을 연결하면서 Cycle(순환)을 막는 기준을 설명한다.

전이 확인 · 이미 본 패턴을 새 조건에 적용

Hash(해시)

의상 ↗에서 종류별 개수를 세고, 베스트앨범 ↗에서 집계와 정렬 기준을 함께 다룬다.

Stack·Queue

프로세스 학습 기록 →에서 원래 인덱스를 함께 저장하고, Queue에서 꺼낸 횟수와 실제 실행 횟수 및 Queue 회전을 분리했다.

정렬

가장 큰 수 ↗에서 숫자 크기가 아니라 이어 붙인 문자열의 순서를 비교하는 이유를 설명한다.

완전탐색·백트래킹

소수 찾기 ↗와 피로도 ↗에서 후보 생성, 중복 제거, 가지 상태 복원을 확인한다.

구현·Simulation(시뮬레이션)

주차 요금 계산 ↗에서 문자열 Parsing(파싱), 시간 계산, 누락된 출차 처리와 정렬된 출력을 하나의 흐름으로 연결한다.

언제 수행할까

첫 순환을 방해하며 전부 선행하지 않는다. 이미 배운 패턴인데 새 문제에서 선택하지 못했거나 구현이 흔들렸을 때 해당 카드의 문제로 전이 능력을 확인한다.

문제 하나를 완료하는 6개 관문

1 · 문제 모델링
입력·출력·제약을 자기 말로 바꾸고 작은 예제의 결과를 코드 전에 예측한다.
2 · Baseline(기준 풀이)
가장 단순한 풀이를 먼저 말하고, 입력 크기에서 충분한지 연산 수로 판단한다.
3 · 선택 근거
왜 이 자료구조와 알고리즘인지, 다른 후보는 왜 불리한지 설명한다.
4 · 구현과 상태 추적
핵심 변수·Queue·Stack·방문 배열·DP Table이 한 단계마다 어떻게 바뀌는지 실제 값으로 추적한다.
5 · 검증과 복잡도
빈 경계, 최소·최대, 중복, 도달 불가 같은 입력을 만들고 시간·공간 복잡도를 설명한다.
6 · 재풀이
정답이나 이전 코드를 보지 않고 다시 구현한 뒤, 핵심 선택 이유까지 말한다.

실전 전환과 로드맵 완료 조건

혼합 세트유형을 미리 보지 않은 프로그래머스 문제들을 묶어 풀고, 문제마다 해시·탐색·정렬·그래프·DP 같은 후보를 비교한 기록을 남긴다.
시간 제한읽기, 설계, 구현, 테스트 시간을 나눠 관찰한다. 막히면 무작정 오래 붙들지 않고 실패 지점을 문제 해석·알고리즘 선택·구현·디버깅 중 하나로 분류한다.
설명핵심 invariant(반복 중 계속 참이어야 하는 조건), 자료구조, 복잡도와 예외 처리를 코드 없이 먼저 설명한다.
재현풀이를 외운 대표 문제만이 아니라 처음 보는 프로그래머스 문제에서도 같은 판단 절차를 반복한다.
전체 완료
모든 알고리즘 이름을 암기했을 때가 아니다. 처음 보는 프로그래머스 문제에서 제약을 근거로 후보를 좁히고, 실행 가능한 풀이를 구현·테스트하며, 실패 원인과 복잡도를 설명하고 다시 풀 수 있을 때 완료한다.

문제를 풀며 확인한 Python 문법

dict와 set

d.get(key, default)로 기본값을 정하고, set.add(value)는 원본을 수정하지만 반환값은 None이다.

삭제와 Queue

remove(value)는 값을, pop(index)는 위치를 삭제하고 값을 반환한다. Queue 앞 삭제는 deque.popleft()를 사용한다.

순회와 문자열

enumerate()로 위치와 값을 함께 받고, split()과 split(" ")의 연속 공백 처리 차이를 구분한다. join()으로 다시 연결한다.

문자 검사와 변경

isalpha(), isdigit(), isalnum(), upper(), lower()를 사용한다. 문자열은 immutable이라 새 문자열을 만든다.

변환과 정렬

map 또는 리스트 컴프리헨션으로 문자열을 숫자로 바꾸고, key=lambda x: (-x[1], x[0])처럼 여러 정렬 조건을 표현한다.

재귀와 nonlocal

종료 조건 뒤 다음 상태를 호출한다. 중첩 함수가 바깥 함수의 지역변수를 수정할 때는 nonlocal을 사용한다.

지금까지 연결한 알고리즘 사고

조합·완전탐색j=i+1, k=j+1로 중복 선택을 없애고 가능한 후보를 모두 검사했다.
그리디예산처럼 정확한 합이 아니라 선택 개수를 최대화할 때 작은 값부터 고르는 이유를 확인했다.
정렬·Queue여러 정렬 조건과 앞 작업을 기준으로 묶이는 배포 순서를 다뤘다.
DP피보나치에서 같은 계산을 반복하는 재귀 대신 이전 값을 보관했다.
DFS타겟 넘버를 선택 두 갈래의 이진트리로 보고 리프의 결과를 부모에서 합산했다.
BFS게임 맵 최단거리에서 FIFO Queue로 같은 거리의 칸을 먼저 탐색하고, 격자에 부모 거리 + 1을 기록했다.
Heap·Priority Queue더 맵게에서 전체 정렬과 최소 힙의 차이를 확인하고, 최솟값 두 개를 꺼내 다시 넣는 연산과 원소 부족 예외를 처리했다.
Queue 우선순위 Simulation프로세스에서 값과 원래 인덱스를 함께 저장하고, Queue 회전과 실제 실행을 분리했다.
