로드맵 운영 원칙

문제 출처대표 문제, 복습 문제, 실전 문제는 모두 프로그래머스 코딩테스트 연습에서 고른다. 다른 플랫폼의 문제는 이 로드맵에 넣지 않는다.
완료 기준정답 제출 한 번으로 완료하지 않는다. 선택 이유·핵심 상태·시간과 공간 복잡도·예외 입력을 설명하고, 풀이를 보지 않은 재구현까지 확인한다.
진행 방식아직 배우지 않은 알고리즘은 혼자 발명하게 두지 않는다. 자주 쓰는 핵심 패턴을 대표 문제와 안내 풀이로 빠르게 한 번 경험하고, 새 패턴 학습과 이전 패턴의 자료 없는 재구현을 병행한다. 핵심 묶음을 한 바퀴 돈 뒤 유형을 가린 혼합 문제로 전환한다.
시작 조건AI·ML 학습보다 우선하는 자동 순환 트랙으로 운영하지 않는다. 사용자가 해당 세션에서 코딩 테스트를 하겠다고 명시했을 때만 현재 관문에서 이어간다.
시간 사용첫 노출에서는 짧게 생각해 본 뒤 알고리즘 자체를 몰라 막혔다면 구조를 바로 학습한다. 오래 버티며 고전 알고리즘을 재발명하는 시간을 요구하지 않는다. 자료 없는 재구현과 혼합 문제 단계부터 독립 풀이 시간과 막힌 위치를 본격적으로 측정한다.
기록 방식문제마다 독립 문서에 입력·출력, 풀이 흐름, 기억할 코드, 실제로 헷갈린 지점과 재풀이 결과를 남긴다. 체크는 대화와 실행 증거를 확인한 뒤 갱신한다.

기업 코딩 테스트 조사에서 가져온 기준

특정 기업의 비공개 문제를 추측하지 않고, 프로그래머스 공식 분류와 공개된 기업 시험 사례에서 반복된 범위만 학습 순서와 실전 조건에 반영한다.

공식 빈출프로그래머스 알고리즘 고득점 Kit ↗의 해시·정렬·완전탐색·DFS/BFS를 고빈도 기반으로, Stack·Queue·Heap을 반복 적용 기반으로 둔다.
문제은행의 범위프로그래머스 기업용 안내 ↗는 1,000개 이상의 보유 문제와 기업의 직접 문제 생성을 안내한다. 공개 문제 원문을 외우는 대신 제약에서 후보 패턴을 좁히고 새 조건에 맞게 변형하는 능력을 훈련한다.
변별 패턴DP·이분 탐색·그래프는 공식 출제 빈도가 상대적으로 낮더라도 평균 점수가 낮은 유형이므로 제외하지 않는다. Kit에 독립 분류가 없는 다익스트라·누적합·투 포인터·슬라이딩 윈도우·Union-Find·MST·위상 정렬도 대표 구조를 한 번씩 장착한다.
공개 사례 기준확인 가능한 기업 시험 사례 23건에서는 알고리즘 문항 수의 중앙값이 3문제였고, 시간이 확인된 사례에서는 120분 형식이 가장 많이 반복됐다. 이를 합격선이 아니라 기본 모의 세트의 크기로 사용한다.
지원 공고 확인같은 기업도 직무와 시기에 따라 코딩 테스트·과제 테스트·SQL·CS 포함 여부가 달라진다. 지원 직전에는 최신 공식 공고를 다시 확인하고, 공고의 실제 형식만 별도 대비에 반영한다.
조사 근거와 한계
기업 코딩 테스트 출제 조사 →에서 공식 자료와 개인 후기를 구분하고, 표본 수·시험 형식·유형 집계·확인할 수 없는 정보를 함께 기록한다.

핵심 패턴 습득에서 혼합 문제 적용으로 가는 3단계

처음 보는 고전 알고리즘을 혼자 발명하는 능력을 요구하지 않는다. 대표 문제로 도구를 먼저 장착하고, 자료 없이 꺼내는 연습을 거쳐, 마지막에 유형을 가린 문제에서 선택·변형하는 힘을 검증한다.

1단계 · 핵심 패턴 습득

대표 문제를 안내받아 빠르게 한 번 구현한다

처음 접하는 패턴은 알고리즘 이름과 필요한 이유를 먼저 배우고, 실제 숫자로 상태 변화를 따라가며 대표 문제를 함께 구현한다. 혼자 오래 막혀 있는 시간을 학습 성과로 보지 않는다.

첫 학습 증거
어떤 상황에서 쓰는지, 무엇을 저장하는지, 어떤 조건으로 상태를 갱신하는지를 설명하고 대표 코드를 따라 구현한다.

2단계 · 자료 없는 재구현

이전 정답 없이 같은 구조를 다시 꺼낸다

새 패턴을 계속 배우는 동안 이전 학습일의 대표 문제를 짧게 다시 푼다. 전체 코드를 보지 않고 뼈대를 복원하며, 막히면 잊은 한 부분만 확인한 뒤 다시 닫는다.

유지 증거
대표 문제를 자료 없이 구현·제출하고, 핵심 상태·갱신 조건·복잡도를 자기 말로 설명한다.

3단계 · 혼합 문제 적용

유형을 밝히지 않은 문제에서 패턴을 선택한다

핵심 패턴 묶음의 첫 학습과 재구현을 마친 뒤 기본 3문제 / 120분 혼합 세트로 전환한다. 문제의 제약과 목표를 근거로 후보 패턴을 비교하고, 기존 구조를 새 조건에 맞게 변형한다.

실전 증거
3문제 중 2문제 이상을 완전히 통과하는 결과를 세 세트 연속 만들고, 실패 원인을 보완한 뒤 남은 문제도 자료 없이 다시 푼다. 이 수치는 기업의 공식 합격선이 아니라 내부 훈련 기준이다.

1단계와 2단계는 병행합니다.
세션 앞부분에서 이전 패턴 하나를 자료 없이 복원하고, 나머지 시간에는 새로운 핵심 패턴을 빠르게 익힙니다. 모든 패턴을 한 번 본 뒤에야 처음 복습하는 방식으로 기억을 방치하지 않습니다.

문제 제시 → 풀이·질문 → 기록 → 다음 처방

미리 정한 문제 수를 소화하는 방식이 아니라, 한 문제에서 확인된 시간·막힘·힌트 의존도·재풀이 결과를 다음 문제 선택에 사용한다.

1 · 문제 제시아직 접하지 않은 패턴이면 이름과 용도를 밝히고 대표 문제를 고른다. 이미 배운 패턴의 재구현이나 혼합 적용 단계에서는 유형을 가리고 스스로 선택하게 한다.
2 · 풀이 또는 막힘 보고풀었다면 코드·제출 결과·걸린 시간·어려웠던 부분을 가져온다. 막혔다면 지금까지 확실히 아는 것, 막힌 코드나 판단, 경과 시간을 가져온다. 시간은 사용자가 실제 측정한 값만 기록한다.
3 · 증거 확인문제 해석, 알고리즘 선택, 상태 설계, 구현, 예외 검증, 복잡도 설명과 힌트 사용 단계를 확인한다. 정답 제출만으로 완료하거나 다음 단계로 올리지 않는다.
4 · 다음 처방첫 학습이라면 다음 핵심 패턴으로 이동하면서 직전 패턴을 복습 목록에 넣는다. 재구현이 흔들리면 잊은 부분만 보강하고, 핵심 묶음이 갖춰진 뒤에는 유형 비공개 혼합 문제로 이동한다.
확인된 결과판정다음 처방
도움 없이 풀고 선택 이유·복잡도까지 설명함대표 문제 이해 확인같은 패턴의 처음 보는 전이 문제
정답이지만 시간이 오래 걸리거나 구현을 여러 번 되돌림개념보다 숙련도 보강 필요같은 패턴의 유사 문제에서 시간 구간을 다시 측정
큰 힌트나 정답 코드를 본 뒤 완성함아직 독립 풀이 증거 없음다음 코딩 테스트 세션에 자료 없이 같은 문제 재풀이
처음 보는 알고리즘이라 선택이나 상태 정의가 불가능함미학습 패턴알고리즘 이름·사용 신호·핵심 상태를 설명하고 대표 문제를 안내 풀이
알고리즘은 맞지만 문법·인덱스·자료구조 구현에서 반복해 막힘구현 blocker같은 코드 구조를 쓰는 더 쉬운 구현 보강 문제
유형이 가려진 새 조건에서도 독립적으로 해결함전이 확인다음 알고리즘 관문 또는 제한시간 혼합 세트

힌트 사다리

질문으로 막힌 위치 확인 → 핵심 상태·자료구조 → 작은 입력 한 단계 추적 → 의사코드 → 전체 풀이 순서로 올린다. 처음부터 완성 코드를 주지 않고 필요한 최소 단계에서 멈춘다.

문제별 기록

첫 시도 시간, 제출 결과, 막힌 단계, 힌트 수준, 몰랐던 개념·문법, 예외 입력, 복잡도 설명, 재풀이 시간과 결과, 다음 처방과 이유를 같은 문제 문서에 누적한다.

오답 기록 네 항목

처음 놓친 신호 → 잘못 고른 접근 → 정답의 핵심 상태·invariant → 다음 재풀이에서 먼저 만들 경계 사례만 구체적으로 남긴다. 정답 코드를 그대로 복사한 요약은 재풀이 근거로 사용하지 않는다.

핵심 패턴 첫 순환

이미 익힌 패턴은 증거를 보존하고, 아직 모르는 고전 알고리즘은 대표 문제로 빠르게 구조를 배운다. 다익스트라 첫 학습을 닫았고 현재는 DP 상태 설계부터 이어간다. 아래 남은 패턴을 안내에 따라 구현하고 다음 학습일에 자료 없이 다시 구성한 뒤 유형 비공개 혼합 문제로 전환한다.

1 · 이분 탐색 · 완료입국심사 학습 기록 → · 자료 없이 코드를 다시 구현해 전체 테스트에 통과하고, 최초 가능 경계와 O(m log R) 복잡도를 설명했다.
2 · Heap(힙) · 적용 완료더 맵게 학습 기록 → · heap[0]만 최솟값을 보장한다는 성질, heappop()·heappush()의 역할과 마지막 원소 예외를 확인했다. 배달에서는 작은 누적 비용을 먼저 꺼내는 다익스트라 탐색 순서로 확장했다.
3 · 일반 그래프 탐색 · 완료네트워크 학습 기록 → · 단어 변환 학습 기록 → · 연결 요소 개수에는 DFS를, 무가중치 최소 단계에는 BFS를 선택해 구현하고 제출에 통과했다.
4 · 가중치 최단 경로 · 완료배달·다익스트라 첫 학습 기록 → · 자료 없이 전체 구조를 다시 만들고 Tuple 순서·누적 비용은 힌트로 교정했다. 표준 코드의 정확성 100점·32개 테스트 통과와 BFS 비교·갱신 이유·복잡도 설명을 확인했으며 9월 3일 무자료 복습을 유지한다.
5 · DP 상태 설계 · 현재땅따먹기 ↗ → 정수 삼각형 ↗ → 등굣길 ↗ · Level 2의 행 상태부터 시작해 dp[i] 또는 dp[r][c]가 무엇을 뜻하는지 먼저 한 문장으로 정의하고 점화식·초깃값·순서를 구현한다.
6 · 구간 탐색연속된 부분 수열의 합 ↗ → 할인 행사 ↗ → 광고 삽입 ↗ · 투 포인터·고정 Window·누적합의 경계 이동과 계산 재사용을 차례로 구현한다.
7 · 백트래킹피로도 ↗ · 선택 → 재귀 → 상태 복원과 가지치기의 역할을 실제 호출 흐름으로 추적한다.
8 · Union-Find·MST섬 연결하기 ↗ · 같은 집합 판정으로 Cycle을 막고 모든 정점을 최소 비용으로 연결하는 기준을 구현한다.
9 · 위상 정렬작은 자체 예제에서 진입 차수 0인 정점을 Queue에 넣고 연결을 제거하며 실행 순서를 만든다. 이후 스킬트리 ↗로 선행관계를 해석하되, 이 문제를 전형적인 위상 정렬 구현 문제로 잘못 분류하지 않는다.

핵심 패턴 묶음과 복습 방식

첫 학습에서는 패턴의 존재와 기본 구조를 빠르게 장착한다. 다음 학습일부터는 새 패턴을 배우기 전에 직전 패턴 하나를 자료 없이 복원해, 첫 순환과 기억 강화를 함께 진행한다.

Hash(해시)

전화번호 목록 ↗에서 존재·접두 관계를 확인하고, 의상 ↗에서 종류별 개수를 세며, 베스트앨범 ↗에서 집계와 정렬 기준을 함께 다룬다.

Stack·Queue

프로세스 학습 기록 →에서 원래 인덱스를 함께 저장하고 Queue 회전과 실제 실행을 분리했다. 주식가격 ↗으로 이전 후보를 언제 제거하는지 전이 확인한다.

정렬

가장 큰 수 ↗에서 숫자 크기가 아니라 이어 붙인 문자열의 순서를 비교하는 이유를 설명한다.

Greedy(그리디)

구명보트 ↗에서 현재 선택이 이후 선택을 망치지 않는 근거를 먼저 확인하고, 정렬 뒤 선택·구간 선택처럼 반복해서 등장하는 대표 형태에 적용한다.

완전탐색·백트래킹

소수 찾기 ↗와 피로도 ↗에서 후보 생성, 중복 제거, 가지 상태 복원을 확인한다.

DFS·BFS

연결 요소·모든 경로 탐색·무가중치 최소 단계라는 목표 차이로 DFS와 BFS를 선택하고, 재귀 Stack과 FIFO Queue의 상태 변화를 구분한다.

이분 탐색·Heap

단조롭게 변하는 정답 후보의 최초 가능 경계를 이분 탐색하고, 반복해서 최솟값이 필요할 때 전체 재정렬 대신 최소 Heap을 사용한다.

구현·Simulation(시뮬레이션)

주차 요금 계산 ↗에서 문자열 Parsing(파싱), 시간 계산, 누락된 출차 처리와 정렬된 출력을 하나의 흐름으로 연결한다.

가중치 최단경로·DP

배달에서 최소 누적 비용과 Heap 기반 거리 갱신을, 땅따먹기·정수 삼각형·등굣길에서 상태 정의·점화식·초깃값·계산 순서를 익힌다.

누적합·투 포인터·슬라이딩 윈도우

연속된 부분 수열의 합 ↗·할인 행사 ↗·광고 삽입 ↗으로 경계 이동과 계산 재사용을 구분한다.

Union-Find·MST·위상 정렬

섬 연결하기 ↗에서 집합 대표값과 Cycle 판정을 적용하고, 위상 정렬은 작은 그래프에서 진입 차수와 Queue를 먼저 추적한다.

세션 운영

세션 앞부분에는 이전 패턴 하나를 자료 없이 재구현하고, 나머지에는 새로운 패턴을 안내 풀이로 빠르게 익힌다. 이미 배운 구현·문자열·Hash·정렬·Stack·Queue는 유형을 숨긴 Level 2 전이 문제로 유지하고, 핵심 묶음을 모두 경험한 뒤에는 유형을 밝히지 않은 문제만 사용한다.

첫 순환의 범위

프로그래머스 공식 Kit 10개 유형에 다익스트라·누적합·투 포인터·슬라이딩 윈도우·Union-Find·MST·위상 정렬을 보강한다. Segment Tree·Trie·SCC·Network Flow 같은 고급 패턴은 지원 공고나 실제 문제에서 필요가 확인될 때 확장하며, 첫 순환을 끝없이 늘리지 않는다.

백엔드 직무 SQL 병행 트랙

기업 공개 사례에서 알고리즘과 SQL을 함께 출제한 형식이 반복됐으므로 SQL을 선택 과목으로 미루지 않는다. 다만 현재 알고리즘 관문의 완료 수에는 합치지 않고 별도 실전 역량으로 병행한다.

공식 문제 풀프로그래머스 SQL 고득점 Kit ↗만 사용한다.
첫 순환SELECT·WHERE·ORDER BY → COUNT·SUM·MAX·MIN → GROUP BY·HAVING → JOIN → NULL·String·Date → 서브쿼리 순서로 결과 집합이 만들어지는 과정을 설명하고 쿼리를 작성한다.
완료 증거테이블 관계와 중간 결과를 먼저 설명하고, 유형을 가린 SQL 문제에서 집계 기준·JOIN 조건·NULL 처리·정렬 기준을 자료 없이 작성해 제출한다.
직무별 조정지원 공고에 SQL·데이터 처리·과제 테스트가 명시되면 비중을 높인다. 알고리즘 코딩 테스트만 명시된 경우에도 주기적인 복습 문제로 유지한다.

혼합 문제 전환과 로드맵 완료 조건

핵심 패턴의 첫 학습만 끝났다고 바로 실전 준비가 완료되는 것은 아니다. 각 패턴에서 최소 한 번의 자료 없는 재구현 증거를 확보한 뒤 유형을 가린 혼합 세트로 전환한다.

혼합 세트기본 세트는 유형을 미리 보지 않은 프로그래머스 3문제로 구성한다. 구현·문자열·배열 Level 1~2 한 문제, 자료구조·탐색 Level 2 한 문제, DP·그래프·이분 탐색 같은 변별 Level 3 한 문제를 섞되 실제 문제의 유형은 풀이 전 공개하지 않는다.
시간 제한기본 제한은 120분이다. 읽기, 설계, 구현, 테스트 시간을 나눠 관찰하고, 막히면 무작정 오래 붙들지 않고 실패 지점을 문제 해석·알고리즘 선택·구현·디버깅 중 하나로 분류한다.
내부 통과 기준3문제 중 2문제 이상을 완전히 통과하는 결과를 세 세트 연속 만들고, 각 세트의 미해결 문제도 보완 뒤 자료 없이 다시 푼다. 공개되지 않은 기업 합격선과 이 훈련 기준을 같은 값으로 취급하지 않는다.
공식 공개 세트핵심 패턴을 장착한 뒤에는 카카오 공식 공개 문제 ↗와 Dev-Matching 공개 문제를 유형 비공개 혼합 후보 풀로 사용한다. 공개 세트 전체를 필수 문제 수로 바꾸지 않고, 현재 약점을 드러내는 세트를 고른다.
설명핵심 invariant(반복 중 계속 참이어야 하는 조건), 자료구조, 복잡도와 예외 처리를 코드 없이 먼저 설명한다.
재현풀이를 외운 대표 문제만이 아니라 처음 보는 프로그래머스 문제에서도 같은 판단 절차를 반복한다.
전체 완료
모든 알고리즘 이름을 암기했을 때가 아니다. 처음 보는 프로그래머스 문제에서 제약을 근거로 후보를 좁히고, 실행 가능한 풀이를 구현·테스트하며, 실패 원인과 복잡도를 설명하고 다시 풀 수 있을 때 완료한다.

문제를 풀며 확인한 Python 문법

dict와 set

d.get(key, default)로 기본값을 정하고, set.add(value)는 원본을 수정하지만 반환값은 None이다.

삭제와 Queue

remove(value)는 값을, pop(index)는 위치를 삭제하고 값을 반환한다. Queue 앞 삭제는 deque.popleft()를 사용한다.

순회와 문자열

enumerate()로 위치와 값을 함께 받고, split()과 split(" ")의 연속 공백 처리 차이를 구분한다. join()으로 다시 연결한다.

문자 검사와 변경

isalpha(), isdigit(), isalnum(), upper(), lower()를 사용한다. 문자열은 immutable이라 새 문자열을 만든다.

변환과 정렬

map 또는 리스트 컴프리헨션으로 문자열을 숫자로 바꾸고, key=lambda x: (-x[1], x[0])처럼 여러 정렬 조건을 표현한다.

재귀와 nonlocal

종료 조건 뒤 다음 상태를 호출한다. 중첩 함수가 바깥 함수의 지역변수를 수정할 때는 nonlocal을 사용한다.

지금까지 연결한 알고리즘 사고

조합·완전탐색j=i+1, k=j+1로 중복 선택을 없애고 가능한 후보를 모두 검사했다.
그리디예산처럼 정확한 합이 아니라 선택 개수를 최대화할 때 작은 값부터 고르는 이유를 확인했다.
정렬·Queue여러 정렬 조건과 앞 작업을 기준으로 묶이는 배포 순서를 다뤘다.
DP피보나치에서 같은 계산을 반복하는 재귀 대신 이전 값을 보관했다.
DFS타겟 넘버를 선택 두 갈래의 이진트리로 보고 리프의 결과를 부모에서 합산했다.
BFS게임 맵 최단거리에서 FIFO Queue로 같은 거리의 칸을 먼저 탐색하고, 격자에 부모 거리 + 1을 기록했다.
Heap·Priority Queue더 맵게에서 최솟값 두 개를 다뤘고, 배달에서는 가장 작은 누적 비용의 마을을 먼저 꺼내는 다익스트라의 탐색 순서로 확장했다. 힌트 재구현·100점 제출 증거·복잡도 설명을 확인했고 9월 3일 무자료 복습을 남겼다.
Queue 우선순위 Simulation프로세스에서 값과 원래 인덱스를 함께 저장하고, Queue 회전과 실제 실행을 분리했다.
