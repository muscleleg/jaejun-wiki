단어 변환

단어를 그래프의 상태로 보고, 한 글자만 다른 후보를 다음 상태로 연결해 BFS의 깊이로 최소 변환 횟수를 구했다.

제출 통과BFSqueuevisitedshortest path
프로그래머스 문제 열기 ↗
이 문제 복습상태 설계한 글자 차이BFS 흐름방문 처리검증 증거← 전체 문제

Queue에는 현재 단어와 변환 횟수를 함께 넣는다

현재 단어만 저장하면 목표 단어에 도착했을 때 몇 번 변환했는지 알 수 없다. 따라서 BFS 상태를 (현재 단어, 변환 횟수)로 묶어 Queue에 넣고, 다음 단어를 넣을 때 횟수를 하나 늘린다.

(begin, 0)
→ (다음 단어, 1)
→ (그다음 단어, 2)

글자 차이가 정확히 하나일 때만 이동할 수 있다

현재 단어와 후보 단어의 같은 위치를 비교해 서로 다른 글자 수를 센다. 차이가 정확히 하나인 후보만 그래프에서 직접 연결된 다음 상태다. 차이가 0이면 같은 단어이고, 2 이상이면 한 번에 변환할 수 없다.

BFS의 첫 도착이 최소 변환 횟수다

Queue는 먼저 들어온 상태부터 꺼내므로 변환 횟수가 작은 상태들을 먼저 처리한다. Queue에서 상태를 꺼낸 직후 현재 단어가 목표 단어인지 확인하면, 처음 목표에 도착한 count가 최소 변환 횟수다.

queue.popleft()
→ 목표 단어인지 확인
→ 한 글자 차이인 미방문 후보 탐색
→ (후보, count + 1) 추가

방문 집합은 Queue에 넣는 순간 갱신한다

visited = {begin}은 Key와 Value를 가진 dict가 아니라 방문한 단어 값만 저장하는 set이다. 후보를 Queue에 넣는 순간 방문 처리하면 다른 경로가 같은 단어를 다시 Queue에 넣는 중복과 순환을 막을 수 있다. 이미 방문한 후보는 글자 비교 전에 건너뛰어 불필요한 비교도 줄인다.

확인한 완료 증거

  • Queue의 상태를 (현재 단어, 변환 횟수)로 설명했다.
  • 한 글자 차이 조건이 그래프의 간선 역할을 한다고 연결했다.
  • BFS가 작은 변환 횟수부터 처리하므로 첫 도착이 최소 단계임을 설명했다.
  • set 방문 집합과 Queue 삽입 시점 방문 처리의 이유를 정리했다.
  • 직접 구현한 뒤 프로그래머스 전체 테스트에 통과했다.
