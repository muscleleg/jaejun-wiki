배달 · 다익스트라 첫 학습

1번 마을에서 각 마을까지의 최소 누적 비용을 갱신하고, 비용이 K 이하인 마을 수를 센다. 구조는 이해했지만 전체 코드를 안내받았으므로 아직 완료 문제로 세지 않는다.

구하려는 것은 방문 횟수가 아니라 최소 누적 비용이다

출발 마을은 항상 1번이다. 모든 마을까지 가는 최소 비용을 구한 뒤 그 비용이 K 이하인 마을의 개수를 반환한다. 도로마다 비용이 다르므로 먼저 들어간 경로가 가장 싼 경로라는 보장이 없고, FIFO Queue로 단계 수를 세는 일반 BFS만으로는 부족하다.

1 → 3 : 비용 10
1 → 2 → 3 : 비용 1 + 1 = 2

한 번 이동한 경로보다 두 번 이동한 경로가 더 싸다.

distance에는 출발점부터 현재까지 알려진 최소 비용을 적는다

마을 번호와 배열 인덱스를 맞추기 위해 길이를 N + 1로 만들고 0번 칸은 사용하지 않는다. 출발점 1까지의 비용은 자기 자신이므로 0이고, 아직 발견하지 못한 나머지 마을은 무한대로 시작한다. 무한대는 갈 수 없다는 최종 판정이 아니라 아직 알려진 경로가 없다는 뜻이다.

distance = [float("inf")] * (N + 1)
distance[1] = 0

distance에는 비용만 남고 실제 경로는 남지 않는다. 경로 자체가 필요하다면 별도의 이전 마을 배열을 함께 기록해야 하지만, 이 문제는 도달 가능한 마을 수만 필요하므로 비용 배열이면 충분하다.

도로 목록을 양방향 인접 리스트로 바꾼다

[start, end, cost]는 입력의 한 도로일 뿐, 첫 원소가 전체 탐색 시작점이라는 뜻은 아니다. 도로를 양쪽 마을에서 모두 사용할 수 있으므로 두 방향을 모두 저장한다.

graph = [[] for _ in range(N + 1)]

for start, end, cost in road:
    graph[start].append((end, cost))
    graph[end].append((start, cost))

[[]] * (N + 1)을 사용하면 독립된 빈 배열 여러 개가 아니라 같은 내부 배열 하나를 여러 칸이 공유한다. 한 칸에 추가한 도로가 모든 칸에 나타나므로 반드시 컴프리헨션으로 각각 새 배열을 만든다.

Heap에는 누적 비용과 마을을 함께 넣는다

Python의 Heap은 별도 Container를 생성하는 방식이 아니라 일반 list를 만들고 heapq 함수로 넣고 뺀다. Tuple을 넣으면 첫 값인 누적 비용부터 비교하므로 가장 싼 후보가 먼저 나온다.

import heapq

heap = []
heapq.heappush(heap, (0, 1))

current_cost, current_village = heapq.heappop(heap)

deque.popleft()는 먼저 들어온 값을 꺼내는 FIFO Queue이고, heapq.heappop()은 현재 가장 작은 값을 꺼낸다. 다익스트라는 탐색 순서가 아니라 지금까지 발견한 누적 비용을 기준으로 다음 마을을 고른다.

더 싼 경로를 찾았을 때만 거리와 Heap을 갱신한다

현재 마을까지 온 비용과 다음 도로의 비용을 더해 새 후보 비용을 만든다. 이 값이 저장된 거리보다 작을 때만 최단거리 후보가 개선된 것이다.

new_cost = current_cost + road_cost

if new_cost < distance[next_village]:
    distance[next_village] = new_cost
    heapq.heappush(heap, (new_cost, next_village))

더 비싼 도착은 최소 비용을 구하는 데 도움이 되지 않으므로 그 위치에서 다시 이웃을 조사할 필요가 없다. 반대로 처음 발견한 마을의 기존 값은 무한대이므로 유한한 경로가 반드시 갱신되고 Heap에 들어간다. 이 때문에 1 → 4 → 5처럼 하나뿐인 경로가 중간에서 잘리는 일도 없다.

Heap에 남은 오래된 후보는 건너뛴다

어떤 마을을 비용 10으로 먼저 넣은 뒤 더 좋은 비용 3을 발견하면 Heap에는 두 후보가 모두 남을 수 있다. 비용 10 후보를 나중에 꺼냈을 때 현재 최소 거리 3보다 크면 이미 낡은 정보다.

if current_cost > distance[current_village]:
    continue

이 조건이 없어도 아래의 new_cost < distance[next_village]가 잘못된 거리 갱신을 막으므로 이 문제에서 정답이 달라지지는 않는다. 다만 낡은 후보에서 이웃을 다시 훑는 불필요한 작업을 줄이는 최적화다. 순환 역시 출발점으로 돌아온 비용이 distance[1] = 0보다 클 수밖에 없어 갱신 조건에서 막힌다.

마지막 결과와 제너레이터 문법

0번 더미 칸을 제외하고 비용이 K 이하인지 검사한다. Python에서 True는 합산할 때 1, False는 0으로 취급되므로 조건식의 합이 마을 수가 된다.

return sum(cost <= K for cost in distance[1:])

[cost <= K for ...]은 결과 전체를 메모리에 만드는 리스트 컴프리헨션이고, (cost <= K for ...)은 값을 하나씩 만드는 제너레이터 표현식이다. 함수의 유일한 인수로 바로 전달할 때는 위 코드처럼 제너레이터의 소괄호를 생략할 수 있다. 변수에 저장할 때는 values = (cost <= K for ...)처럼 소괄호가 필요하며, 일반 리스트를 만들려면 대괄호가 필요하다.

현재 판정과 다음 복습 기준

오늘은 문제의 목적과 각 코드 조각의 역할을 이해했지만 전체 구조를 처음부터 혼자 떠올린 것이 아니고 완성 코드도 안내받았다. 따라서 제출 통과 문제나 완료 관문으로 기록하지 않는다.

  • 정리와 정답 코드를 보지 않고 distance 초기화부터 결과 반환까지 다시 구현한다.
  • 일반 BFS가 실패하는 가중치 반례를 자기 말로 설명한다.
  • 더 싼 경로일 때만 갱신·Heap 삽입하는 이유와 낡은 후보 제거의 역할을 설명한다.
  • 프로그래머스 전체 테스트에 통과하고 시간 복잡도를 설명한다.
