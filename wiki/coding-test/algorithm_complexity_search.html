알고리즘 복잡도와 순차·이분 탐색

“빠르다”를 느낌으로 말하지 않고, 입력 크기가 커질 때 연산 횟수가 어떻게 증가하는지와 탐색 구간이 왜 줄어드는지를 설명합니다.

점근 표기연산 세기공간순차 탐색이분 탐색불변식경계선택검증결론

1. Big-O는 충분히 큰 입력에서의 증가율 상한이다

함수 T(n)이 O(g(n))이라는 것은 어떤 양의 상수 c와 n₀가 있어 모든 n ≥ n₀에서 T(n) ≤ c·g(n)임을 뜻합니다. 낮은 차수와 상수 계수를 버리는 이유는 “항상 공짜”라서가 아니라 입력이 커질 때 지배하는 증가율을 비교하기 위해서입니다.

표기뜻읽는 질문
O(g(n))점근적 상한이보다 빠르게 커지지 않는가?
Ω(g(n))점근적 하한적어도 이 정도로 커지는가?
Θ(g(n))상·하한이 같은 tight bound증가율을 양쪽에서 정확히 묶는가?

Big-O를 곧바로 “최악의 경우”라는 뜻으로 정의하면 안 됩니다. 최악·평균·최선은 어떤 입력 집합의 비용을 말하는지이고, O·Ω·Θ는 그 비용 함수의 증가율을 표현하는 표기입니다.

2. 복잡도는 함수 전체가 아니라 특정 연산을 기준으로 센다

total = 0                  # 1회
for value in values:       # n회 반복
    total += value         # n회
return total               # 1회

정확한 model에 따라 loop 조건 검사와 index 증가를 더 셀 수 있지만 전체는 an + b 꼴이고 증가율은 Θ(n)입니다. 같은 O(n)이라도 disk I/O(입출력) 1회와 integer 덧셈 1회의 실제 비용은 다르므로 실무에서는 상수와 memory locality도 측정합니다.

형태대표 증가율예
고정 횟수O(1)array index 접근
입력을 절반씩 축소O(log n)정렬 array의 이분 탐색
모든 항목 한 번O(n)최댓값 찾기
모든 쌍O(n²)중첩 loop 쌍 비교
모든 부분집합O(2ⁿ)선택/비선택 완전 탐색

3. 보조 공간과 입력·출력 공간을 구분한다

입력 array를 제외하고 counter 몇 개만 쓰면 auxiliary space(보조 공간)는 O(1)입니다. 입력을 복사하거나 길이 n의 방문 배열을 만들면 O(n)입니다. 재귀 함수는 눈에 보이는 collection이 없어도 call stack을 사용합니다.

“in-place”라는 표현도 알고리즘이 입력 크기에 비례하는 별도 저장소를 쓰지 않는다는 뜻에 가깝습니다. 언어 runtime의 상수 크기 object와 출력 자체가 반드시 0 byte라는 뜻은 아닙니다.

4. 순차 탐색은 정렬이 필요 없고 최악에는 모두 본다

def linear_search(values, target):
    for index, value in enumerate(values):
        if value == target:
            return index
    return -1

최선은 첫 항목에서 성공해 Θ(1), 최악은 마지막 성공이나 실패로 Θ(n)입니다. 성공 위치가 1부터 n까지 균등하다고 가정하면 성공한 탐색의 평균 비교 횟수는 (1 + 2 + … + n) / n = (n + 1) / 2입니다.

성공 확률을 p라 하고 실패 때 n번 비교한다면 기대 비교 횟수는 p(n + 1)/2 + (1-p)n입니다. 특정 글에 적힌 3n/4 같은 값은 p = 1/2와 큰 n을 가정할 때 나오는 근삿값이지 보편적인 평균이 아닙니다.

5. 이분 탐색은 정렬된 구간을 절반씩 버린다

def binary_search(values, target):
    low, high = 0, len(values) - 1
    while low <= high:
        mid = low + (high - low) // 2
        if values[mid] == target:
            return mid
        if values[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

한 번 비교할 때 후보 크기가 대략 n → n/2 → n/4 → … → 1로 줄어듭니다. n / 2ᵏ ≤ 1을 만족하는 k가 log₂ n 규모이므로 시간 복잡도는 O(log n)입니다.

6. loop invariant가 경계 이동의 근거다

불변식
target이 array에 존재한다면 매 반복 시작 시 폐구간 [low, high] 안에 있다.

values[mid] < target이면 정렬 조건 때문에 mid 이하에는 target이 없습니다. 그래서 low = mid + 1로 버립니다. low = mid로 두면 두 원소 구간에서 mid가 바뀌지 않아 무한 loop가 될 수 있습니다.

반복이 끝날 때 low > high이면 후보 구간이 비었고, 불변식에 따라 target이 없다고 결론 낼 수 있습니다.

7. 구현 전에 구간 표현을 하나로 고정한다

  • 폐구간 [low, high]: high = len(values)-1, 반복 조건 low <= high
  • 반개구간 [low, high): high = len(values), 반복 조건 low < high

두 convention을 섞으면 마지막 원소 누락과 index 초과가 생깁니다. Java처럼 정수 overflow가 가능한 언어에서는 (low + high) / 2보다 low + (high - low) / 2를 사용합니다. Python integer는 overflow하지 않지만 같은 식이 구간 의미를 더 분명히 합니다.

중복 값의 첫 위치나 삽입 위치를 찾는 lower bound는 “같으면 종료”가 아니라 조건을 만족하는 최초 경계를 좁히는 별도 계약입니다.

8. 정렬 비용까지 포함해 탐색 방법을 선택한다

상황선택이유
한 번만 찾는 미정렬 data순차 탐색정렬 O(n log n)이 더 큼
정렬된 array에서 반복 탐색이분 탐색query마다 O(log n)
동등성 조회가 매우 많음hash set/map 검토평균 O(1), 순서·충돌·memory trade-off
삽입·삭제가 빈번한 정렬 구조tree 또는 다른 자료구조array 중간 이동 비용 고려

9. 최소 검증 집합

  • 빈 array
  • 한 원소에서 성공·실패
  • 첫 원소·마지막 원소
  • 짝수·홀수 길이
  • target보다 모두 작거나 큰 경우
  • 중복 값과 “아무 위치/첫 위치/마지막 위치” 계약

작은 n에서 비교 횟수를 직접 세고, 입력을 두 배로 늘렸을 때 순차 탐색은 약 두 배, 이분 탐색은 약 한 단계 늘어나는지 확인하면 증가율을 숫자로 연결할 수 있습니다.

10. 결론

복잡도는 코드를 보고 이름을 붙이는 문제가 아니라 무엇을 세는가 → 입력이 커질 때 몇 번 반복되는가 → 어떤 가정에서 평균을 내는가의 문제입니다. 이분 탐색은 code 암기보다 정렬 전제와 후보 구간 불변식으로 설명할 수 있어야 합니다.
