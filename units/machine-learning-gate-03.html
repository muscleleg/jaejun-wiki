    `decision_function()`의 제한 없는 원시 점수에 sigmoid를 적용하면 `predict_proba()`의 Yes 확률과 같아지는 것을 확인했다. 기본 Threshold `0.5`에서는 Yes 318명, `0.3`에서는 Yes 543명을 예측했으며, 기준을 낮추면 Yes Recall은 `55.88% → 75.40%`로 오르고 Precision은 `65.72% → 51.93%`로 내려가는 trade-off를 읽었다. `y=df["Churn"]`은 No·Yes 정답을 가진 Pandas Series이고, `fit(X_train,y_train)`이 이 정답 클래스를 모델에 전달한다는 점을 확인했다. Pipeline은 Tree가 전처리까지 스스로 하는 모델이 아니라 `원본 X → 전처리기 → 모델` 호출 순서를 묶는 관리자이며, `named_steps["model"]`은 그 안에서 학습된 모델 객체를 꺼내는 문법이다. 각 노드는 현재까지 같은 답을 따라온 고객 묶음이고, 45개 Feature는 45개의 트리가 아니라 각 노드에서 시험할 질문 후보임을 정리했다. 숫자 경계 질문마다 No·Yes가 얼마나 덜 섞이는지 Gini로 비교해 하나를 고르고, 더 나누지 않는 잎에서는 다수 Label을 최종 No·Yes로 낸다. `get_depth()`는 가장 긴 질문 경로, `get_n_leaves()`는 깊이가 달라도 모든 최종 잎의 개수다. 제한 없는 Tree는 깊이 22·잎 1,106개, Train `99.8048%`·Validation `72.8886%`로 Train을 거의 외운 과적합 상태였다. `max_depth=3`은 Validation `78.2115%`, 깊이 5는 `79.8439%`, 깊이 7은 `78.6373%`, `min_samples_leaf=10`은 `76.7211%`였다. Train 점수가 내려가더라도 Validation이 오르면 처음 보는 데이터에는 더 나아진 모델일 수 있음을 확인했다. Logistic Regression은 Feature의 가중합으로 경계를 만들고 Tree는 조건 질문을 이어 비선형 구간을 만든다는 차이를 정리했다. 같은 Split과 Metric에서 시험한 Tree 중 깊이 5가 가장 좋았지만 Logistic Validation `80.5536%`보다 낮았다. 또한 깊이 5 Tree의 Yes Recall은 약 `0.57`이므로 Accuracy만 보면 실제 이탈자를 많이 놓치는 문제를 숨길 수 있다는 점을 확인했다. 데이터 품질·분할·Dummy·One-Hot과 StandardScaler·Logistic 평가·Threshold·DecisionTree 과적합과 제한 비교까지 완료했다. 다음 활성 학습은 PyTorch `nn.Module`과 Optimizer로 `y=3x+2` 학습 루프를 구현하는 것이며, 그 뒤 Tiny Decoder LM으로 복귀한다. 같은 활동에 관해 기존 복습 기록에 남아 있던 검증 요약 (새 활동·추가 시간 아님) Threshold 0.5→0.3에서 Yes Recall 55.88%→75.40%, Precision 65.72%→51.93% 변화를 읽고 비용 기준을 설명했습니다.
