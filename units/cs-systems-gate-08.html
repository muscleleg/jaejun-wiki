학습 안내

이 학습이 필요한 이유
개별 개념과 관찰 명령을 실제 요청 경로 및 하나의 장애 분석으로 연결해 재현 가능한 시스템 이해를 확인한다.
완료 후 이어지는 일
관찰 근거가 있는 장애 진단 결과물을 만들고 Kubernetes·모델 Serving 운영의 문제 분석에 적용할 수 있다.
학습 내용 자세히 보기

Client 요청 → API → Queue → Batch → Model Worker → GPU Memory·KV Cache → Streaming 응답의 흐름을 그리고 앞서 배운 숫자 표현·자료구조·CPU·메모리·운영체제·Network·Storage·분산 실패 원리를 연결합니다. 느린 API·Memory 증가·File Descriptor 고갈·Container OOM 중 하나를 재현하고 현상 → 가설 → 관찰 → 반증 → 원인 → 수정 → 재검증을 기록합니다. Process·Memory·Filesystem·I/O·Namespace·cgroup 중 관련 자원을 근거로 삼고, 고정 조건의 TTFT·Token 생성 속도·Throughput·Peak VRAM과 실패 원인을 해석합니다. AI 요청 흐름 연결과 Linux 장애 진단의 두 기존 달성 기준을 보존하며, 하나의 충분한 실험 기록은 각 기준에서 검토해 재사용합니다.
