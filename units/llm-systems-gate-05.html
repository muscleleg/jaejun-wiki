Multi-GPU Parallelism과 Scaling

짧은 제목 · TP·DP Scaling

선수 대기완료 조건 0 / 5

학습 후 할 수 있는 일Tensor Parallel과 Data Parallel의 분산 방식·메모리·처리량·지연·통신 비용을 비교하고 Workload와 모델 크기에 맞는 방식을 선택한다.

학습 안내

이 학습이 필요한 이유
단일 GPU 병목 기준선이 있어야 Multi-GPU에서 추가된 통신·분할 비용을 구분할 수 있다.
완료 후 이어지는 일
모델 적재와 처리량 요구에 따라 TP·DP를 선택하고 Kubernetes Replica 확장의 성능 조건을 검증할 수 있다.
학습 내용 자세히 보기

동일한 Serving Workload를 Tensor Parallel과 Data Parallel로 확장한다. Collective 통신·GPU Topology·Replica별 Queue와 KV Cache·Scaling Efficiency를 연결해 1 GPU·TP=2·DP=2의 계산 분산, 모델 복제, 통신 및 Load Balancing 비용을 구분한다.

○

TP에 필요한 Collective 이해

미충족

AllReduce·AllGather·ReduceScatter의 입력·출력과 통신량을 작은 Tensor 및 GPU 수별 계산으로 검산한다. Tensor Parallel에서 각 Collective가 어떤 Tensor 분할과 부분 결과 결합에 사용될 수 있는지 설명하고, 실제 vLLM Tensor Parallel 실행의 로그 또는 Profiler에서 호출된 Collective와 custom all-reduce 또는 NCCL 사용 여부를 확인한다. nvidia-smi topo -m 결과로 GPU 간 NVLink·PCIe 연결 유형과 CPU·NUMA Affinity를 기록하고, NCCL 로그 또는 Profiler에서 관측 가능한 Rank 간 통신 Transport와 경로를 연결해 설명하면 완료된다.

Data Parallel Serving

미충족

동일 모델을 GPU별로 복제해 DP=2 Serving을 구성한다. 사용 중인 vLLM 버전의 내부 Data Parallel 또는 GPU별 독립 Replica와 Load Balancer 중 한 방식을 선택하고 선택 이유를 설명한다. Replica별 Request 분배·KV Cache·GPU VRAM·GPU Utilization과 정상 Generation 결과를 남기면 완료된다.

○

1 GPU·TP=2·DP=2 Scaling 비교

미충족

1 GPU에 적재 가능한 동일 모델과 동일 Request Arrival Workload를 1 GPU·TP=2·DP=2로 실행한다. 각 구성의 Throughput·TTFT·TPOT·Queue Time·GPU별 VRAM·GPU Utilization과 기준선 대비 Scaling Efficiency를 Benchmark Table과 Graph로 비교하면 완료된다.

○

Parallelism 선택과 Multi-GPU 병목 분석

미충족

TP의 모델 분할·AllReduce·NCCL·GPU Interconnect 비용과 DP의 모델 복제·독립 KV Cache·Request Load Balancing 비용을 관측값으로 구분한다. 모델이 한 GPU에 적재되고 전체 Throughput 확장이 목적일 때의 DP와, 모델 적재 또는 단일 요청 계산 분산이 필요할 때의 TP 선택 기준을 제시한다. Scaling Efficiency·Queue·GPU Utilization·Communication 근거를 연결해 선형 확장이 되지 않는 이유와 최종 선택을 설명하면 완료된다.
