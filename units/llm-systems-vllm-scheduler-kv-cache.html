vLLM Scheduler와 KV Cache

짧은 제목 · Scheduler·KV Cache

선수 대기완료 조건 0 / 6

학습 후 할 수 있는 일vLLM이 여러 요청과 KV Cache를 Iteration별로 어떻게 Scheduling하고 관리하는지 설명하고, Cache Pressure와 Overload 동작을 검증한다.

학습 안내

이 학습이 필요한 이유
재현 가능한 Serving 기준선이 있어야 요청 상태와 Cache 변화가 Scheduler 동작에서 발생한 것인지 구분할 수 있다.
완료 후 이어지는 일
Scheduler·Cache·Admission 설정을 독립 변수로 다루고 정상 처리 용량과 과부하 경계를 구분하는 Serving Benchmark를 설계할 수 있다.
학습 내용 자세히 보기

Request Lifecycle·Continuous Batching·KV Cache·Prefix Caching·Chunked Prefill의 동작을 요청과 Token 흐름으로 관찰한다. 길이와 요청량이 다른 Workload에서 Scheduler 상태와 Cache 점유가 어떻게 바뀌는지 측정하고, 정상 처리·Queue 증가·Preemption·요청 거절로 이어지는 Overload 경계를 검증한다.

Scheduler Request Lifecycle 설명

Continuous Batching 동작 검증

미충족

길이가 다른 여러 요청을 동시에 보내 먼저 끝난 요청이 빠지고 새 요청이 Batch에 들어오는 현상을 확인한다. Concurrency 1·4·8·16에서 Throughput·TTFT·TPOT·Running Request·Waiting Request 변화를 기록하면 완료된다.

vLLM KV Cache Lifecycle 이해

미충족

Prefill에서 KV Cache가 생성되고 Decode에 따라 증가하며 여러 동시 요청이 GPU 메모리를 점유하고 요청 종료 후 공간이 재사용되는 흐름을 설명한다. Prompt Length·동시 요청 수별 KV Cache 사용량·kv_cache_usage_perc 변화·직접 계산한 예상값과 관측값 비교를 남기면 완료된다.

Prefix Caching 효과 검증

미충족

공통 Prefix 유무와 Prefix Caching ON·OFF를 비교하고 Cached Prompt Token 수·TTFT·Prefill Token 처리량 변화를 측정해 효과를 설명하면 완료된다.

○

Chunked Prefill과 Token Budget 분석

미충족

긴 Prompt 요청과 Decode 중인 요청을 함께 실행하고 Chunked Prefill이 긴 Prefill을 여러 Iteration으로 나누는 이유를 설명한다. Chunked Prefill ON·OFF와 max_num_batched_tokens별 TTFT·TPOT 및 긴 Prompt와 짧은 Prompt 혼합 Workload 결과를 비교해 Prefill·Decode 경쟁 관계를 설명하면 완료된다.

○

KV Cache Pressure와 Overload 동작 검증

미충족

Prompt Length와 Concurrency 또는 Request Rate를 단계적으로 높여 정상 처리·Waiting 증가·Preemption 또는 요청 거절의 경계를 만든다. Running·Waiting Request, Queue Time, KV Cache Usage, Preemption 횟수와 HTTP 응답 상태를 기록하고, max_num_seqs·KV Cache 크기 관련 설정 및 사용 중인 vLLM 버전에서 지원하는 max_num_queued_reqs·max_num_queued_tokens 등의 Admission 설정이 처리 용량에 미치는 영향을 연결해 설명하면 완료된다.
