Scheduler Request Lifecycle 검증

부분 충족

요청의 Waiting·Running·Finished 전이와 Prefill·Decode를 구분하고 여러 요청의 Decode Token이 한 Iteration에서 함께 처리되는 이유 및 Static Batching과 Continuous Batching의 차이를 설명한다. Prompt와 생성 길이가 다른 요청 A·B·C의 시간축·상태·Iteration별 Batch 변화를 기록한다.

확인한 내용

  • Scheduler의 Waiting·Running·Finished 상태와 Prefill·Decode 계산 단계를 서로 다른 축으로 구분하고, Engine Iteration이 실행 대상 선택·모델 실행·상태 갱신을 반복하는 단위임을 정리했다.
  • 여러 요청의 Decode Token을 하나의 Batch로 묶는 이유와 Static Batching의 고정 구성, Continuous Batching의 Iteration별 구성 교체 및 KV Cache·Prefix Caching·Chunked Prefill의 서빙상 역할을 설명했다.

남은 내용

  • 실제 vLLM Server에 Prompt와 생성 길이가 다른 요청 A·B·C를 보내고 요청별 도착·최초 실행·첫 Token·완료 시각을 기록해야 한다.
  • 실제 Running·Waiting Metrics의 시간축 변화를 수집해야 한다.
  • Scheduler Trace로 Iteration별 Request ID·처리 Token 수·Prefill·Decode 단계를 기록하고 같은 Iteration에 여러 Decode 요청이 선택되는 사례를 확인해야 한다.
  • 먼저 끝난 요청 뒤 Waiting 요청이 Batch에 들어오는 실제 변화를 확인하고 Static 제출과 Continuous 제출의 결과를 비교해야 한다.

관련 학습 기록

  • LLM을 실행하는 것과 여러 요청을 서비스하는 것은 다른 문제이며, Scheduler가 매 Engine Iteration마다 Waiting·Running 요청과 Token 작업을…

    LLM을 실행하는 것과 여러 요청을 서비스하는 것은 다른 문제이며, Scheduler가 매 Engine Iteration마다 Waiting·Running 요청과 Token 작업을 다시 선택한다는 구조를 정리했다. Prefill과 Decode는 Scheduler 상태와 다른 계산 단계이고, 여러 요청의 Decode Token을 하나의 Batch로 묶어 GPU에서 함께 처리할 수 있음을 확인했다. Static Batching은 Batch 구성원을 고정하지만 Continuous Batching은 요청이 Finished되면 다음 Iteration에 Waiting 요청을 투입한다. 요청별 KV Cache가 Scheduler가 관리하는 GPU 자원이며 Prefix Caching과 Chunked Prefill이 각각 중복 Prefill과 긴 Prompt의 독점을 줄이는 방식도 정리했다. 표준 /metrics는 Running·Waiting 수와 Iteration Token 통계를 보여주지만 Request ID별 Iteration Batch 구성은 직접 증명하지 못하므로 학습용 Scheduler Trace가 필요하다는 관찰 경계를 구분했다. 실제 A·B·C 요청의 상태·시간축·Iteration별 Batch 기록은 다음 실습에서 확인할 범위로 남겼다.

Continuous Batching 동작 검증

미충족

길이가 다른 여러 요청을 보내 먼저 완료된 요청이 Batch에서 빠지고 실행 도중 새 요청이 들어오는 현상을 확인한다. Concurrency 1·4·8·16에서 Running·Waiting Request·Throughput·TTFT·TPOT를 기록하고 고정 Batch와 다른 동작을 관측 근거로 설명한다.

KV Cache Lifecycle과 메모리 검증

미충족

Prefill의 초기 K·V 생성, Decode Token 증가에 따른 Cache 증가, 동시 요청별 점유, 요청 종료 후 Block 회수와 후속 요청의 공간 재사용을 설명하고 관찰한다. Prompt Length·동시 요청별 이론적 KV Cache Byte와 실제 KV Cache Usage를 비교해 차이를 분석한다.

○

Prefix Caching 효과 검증

미충족

공통 Prefix가 없는 요청과 있는 요청에서 Prefix Caching ON·OFF, 첫 요청과 후속 요청을 비교한다. Cache Hit 여부를 실제 Metric 또는 Log로 확인하고 Cached Prompt Token·TTFT·Prefill Token Throughput을 기록하며 TTFT 변화만으로 Hit을 추정하지 않는다.

○

Chunked Prefill과 Token Budget 검증

미충족

긴 Prompt 요청과 Decode 중인 요청을 함께 실행하고 Chunked Prefill이 긴 Prefill을 여러 Iteration으로 나누는 이유를 설명한다. ON·OFF와 max_num_batched_tokens를 한 번에 하나씩 바꾸고 긴·짧은 Prompt 혼합 Workload의 TTFT·TPOT·Queue 변화로 Prefill·Decode Token Budget 경쟁을 설명한다.

○

KV Cache Pressure와 Overload 경계 검증

미충족

Prompt Length와 Concurrency 또는 Request Rate를 단계적으로 높여 정상 처리·Waiting 증가·Preemption·Reject·Timeout·OOM 경계를 찾는다. Running·Waiting·Queue Time·KV Cache Usage·Preemption·HTTP 결과를 기록하고 max_num_seqs·KV Cache·지원되는 Admission 설정의 영향을 설명하며 OOM과 제어된 Reject를 구분한다.
