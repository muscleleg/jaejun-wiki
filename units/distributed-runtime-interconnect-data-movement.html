    GPU 통신의 전달 방식(SHM·P2P), 물리 연결(PCIe·NVLink·NVSwitch), 통신 라이브러리(NCCL·NIXL), 실행 시 선택된 경로를 구분했다. P2P는 호스트 DRAM의 중간 복사를 생략한다는 뜻이며 CPU 쪽 PCIe Root Complex나 NVSwitch 같은 연결 장치가 없다는 뜻은 아니다. CPU 버퍼는 CPU 내부 SRAM 캐시가 아니라 호스트 DRAM의 버퍼를 뜻한다. NCCL_P2P_DISABLE은 해당 NCCL 프로세스의 전송 선택지를 바꾸며 RunPod 하드웨어나 NIXL 경로를 직접 바꾸지 않는다. P2P/CUMEM/read의 CUMEM은 GPU 메모리 할당·공유 방식, read는 접근 방식이며 SHM/direct/direct의 direct를 GPU 간 직접 전송으로 해석하지 않는다. 보존된 A100-SXM4-80GB 2장 환경 자료에서 AMD EPYC 7763 2소켓, 논리 CPU 256개, 호스트 RAM 약 2 TiB, Driver 595.91.07, PyTorch 2.13.0+cu130·CUDA 13.0·NCCL 2.29.7을 확인했다. 호스트 전체 RAM을 컨테이너 보장량으로 간주하지 않는다. topo -m의 NV12, NUMA 0, CPU Affinity 0-63·128-191, 양방향 P2P 접근 가능성을 기록했다. NVLink 상태와 NCCL 토폴로지의 NVS/0-0·NVL 표현을 근거로 NVLink 연결과 스위치 토폴로지 모델을 구분했으며, GPU 제품명만으로 연결을 사전 가정하거나 물리 칩 수·전송 바이트별 NVSwitch 홉을 단정하지 않았다. 예상과 다른 경로가 나타나면 실제 출력과 로그를 보존한다는 원칙으로 P2P 허용 시 P2P/CUMEM/read, 차단 시 SHM/direct/direct 및 각 24·4개 채널을 기록했다. AllReduce SUM은 각 GPU의 동일 위치 원소를 합산해 양쪽에 같은 결과를 둔다. GPU당 입력 S와 전체 완료 시간 t로 AlgBW=S/t를 계산하고, AllReduce의 표준 전송량 모델에 따라 BusBW=AlgBW×2(N−1)/N으로 보정한다. N=2이면 보정계수가 1이므로 두 값은 같다. N=4에서는 ReduceScatter와 AllGather 각각 (N−1)S/N을 보내는 모델이므로 1.5배다. BusBW는 연산 시간을 제거한 실측 링크 속도나 HBM 대역폭이 아니다. 사용한 실험은 PyTorch NCCL AllReduce 테스트이며 공식 nccl-tests 실행 파일을 돌린 것은 아니다. 호스트 호출·CUDA 완료 대기를 포함한 회차별 두 Rank의 최대 시간으로 지연과 AlgBW·BusBW를 계산했다. 4 KiB~64 MiB, FP32, Ring·Simple, 예열 5회·측정 30회에 한정하며 작은 입력의 고정 비용과 큰 입력의 경로 차이를 구분했다. A40 기존 4 KiB·64 KiB·1 MiB·16 MiB·64 MiB 평균 시간 0.059·0.068·0.185·1.796·6.822ms와 A100 P2P 재실행 0.083·0.098·0.105·0.198·0.637ms, SHM 재실행 0.084·0.109·0.329·3.771·14.794ms를 나란히 비교했다. 초기 A100 측정과 재실행을 구분하고 64 MiB 재실행의 최대 4.811ms 이상치도 숨기지 않았다. GPU Architecture·Memory·Compute·소프트웨어·채널 조건이 함께 달라지므로 환경 간 차이를 Interconnect 하나의 인과 효과로 단정하지 않는다. Decode 서버의 UCX 로그에서 ucp_get GPU 메모리 읽기에 zero-copy cuda_ipc/cuda가 선택된 것을 확인했으며 별도의 UCX 서버 프로세스 로그로 오해하지 않는다. TCP 제어 메시지와 KV 데이터 전송을 구분했다. NIXL 메트릭의 전송 Byte·건수·누적 시간 증분으로 평균 시간과 유효 대역폭을 계산하고 병렬 전송 시간 합계를 벽시계 시간으로 읽지 않는다. 128·673·2048토큰의 18·96.75·288MiB와 0.785·6.453·20.647ms를 연결했다. 673토큰의 94.64MiB 논리량과 96.75MiB 실전송량은 16토큰 블록 43개로 설명하며 GQA의 KV Head 8개는 이미 계산에 반영돼 있다. 동일한 단독/P/D 비교 구간의 E2E 차이 72.131ms와 KV 평균 4.582ms는 별도 측정 범위이므로 나머지를 모두 HTTP 비용으로 단정하지 않는다. 이전 RTX PRO의 NIXL 경로는 미확인이며 느리다는 이유만으로 SHM이라 부르지 않는다. 이 해석은 저장된 노트북·원본 로그·JSON과 재현 조건을 다시 읽어 11개 계층 문서로 연결한 결과다. 원본 143개 파일은 manifest 해시로 검증된 Git 커밋 80d7c6eb718846ae2d9ca089b740797aa29dc6b1에 보존돼 있다. 새 GPU 실행이나 공식 nccl-tests 실행, 물리 홉별 프로파일링, Cross-node 검증을 추가로 수행했다는 의미는 아니다.

    GPU 통신의 전달 방식(SHM·P2P), 물리 연결(PCIe·NVLink·NVSwitch), 통신 라이브러리(NCCL·NIXL), 실행 시 선택된 경로를 구분했다. P2P는 호스트 DRAM의 중간 복사를 생략한다는 뜻이며 CPU 쪽 PCIe Root Complex나 NVSwitch 같은 연결 장치가 없다는 뜻은 아니다. P2P/CUMEM/read의 CUMEM은 GPU 메모리 할당·공유 방식, read는 접근 방식이며 SHM/direct/direct의 direct를 GPU 간 직접 전송으로 해석하지 않는다. 보존된 A100-SXM4-80GB 2장 환경 자료에서 AMD EPYC 7763 2소켓, 논리 CPU 256개, 호스트 RAM 약 2 TiB, Driver 595.91.07, PyTorch 2.13.0+cu130·CUDA 13.0·NCCL 2.29.7을 확인했다. 호스트 전체 RAM을 컨테이너 보장량으로 간주하지 않는다. topo -m의 NV12, NUMA 0, CPU Affinity 0-63·128-191, 양방향 P2P 접근 가능성을 기록했다. NVLink 상태와 NCCL 토폴로지의 NVS/0-0·NVL 표현을 근거로 NVLink 연결과 스위치 토폴로지 모델을 구분했으며, GPU 제품명만으로 연결을 사전 가정하거나 물리 칩 수·전송 바이트별 NVSwitch 홉을 단정하지 않았다. 예상과 다른 경로가 나타나면 실제 출력과 로그를 보존한다는 원칙으로 P2P 허용 시 P2P/CUMEM/read, 차단 시 SHM/direct/direct 및 각 24·4개 채널을 기록했다. AllReduce SUM은 각 GPU의 동일 위치 원소를 합산해 양쪽에 같은 결과를 둔다. GPU당 입력 S와 전체 완료 시간 t로 AlgBW=S/t를 계산하고, AllReduce의 표준 전송량 모델에 따라 BusBW=AlgBW×2(N−1)/N으로 보정한다. N=2이면 보정계수가 1이므로 두 값은 같다. N=4에서는 ReduceScatter와 AllGather 각각 (N−1)S/N을 보내는 모델이므로 1.5배다. BusBW는 연산 시간을 제거한 실측 링크 속도나 HBM 대역폭이 아니다. 사용한 실험은 PyTorch NCCL AllReduce 테스트이며 공식 nccl-tests 실행 파일을 돌린 것은 아니다. 호스트 호출·CUDA 완료 대기를 포함한 회차별 두 Rank의 최대 시간으로 지연과 AlgBW·BusBW를 계산했다. 4 KiB~64 MiB, FP32, Ring·Simple, 예열 5회·측정 30회에 한정하며 작은 입력의 고정 비용과 큰 입력의 경로 차이를 구분했다.     GPU 통신의 전달 방식(SHM·P2P), 물리 연결(PCIe·NVLink·NVSwitch), 통신 라이브러리(NCCL·NIXL), 실행 시 선택된 경로를 구분했다. P2P는 호스트 DRAM의 중간 복사를 생략한다는 뜻이며 CPU 쪽 PCIe Root Complex나 NVSwitch 같은 연결 장치가 없다는 뜻은 아니다. CPU 버퍼는 CPU 내부 SRAM 캐시가 아니라 호스트 DRAM의 버퍼를 뜻한다. NCCL_P2P_DISABLE은 해당 NCCL 프로세스의 전송 선택지를 바꾸며 RunPod 하드웨어나 NIXL 경로를 직접 바꾸지 않는다. P2P/CUMEM/read의 CUMEM은 GPU 메모리 할당·공유 방식, read는 접근 방식이며 SHM/direct/direct의 direct를 GPU 간 직접 전송으로 해석하지 않는다. 보존된 A100-SXM4-80GB 2장 환경 자료에서 AMD EPYC 7763 2소켓, 논리 CPU 256개, 호스트 RAM 약 2 TiB, Driver 595.91.07, PyTorch 2.13.0+cu130·CUDA 13.0·NCCL 2.29.7을 확인했다. 호스트 전체 RAM을 컨테이너 보장량으로 간주하지 않는다. topo -m의 NV12, NUMA 0, CPU Affinity 0-63·128-191, 양방향 P2P 접근 가능성을 기록했다. NVLink 상태와 NCCL 토폴로지의 NVS/0-0·NVL 표현을 근거로 NVLink 연결과 스위치 토폴로지 모델을 구분했으며, GPU 제품명만으로 연결을 사전 가정하거나 물리 칩 수·전송 바이트별 NVSwitch 홉을 단정하지 않았다. 예상과 다른 경로가 나타나면 실제 출력과 로그를 보존한다는 원칙으로 P2P 허용 시 P2P/CUMEM/read, 차단 시 SHM/direct/direct 및 각 24·4개 채널을 기록했다.
