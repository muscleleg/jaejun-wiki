    Chunked Prefill은 긴 Prefill을 작은 작업으로 나눠 Decode와 함께 스케줄링할 기회를 만드는 방식이고, P/D는 Prefill과 Decode의 실행 자원을 분리하고 KV를 전달하는 방식임을 구분했다. Chunked Prefill만으로 자원 공유가 사라지지는 않으며 P/D에서도 이를 사용할 수 있다. 두 방식의 튜닝 우열을 추가 실험으로 검증한 것은 아니다. GQA에서 Q별 Attention 계산은 유지하면서 여러 Q Head가 더 적은 K/V Head를 공유함을 이해했다. PyTorch Projection 가중치의 출력 행 감소와 토큰별 출력 벡터의 열 감소를 구분했고, Head 수가 늘어나는 것이 아니라 처리 토큰별 K/V 벡터가 캐시에 쌓임을 확인했다. 예시 Q 4개·KV 2개·Head 차원 2에서는 결합 출력 8차원이 유지된다. GQA는 임의의 서버 옵션이 아니라 모델의 구조와 학습된 가중치에 대응한다. Qwen3-8B의 Q Head 32개·KV Head 8개, 36레이어, Head 차원 128, BF16 2bytes로 토큰당 KV 144KiB와 673토큰 94.640625MiB를 계산했다. 나머지 조건을 고정하고 KV Head도 32개라고 가정한 MHA는 토큰당 576KiB·673토큰 378.5625MiB다. GQA 값은 이미 1/4이므로 다시 절감하지 않는다. 관측 96.75MiB와의 차이는 16토큰 블록 43개=688슬롯의 올림이며 GQA와 별개다. MHA 수치는 가상 구조의 산술 비교이고 별도 MHA 모델 실행 결과가 아니다. 보존된 동일 구간의 전송량·시간으로 유효 처리량을 계산했다. 건당 96.75MiB를 단일 요청 347.9ms, 동시16의 2P1D 1625.3ms 및 1P2D 4372.8ms로 나누면 약 278.1·59.5·22.1MiB/s다. B를 bytes 합계, S를 개별 시간 합계, N을 건수라고 할 때 평균 크기/평균 시간은 B/S이고 개별 비율의 단순 평균과 다르다. B/벽시계 경과 시간은 동시성을 포함한 전체 처리량이므로 B/S와 혼동하지 않는다. 이 값만으로 실제 물리 경로·이론 대역폭 대비 이용률·경합 장치를 확정하지 않는다. 대화로 개념을 보강하고 기존 측정치를 다시 계산한 내용이다. GPU 재실험, 상세 전송 Trace, 전 구성 Queue·TTFT·TPOT 직접 비교, KV·Logit 수치 동등성은 추가 검증하지 않았다.
