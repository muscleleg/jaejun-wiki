LLM-aware Routing과 GPU 배치의 구분

짧은 제목 · Routing·배치 구분

선수 대기달성 기준 0 / 6

학습 후 할 수 있는 일Endpoint 부하·Locality와 Pod 배치를 독립적으로 바꿔 Routing과 Scheduling을 구분한다.

학습 안내

이 학습이 필요한 이유
요청 경로가 연결된 상태에서 배치와 부하를 독립적으로 바꿔야 Routing 결정의 원인을 분리할 수 있다.
완료 후 이어지는 일
통합 부하 실험에서 Routing 변화와 GPU 재배치 효과를 분리한다.
학습 내용 자세히 보기

핵심 질문: 같은 서버 배치에서 어떤 상태가 요청 대상 선택을 바꾸는가? 개념·실습 흐름 Endpoint 부하와 Mock Prefix Locality를 바꿔 일반 Load Balancing과 LLM-aware Selection을 비교한다. Request Rate·Health·Endpoint 선택을 같은 시간축에서 관찰한다. Pod 배치를 고정한 실험과 변경한 실험을 구분하고 Routing 변경이 GPU 재할당을 의미하지 않음을 검증한다. Mock Locality를 실제 KV Cache 성능 근거로 사용하지 않는다. 실험과 달성 기준 연결 부하·Prefix Locality·일반/LLM-aware 비교는 달성 기준 1~3, 시간축·성능 경계는 4~5, 배치 고정/변경 대조는 6과 연결한다.
