핵심 질문: 부하 증가부터 Queue 회복까지 인과관계를 입증할 수 있는가? 개념·실습 흐름 전체 Architecture·Resource 관계·Request Sequence·통합 Dashboard를 구성하고 모든 계층의 Metric 수집을 확인한다. 부하 → Queue → EPP 선택 → Autoscaling → Scheduling → Running/Ready → Endpoint 등록 → Reject/Failure → 회복을 같은 시간축으로 기록하고 운영 병목 가설 하나를 검증한다. 상위 Multi-GPU 설정부터 요청 성공까지 추적하며 자원 단편화 또는 배치 조건 실패까지 통합한다. 실험과 달성 기준 연결 Architecture·리소스·요청 관계는 달성 기준 1~4, 통합 관측은 5~12, 부하·과부하·병목 가설은 13~15, GPU 요청→배치→응답 및 배치 실패는 16과 연결한다. 실행 조건과 검증 경계 낮은 Replica와 부하를 사용해도 요청·라우팅·수용 제어·확장·배치·관측의 연결은 실제 유지한다. 구성요소를 따로 실행한 결과의 합으로 통합 실험을 완료하지 않는다. 자원이 부족하면 검증 가능한 환경을 확보할 때까지 해당 기준을 미충족으로 둔다.
