    CNI는 멀티노드 전용 기능이 아니라 Pod가 통신할 Network를 준비하는 표준 경계임을 정리했다. 일반적인 veth 기반 구현에서 Pod Network Namespace, veth pair, Pod IP와 Route를 구성하고 Host 쪽 끝점을 Bridge·Route·Tunnel·eBPF 같은 Datapath에 연결하는 과정을 설명했다. eth0은 장치 종류가 아니라 Pod 쪽 Interface에 붙인 이름이며, ip link의 Peer Index와 Link 상태는 연결 구조를 확인하는 단서라는 점도 구분했다.

    Application이 만든 Packet은 목적지 IP가 무엇이든 먼저 현재 Network Namespace의 Routing Table에서 다음 Hop과 출력 Interface를 선택한다는 원칙을 정리했다. Pod eth0에서 TX된 Packet이 veth Peer인 Host Interface에서 RX로 나타나 Node의 입력 Packet이 되고, Netfilter Hook과 목적지 변환 뒤 다시 Routing Table을 통해 출력 경로가 결정되는 과정을 설명했다. Routing Table은 목적지 자체를 바꾸는 것이 아니라 가장 긴 Prefix가 일치하는 Route에서 다음 Hop과 Interface를 선택한다는 점도 구분했다.
