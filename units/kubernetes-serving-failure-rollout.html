이 학습이 필요한 이유
정상 요청 경로와 안전한 종료를 기준선으로 두어야 비계획 장애의 전파와 자원 부족에 따른 복구 실패를 구분할 수 있다.

학습 내용 자세히 보기

핵심 질문: 어디가 고장났으며 대체 자원은 복구에 충분한가? 개념·실습 흐름 Model Server·Gateway·EPP·Worker Node 장애를 개별 주입하고 Endpoint 제외 시간과 신규/Streaming 요청 결과를 비교한다. Endpoint Health·EPP 선택·응답·Reconcile 복구를 같은 시간축에서 기록한다. Node 장애와 계획된 Drain을 별도로 실행하고 대체 GPU 수량·종류·배치 조건이 충분/부족한 경우를 비교한다. 같은 Host의 Node 장애 및 Mock 장애의 검증 경계를 명시한다. 실험과 달성 기준 연결 Model Server·Gateway·EPP·Worker 장애는 달성 기준 1~5, 요청·Endpoint·Controller 복구 시간축은 6~7, 장애 증거의 경계는 8~9, Node 장애/Drain 및 대체 자원 충분/부족 비교는 10과 연결한다. 실행 조건과 검증 경계 장애 주입은 학습용 클러스터와 테스트 워크로드에 한정한다. 기존 사용자 환경을 중단하지 않으며 같은 맥의 Node 중단을 물리 Host 장애 격리로 해석하지 않는다.
