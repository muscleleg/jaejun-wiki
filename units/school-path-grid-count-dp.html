    프로그래머스 등굣길 문제에서 처음에는 최단거리와 경로 수가 섞여 Heap·BFS·Dijkstra 탐색을 생각했지만, 오른쪽과 아래로만 이동하면 도착에 필요한 좌표 변화량이 오른쪽 m-1번·아래 n-1번으로 고정되어 모든 성공 경로의 길이가 같다고 자기 말로 정리했다. dp[r][c]를 거리 대신 시작점에서 현재 칸까지 도달하는 경로 수로 정의하고, 현재 칸에 들어오는 위쪽 경로 묶음과 왼쪽 경로 묶음은 서로 겹치지 않는 OR 관계라 합의 법칙으로 더한다는 점을 이해했다. 시작점은 경로 수 1, 물웅덩이는 0으로 두고 첫 행·첫 열을 별도로 누적한 뒤 내부 칸을 위+왼쪽으로 채우는 코드를 직접 작성했다. 최초 제출은 첫 행 물웅덩이 분기의 dp를 d로 잘못 쓴 오타 때문에 일부 테스트에서 NameError가 발생해 정확성 35점·효율성 45점, 합계 80점이었고, 원인을 찾아 dp로 고쳐야 함과 누적 단계마다 1,000,000,007 나머지 연산을 적용해야 함을 확인했다. 전체 테스트 재통과와 자료 없는 재구현·복잡도 설명은 아직 확인되지 않았다.
