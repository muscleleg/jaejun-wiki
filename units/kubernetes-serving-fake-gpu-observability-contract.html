학습 내용 자세히 보기

핵심 질문: GPU는 어떻게 Kubernetes 자원이 되어 Pod에 할당되는가? 개념·실습 흐름 구성요소의 역할을 먼저 배우고 멀티노드 Minikube·Fake GPU Node Pool을 만든다. GPU 게시 → Capacity/Allocatable → Pod 요청 → 배치 → 자원 소진 시 Pending을 추적한다. Fake GPU Metric과 실제 하드웨어 관측의 차이를 설명한다. Allocatable이 예약 후 남은 GPU 수처럼 자동 감소한다고 해석하지 않는다. 실험과 달성 기준 연결 구성요소 설명과 Fake/실제 경계는 달성 기준 10~11, 멀티노드·Pool 구성은 1~6, GPU 게시·요청·소진 실험은 7~9와 연결한다. 실행 조건과 검증 경계 Apple Silicon에서는 Docker Driver와 ARM64 이미지를 사용하고 기존 프로필과 분리한 학습용 프로필을 선택한다. 단일 노드는 예비 실습일 뿐이며 이 학습 단원의 완료에는 Control Plane 1개와 Worker 2개 이상, 서로 다른 Fake GPU Pool이 필요하다. CUDA 연산 대신 CPU 컨테이너를 실행한다. Allocatable 총량을 예약 후 남은 수량으로 해석하지 않는다.

미충족

실제 GPU 클러스터의 Driver·Container Runtime·GPU Operator·Device Plugin·kubelet·Scheduler 관계를 설명한다. 실습에서 Fake로 대체한 구성요소를 표시하고 Node Capacity·Allocatable 게시부터 Pod GPU 요청과 배치까지 흐름을 추적한다.

목표 문맥별 선택 이유

쿠버네티스 GPU 클러스터와 Multi-GPU Serving 학습에서 선택한 이유

Fake GPU 환경에서 쿠버네티스의 GPU 자원 등록·할당·Node 및 그룹 배치와 LLM Serving 운영을 먼저 익힌다. 이후 실제 Multi-GPU 환경에서 분산 추론의 계산·통신·메모리·성능을 검증하고 Kubernetes의 자원 관리와 Runtime의 GPU 사용·통신 책임을 구분한다.
