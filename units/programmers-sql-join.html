충족

일치하는 키와 일치하지 않는 키가 있는 예제로 INNER JOIN과 LEFT JOIN의 결과 차이를 설명하고 LEFT JOIN 뒤 NULL 검사로 미매칭 행을 찾는다.

    프로그래머스 「입양 시각 구하기(2)」에서 SELECT HOUR(DATETIME), COUNT(*)와 GROUP BY로 시작했다. 원본에 없는 시간은 그룹도 생기지 않아 0~23 시간 목록을 먼저 만들어야 한다는 설명을 받고 SELECT 상수·UNION ALL을 학습했다. WITH RECURSIVE의 시작 행, 자기 참조 FROM, 직전 단계의 새 행을 입력으로 사용하는 평가, 종료 조건을 반복 질문했다. SELECT 별칭 n이 결과 열 이름이며 물리 테이블 생성이나 전역 변수 선언이 아니라는 점을 학습하고 재귀 CTE를 직접 작성했다. WITH와 AS 위치, FROM과 WHERE 분리, 파생 테이블 이름·열 범위, HOUR 함수명, COUNT 괄호 공백의 오류를 안내받아 교정했다. INNER·LEFT·RIGHT·FULL JOIN의 보존 기준을 자기 말로 정리하고 hours.n=HOUR(DATETIME) 조건의 LEFT JOIN을 작성했다. 오른쪽 시간으로 GROUP BY한 시도를 hours.n으로 수정했으며, LEFT JOIN의 NULL 채움 행도 COUNT(*)는 세기 때문에 실제 ANIMAL_ID를 세어야 빈 시간이 0이 된다는 이유를 자기 말로 설명했다. 먼저 집계 후 JOIN하는 풀이에서는 없는 집계 행의 CNT가 NULL이 되어 COALESCE(CNT,0)가 필요하다는 순서 차이를 스스로 짚었다. 재귀·JOIN 문법과 최종 수정 풀이의 도움을 받았고 설명용 행 표는 실행 결과가 아니다. 최종 COUNT(ANIMAL_ID) 쿼리의 제출·전체 채점 통과와 도움 없는 재구현은 확인하지 않았다.

NULL 비교는 일반 등호로 참이 되지 않아 IS NULL로 검사해야 한다는 교정과 출력 열·정렬 안내를 받은 뒤, 왼쪽 ANIMAL_ID·NAME 출력, 오른쪽 ANIMAL_ID IS NULL 필터, 왼쪽 ANIMAL_ID 오름차순 정렬을 갖춘 최종 쿼리를 직접 작성하고 했어라고 완료를 확인했다. LEFT JOIN이 입양 기록을 보존하고 연결되지 않은 보호 시작 열을 NULL로 채운 결과에서 미매칭 동물을 찾는 흐름을 학습했다. JOIN 방향과 키 연결은 첫 시도에서 정했지만 NULL 문법과 최종 코드 안내를 받았으므로 독립 풀이 완료로 기록하지 않는다. 구체적인 제출 점수와 전체 테스트 통과 범위는 명시하지 않았다.

키 관계에서 JOIN 조건 결정

부분 충족

두 테이블의 PK/FK 또는 문제에서 제시한 키 관계를 보고 JOIN 조건을 직접 정하고, 일대다 연결에서 행 수와 집계 값이 어떻게 달라지는지 확인한다.

확인한 내용

  • BOOK_SALES.BOOK_ID=BOOK.BOOK_ID 조건으로 카테고리를 판매 기록에 연결하는 JOIN 문법을 설명받아 작성하고, 날짜별 판매 기록의 SALES 합계와 행 개수를 구분했다.
  • 시간 목록과 실제 기록을 hours.n=HOUR(ANIMAL_OUTS.DATETIME)로 연결하는 조건을 안내 후 작성했다. 한 시간에 여러 기록이 연결되는 예제와 미매칭 시간에 결과 행 하나가 보존되는 구조를 학습하고, 그 구조가 행 수와 COUNT 대상 선택에 미치는 영향을 설명했다. 원본 JOIN 후 집계와 요약 결과 JOIN의 차이를 자기 말로 정리했다.
  • ANIMAL_INS.ANIMAL_ID=ANIMAL_OUTS.ANIMAL_ID로 두 동물 기록을 연결하는 조건을 첫 쿼리에서 직접 작성했다. INNER JOIN의 같은 동물 기록에서 보호 시작일과 입양일을 비교하고 정렬했다. 최종 출력·날짜 비교는 검토 안내를 받았으며 일대다 집계 결과를 실행한 학습은 아니다.
  • 입소 상태를 미리 거른 CTE INTACT를 직접 구성하고 INTACT.ANIMAL_ID=ANIMAL_OUTS.ANIMAL_ID로 입양 기록을 연결하는 최종 쿼리를 작성했다. 문장 순서와 상태 조건의 교정 도움을 받았으며 일대다 집계 실행 결과를 확인한 활동은 아니다.
  • 상품·판매 테이블을 PRODUCT_ID로 직접 연결하고 상품코드별 SUM(가격×판매량)을 계산한 정답을 확인했다. 한 상품에 여러 판매 기록이 연결되는 구조와 그룹 합산은 정답 확인 뒤 설명받았으며 JOIN 전후의 중간 행 수를 별도 조회·측정한 기록은 없다.
  • 식품 매출 문제에서 PRODUCT_ID 키 연결과 상품별 SUM(가격×주문량)을 독립 작성했다. 보호 동물 문제에서도 두 ANIMAL_ID 연결과 LEFT JOIN 방향·IS NULL 조건을 LIMIT 안내 전에 직접 결정했다.
  • 최다 리뷰 회원을 MEMBER_ID로 원본 리뷰에 다시 연결한 쿼리에서 공동 최다 세 명의 각 세 리뷰, 총 아홉 행을 직접 관찰하고 채점 100점을 확인했다. 회원당 한 행의 집계와 리뷰당 한 행의 최종 결과를 분리하는 과정을 도움받았다.

남은 내용

  • 일대다 연결에서 행 수와 합계가 어떻게 달라지는지 직접 조회한 결과로 확인한다.

    프로그래머스 「카테고리 별 도서 판매량 집계하기」에서 BOOK_SALES에 없는 PRICE와 CATEGORY를 요청한 오류를 시작으로, BOOK_ID가 같은 BOOK 행을 JOIN해 판매 기록에 카테고리를 연결하는 문법을 학습했다. 판매 행 한 건이 책 한 권이 아니라 날짜별 판매량 기록임을 이해하고 COUNT 대신 SUM(SALES)가 필요하다고 확인했다. JOIN 설명과 수정 예시의 도움을 받은 뒤 SUM(*)를 SUM(BOOK_SALES.SALES)로 고치고, 기간 필터 누락 및 출판일 PUBLISHED_DATE와 판매일 SALES_DATE의 혼동을 수정했다. JOIN 문제 풀이와 테스트 통과

부분 충족

지정된 JOIN 문제 5개를 풀이해 전체 테스트를 통과하고, 그중 3개 이상은 해설·힌트·정답 코드의 도움 없이 직접 해결한다. 날짜·상태 비교와 JOIN 후 GROUP BY·SUM·ORDER BY를 설명한다.

확인한 내용

  • 없어진 기록 찾기에서 LEFT JOIN 방향과 ANIMAL_ID 연결을 직접 작성하고, NULL 검사·출력·정렬의 수정 안내 뒤 최종 쿼리를 작성해 완료를 확인했다. 도움받은 풀이이며 전체 채점 범위는 명시하지 않았다.
  • 있었는데요 없었습니다에서 날짜 비교 JOIN과 보호 시작일 정렬을 작성하고 이름 출력·엄격한 비교 교정 후 최종 쿼리 작성 및 완료를 확인했다. 같은 시각 행이 없다면 >와 >= 결과가 같다는 점을 질문했다. 출력 조건과 날짜 비교의 검토 도움을 받았으며 상세 전체 채점 결과는 명시하지 않았다.
  • 보호소에서 중성화한 동물의 입소·입양 상태 조건을 IN과 CTE로 구성하고, 중복 FROM·JOIN 위치·입소 상태의 반대 조건을 교정받은 뒤 최종 JOIN·WHERE·ORDER BY 쿼리를 작성했다. 최종 작성은 확인했지만 전체 테스트 통과 범위는 명시하지 않았고 도움 없는 풀이로 기록하지 않는다.
  • 상품 별 오프라인 매출 구하기를 풀이 전 해설·힌트·정답 코드 없이 직접 작성해 정답을 확인했다. 지정 JOIN 문제의 독립 풀이 1개 근거로 기록한다. 정답 확인 후 SUM의 그룹 입력과 다중 ORDER BY 동점 정렬 의미를 설명받았으며 원리를 독립적으로 설명한 것으로 확대하지 않는다.
  • 5월 식품들의 총매출 조회하기를 풀이 전 힌트·해설·정답 코드 없이 독립 작성하고 혼자 풀었다고 확인했다. 오프라인 매출 문제와 함께 지정 JOIN 문제 독립 작성 두 개의 근거이며 별도 채점 화면은 관찰하지 않았다.

남은 내용

  • 지정 JOIN 문제들의 최종 전체 채점 통과 범위를 확인한다. 이미 독립 풀이로 확인한 오프라인 매출 문제의 정답 사실은 유지한다.
  • 상품 별 오프라인 매출과 5월 식품 매출 외 지정 JOIN 문제 한 개 이상을 도움 없이 직접 해결해 독립 풀이 총 세 개 이상을 확보한다.
