집계 함수 선택과 결과 검증

부분 충족

COUNT, SUM, AVG, MAX/MIN을 요구사항에 맞게 사용하고 NULL·중복·데이터 없는 그룹이 결과에 주는 영향을 예제로 확인한다.

확인한 내용

  • COUNT(*)와 COUNT(표현식)의 NULL 처리, 중복 값의 개수와 종류 수, CASE 조건부 COUNT를 예제로 학습했다. 판매 기록 수와 판매량 합계를 구분해 SUM(SALES)로 수정했다.
  • 입양이 없는 시간에는 원본 GROUP BY의 그룹도 없다는 이유를 학습했다. LEFT JOIN의 NULL 채움 결과 행을 COUNT(*)는 세지만 COUNT(ANIMAL_ID)는 세지 않는 차이를 설명받은 뒤 자기 말로 정리했다. 먼저 집계한 뒤 JOIN하면 빈 시간의 CNT가 NULL이 되어 COALESCE가 필요하고, JOIN한 뒤 ID를 집계하면 0이 계산된다는 순서 차이를 스스로 짚었다.
  • SUM(PRICE*SALES_AMOUNT)을 직접 선택하고 상품코드 그룹별 매출 합계 쿼리를 작성해 정답을 확인했다. SUM이 그룹 안의 각 기록별 계산 결과를 더하며 COUNT는 기록 수, SUM(SALES_AMOUNT)는 수량 합이라는 구분을 정답 확인 후 예제로 설명받았다.
  • 생산일 조건을 적용한 상품별 SUM(PRICE*AMOUNT)을 독립 작성했다. 리뷰 개수의 CTE 결과에서 MAX(REVIEW_COUNT)를 사용해 동점 최다 회원을 찾는 조건을 도움받아 구현하고 최종 쿼리 채점 100점을 확인했다.

남은 내용

  • AVG·MIN을 요구사항에 맞게 직접 사용하고 결과를 확인한다.
  • NULL·중복·빈 그룹과 LEFT JOIN의 집계 영향을 직접 작성·실행한 예제로 검증한다.

    프로그래머스 「입양 시각 구하기(2)」에서 SELECT HOUR(DATETIME), COUNT(*)와 GROUP BY로 시작했다. 원본에 없는 시간은 그룹도 생기지 않아 0~23 시간 목록을 먼저 만들어야 한다는 설명을 받고 SELECT 상수·UNION ALL을 학습했다. WITH RECURSIVE의 시작 행, 자기 참조 FROM, 직전 단계의 새 행을 입력으로 사용하는 평가, 종료 조건을 반복 질문했다. SELECT 별칭 n이 결과 열 이름이며 물리 테이블 생성이나 전역 변수 선언이 아니라는 점을 학습하고 재귀 CTE를 직접 작성했다. WITH와 AS 위치, FROM과 WHERE 분리, 파생 테이블 이름·열 범위, HOUR 함수명, COUNT 괄호 공백의 오류를 안내받아 교정했다. INNER·LEFT·RIGHT·FULL JOIN의 보존 기준을 자기 말로 정리하고 hours.n=HOUR(DATETIME) 조건의 LEFT JOIN을 작성했다. 오른쪽 시간으로 GROUP BY한 시도를 hours.n으로 수정했으며, LEFT JOIN의 NULL 채움 행도 COUNT(*)는 세기 때문에 실제 ANIMAL_ID를 세어야 빈 시간이 0이 된다는 이유를 자기 말로 설명했다. 먼저 집계 후 JOIN하는 풀이에서는 없는 집계 행의 CNT가 NULL이 되어 COALESCE(CNT,0)가 필요하다는 순서 차이를 스스로 짚었다. 재귀·JOIN 문법과 최종 수정 풀이의 도움을 받았고 설명용 행 표는 실행 결과가 아니다. 최종 COUNT(ANIMAL_ID) 쿼리의 제출·전체 채점 통과와 도움 없는 재구현은 확인하지 않았다.
