    프로그래머스 「헤비 유저가 소유한 장소」에서 COUNT(*)>1을 WHERE에 넣은 시도로 시작해 그룹 개수 조건은 GROUP BY 뒤 HAVING에 적용한다는 교정을 받았다. SELECT ID, NAME, HOST_ID와 GROUP BY HOST_ID를 함께 쓰면 공간 여러 행이 소유자 한 행으로 요약돼 ID 일부만 보인다는 문제를 직접 짚었다. GROUP BY HOST_ID HAVING COUNT(*)>1로 대상 소유자 ID를 구하고 원본 PLACES의 HOST_ID IN(서브쿼리)로 모든 공간을 다시 조회하는 구조를 작성했다. ORDER BY HOST_ID를 공간 ID 기준인 ORDER BY ID로 교정받은 뒤 풀이를 마쳤다고 확인했다. 집계 결과와 원본 출력 행의 분리, HAVING과 IN 조건을 도움받아 완성한 풀이이며 별도의 채점 점수는 관찰하지 않았다.

    프로그래머스 「그룹별 조건에 맞는 식당 목록 출력하기」에서 회원 ID별 COUNT를 만들고 최상위 작성자 결과를 원본 리뷰에 다시 JOIN하는 방향을 직접 제안했다. 공동 최다 작성자가 세 명이어서 LIMIT 대신 REVIEW_COUNT=(SELECT MAX(REVIEW_COUNT) FROM review_counts)로 모두 남기는 조건을 설명받았다. 회원별 그룹 결과에서 리뷰 텍스트·날짜를 바로 출력하려던 시도는 회원당 한 행으로 요약돼 모든 리뷰가 유지되지 않는다는 교정을 받았고, MAX_MEMBERS의 ID·이름을 원본 REST_REVIEW에 다시 JOIN하는 쿼리를 작성했다. 같은 수준의 WITH를 두 번 써 발생한 1064 오류는 WITH 한 번과 CTE 사이 쉼표로 수정했다. 참고 DENSE_RANK 코드도 동점 모두에 순위 1을 부여하므로 한 명만 고르는 코드가 아님을 설명받았다. 크롬에서 마지막 원래 쿼리를 그대로 제출 후 채점하여 정답·테스트 1 통과·100.0/100.0을 직접 확인했다. 첫 CTE의 미사용 리뷰 컬럼과 ORDER BY가 남고 DATE_FORMAT이 없는 원래 코드도 통과했다. 같은 코드의 코드 실행에서는 정소율·김민재·김서준의 리뷰 총 아홉 행을 정상 반환하면서 실패 표시가 나타났으며, 두 경로 판정 불일치의 내부 원인은 확인하지 않았다. 날짜 형식이나 한 명 선택을 실패 원인으로 추측했던 튜터의 안내를 실제 채점 결과에 따라 정정했다. MAX 조건과 CTE·원본 행 분리는 도움받아 완성했으므로 독립 초기 풀이로 확대하지 않는다.

    프로그래머스 「그룹별 조건에 맞는 식당 목록 출력하기」에서 회원 ID별 COUNT를 만들고 최상위 작성자 결과를 원본 리뷰에 다시 JOIN하는 방향을 직접 제안했다. 공동 최다 작성자가 세 명이어서 LIMIT 대신 REVIEW_COUNT=(SELECT MAX(REVIEW_COUNT) FROM review_counts)로 모두 남기는 조건을 설명받았다. 회원별 그룹 결과에서 리뷰 텍스트·날짜를 바로 출력하려던 시도는 회원당 한 행으로 요약돼 모든 리뷰가 유지되지 않는다는 교정을 받았고, MAX_MEMBERS의 ID·이름을 원본 REST_REVIEW에 다시 JOIN하는 쿼리를 작성했다. 같은 수준의 WITH를 두 번 써 발생한 1064 오류는 WITH 한 번과 CTE 사이 쉼표로 수정했다. 참고 DENSE_RANK 코드도 동점 모두에 순위 1을 부여하므로 한 명만 고르는 코드가 아님을 설명받았다. 크롬에서 마지막 원래 쿼리를 그대로 제출 후 채점하여 정답·테스트 1 통과·100.0/100.0을 직접 확인했다. 첫 CTE의 미사용 리뷰 컬럼과 ORDER BY가 남고 DATE_FORMAT이 없는 원래 코드도 통과했다. 같은 코드의 코드 실행에서는 정소율·김민재·김서준의 리뷰 총 아홉 행을 정상 반환하면서 실패 표시가 나타났으며, 두 경로 판정 불일치의 내부 원인은 확인하지 않았다. 날짜 형식이나 한 명 선택을 실패 원인으로 추측했던 튜터의 안내를 실제 채점 결과에 따라 정정했다. MAX 조건과 CTE·원본 행 분리는 도움받아 완성했으므로 독립 초기 풀이로 확대하지 않는다.
