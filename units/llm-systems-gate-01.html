PyTorch Causal LM 추론 Baseline

짧은 제목 · KV Cache·Batch

계획됨완료 조건 0 / 5

학습 후 할 수 있는 일동일 모델·Prompt에서 Cache·Batch·장치 이동·동기화와 현대 Decoder 연산을 분리해 PyTorch 추론 기준선을 만든다.

이 학습이 필요한 이유
모델 구조와 실행 조건의 효과를 먼저 분리해야 이후 vLLM의 스케줄링과 KV 관리 효과를 공정하게 해석할 수 있다.
완료 후 이어지는 일
고정 Benchmark 계약 아래 추론 엔진의 지연·처리량·메모리를 비교할 수 있다.
학습 내용 자세히 보기

입력 Tiny Decoder LM의 Forward·학습·생성 완료 결과와 로컬에서 실행 가능한 최소 사전학습 Causal LM을 사용한다. 특정 Parameter 규모를 강제하지 않고 현재 장치에 들어가는 가장 작은 모델로 흐름을 먼저 검증한다. 같은 모델·Prompt에서 No-cache와 KV Cache 생성, Batch 1과 Batch N을 비교합니다. GPU 실험에서는 모델·Tensor의 장치와 CPU↔GPU 메모리 이동, PyTorch의 CUDA 장치 디스패치, CUDA 비동기 실행과 동기화된 측정 경계를 확인합니다. RoPE·GQA·RMSNorm·SwiGLU를 작은 Module과 Shape으로 이해하고, 조건을 고정한 Naive PyTorch 추론 기준선을 만듭니다. RMSNorm에서 확인한 정규화 차이를 바탕으로 SwiGLU의 게이트 FFN, RoPE의 Q·K 위치 회전, GQA의 KV Head 공유를 차례로 확인합니다. GQA를 모델 가중치·KV Cache 메모리 예상에 연결하고 실제 할당량과 비교합니다. 같은 모델에서 입력 길이·출력 길이·Batch를 바꾸며 Prefill과 Decode의 계산·메모리 비용을 각각 측정합니다. 장치·Cache·실행 방식 변경 전후의 Logit 오차와 생성 결과를 검증한 뒤 속도·메모리 차이를 해석합니다. Prefill·Decode의 동작과 측정은 여기서 다루고, 별도 서버로의 분리 및 KV 전송 실험은 후속 학습 범위로 둡니다.

Prefill·Decode 비용 분리 측정

미충족

Prompt 전체로 초기 Cache를 만드는 Prefill과 Cache를 사용해 새 Token을 생성하는 Decode의 입력·연산·메모리 접근 차이를 설명합니다. 같은 모델·dtype·장치에서 Warm-up 및 GPU 동기화 경계를 고정하고 입력 길이·생성 길이·Batch를 하나씩 바꾸어 Prefill 시간·Decode Token당 시간·Peak 메모리를 기록합니다. Tensor Shape·Profiler 또는 측정 변화로 병목을 설명하고, Prefill은 항상 연산 병목이고 Decode는 항상 메모리 병목이라고 단정하지 않습니다. 모델 구간 시간과 서비스 Queue 등을 포함한 TTFT를 구분합니다.
