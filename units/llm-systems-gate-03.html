짧은 제목 · vLLM Serving

학습 후 할 수 있는 일PyTorch 추론 기준선을 실제 vLLM Serving Workload로 이전하고 동일 조건의 출력을 검증한다.

학습 내용 자세히 보기

PyTorch Benchmark 계약과 동일한 모델·입력·생성 조건으로 vLLM을 실행하고, OpenAI-compatible API Serving과 PyTorch 대비 출력 재현성을 검증한다. Scheduler와 KV Cache 최적화는 기본 Serving 기준선을 확보한 뒤 후속 Learning Unit에서 다룬다.

○

동일 모델을 vLLM에서 실행

미충족

Model·Revision·Tokenizer·dtype·Generation 조건을 Benchmark 계약과 동일하게 고정하고 PyTorch에서 사용한 모델을 vLLM으로 로드해 단일 Prompt 생성을 성공시킨다. vLLM·CUDA·PyTorch 버전과 GPU 모델, 전체 vllm serve 인자, max_model_len·gpu_memory_utilization 및 감지된 Attention Backend를 기록한다. 모델 시작 로그·Prompt와 Output Token ID·GPU VRAM 사용량까지 결과로 남기면 완료된다.

○

vLLM API Serving

미충족

vllm serve로 OpenAI-compatible API 서버를 실행하고 Non-streaming·Streaming 및 여러 동시 요청을 성공시킨다. 서버 실행 명령·Request와 Response·Streaming Token 도착 기록·동시 요청 성공 결과를 남기면 완료된다.

○

PyTorch와 vLLM 출력 검증

미충족

동일 Prompt·Tokenizer·Generation 조건에서 PyTorch와 vLLM의 Greedy Token ID를 비교하고 최초 불일치 위치를 찾는다. 차이가 있다면 Tokenizer·Position·dtype·Generation 설정을 확인하고 PyTorch와 vLLM Token ID 비교표·최초 불일치 위치·Generation Configuration·원인 분석을 남기면 완료된다.
