단일 GPU vLLM Serving Baseline

짧은 제목 · 단일 GPU vLLM Baseline

계획됨완료 조건 0 / 5

학습 후 할 수 있는 일다른 로드맵의 완료나 Evidence를 요구하지 않고 단일 GPU vLLM Serving 기준선과 비교 계약을 자체적으로 확립한다.

학습 안내

이 학습이 필요한 이유
Scheduler와 KV Cache를 분석하기 전에 단일 GPU 실행 환경·API·출력·측정 경계를 독립적으로 고정해야 한다.
완료 후 이어지는 일
같은 로드맵 안에서 Scheduler·Continuous Batching·KV Cache 변화를 통제된 조건으로 관찰할 수 있다.
학습 내용 자세히 보기

하나의 물리 GPU에서 사용할 모델·입력·생성·측정 계약을 이 유닛 안에서 정의하고, Transformers/PyTorch와 vLLM을 각각 새로 실행해 OpenAI-compatible API Serving·출력 검증·재시작 재현성을 확인한다.

단일 GPU 실행 환경과 생성 검증

미충족

CUDA_VISIBLE_DEVICES와 vLLM 설정에서 하나의 물리 GPU만 사용했음을 확인한다. Model·Revision·Tokenizer·Chat Template·Weight dtype·KV Cache dtype·max_model_len·gpu_memory_utilization·max_num_seqs, GPU·Driver·CUDA·PyTorch·vLLM 버전과 Attention Backend 및 전체 Server 명령을 기록한다. 동일 Prompt와 Generation 조건으로 단일 Prompt 생성을 성공시키고 Prompt·Output Token ID·Peak VRAM·정상 종료 및 유한값 여부를 남긴다.

○

OpenAI-compatible API Serving 검증

미충족

단일 GPU vLLM Server에서 Non-streaming·Streaming·여러 동시 요청을 성공시킨다. HTTP Status·오류 응답·Streaming Token 도착 순서와 종료 상태·Client와 Server Timeout 조건·요청과 응답·Server와 Client Log를 기록한다.

○

Transformers/PyTorch와 vLLM 출력 검증

미충족

동일한 로컬 Model Artifact를 Transformers/PyTorch와 vLLM에서 각각 새로 로드하고 이 유닛에서 선언한 Tokenizer·Prompt·Greedy Generation 조건으로 첫 Token Logit 또는 비교 가능한 출력·Greedy Token ID·생성 Sequence를 비교한다. 최초 불일치 위치를 찾고 Tokenizer·Chat Template·Position·dtype·Generation 설정 순서로 원인을 분석하며, 출력 일치를 일반적인 모델 품질로 확대하지 않는다.

○

단일 GPU 실행·비교 계약 자체 정의

미충족

Model·Revision·Tokenizer·Chat Template·Weight와 KV Cache dtype·Prompt·Output Token·Sampling·Seed·평가 모드·Greedy 조건을 지정한다. Warm-up·반복·측정 경계와 TTFT·TPOT·ITL·E2E·Throughput·Peak VRAM 계산 방식, Logit 허용오차와 Token·Sequence 일치 기준을 정의하고 이 로드맵 내부 기준으로 저장한다.

○

단일 GPU Server 재시작 재현성

미충족

Server를 종료한 뒤 저장된 명령과 설정만으로 다시 실행한다. Model·Tokenizer·Generation 설정과 GPU 한 장 사용이 동일하게 복원됐는지 확인하고 같은 요청의 Token ID 또는 생성 결과 및 API 성공 여부를 재시작 전후로 비교한다.

목표 문맥별 선택 이유

AI 모델 이해·추론·단일 GPU Serving에서 선택한 이유

Machine Learning의 문제 정의와 평가에서 시작해 PyTorch 학습 구조, Transformer 내부 계산과 사전학습 Causal LM 추론을 이해한다. 하나의 물리 GPU에서 실행할 모델·입력·생성·측정 계약을 독립적으로 정의하고, vLLM API Serving·Scheduler·Continuous Batching·KV Cache·SLO·Capacity·Observability를 검증해 병목을 측정 근거로 설명한다.
