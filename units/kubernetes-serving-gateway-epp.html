llm-d 요청 경로와 Gateway 연결

짧은 제목 · llm-d·Gateway 경로

선수 대기달성 기준 0 / 13

학습 후 할 수 있는 일실제 Gateway·EPP·Endpoint 요청 경로와 자원 관리·Runtime 책임을 연결해 설명한다.

학습 안내

이 학습이 필요한 이유
배포·복구·그룹 관계를 확인한 뒤 실제 요청 경로를 연결해 자원 관리와 요청 전달의 경계를 완성한다.
완료 후 이어지는 일
Routing·Admission·Streaming·장애를 실제 연결과 관측으로 비교한다.
학습 내용 자세히 보기

핵심 질문: GPU를 할당받은 서버까지 요청은 어떤 경로로 도달하는가? 개념·실습 흐름 Gateway·HTTPRoute·InferencePool·EPP(Endpoint 선택기)의 역할을 소개하고 실제 Mock Endpoint까지 연결한다. Streaming/Non-streaming 응답, 선택된 Endpoint·Health·Ready와 Gateway/EPP 수집 구성을 확인한다. llm-d의 관리 흐름과 요청 Sequence를 그린다. Device Plugin/DRA·GPU 요청·그룹·Pod Ready·Routing과 Runtime TP/NCCL/P-D/KV Transfer의 책임 및 설정 위치를 연결한다. 실험과 달성 기준 연결 구성요소·Endpoint·Pool 연결은 달성 기준 1~3 및 9~10, Streaming·Non-streaming·관측은 4~8, Sequence·계층 위치·자원 책임 설명은 11~13과 연결한다. 실행 조건과 검증 경계 호환되는 Gateway·InferencePool API·EPP 버전을 함께 고정한다. 맥에서 클러스터 접근이 필요하면 포트 전달 또는 적절한 터널을 사용하고 HTTP 응답과 라우팅 관측으로 연결을 검증한다. TP·NCCL·P/D·KV Transfer는 여기서 위치와 책임만 설명한다.
