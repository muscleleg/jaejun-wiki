학습 후 할 수 있는 일확장 신호에서 GPU 확보·Startup·Ready까지 시간축과 그룹별 자원 요구를 설명한다.

이 학습이 필요한 이유
과부하 신호와 그룹 자원 요구를 알고 나면 확장 결정과 실제 Ready 사이의 지연·병목을 분해할 수 있다.
완료 후 이어지는 일
전체 시간축에서 확장 지연·GPU 부족·Queue 회복의 관계를 검증한다.
학습 내용 자세히 보기

핵심 질문: Replica 증가 결정이 요청 처리 가능한 Endpoint가 되기까지 무엇이 필요한가? 개념·실습 흐름 GPU Utilization·Running·Waiting·Queue 신호를 비교하고 Autoscaling 입력과 Decision 근거를 기록한다. Replica 1→2, 다른 GPU Node 배치, GPU 부족과 반환, Startup Delay 변경을 통해 Metric → Decision → Desired → GPU 확보/Scheduling → Startup → Ready 시간축을 검증한다. 단일 Multi-GPU Pod와 LeaderWorkerSet 그룹 Replica의 총 GPU 예산을 비교하고 P/D 독립 확장 신호를 설명한다. Fake 확장·Startup을 실제 처리량·가중치 로딩 성능으로 해석하지 않는다. 실험과 달성 기준 연결 확장 신호 비교는 달성 기준 1~3 및 12, Scale-out·Node 배치·부족·관측은 4~9 및 15, Startup Delay와 Queue 결과는 10~11, 모의 성능 경계는 13~14, 그룹 확장 예산 비교는 16과 연결한다. 실행 조건과 검증 경계 선택한 Autoscaler·메트릭 연동 버전을 고정하고 낮은 Replica 수에서도 확장·부족·반환을 재현할 수 있게 Fake GPU 예산과 부하를 설정한다. 큰 처리량 수치가 아니라 결정·자원 확보·Ready의 인과관계를 검증한다.
