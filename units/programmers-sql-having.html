HAVING과 그룹 조건

짧은 제목 · HAVING·그룹 조건

계획됨달성 기준 0 / 3

학습 후 할 수 있는 일WHERE는 그룹화 이전의 행을, HAVING은 그룹화된 결과를 거른다는 차이를 설명하고 문제에 맞게 선택한다.

학습 안내

이 학습이 필요한 이유
개별 행의 조건과 그룹 전체의 조건을 혼동하지 않아야 집계 요구사항을 정확히 구현할 수 있다.
완료 후 이어지는 일
조건을 만족한 그룹의 ID를 다시 조회에 사용하는 풀이로 이어진다.
학습 내용 자세히 보기

WHERE와 HAVING의 적용 대상을 구분하고 그룹 필터링을 연습한다. 연습 문제: 헤비 유저가 소유한 장소, 우유와 요거트가 담긴 장바구니. 그룹에서 대상 ID를 찾은 뒤 원래 행을 조회하는 부분은 서브쿼리 학습과 연결한다.

WHERE와 HAVING 차이 설명

부분 충족

같은 테이블의 예제로 WHERE와 HAVING이 각각 어떤 대상을 거르는지 설명하고 조건 위치에 따라 결과가 달라지는 경우를 확인한다.

확인한 내용

  • 동명 동물 예제로 WHERE NAME IS NOT NULL은 행을, HAVING COUNT(*)>=2는 그룹을 거른다는 설명을 학습하고 행 필터→이름별 그룹→2행 이상 그룹→정렬의 흐름을 자기 말로 설명했다. HAVING 누락이 한 번 나온 이름까지 출력하는 원인임을 확인했다.

남은 내용

  • 같은 테이블에서 WHERE와 HAVING의 적용 위치에 따라 결과가 달라지는 비교 쿼리를 직접 작성하고 설명한다.

관련 학습 기록

  • 프로그래머스 「동명 동물 수 찾기」에서 SELECT NAME, COUNT(*)와 GROUP BY NAME을 직접 작성했다. 이름이 NULL인 행을 제외하는 WHERE와 이름별 개…

    프로그래머스 「동명 동물 수 찾기」에서 SELECT NAME, COUNT(*)와 GROUP BY NAME을 직접 작성했다. 이름이 NULL인 행을 제외하는 WHERE와 이름별 개수가 2 이상인 그룹을 남기는 HAVING을 설명받았고, HAVING을 빠뜨린 쿼리의 수정 안내 뒤 됐음을 확인했다. 이름 있는 행을 남기고 이름별로 논리 분리한 다음 2행 이상인 그룹을 남긴다는 흐름을 자기 말로 정리했으며 SELECT 결과를 모은 뒤 ORDER BY가 이름순으로 정렬함을 이해했다. HAVING과 NULL 제외 조건은 도움받아 보완했으며 독립 재구현이나 상세 채점 결과는 확인하지 않았다.

그룹 조건 직접 구현

부분 충족

그룹별 개수 조건과 여러 항목의 동시 존재 조건을 GROUP BY·HAVING으로 직접 작성한다.

확인한 내용

  • 동명 동물 수 찾기에서 GROUP BY NAME과 그룹별 개수 조건 HAVING COUNT(*)>=2를 수정 안내 후 적용했다.

남은 내용

  • 그룹별 개수 조건을 새 사례에서 직접 작성한다.
  • 여러 항목이 동시에 존재해야 하는 조건을 GROUP BY·HAVING으로 직접 구현한다.
