HAVING과 그룹 조건

WHERE는 그룹화 이전의 행을, HAVING은 그룹화된 결과를 거른다는 차이를 설명하고 문제에 맞게 선택한다.

WHERE와 HAVING 차이 설명

부분 충족

같은 테이블의 예제로 WHERE와 HAVING이 각각 어떤 대상을 거르는지 설명하고 조건 위치에 따라 결과가 달라지는 경우를 확인한다.

확인한 내용

  • 동명 동물 예제로 WHERE NAME IS NOT NULL은 행을, HAVING COUNT(*)>=2는 그룹을 거른다는 설명을 학습하고 행 필터→이름별 그룹→2행 이상 그룹→정렬의 흐름을 자기 말로 설명했다. HAVING 누락이 한 번 나온 이름까지 출력하는 원인임을 확인했다.
  • Milk·Yogurt 행을 WHERE의 OR로 남기고 CART_ID별 HAVING 종류 수 2 조건을 적용하는 쿼리를 직접 작성했다. 행을 먼저 거르고 그룹을 만든 뒤 조건을 만족하는 그룹의 공통 CART_ID를 출력한다는 흐름을 자기 말로 설명했다. HAVING에서도 AND로 그룹 조건을 조합할 수 있음을 확인했다.

남은 내용

  • 같은 테이블에서 WHERE와 HAVING의 적용 위치에 따라 결과가 달라지는 비교 쿼리를 직접 작성하고 설명한다.

관련 학습 기록

    프로그래머스 「동명 동물 수 찾기」에서 SELECT NAME, COUNT(*)와 GROUP BY NAME을 직접 작성했다. 이름이 NULL인 행을 제외하는 WHERE와 이름별 개수가 2 이상인 그룹을 남기는 HAVING을 설명받았고, HAVING을 빠뜨린 쿼리의 수정 안내 뒤 됐음을 확인했다. 이름 있는 행을 남기고 이름별로 논리 분리한 다음 2행 이상인 그룹을 남긴다는 흐름을 자기 말로 정리했으며 SELECT 결과를 모은 뒤 ORDER BY가 이름순으로 정렬함을 이해했다. HAVING과 NULL 제외 조건은 도움받아 보완했으며 독립 재구현이나 상세 채점 결과는 확인하지 않았다.

    프로그래머스 「우유와 요거트가 담긴 장바구니」에서 같은 행의 NAME이 두 값일 수 없으므로 그룹 안의 서로 다른 행에 대한 동시 존재를 검사해야 한다는 설명과 COUNT(DISTINCT NAME)=2 힌트를 받았다. Milk 또는 Yogurt 행을 남기는 WHERE, GROUP BY CART_ID, HAVING COUNT(DISTINCT NAME)=2, ORDER BY CART_ID를 직접 작성했다. SELECT에 CART_ID와 ID를 함께 넣었는데 실행 오류가 없었다고 확인하고, 한 그룹에 여러 ID가 있어 단일 값으로 정해지지 않는 이유를 질문했다. 행 필터→장바구니별 그룹→종류 수 조건→공통 CART_ID 출력→정렬의 흐름을 자기 말로 설명했다. COUNT(DISTINCT NAME)은 행 수가 아닌 종류 수라는 점을 보완했다. 일반 ID·NAME·PRICE 출력의 모호성, ONLY_FULL_GROUP_BY 설정에 따른 허용·거절, 우연히 같은 가격과 WHERE가 보장하는 단일 값의 차이를 질문하며 설명받았다. Milk·Yogurt 그룹의 가격까지 같은 확장 예제로 HAVING의 MIN(PRICE)=MAX(PRICE)와 SELECT MIN(PRICE), NULL 제외 조건을 학습하고 HAVING에도 AND 조건을 결합할 수 있음을 확인했다. 서버 SQL 모드 조회와 가격 비교 확장 예제의 직접 실행은 확인하지 않았다. 힌트와 검토를 받은 풀이이며 ID를 제거한 최종 쿼리의 전체 제출 통과나 도움 없는 독립 풀이로 기록하지 않는다.

그룹 조건 연습 문제 통과

부분 충족

헤비 유저가 소유한 장소와 우유와 요거트가 담긴 장바구니의 전체 테스트를 통과하고 대상 그룹과 최종 출력 행의 관계를 설명한다.

확인한 내용

  • Milk·Yogurt 동시 존재 조건을 CART_ID 그룹과 COUNT(DISTINCT NAME)=2로 직접 작성하고, 그룹 공통 값인 CART_ID를 출력한다는 관계를 설명했다. 불필요한 일반 ID 출력의 문제를 학습해 제거 안내를 받았다. 힌트와 검토를 받은 풀이이며 최종 전체 채점 통과는 확인하지 않았다.
  • 헤비 유저 문제에서 소유자별 HAVING 개수 조건으로 대상 HOST_ID를 찾고 원본 공간을 IN으로 다시 조회하는 쿼리를 작성했다. 그룹별 SELECT에서 공간 ID가 일부 빠지는 문제를 직접 짚었으며 HAVING·원본 재조회·정렬 교정을 도움받아 풀이 완료를 확인했다.

남은 내용

  • 우유와 요거트가 담긴 장바구니의 최종 CART_ID 조회 쿼리를 제출해 전체 테스트 통과를 확인한다.
  • 헤비 유저가 소유한 장소의 전체 테스트 통과 범위와 대상 그룹·원본 출력 행의 관계를 확인한다.

    프로그래머스 「헤비 유저가 소유한 장소」에서 COUNT(*)>1을 WHERE에 넣은 시도로 시작해 그룹 개수 조건은 GROUP BY 뒤 HAVING에 적용한다는 교정을 받았다. SELECT ID, NAME, HOST_ID와 GROUP BY HOST_ID를 함께 쓰면 공간 여러 행이 소유자 한 행으로 요약돼 ID 일부만 보인다는 문제를 직접 짚었다. GROUP BY HOST_ID HAVING COUNT(*)>1로 대상 소유자 ID를 구하고 원본 PLACES의 HOST_ID IN(서브쿼리)로 모든 공간을 다시 조회하는 구조를 작성했다. ORDER BY HOST_ID를 공간 ID 기준인 ORDER BY ID로 교정받은 뒤 풀이를 마쳤다고 확인했다. 집계 결과와 원본 출력 행의 분리, HAVING과 IN 조건을 도움받아 완성한 풀이이며 별도의 채점 점수는 관찰하지 않았다.
