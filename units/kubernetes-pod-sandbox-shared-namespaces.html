학습 안내

이 학습이 필요한 이유
kubelet·Runtime·CNI가 Pod를 준비한다는 제어 흐름을 실제 Linux 프로세스와 Namespace 구조로 내려가 이해해야 cgroup·Volume·Pod Network의 경계를 혼동하지 않는다.
완료 후 이어지는 일
Pod 프로세스의 자원 통제를 cgroup 계층으로 연결하고, Mount Namespace와 Volume 및 Pod에서 Node로 이어지는 네트워크 경로를 더 정확히 분석한다.
학습 내용 자세히 보기

Kubernetes Pod라는 논리적 객체가 Node에서 Pod Sandbox와 컨테이너 프로세스로 구현되는 구조를 살펴보고, pause 컨테이너를 기준으로 Network·IPC·UTS와 선택적 PID Namespace가 공유되는 방식을 정리한다. 컨테이너 프로세스의 실제 Socket Port, containerPort 선언, 같은 Pod의 eth0·veth 공유 관계도 함께 연결한다.
