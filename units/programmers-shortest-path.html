    풀이 횟수: 1회. 이전 풀이를 보지 않고 양방향 인접 리스트, `distance` 무한대 초기화와 `distance[1]=0`, Heap 반복, 낡은 후보 확인, 거리 완화와 `K` 이하 개수 계산까지 다시 구성했다. 처음에는 Heap Tuple 순서와 다음 후보에 전달할 도로 하나의 비용·누적 비용을 혼동했지만, `heapq`가 Tuple의 첫 값부터 비교하므로 표준 다익스트라는 `(new_cost, next_village)`를 저장해야 한다고 교정했다. 누적 비용을 보존한 채 마을 번호를 첫 값으로 두면 반복 완화로 수렴할 수 있어도 비용 우선 탐색과 효율성 보장을 잃는다는 차이도 설명했다. `heapq.heappop(heap)` 호출과 변수명 오타를 함께 수정했다. 제시한 제출 화면에서 같은 표준 코드의 프로그래머스 정확성 `100점`과 전체 `32개` 테스트 통과를 확인했다. 화면의 성공 제출 시각은 이전 날짜로 표시되므로 이번 학습일의 새 제출 시각으로 기록하지 않는다. 일반 BFS는 이동 단계만 최소화하므로 서로 다른 도로 비용의 최소 누적 비용을 보장하지 못한다는 점, 더 비싼 후보는 이후 양수 비용을 더해도 유리해질 수 없어 다시 넣지 않는다는 점을 설명했다. 시간 복잡도에서는 마을 수 `V`와 도로 수 `E`가 서로 다른 기준이며, Heap 삽입과 삭제는 각각 `O(E log V)`로 더한다는 점을 확인했다. 일반식 `O((V+E) log V)`에서 모든 마을이 거의 연결된 경우에만 `E≈V²`를 대입해 `O(V² log V)`가 된다고 자기 말로 정리했다. 핵심 Tuple 상태는 힌트로 교정했으므로 힌트 재구현 성공으로 기록하고, 9월 3일 무자료 복습은 유지한다. 배달 문제를 안내에 따라 처음 구현한 뒤 이전 코드를 보지 않고 인접 리스트·distance·Heap 반복·거리 완화·결과 계산을 다시 구성했습니다. Tuple 순서와 누적 new_cost 전달은 힌트로 교정했고, 표준 코드의 프로그래머스 정확성 100점·전체 32개 테스트 통과 증거와 BFS 비교·갱신 조건·복잡도 설명을 확인했습니다. 이전 코드를 보지 않고 인접 리스트·distance·Heap 반복·거리 완화·결과 계산을 다시 구성했습니다. Heap의 Tuple 순서와 누적 new_cost 전달은 힌트로 교정했으며, 표준 코드로 정확성 100점·32개 테스트 통과 증거를 확인했습니다. 일반 BFS와 가중치 최단경로의 차이, 개선되지 않은 경로를 다시 넣지 않는 이유, V·E 기준과 Heap 삽입·삭제를 합친 O((V+E) log V), 빽빽한 그래프에서 E≈V²를 대입한 O(V² log V)를 설명했습니다.

확인한 내용

  • 답과 단계별 설명을 참고해 양방향 가중치 그래프를 인접 리스트로 구성하고, heap 기반 다익스트라의 거리 갱신·오래된 후보 제외를 구현했으며, s·a·b에서 만든 거리표로 모든 분기점 k의 합승 비용을 비교하는 구조를 설명했다.
  • 두 번째 풀이에서 전체 구조를 다시 작성하고, current_node와 next_node의 역할 및 graph의 (다음 노드, 간선 비용)과 heap의 (누적 비용, 노드 번호) 차이를 오류 교정을 통해 확인했다.

남은 내용

  • 완성한 코드를 프로그래머스에 제출해 전체 테스트 통과 결과를 확인한다.
