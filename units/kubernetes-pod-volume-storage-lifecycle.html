Pod Volume과 Storage 연결

짧은 제목 · Pod Volume·Storage

완료달성 기준 3 / 3

학습 후 할 수 있는 일컨테이너 프로세스가 보는 파일 경로가 Pod Volume과 실제 Storage에 연결되는 과정 및 Pod·Container·Persistent Volume의 서로 다른 데이터 수명을 설명한다.

학습 안내

이 학습이 필요한 이유
Namespace와 cgroup으로 프로세스의 가시성과 자원 경계를 이해한 다음, 실행 환경의 나머지 축인 파일 시스템 경로와 데이터 수명 경계를 연결해야 한다.
완료 후 이어지는 일
Stateful Workload에서 Volume Mount 실패, PVC Pending, Zone 불일치, 재생성 후 데이터 유지 여부를 계층별로 진단한다.
학습 내용 자세히 보기

프로세스가 파일 경로를 통해 저장소에 접근하는 Linux Mount 원리에서 시작해 Pod Volume이 Container의 Mount Namespace에 연결되는 방식과, PVC·PV·StorageClass·CSI를 통한 Persistent Storage의 생성·연결·수명주기를 정리한다.

    컨테이너의 실제 실행 주체인 프로세스는 Storage 객체가 아니라 Mount Namespace에 보이는 파일 경로를 사용하며, Kubernetes Volume 선언이 파일 시스템을 컨테이너의 mountPath에 연결한다는 구조를 정리했다. Container 쓰기 계층·emptyDir·hostPath·Persistent Volume의 수명 차이와 같은 Volume을 여러 컨테이너가 서로 다른 경로로 Mount할 수 있다는 점을 설명했다. PVC가 저장소 요구를, PV가 제공된 Storage를 표현하고 Pod는 PV가 아니라 PVC를 참조한다는 관계를 구분했다. 정적 방식에서는 PV가 먼저 준비되지만 동적 방식에서는 PVC가 StorageClass를 선택해 CSI Provisioner의 실제 Storage와 PV 생성을 촉발하며, WaitForFirstConsumer가 Pod 배치 위치를 기다리는 이유도 연결했다.
