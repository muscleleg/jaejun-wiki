    첫 Residual 결과의 Token별 평균을 빼고 표준편차로 나누면 각 Token의 마지막 특징 차원이 평균 0, 분산 1에 가까워진다는 흐름을 확인했다. `2.9802e-08`은 정확한 0을 Float로 계산하면서 생긴 매우 작은 오차이므로 사실상 0으로 해석했다. 두 번째 Residual 뒤에도 같은 이유로 별도의 `nn.LayerNorm(d_model)`이 필요하다고 먼저 예측하고 실행 결과로 검증했다. `nn.Linear(2,4)`는 층을 만드는 것이고, `expanded_output = ffn_expand(normalized_output)`은 그 층에 실제 Tensor를 넣어 실행하는 것임을 구분했다. 첫 Linear는 Token마다 더 넓은 중간 특징 공간을 만들고, GELU는 음수를 곧바로 노이즈로 판정하는 것이 아니라 학습된 중간 반응의 전달 정도를 부드럽게 조절하며, 두 번째 Linear는 `4 → 2`로 돌아오면서 현재 표현에 더할 수정값을 만든다고 이해했다. `x + Attention`을 정돈한 `normalized_output`에 FFN이 만든 `contracted_output`을 다시 더해 현재 표현이 사라지지 않게 한다고 설명했다. Dropout은 훈련 중 일부 원소를 확률적으로 0으로 만들고 살아남은 값을 보정하지만 Shape은 유지하며, `eval()`에서는 무작위 제거가 꺼져 같은 입력에 같은 결과가 나오는 것을 확인했다. Attention → Attention Dropout → 첫 Residual → LayerNorm → FFN 확장 → GELU → 축소 → FFN Dropout → 두 번째 Residual → LayerNorm을 하나의 클래스에 연결했다. 입력과 최종 출력 Shape이 모두 `[1,2,2]`로 유지되고, 최종 Token별 평균은 사실상 0, `unbiased=False` 분산은 1임을 확인했다. 각 Token의 Q가 질의 역할을 하고 K와 비교해 다른 Token을 얼마나 참고할지 비율을 만든 뒤, 그 비율로 V를 섞어 현재 Token의 문맥 정보를 만든다고 설명했다. 첫 Residual은 이 문맥 정보를 원래 `x`와 합쳐 기존 의미를 보존하고, 두 번째 Residual은 정규화된 현재 표현과 FFN 수정값을 합쳐 기존 표현을 보존한다. TransformerBlock의 구현·Shape·설명 완료 조건을 모두 충족해 Transformer 로드맵 6개 중 5개를 닫았다. 최근 Transformer 집중은 이 마일스톤을 완성하기 위한 생산적인 집중이었지만, 다음 Tiny Decoder LM에 바로 들어가기 전에 실제 데이터 분할·Baseline·Metric·일반화 경험과 PyTorch 학습 구조를 보강하기로 했다. 현재 순서는 회원 이탈 데이터 Baseline → `nn.Module`·Optimizer → Tiny Decoder LM 복귀다. IBM 공개 회원 이탈 CSV의 `7,043행 × 21열` 구조에서 한 행이 고객 한 명임을 확인했다. 숫자여야 할 `TotalCharges`가 `object`였고, `isna()`는 정식 NA만 찾기 때문에 공백 문자열 11개를 놓친다는 점을 구분했다. `str.strip().eq("").sum()`으로 숨은 공백을 찾고, Boolean 조건을 `df.loc[행 조건, 열]`에 넣는 불리언 인덱싱으로 해당 행을 확인했다. 공백 11행의 `tenure`가 모두 0임을 먼저 확인한 뒤 `pd.to_numeric(errors="coerce")`로 숫자가 아닌 공백을 `NaN`으로 바꾸고 `fillna(0)`으로 처리했다. 처리 뒤 결측값은 0개였고, 완전히 같은 중복 행도 0개였다. `isna()`는 “is NA?”로, `fillna()`는 “NA를 채운다”로 연결해 기억했다. `Churn`은 No 5,174명(73.46%), Yes 1,869명(26.54%)이었으며, `value_counts(normalize=True)`의 `normalize`는 평균이 아니라 각 개수를 전체 개수로 나눈 비율이라는 점을 확인했다. `customerID`와 정답 `Churn`을 제외해 `X=[7043,19]`, `y=[7043]`로 나누고, 80:20 분할로 Train 5,634명과 Validation 1,409명을 만들었다. `stratify=y`가 두 집합의 No·Yes 비율을 원본과 거의 같게 유지한다는 것도 직접 검증했다. Train에서는 `X_train`으로 만든 예측을 `y_train`과 비교해 가중치를 수정하고, Validation에서는 `X_valid`의 예측을 `y_valid`와 비교하되 가중치를 수정하지 않는다고 설명했다. 모델은 입력을 예측으로 바꾸는 계산 구조이고, 학습은 그 구조 안의 가중치를 정답에 가까워지도록 조정하는 과정이라고 이해했다. `DummyClassifier(strategy="most_frequent")`는 Feature 패턴을 사용하지 않고 `y_train`에서 가장 많은 No만 모든 Validation 고객에게 예측했다. 1,409개 예측이 모두 No임을 확인하고, 예측과 실제 정답을 비교한 Boolean 배열의 평균으로 Accuracy 73.456%를 수동 계산했다. NumPy `ndarray`는 값과 Shape 중심의 다차원 배열이고 Pandas `Series`는 index와 이름을 가진 1차원 자료구조이며, `pd.Series(dummy_predictions).value_counts()`로 예측별 개수를 세었다. 예측 출력 Shape은 입력 Feature 수가 아니라 예측 Target 수와 API의 반환 규칙에 따라 결정된다는 점도 구분했다. 숫자형 Feature와 범주형 Feature를 구분해 전처리한 뒤 Logistic Regression을 학습하고, 동일한 Train·Validation 분할과 Metric에서 Dummy Accuracy 73.456%를 넘어서는지 비교한다.
