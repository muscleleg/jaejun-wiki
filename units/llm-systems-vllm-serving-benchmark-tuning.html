대표 요청 선정과 Serving 실험 조건

미충족

짧은 질문·긴 입력·긴 출력·혼합 요청의 차이를 설명하고, 목표 서비스에 맞는 대표 요청 몇 가지를 선택해 이유를 기록한다. 입력·출력 Token 수, 공통 Prefix 유무, Sampling, 동시 요청 수, 초당 요청 수, 요청이 몰리는 정도, Warm-up·반복·측정 시간을 명시한다. 모든 요청과 설정의 조합을 전부 시험하지 않고 기본 설정에서 시작해 한 번에 분석할 변수를 구분한다.

○

SLO 설정과 Goodput·지연 변화 분석

미충족

본 측정 전에 첫 Token 대기 시간(TTFT)과 출력 중 Token당 시간(TPOT) 또는 Token 간격(ITL)의 허용값, 이를 만족해야 하는 요청 비율과 허용 오류율을 정한다. 실제 서비스 요구가 없으면 학습용 가정임을 밝힌다. 초당 성공 요청 수와 정한 지연 조건을 모두 만족하며 성공한 초당 요청 수(Goodput)를 구분한다. 거부·실패·Timeout도 전체 요청 수와 결과 집계에 포함한다. 초당 요청 수와 요청이 몰리는 정도를 높이며 처리량·대기·지연 분포·Goodput이 어떻게 변하고 어느 조건에서 SLO를 충족하지 못하는지 해석한다. 처리량 증가와 Goodput 감소가 반드시 동시에 나타나야 하는 것은 아니다.

○

단일 GPU 성능 지표와 충분한 표본 측정

미충족

고정한 대표 요청과 Server 설정에서 TTFT·TPOT 또는 ITL·전체 응답 시간·초당 요청 및 Token 처리량·Queue Time·Running·Waiting·Peak VRAM·KV Cache Usage·성공·거부·실패·Timeout을 수집한다. 각 지표의 출처·단위·측정 경계를 명시하고 직접 측정값과 추정값을 구분한다. Warm-up을 통계에서 제외하고 측정 시간·실제 요청 수·반복 횟수·분위수 계산법을 기록한다. P50·P95·P99를 산출하되 몇 회 실행한 결과만으로 P99를 확정하지 않는다. 높은 분위수를 해석할 표본 수와 반복 간 변동을 확인하고 부족하면 측정을 늘리거나 결론을 보류한다. 요청별 원본 결과와 집계를 함께 보존한다.

○

측정된 문제에 맞춘 Serving 설정 비교

미충족

기본 설정의 측정 결과에서 지연·대기·KV Cache 사용량 등의 문제를 하나 선택하고 원인 가설을 세운다. max_num_seqs·max_num_batched_tokens·gpu_memory_utilization·Prefix Caching·Chunked Prefill·지원되는 Admission 설정 중 가설과 관련된 설정만 골라 한 번에 하나씩 바꾼다. 동일한 대표 요청과 부하에서 변경 전후의 지연·처리량·Goodput·대기·메모리·거부와 실패를 비교해 유지할 설정과 이유를 정한다. 모든 설정을 빠짐없이 시험하거나 이미 검증한 내부 동작 실습을 반복할 필요는 없으며, 과거 결과를 재사용할 때는 현재 환경·요청·측정 조건과의 차이를 밝힌다.

○

SLO를 지키는 단일 GPU 수용 범위 정리

미충족

대표 요청별로 부하를 단계적으로 높여, 정한 측정 시간 동안 SLO와 허용 오류율을 충족하고 대기가 계속 누적되지 않는 가장 높은 시험 부하를 찾는다. 그때의 초당 요청 수·동시 요청 수·입력과 출력 길이·Server 설정을 기록한다. 다음 시험 부하에서 SLO 위반 또는 지속적인 대기 증가가 관찰되면 두 부하 사이를 수용 한계 범위로 제시한다. 안전상 중단하거나 시험 상한까지 문제가 없으면 확인한 범위만 기록하고 절대 최대치라고 단정하지 않는다. GPU·VRAM·모델·dtype·요청 조건·측정 시간·표본 수·지연 분포·처리량·Goodput·대기·KV Cache Usage와 정상·포화·과부하 판단 근거를 Capacity Table로 정리한다. 거부·Timeout·OOM은 관찰 여부를 기록하되 실제 OOM 유발은 필수가 아니다. 서버 장애까지 유도하지 않도록 중단 조건을 미리 정한다.
