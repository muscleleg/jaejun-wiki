단일 GPU Serving Benchmark·SLO·Capacity

짧은 제목 · 단일 GPU Benchmark·Capacity

선수 대기완료 조건 0 / 6

학습 후 할 수 있는 일단일 GPU의 Workload별 성능 분포를 측정하고 SLO를 만족하는 지속 가능한 Request Rate·Concurrency와 추천 Serving 설정을 결정한다.

학습 안내

이 학습이 필요한 이유
Scheduler와 KV Cache 원리를 검증한 뒤 측정해야 설정과 Workload 변화가 성능에 미치는 영향을 설명할 수 있다.
완료 후 이어지는 일
단일 GPU의 포화·과부하 경계와 병목 가설을 Serving·GPU Metric으로 검증할 수 있다.
학습 내용 자세히 보기

단일 GPU에서 Closed-loop와 Open-loop Workload를 구분하고 Prompt·Output·Request Rate·Concurrency·Burstiness를 통제한다. 지연·처리량·Queue·VRAM·KV Cache 결과로 SLO Goodput과 Capacity Envelope를 산출한다.

○

SLO·Goodput과 Trade-off 분석

미충족

측정 전에 TTFT와 TPOT 또는 ITL SLO를 정하고 성공 Throughput과 SLO를 만족한 Goodput을 구분한다. Reject·Failure·Timeout을 제외하지 않고 Request Rate·Burstiness 증가에 따른 Throughput·Queue·P50·P95·P99·Goodput을 비교해 Throughput은 증가하지만 Goodput이 감소하는 구간과 추천 설정을 찾는다.

○

Closed-loop와 Open-loop Benchmark 구분

미충족

Max Concurrency 기반 Closed-loop와 Request Rate 기반 Open-loop 실험을 각각 수행하고 요청 도착 모델, Client-side와 Server-side Queue, 시작·종료·Warm-up·측정 구간, GPU 동기화가 필요한 내부 측정과 서비스 E2E 측정의 차이를 설명한다.

○

단일 GPU Capacity Envelope 산출

미충족

Workload별 최대 지속 가능 Request Rate와 Concurrency, SLO를 만족하는 Prompt·Output 조합, Queue와 KV Cache Pressure 증가 지점, Reject·Timeout·OOM 시작 지점과 해당 vLLM 설정을 기록한다. GPU·VRAM·Model·dtype·Workload·TTFT·TPOT·P95·P99·Throughput·Goodput·Queue·KV Usage·정상·포화·과부하 판정을 Capacity Table로 정리한다.
