Multi-node 실행 그룹과 Gang·Topology 배치

학습 내용 자세히 보기

핵심 질문: 여러 Node의 Worker를 하나의 실행 그룹으로 어떻게 배치하고 복구하는가? LeaderWorkerSet·PodGroup·Volcano Scheduler의 책임과 호환 설정을 확인하고, Leader·Worker 및 그룹 Replica별 GPU 예산을 계산한다. 기본 Scheduler의 부분 배치와 Volcano의 그룹 단위 대기를 비교하고, GPU가 충분할 때 하나의 그룹이 여러 Node에 배치되는 결과를 확인한다. Node의 Rack Label과 exclusive-topology가 정의하는 같은 그룹 내 영역 제약, 서로 다른 그룹 Replica의 영역 분리도 다룬다. 실제 정책 적용에 따른 배치·대기 관찰은 별도 검증 대상으로 유지한다. 선택한 LWS 재시작 정책에서 Worker 장애 후 그룹 재생성과 Ready 복귀를 추적한다. Gang 배치 허용·Pod Ready·실제 모델 서빙을 구분하며, BusyBox·Fake GPU 실습을 실제 GPU 통신·추론 성능 검증으로 해석하지 않는다.
