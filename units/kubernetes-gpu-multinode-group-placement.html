Multi-node 실행 그룹과 Gang·Topology 배치

짧은 제목 · 그룹·Gang·Topology

선수 대기달성 기준 0 / 8

학습 후 할 수 있는 일멀티노드 실행 그룹의 GPU 예산·Gang·Topology·Worker 복구를 재현한다.

학습 안내

이 학습이 필요한 이유
개별 Pod 배치와 Controller 복구를 바탕으로 실행 그룹의 자원·Ready·재시작 조건을 확장한다.

요청 경로의 그룹 책임과 그룹 단위 확장·업데이트 예산을 설명한다.
학습 내용 자세히 보기

핵심 질문: 여러 Node의 Worker를 하나의 실행 그룹으로 어떻게 배치하고 복구하는가? 개념·실습 흐름 LeaderWorkerSet·PodGroup·Scheduler의 책임과 호환 설정을 확인하고 Leader·Worker 그룹 및 Replica별 GPU 예산을 계산한다. Gang Scheduling의 최소 그룹 자원 요구와 가상 Topology 조건을 바꿔 정상 배치·대기를 비교한다. Worker 장애에서 재시작 정책·개별/그룹 재생성·재할당·Ready를 추적하고 GPU 여유가 충분/부족한 경우를 재현한다. 실제 GPU 연결 성능과 구분한다. 실험과 달성 기준 연결 버전·그룹 구성·예산 계산은 달성 기준 1~3, Gang·Topology 정상/부족 비교는 4~5, Worker 복구는 6, 관계·책임 설명과 재현은 7~8과 연결한다. 실행 조건과 검증 경계 모든 Node는 같은 Host에서 실행되는 논리적 Node다. 그룹 구성원이 실제 CPU 컨테이너로 실행되는지 확인하고 Gang 조건과 동시 Ready를 구분한다.

미충족

그룹 크기와 Replica 수 구분

미충족

○

그룹 단위 자원 확보와 대기

미충족

선택한 Scheduler의 지원되는 Gang 설정에서 최소 그룹 요구량보다 Fake GPU가 부족한 상황과 충분한 상황을 비교한다. PodGroup 상태·Pod binding·Event로 그룹 단위 스케줄링 결정을 확인하고 자원이 풀린 뒤 배치가 진행되는지 검증한다. 동시 배치 허용과 모든 컨테이너의 같은 순간 실행·Ready를 구분한다.

○

가상 토폴로지 조건에 따른 그룹 배치

미충족

Node의 가상 rack·zone 등 Topology Label과 지원되는 그룹 배치 정책을 설정한다. 그룹을 같은 영역에 배치하거나 조건 미충족으로 대기시키는 사례를 관찰한다. Label 기반 배치 검증을 실제 NVLink·RDMA 연결이나 성능 검증으로 해석하지 않는다.

○

미충족

Mock Worker를 종료하고 선택한 LeaderWorkerSet 재시작 정책에 따른 개별·그룹 재생성, Ready 상태와 Fake GPU 재할당을 추적한다. 대체 자원이 부족한 경우와 충분한 경우를 비교한다.
