핵심 질문: 지금의 배치 상태를 수집하고 같은 환경을 다시 만들 수 있는가? 개념·실습 흐름 Prometheus·Grafana·kube-state-metrics를 연결하고 Pod·Replica·Scheduling Event를 같은 관측 환경에서 확인한다. 실제 상태와 Synthetic 값의 Label·Dashboard·문서 구분, Fake/관측 도구의 버전·지원 범위를 고정한다. 기본 환경의 Helm Values·Manifest·Dashboard·Topology를 보존한 뒤 재생성하고 수집·화면 복구를 확인한다. 실험과 달성 기준 연결 수집·Dashboard 구성은 달성 기준 1~6, 실제/Synthetic 구분은 7, 저장·재생성·수집 복구는 8~10, 버전·실행 경계 고정은 11과 연결한다. 실행 조건과 검증 경계 ARM64 이미지·Kubernetes API·Helm 설정의 실제 호환 버전을 고정한다. 메모리가 제한된 환경에서는 필요한 수집기만 켜고 보관량을 줄이되 관측 대상은 생략하지 않는다. 멀티노드 저장소 호환성을 확인하고 생성물은 클러스터 밖에 보존한다. GPU 등록 단계에서 시작한 환경 기록을 여기서 관측 도구까지 완성한다.

미충족

Kubernetes·Minikube·Fake GPU Operator·관측 도구의 버전과 지원 범위를 기록한다. GPU 종류·수량·메모리가 다른 Node Pool을 정의하고 컨테이너가 실제 실행되는 Node를 사용한다. 단순 상태 시뮬레이션 Node와 실제 Mock HTTP 응답을 구분한다.

Fake GPU 환경에서 쿠버네티스의 GPU 자원 등록·할당·Node 및 그룹 배치와 LLM Serving 운영을 먼저 익힌다. 이후 실제 Multi-GPU 환경에서 분산 추론의 계산·통신·메모리·성능을 검증하고 Kubernetes의 자원 관리와 Runtime의 GPU 사용·통신 책임을 구분한다.
