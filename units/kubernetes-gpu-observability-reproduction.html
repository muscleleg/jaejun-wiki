학습 내용 자세히 보기

핵심 질문: GPU 배치 결과를 메트릭과 Event로 어떻게 관찰할 수 있는가? Prometheus·Grafana·kube-state-metrics를 연결해 Node·Pod·Deployment·Replica 상태를 수집한다. Pod의 Running·Pending·Ready·Restart Count와 Deployment의 Desired·Current·Ready를 조회하고, 스케줄링 불가 원인은 상태 메트릭과 Scheduler Event를 함께 해석한다. Fake GPU Exporter의 합성 사용률, Kubernetes 객체 상태 메트릭과 실제 GPU 하드웨어 측정의 증거 범위를 구분한다.

목표 문맥별 선택 이유

쿠버네티스 GPU 클러스터와 Multi-GPU Serving 학습에서 선택한 이유

Fake GPU 환경에서 쿠버네티스의 GPU 자원 등록·할당·Node 및 그룹 배치와 LLM Serving 운영을 먼저 익힌다. 이후 실제 Multi-GPU 환경에서 분산 추론의 계산·통신·메모리·성능을 검증하고 Kubernetes의 자원 관리와 Runtime의 GPU 사용·통신 책임을 구분한다.

  1. 경로 4 · GPU 배치 결과를 Prometheus·kube-state-metrics·Grafana에서 함께 관찰하고, 이후 Serving 계층의 Gateway·EPP·Mock Server 메트릭을 추가할 기준선을 마련한다.
