    Qwen2.5-1.5B-Instruct·vLLM 0.29.0에서 Prefix Caching과 Chunked Prefill을 끄고 전체 60Block 중 요청용 59Block으로 제한해 과부하 동작을 분리했다. max_num_seqs=2에 짧은 요청 세 개를 보내 Running 2·Waiting 1, 최대 Cache 사용률 69.49%, Preemption 0을 관찰했다. C의 TTFT 4052.13ms는 A·B의 약 4초 완료 시간과 대응해 실행 자리 대기가 원인임을 설명했다. Prompt 433·407Token인 A·B는 Prefill에서 54Block으로 시작했으나 Decode 중 59Block을 채웠다. A가 추가 Block을 요구할 때 B가 한 번 Preemption됐고 B의 29Block 반환 후 A가 1개를 받아 Free 28개가 됐다. B는 기존 출력 Token ID를 유지한 채 454Token을 다시 Prefill했고 두 요청은 모두 출력 256Token으로 완료했으며 Free 59개로 복구됐다. 요청 수 제한 2에서는 세 번째 C가 2.76ms에 503으로 거부됐고 Scheduler Trace에는 없었다. Prefill 대기량 제한 400에서는 Waiting Prompt 433Token인 B가 수용된 뒤 다음 C가 2.83ms에 503으로 거부되어 현재 대기량을 검사하는 동작을 확인했다. Client Read Timeout 0.5초인 B는 수용·Waiting·Trace 진입 후 521.70ms에 ReadTimeout이 발생했고 연결 종료 뒤 Waiting에서 제거됐다. A는 정상 완료하고 서버는 생존했다.
