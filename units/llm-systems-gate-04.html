단일 GPU Serving Metric 계약

미충족

현재 vLLM 버전의 /metrics에서 실제 노출되는 이름과 Label을 확인하고 Running·Waiting·Queue Time·성공·실패·Reject·Preemption·KV Cache Usage·Prompt와 Cached Token·Prefill과 Decode Time·TTFT·TPOT 또는 ITL·E2E·Request와 Token Throughput을 수집한다. 문서상의 Metric 이름을 실제 노출 확인 없이 가정하지 않는다.

○

단일 GPU 상태와 Serving Metric 연결

미충족

단일 GPU Utilization·VRAM Used 및 관측 가능한 Allocated·Reserved·Memory Activity 또는 Bandwidth·Power·Temperature를 수집하고 Sampling Interval을 기록한다. Client·Server·GPU Clock 기준을 맞춰 Request Rate·Queue·Prefill·Decode·KV Cache·실패 상태와 같은 시간축에서 비교한다.

○

통제된 Before/After 병목 검증

미충족

Queue·Prefill·Decode·KV Cache Capacity·GPU Compute·GPU Memory 또는 Bandwidth·CPU Tokenization·Client 중 병목 가설 하나 이상을 선택한다. 모델·입력·생성·측정 조건을 고정하고 설정 또는 Workload 변수 하나만 변경해 TTFT·TPOT·Queue·Throughput·VRAM Before/After를 비교한 뒤 가설을 채택·기각·보류하고 결과의 적용 범위를 명시한다.

○

단일 GPU Serving·GPU 시간축 Dashboard

미충족

Prometheus-compatible Backend와 Grafana 또는 동등한 관측 구성을 Kubernetes 없이 사용한다. Request Rate와 Running·Waiting, Queue와 TTFT, Prefill-heavy와 GPU Utilization, Decode-heavy와 TPOT, KV Cache와 Preemption·Reject, VRAM Pressure와 실패, Prefix Cache Hit과 Prefill·TTFT를 같은 시간축에서 관찰한다.

○

반증 가능한 병목 가설 수립

미충족

○

단일 GPU 최종 운영 판단

미충족

Workload별 추천 vLLM 설정과 만족하는 SLO, 안전한 Request Rate 또는 Concurrency 범위, Saturation 조기 경보 Metric과 Threshold 후보를 제시한다. Queue 증가·Preemption·Reject·OOM 발생 시 확인 순서를 재현 가능한 Runbook으로 작성한다.

AI 모델 이해·추론·단일 GPU Serving에서 선택한 이유
