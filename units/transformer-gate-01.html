    Tensor.remainder(divisor)는 Tensor의 각 원소를 divisor로 나눈 나머지를 반환하며 `%` 연산자와 같은 의미다. torch.arange(1, fixed_prompt_length + 1)로 연속 Token ID를 만든 뒤 remainder(vocab_size)를 적용하면 각 값이 0 이상 vocab_size 미만 범위로 순환하고, unsqueeze(0)으로 Shape [sequence]를 [batch, sequence]로 바꿀 수 있다. fixed_prompt_length=5, vocab_size=4에서는 [1,2,3,4,5]가 [1,2,3,0,1]로 바뀌고 [1,5] Shape이 된다. 현재 실습의 Prompt 길이 512와 vocab_size 32000에서는 값이 그대로 1~512이지만, Prompt 길이가 Vocabulary 범위를 넘을 때 Embedding 입력 Token ID가 유효 범위를 유지하도록 하는 안전장치로 사용할 수 있다.

    `torch.zeros(1,3,10)`을 Batch 1개·예측 위치 3개·Vocabulary Token 10개의 Logit Tensor로 해석했다. `logits[0,0,7]=2.0`, `logits[0,1,2]=1.0`, `logits[0,2,9]=3.0`은 모델이 계산한 값이 아니라 각 위치의 특정 Token 칸에 직접 넣은 연습용 점수임을 구분했다. 따라서 이 단계는 학습된 예측의 성능 확인이 아니라 Logit 축과 이후 Loss 계산을 이해하기 위한 수동 예제다. `logits[0,0]`은 첫 Batch의 첫 위치에서 Token 10개에 준 점수 벡터이고, `softmax(...,dim=-1)`의 `-1`은 현재 Tensor의 마지막 축인 Vocabulary 축을 뜻한다. 따라서 `[1,3,10]`에서는 세 위치마다 Token 10개를 각각 Softmax하며, 점수 2를 넣은 7번 칸은 약 `0.4509`, 나머지 칸은 약 `0.0610`이 되었다. 선택된 값 하나에도 분모를 만드는 나머지 아홉 Token 점수가 모두 반영된다는 점을 확인했다. `first_target=7`은 값을 더하거나 정답에 보너스를 주는 수가 아니라, 첫 위치의 Softmax 벡터에서 채점할 7번 열을 고르는 인덱스다. 선택값 `first_position_values[7]≈0.4509`에 `-log`를 적용해 Loss 약 `0.7966`을 얻었다. 선택값이 1에 가까우면 Loss가 0에 가까워지고, 0에 가까우면 Loss가 크게 증가한다는 방향도 설명했다. `[3,10]` Logit의 각 행에서 Target `[7,2,9]`가 지정한 열을 하나씩 채점했다. `CrossEntropyLoss(reduction="none")`으로 위치별 Loss `[0.7966,1.4612,0.3702]`를 확인하고, 그 평균이 `0.8760`임을 계산했다. 기본 `CrossEntropyLoss()`가 위치별 결과를 평균내 Scalar 하나를 돌려준다는 점과, 이 계산이 분산의 `(값-평균)²`이나 MSE의 `(예측-정답)²`와 다른 방식임을 구분했다. 수동 Hidden State `[1,3,2]`에 `Linear(in_features=2,out_features=10)`을 적용해 Logit `[1,3,10]`이 되는 결과를 실행했다. LM Head가 Token 위치를 알아서 찾는 것이 아니라 `nn.Linear`가 입력의 마지막 Feature 축에 같은 선형식을 적용하고 앞의 Batch·Sequence 축을 보존한다는 원리다. 여기서 `in_features`는 `d_model`, `out_features`는 `vocab_size`이므로 각 위치마다 Vocabulary의 모든 Token 점수 하나씩이 나온다. 원본 `[[3,7,2,9]]`에서 입력 `[[3,7,2]]`과 Target `[[7,2,9]]`을 사용했다. LM Head가 이미 만든 Logit `[1,3,10]`을 `reshape(-1,10)`으로 `[3,10]`에 펼치고, Target `[1,3]`은 `reshape(-1)`로 `[3]`에 펼쳤다. `10`은 reshape가 새로 만드는 값이 아니라 LM Head 출력의 기존 Vocabulary 축이며, `-1`은 Batch와 위치를 합친 행 수 3을 자동 계산한다. 기본 Cross Entropy로 세 위치의 평균 Token Loss `2.4862`가 Scalar 하나로 나오는 실행 결과를 확인했다. `Embedding(num_embeddings=10,embedding_dim=2)`에 Token ID `[[3,7,2]]`을 넣어 `[1,3,2]` Hidden State를 얻었다. `vocab_size=10`은 반환 Shape에 10을 붙이는 값이 아니라 ID 0~9에 대응하는 `[10,2]` Embedding 표의 행 수이며, 입력 ID 3·7·2가 그 표의 해당 행을 조회한다. 학습 전 같은 Embedding 표에서는 어느 Sequence에 있든 같은 Token ID가 같은 벡터를 가져오고, 이후 위치 정보와 Attention 문맥이 더해지면 표현이 달라진다는 점까지 연결했다. 오래전 셀의 `target_tokens`처럼 현재 화면에 없는 변수를 기억한다고 가정하면 Shape과 값의 출처를 추적하기 어렵다는 문제를 확인했다. 앞으로 새 개념을 확인하는 연습 셀은 필요한 작은 입력·Target Tensor를 셀 안이나 바로 위 셀에서 다시 선언하고, Target을 먼저 추상적인 “정답 목록”으로 부르기보다 각 Logit 행에서 채점할 열 인덱스로 실제 선택 과정을 먼저 보여 주기로 했다. 오늘은 Token Embedding 실행까지 확인했다. 다음에는 학습 가능한 Position Embedding 예제를 새 독립 셀에서 실행해 Token 벡터와 위치 벡터의 합을 확인하고, 이를 기존 Causal TransformerBlock·LM Head에 연결한다. 그 뒤 전체 Target shift·Token Cross Entropy로 작은 학습을 수행하고 한 Token씩 생성해야 Tiny Decoder LM 완료 조건을 충족한다.
