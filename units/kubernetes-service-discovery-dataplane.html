    Service 이름 해석과 Packet 전달 규칙은 서로 다른 상태 동기화 과정임을 정리했다. CoreDNS의 Kubernetes Plugin은 API Server의 Service와 필요한 Endpoint 정보를 관찰해 DNS 응답을 만들고, 각 Node의 kube-proxy는 Service와 EndpointSlice를 관찰해 로컬 Service Data Plane을 갱신한다. API Server와 Watch는 상태 전달의 Control 경로이고 실제 DNS 질의와 Service Packet은 준비된 Data Plane을 사용한다는 점을 설명했다.

    ClusterIP는 특정 Node가 소유한 실제 Interface 주소가 아니라 각 Node에 미리 준비된 Service Data Plane이 인식하는 가상 접근점임을 정리했다. 하나의 Service IP와 여러 Endpoint Pod IP의 관계를 모두 반영하고 새 연결마다 Endpoint 하나를 선택해 목적지를 바꾸며, iptables Mode에서는 Service Chain과 확률 분기·Endpoint Chain·DNAT 규칙으로 이를 표현할 수 있음을 설명했다. IPVS·nftables·eBPF처럼 구현이 달라도 Service IP를 사용 가능한 Endpoint로 연결한다는 추상적 역할은 같다는 점도 구분했다.
