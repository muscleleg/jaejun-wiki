이 학습이 필요한 이유
PyTorch 기준선을 먼저 완료한 뒤 비교 조건을 고정해야 엔진 변경 효과와 모델·입력 길이·측정 방식의 차이가 섞이지 않는다.

모델·워크로드 조건 고정

미충족

비교에 사용할 모델·Revision·Tokenizer·가중치, dtype·Device, Seed·평가 모드, Prompt·Batch·Output Token 수와 Sampling 조건을 명시합니다. 해당되지 않는 Revision·Tokenizer 등의 항목은 임의 값을 만들지 않고 해당 없음으로 기록하며, PyTorch와 vLLM이 같은 의미의 입력과 생성 조건을 사용하도록 고정하면 완료됩니다.

○

측정 경계와 지표 고정

미충족

Warm-up·반복 횟수와 CUDA synchronize 위치, H2D·D2H 및 입력 준비·Cache 준비의 포함 여부를 명시하고 Prefill·Decode Token당·E2E 측정 경계를 구분합니다. 순수 모델 Prefill 시간과 Queue·전처리·통신을 포함할 수 있는 서비스 TTFT를 구분하며 Latency·TPOT 또는 ITL·Throughput·Peak VRAM의 계산식을 고정하면 완료됩니다.

○

출력 검증 계약 고정

미충족

같은 Token 문맥의 Logit에 적용할 atol·rtol과 유한값 검사, Greedy Token·생성 Sequence 일치 기준을 명시합니다. 허용오차 안의 차이를 수치 오차로 판정하는 기준과 허용오차 초과 시 첫 분기 Token에서 Mask·Position·KV Cache·Block·LM Head를 순서대로 확인하는 진단 경계를 정하면 완료됩니다.
