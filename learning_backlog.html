작은 Tokenizer와 Tiny Decoder 연결: 문자열을 Token ID로 바꾸는 단어장과 인코딩·디코딩을 만들고, Tiny Decoder의 입력·출력에 연결해 보기. 사전학습 모델의 Tokenizer와 Vocabulary가 어떻게 대응하는지도 살펴보기.

Multi-Head Attention과 Tensor 축 변환 복습: Q·K·V부터 Score Scaling, Mask, Softmax, Value 가중합, Head 병합까지 직접 재구성하기. 각 단계의 Shape과 view·transpose·reshape의 정방향·역방향 변환을 함께 연습하기.

PyTorch 고급 인덱싱: 여러 인덱스 Tensor를 짝지어 Batch마다 다른 Token 위치를 선택하는 방법 익히기. 작은 Tensor에서 logits[batch_indices, token_positions, :]를 직접 구성하고 슬라이싱과 결과 Shape의 차이 확인하기.

Autograd 내부 추적: Version Counter, View Tracking, in-place 변경 감지가 작동하는 원리 알아보기. no_grad와 inference_mode가 추적 정보를 다루는 차이 살펴보기.

CUDA 실행 원리와 GPU Kernel 최적화: 목표는 PyTorch가 대신 처리하던 GPU 실행을 한 단계 아래에서 이해하고, 측정 결과를 근거로 연산 병목을 설명하고 개선하는 것이다. 먼저 PyTorch에서 GPU를 사용하는 것과 CUDA Kernel을 직접 작성하는 것의 차이를 구분하고, CPU와 GPU 사이의 데이터 전송, Host·Device 메모리, 비동기 실행, 동기화, Stream의 역할을 확인한다. 이어 Grid·Block·Thread·Warp의 실행 구조와 Register·Shared Memory·Global Memory의 차이, 연속적인 메모리 접근, 분기와 병렬도 저하가 성능에 미치는 영향을 학습한다. PyTorch Profiler·Nsight Systems·Nsight Compute로 연산과 메모리 병목을 찾고, 벡터 연산이나 Reduction 같은 작은 CUDA 또는 Triton Kernel을 구현한다. 기준 구현과 출력의 정확성, Warm-up 이후 Latency·Throughput, 입력 크기별 성능을 비교해 최적화가 실제 이득인지 검증한다. 또한 요청 Scheduling·KV Cache 관리 같은 추론 엔진 최적화와 개별 GPU 연산을 빠르게 만드는 Kernel 최적화가 서로 다른 계층의 문제임을 구분한다.

Kimi K3 구조 손코딩: 모델 구조를 살펴보고 핵심 구성요소를 교육용으로 작게 줄여 직접 구현해 보기.

MoE Router·Expert 구현: Router가 Token을 Expert에 배분하는 흐름을 손코딩하고, Expert Parallel에서 계산과 통신이 어떻게 나뉘는지 연결해 보기.

MLE·NLL·Entropy·KL 연결: 같은 확률 분포 예제로 최대우도와 음의 로그우도, 엔트로피와 KL Divergence의 관계를 계산하고 비교해 보기.

모델 간 KV Cache 전송: 서로 다른 모델 사이에서 KV Cache를 옮겨 쓸 수 있는 조건과 한계, 변환이 필요한 경우를 알아보기.

작은 언어 모델 학습 시스템: 실제 문자열 말뭉치로 Tokenizer를 만들고, 모델 초기화·Optimizer·Checkpoint 저장과 복원을 연결해 작은 언어 모델을 학습시켜 보기.

분산 학습과 메모리 분할: DDP·FSDP·ZeRO가 계산과 학습 상태를 나누는 방식을 비교하고, Activation Checkpointing·Offload의 메모리 절약과 비용을 살펴보기. 분산 추론의 Tensor Parallel과 차이 이해하기.

Scaling Law와 학습 데이터 품질: 모델·Token·Compute 규모의 관계를 공부하고, 데이터 Filtering·Deduplication·Mixing·Lineage를 포함한 학습 데이터 파이프라인 알아보기.

Post-training과 선호 정렬: SFT·Preference Optimization·RLHF·GRPO의 목적과 학습 방식을 비교하고, 조정한 모델의 성능과 선호 정렬을 평가하는 방법 알아보기.

Prefix Cache와 Cache-aware Scheduler 비교: vLLM의 Prefix Caching을 기준으로 Radix Tree 기반 Prefix 재사용과 다른 Runtime의 Scheduling 방식을 비교하기. 같은 Benchmark 조건에서 캐시 재사용 효과 측정하기.

ML Framework 내부: Reverse-mode Autodiff, 계산 Graph 실행, Operator Fusion, Compiler 최적화가 어떻게 연결되는지 공부하기.

데이터 압축·오류 복구·미디어 전송: Huffman Coding·LZ77·JPEG의 압축 원리, CRC·Reed–Solomon의 오류 검출·복구, HLS·DASH의 적응형 전송 방식 알아보기.

Bloom Filter와 확률적 Membership 검사: 원소의 포함 여부를 적은 메모리로 검사하는 원리와 False Positive를 이해하고, 정확한 검사를 하는 Hash Table과 비교하기.

파일 복구와 Git 저장 구조: 삭제된 파일의 Metadata와 Block 재사용이 복구 가능성에 미치는 영향 알아보기. Merkle Tree와 Git의 내용 기반 저장·무결성 검증 방식 공부하기.

CPU·JIT·Debugger·브라우저 Runtime: Branch Prediction, JIT Compilation, Breakpoint의 명령어 치환, Critical Rendering Path를 통해 프로그램이 실행되고 화면이 그려지는 내부 과정 공부하기.

메모리 안전성과 공격 완화: Buffer Overflow·Return Address Overwrite·Use-After-Free·Rowhammer·Meltdown의 원리와 방어 방법 알아보기. Stack Canary 등 완화 기법을 Stack·Heap·가상 메모리·CPU Cache와 연결해 이해하기.

인증·브라우저·애플리케이션 보안: Incognito Mode의 개인정보 보호 범위, TOTP·OAuth PKCE의 인증 흐름, Prototype Pollution·Insecure Deserialization·Unicode Normalization 우회·SQL Injection의 원인과 방어 방법 공부하기.

보안 사고와 공급망 공격 분석: Log4Shell·Heartbleed·XZ Utils 사례에서 취약점과 Package 공급망의 신뢰 경계가 무너진 원인 살펴보기. Process Injection·권한 상승·원격 코드 실행으로 이어지는 과정과 예방 방법 이해하기.

Prefill·Decode 분리와 KV Cache 이동: 긴 Prompt의 Prefill과 Decode가 만드는 자원 병목을 측정하고, 두 단계를 분리했을 때의 이득과 KV 전송 비용 비교하기. 기본 Multi-GPU Scaling을 기준으로 분리가 유리한 조건 알아보기.

토큰화와 서브워드 알고리즘: 문자열이 단어가 아니라 Token·Subword 단위로 분리되어 Vocabulary의 Token ID로 변환되는 원리를 알아보고, BPE·Byte-level BPE·WordPiece·Unigram·SentencePiece의 차이와 Chat Template·Special Token·Embedding으로 이어지는 흐름을 공부하기.

Triton GPU Kernel 입문: Triton이 Python 안에서 GPU Kernel을 작성할 수 있게 해 주는 전용 언어이자 Compiler 도구이며, PyTorch의 고수준 연산과 CUDA C++ Kernel 구현 사이에서 Custom Kernel과 연산 Fusion을 작성하는 데 사용된다는 점을 이해한다. 모델을 HTTP·gRPC로 서빙하는 NVIDIA Triton Inference Server와는 이름만 같을 뿐 목적이 다른 기술임을 구분한다. Program ID, Block Size, Pointer 연산, Mask, Load·Store, JIT Compile과 Autotune의 기본 동작을 학습한다. 먼저 벡터 덧셈 Kernel을 작성해 PyTorch 결과와 수치가 같은지 확인하고, 이후 Activation Fusion이나 Reduction 같은 작은 예제로 확장한다. Warm-up 이후 Latency·Throughput을 PyTorch 기준 구현과 비교하고 입력 크기에 따라 성능이 어떻게 달라지는지 측정한다. 이를 통해 내장 PyTorch 연산을 그대로 사용할 경우와 Triton Custom Kernel을 고려할 경우를 판단한다.

kubelet의 역할과 내부 구성: 각 Node에서 Pod 실행을 조율하는 흐름을 중심으로 Container Manager와 Device Manager가 CPU·Memory·GPU 같은 자원을 관리하는 방식, CRI를 통해 Container Runtime과 통신해 컨테이너를 생성·시작·중지하는 과정, Pod 상태를 관찰하고 API Server에 보고하는 흐름을 연결해 공부하기.

정렬 알고리즘과 복잡도: Bubble·Selection·Insertion·Merge·Quick·Heap Sort의 동작 원리를 직접 구현하고, 입력 크기 n에 따른 최선·평균·최악 시간 복잡도와 공간 복잡도를 비교하기. Stable Sort와 In-place Sort의 의미, 비교 정렬의 O(n log n) 하한, Counting·Radix Sort처럼 입력 조건을 이용하는 비비교 정렬도 함께 알아보고 어떤 상황에 어떤 정렬을 선택할지 판단해 보기.

GPU 모델 서버의 배포 전략과 업데이트 순간 GPU 용량: Rolling Update·Recreate·Blue-Green·Canary의 트래픽 전환, 서비스 중단 여부, 구·신 Pod 동시 실행과 추가 GPU 요구량을 비교하기. Kubernetes Deployment가 직접 제공하는 RollingUpdate·Recreate와 여러 Deployment·Service 또는 Argo Rollouts·Istio·KServe 같은 상위 도구로 구현하는 Blue-Green·Canary를 구분하고, 단일 GPU·GPU 공유·여유 GPU 조건에서 maxSurge·maxUnavailable을 포함해 어떤 전략을 선택할지 실습으로 확인하기.

Kubernetes taint·toleration 실습: Node에 taint를 추가·제거하고 Pod의 toleration 설정 유무에 따른 스케줄링 결과를 비교하기. NoSchedule·PreferNoSchedule·NoExecute를 각각 적용해 Pod 배치와 퇴거 동작을 관찰하고, kubectl describe와 Event로 원인을 확인하기.

/etc/resolv.conf는 무엇인가: 이 파일의 정체와 목적, 왜 필요한지부터 공부하기. DNS와 이름 해석의 기본 개념을 익히고, 프로그램이 도메인 이름으로 접속할 때 /etc/resolv.conf가 어떤 역할을 하는지 간단한 예시로 이해하기.

GPU·LLM 서빙에서 agentgateway 대신 Envoy 계열을 선택하는 이유와 전환 조건을 살펴본다. Envoy Proxy·Envoy Gateway·Envoy AI Gateway·Istio Gateway의 역할을 구분하고, Gateway API·InferencePool·EPP 연동에서 공통으로 유지되는 요청 흐름과 구현체별 설정 차이를 비교한다. 실제 운영 사례, 기존 인프라 연계, TLS·인증·정책, Streaming·타임아웃·재시도, 관측성과 유지보수 관점에서 선택 기준을 정리하고 필요하면 동일한 요청 경로를 Envoy 기반으로 재현한다.

후속 성능 분석: Runtime·Router 실험의 CPU·RAM 상세 인벤토리를 보완하고 요청별 Queue Time·TTFT를 계측해 E2E를 구간별로 분해한다. Routing·Queue·Admission 원리 단원의 필수 완료 조건과 분리한다.

후속 Capacity·SLO 분석: 응답 기한과 측정 구간·유입 조건을 고정하고 정상 완료·거절·실패를 함께 집계해 Goodput을 계산·비교한다. Routing·Queue·Admission 원리 이해 이후의 성능 검증으로 다룬다.

선택 보충: 프록시 Queue에서 아직 전달되지 않은 요청을 취소하고 대기열에서 제거되어 불필요한 Backend 처리가 발생하지 않는지 확인한다. 생성 중 취소 전파와 구분하며 Routing·Queue·Admission 단원의 완료를 막지 않는다.

TP 심화: 동일 호스트 TP=1·2·4의 성능·메모리·전 GPU 쌍 P2P 비교, 실제 추론 Collective 호출 횟수·통신량·소요 시간 프로파일링, 작은 PyTorch 측정과 nccl-tests 결과 대조, 실제 모델 Greedy Token·Logit/Logprob의 수치 차이 검증, 통제된 Worker 실패와 Rank별 오류 전파를 살펴본다.

vLLM 내부 실행 심화: 설치 버전의 API→Engine→Executor→Worker→응답 경로와 Process Tree·Leader/Kubernetes Pod의 역할을 연결하고, 초기 Worker 메모리 프로파일링부터 KV 예산 결정·Engine Block 할당/회수·Token Budget 관리 및 외부 GPU 부하와 예산 재산정의 경계를 추적한다.
