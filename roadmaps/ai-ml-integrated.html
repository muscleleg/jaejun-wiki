Transformer 손코딩·적용

완료 직접 유닛 완료 8 / 8

현재 목표에서 선택한 하위 유닛 (4)
  1. Transformer Block · PyTorch 학습·추론의 실행 흐름을 바탕으로 Attention·FFN·Residual·정규화의 숫자와 Shape을 연결해 Decoder 구현의 핵심 블록을 확인한다.
  2. Tiny Decoder LM · 검증한 Block에 Target shift·Token Loss·Causal Mask를 연결해 작은 Decoder의 학습·생성을 확인하고, 사전학습 모델의 같은 흐름을 해석할 기준을 만든다.
  3. Tokenizer·Model 로컬 저장과 오프라인 복원 · 모델과 토크나이저를 로컬에 함께 저장하고 새 프로세스에서 복원해, 이후 추론 비교에 재사용할 실행 기준을 확보한다.
  4. 사전학습 Causal LM 실제 적용 · 저장·복원을 포함한 토크나이저, Forward, 생성, 평가 흐름을 연결해 LLM 추론 시스템 학습의 바탕을 확인한다.

LLM 시스템·최적화

완료한 사전학습 Causal LM 흐름을 PyTorch 추론 Baseline·vLLM·Multi-GPU로 확장한다. 현재는 No-cache와 KV Cache를 같은 조건으로 비교하는 기준선을 만든다.

일부 완료 직접 유닛 완료 2 / 7

현재 목표에서 선택한 하위 유닛 (7)
  1. LayerNorm Feature 축 정규화 복습 · 같은 입력의 평균 중심화와 분산 정규화를 확인해 다음 RMSNorm 비교의 기준을 마련한다.
  2. RMSNorm 제곱평균 정규화 이해 · 평균을 빼지 않는 제곱평균 정규화를 직접 계산하고 LayerNorm과 비교해 추론 기준선의 정규화 연산을 이해한다.
  3. PyTorch Causal LM 추론 Baseline · 개별 연산 이해를 장치 이동, KV Cache, 측정 조건과 연결해 이후 성능 비교에 사용할 PyTorch 추론 기준선을 확인한다.
  4. vLLM 전에 고정하는 Benchmark 계약 · PyTorch 기준선의 모델·입력·장치와 Timing 경계를 비교 계약으로 고정해, 다음 vLLM 실행의 차이가 조건 변경 때문에 생기지 않도록 한다.
  5. vLLM 서빙과 스케줄러 · 고정한 Benchmark 계약으로 PyTorch와 같은 모델·입력을 실행하고 스케줄러와 KV 관리 설정을 비교해, 엔진 최적화의 효과를 측정한다.
  6. Observability와 병목 분석 · vLLM 실행에서 얻은 요청 지표와 GPU 상태를 Queue·Prefill·Decode에 연결해, Multi-GPU로 넘어가기 전 단일 GPU 병목의 근거를 확보한다.
  7. Multi-GPU Scaling · 단일 GPU 병목 설명을 기준으로 같은 조건의 Multi-GPU 실행과 통신을 비교해, 목표인 지연·처리량·메모리와 Scaling 차이의 종합 설명을 완성한다.
