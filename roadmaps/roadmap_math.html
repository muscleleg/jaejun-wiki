세션 재개와 학습 컨텍스트

  • focusedSessionId가 가리키는 세션이 있으면 그 세션의 첫 pending 단계부터 재개한다.
  • 로드맵·백로그에 소속된 여러 세션을 열어 둘 수 있지만 한 번에 하나만 active로 두며, 사용자의 선택이나 명시적인 session.focus 작업 없이 다른 세션으로 초점을 바꾸지 않는다.
  • 대화 중 한 번 다룬 독립 주제는 날짜별 학습 기록에만 남길 수 있다. 다음 대화에서도 이어갈 필요가 생기면 먼저 백로그 항목으로 승격한 뒤 backlog 세션으로 연다.
  • 학습을 시작하거나 재개할 때는 responseBrief를 사용해 현재까지 확인된 기록, 로드맵 또는 백로그에서의 위치, 현재 학습 단위와 목적, 왜 지금 필요한지, 지금 할 가장 작은 단계와 관찰·완료 근거, 다음에 열리는 결과 순서로 설명한다.
  • Notebook·소스 코드·테스트·CLI·화면·대화 등 현재 매체에서 실행 결과와 사용자 이해를 확인한 뒤, 파일 위치가 아니라 이해·검증·남은 질문·다음 행동을 Markdown 학습 컨텍스트로 기록한다.
  • 학습 컨텍스트는 특정 파일의 현재 존재 여부에 의존하지 않으며, 직접 확인하지 않은 내용은 완료 근거로 기록하지 않는다.
  • 모든 필수 단계의 학습 컨텍스트가 확인되기 전에는 현재 학습 단위를 완료하지 않는다.
  • 모든 단계의 완료와 각 단계의 검증된 학습 컨텍스트가 확인되면 LLM이 해당 sessionId의 범위와 현재 progressionMode·관문 관계를 근거로 다음 작은 학습 단위를 만들고 session.advance-current-unit으로 전환한다. 관문이나 백로그 단계도 끝났다면 같은 Plan에 해당 진행 상태 변경을 별도 작업으로 기록한다.
  • 학습 세션을 마감할 때 LLM은 대화의 실제 학습 구간을 근거로 그날의 하루 총 학습시간을 분 단위로 판정하고 history.set-study-time에 절대값과 추정 여부만 전달한다. 근거가 부족하면 시간을 꾸며내지 않는다.

대화형 손코딩 학습

  • 사용자가 코드를 직접 입력한다.
  • 개념과 필요성을 설명한 뒤 독립 실행 가능한 작은 코드 셀과 예상 Shape·값을 제공하고 저장된 실행 결과를 검증한다.
  • 한 번에 새로운 핵심 개념 하나를 다루며 완료되지 않은 단계를 건너뛰지 않는다.
  • 새로운 클래스·메서드·API·모델 객체는 사용 전에 역할과 입력·출력을 먼저 설명한다.
  • 추상적인 용어보다 현재 코드의 실제 숫자와 Shape을 우선한다.
  • 연습 셀은 필요한 작은 입력·Target·상수를 다시 선언해 독립 실행 가능하게 만들고, 상태를 재사용해야 할 때는 이유를 설명한다.
  • 사용자가 자료 없는 재구현을 선택한 검증 단계가 아니라면 과제 순서만 주고 샘플 코드를 생략하지 않는다.
  • 외부 강의·교재는 출처로 사용하되 학습 단위를 개념 설명·예측·손코딩·실행 증거·자기 말 설명 순서로 재구성한다.

  • 설명을 듣거나 코드를 따라 입력한 사실만으로 완료 처리하지 않는다.
  • 자기 말 설명·조건 변경 결과 예측·자료 없는 재구현·의도적 변경 설명 중 하나 이상의 증거를 확인한다.
  • 대표 실습은 입력과 정답 설명·핵심 Shape 예상·Metric 평가·조건 변경 설명·핵심 코드 재구현을 확인한다.
  • 완료 기준을 충족하면 선택 심화보다 먼저 완료 사실과 남은 필수 단계 수를 명확히 알린다.
  • 캐시된 출력만 믿지 않고 필요한 import·변수·모델·입력이 포함된 상태에서 커널 재시작 후 재현되는지 확인한다.

  • 질문한 대상과 코드 줄을 먼저 특정하고 질문을 다른 개념으로 바꾸어 답하지 않는다.

로드맵 안내

  • 이 로드맵을 쓰는 방법: 독립 선수과목이 아니다 수학을 다 배운 뒤 모델로 넘어가지 않는다. ML·PyTorch·Transformer의 현재 질문을 해결하는 데 필요한 범위만 열고, 해결하면 즉시 원래 실습으로 돌아간다. 한 개념의 검증 순서 현재 코드의 질문 → 작은 숫자와 Shape 예측 → 손계산 → NumPy·PyTorch 결과 비교 → 조건 하나 변경 → 원래 코드에 적용 순서로 확인한다. 완료 판단 공식을 보거나 코드를 따라 실행한 것만으로 완료하지 않는다. 계산의 입력·출력과 모델에서의 역할을 자기 말로 설명하고, 작은 예제를 다시 만들거나 결과를 예측해야 증거로 남긴다.
  • 현재 확보한 연결과 남은 확인: 통계 · 부분 검증 평균·분산·표준편차를 실제 숫자로 계산하고 StandardScaler 결과가 평균 0·표준편차 1이 되는 것을 실행으로 확인했다. 분산 전개를 자료 없이 자기 말로 설명하는 복습은 남아 있다. 벡터와 Scaling · 구현에 사용 벡터 길이, 차원과 1 / √d 가 Attention Score 및 Embedding Scaling에서 어떤 크기를 조절하는지 기존 Transformer 구현과 연결했다. 삼각함수 · 구현에 사용 sin·cos의 파동과 쌍이 위치별 벡터 지문을 만드는 흐름을 Positional Encoding 코드와 연결했다. 미분과 Autograd · 부분 검증 y = wx + b 의 MSE, 수동 Gradient, backward() 와 Optimizer를 작은 PyTorch 예제로 확인했다. 회원 이탈 MLP와 Tiny Decoder LM 관문은 완료했지만, 여러 변수가 이어진 계산의 편미분과 Chain Rule을 유한차분과 Autograd로 대조하는 일은 후속 보강으로 남아 있다. 이는 현재 사전학습 Causal LM 적용의 다음 행동을 대체하지 않는다. 행렬 연산 · 구현에 사용 Transpose·Matrix Multiplication과 QKᵀ 의 Shape을 Attention 구현에서 사용했다. Dot Product·직교성·기저는 필요한 코드와 함께 더 명시적으로 확인한다.
  • 가장 가까운 두 연결: 회원 이탈 MLP · 당시 연결 질문: Logit이 sigmoid와 BCE를 지나 Loss가 되고, 각 Weight의 Gradient로 돌아가는가? 필요 수학: 편미분, 다변수 Chain Rule, 평균 Loss의 Gradient, sigmoid의 기울기. 검증: 한 Batch의 일부 값을 손계산하거나 유한차분으로 구해 Autograd와 비교한다. 당시에는 MLP 진행 순서를 바꾸지 않는 보강이었고, 현재는 완료된 MLP를 되돌리는 관문이 아니라 Tiny Decoder LM 흐름을 막지 않는 후속 복습이다. Tiny Decoder LM · 완료된 연결 질문: Logit에서 다음 Token 후보의 비율과 Token Loss가 어떻게 만들어지는가? 필요 수학: Softmax, Log Probability, Negative Log-Likelihood, Maximum Likelihood, Entropy·Cross Entropy·KL Divergence. 검증: 작은 Vocabulary의 Logit으로 비율 합과 정답 Token Loss를 계산해 PyTorch 결과와 비교하고, TinyDecoderLM 의 Cross Entropy Loss 감소와 자기회귀 생성을 완료했다. 같은 원리는 다음 사전학습 Causal LM의 NLL·Perplexity와 수동 생성에서 다시 사용한다.
  • 필요할 때 여는 수학 역량 지도: 1 · 벡터·Tensor·행렬 Scalar·Vector·Matrix·Tensor, Shape, Norm, Unit Vector, Dot Product, Transpose, Hadamard Product, Reduction, Matrix Multiplication을 실제 연산으로 확인한다. Basis·Orthogonal·Orthonormal은 Embedding·Projection·유사도 또는 차원 축소에서 필요할 때 연결한다. 2 · 미분·Gradient·Autodiff 변화율과 도함수, Product·Quotient·Chain Rule, Partial Derivative, 다변수 Chain Rule, Gradient를 다룬다. 손계산·유한차분·PyTorch Autograd가 같은 방향을 가리키는지 비교한다. 3 · 확률·통계 평균·분산·표준편차·기댓값에서 시작해 결합·조건부확률, Bayes Rule, 분포, Likelihood를 모델 평가와 Loss에 연결한다. Calibration과 불확실성은 실제 예측 확률을 평가할 때 확장한다. 4 · 최적화·수치 안정성 Gradient Descent, Learning Rate, 최소점과 곡률의 직관, 초기화, Floating-point 오차, 안정적인 Softmax와 LogSumExp를 학습 실패와 NaN 디버깅에 연결한다. 5 · 고유값·SVD·Low Rank Eigenvector·Eigenvalue, Eigendecomposition, SVD와 PCA를 차원 축소 실습에서 확인한다. Low-rank 근사는 LoRA의 ΔW = BA 와 모델 압축을 설명할 때 다시 사용한다. 6 · 적분과 평가 면적 적분 과정을 별도로 완주하지 않는다. ROC-AUC가 Threshold에 따른 곡선 아래 면적이라는 뜻을 이해하고, 작은 좌표의 사다리꼴 수치 적분을 라이브러리 결과와 비교할 만큼만 다룬다.
  • 보유 강의에서 취할 것과 미룰 것: 우선 취한다 Norm·Unit Vector, Dot Product·Matrix Multiplication, Transpose·Orthogonality, Chain Rule·Partial Derivative·Autodiff, MSE Gradient, Eigen·SVD·PCA·Low Rank, ROC-AUC의 수치 면적을 위 역량 지도의 해당 실습으로 압축한다. 필요할 때만 취한다 Linear System, Gaussian Elimination, Determinant, Matrix Inverse·Pseudoinverse의 반복 계산은 회귀 해법이나 수치 문제를 설명해야 할 때만 연다. Higher-order Partial Derivative도 곡률이나 최적화를 직접 비교할 때만 다룬다. 현재 제외한다 같은 개념의 TensorFlow 재구현과 API 사용법 반복, 행렬식·역행렬 계산 훈련, 적분 기법 전체 완주는 현재 Python·PyTorch 프로젝트 결과물에 직접 필요하지 않으므로 코어에서 제외한다.
  • 수학 보강 한 단위의 완료 조건: 질문과 대상 코드 특정 어느 값·Shape·Loss·Metric을 이해하기 위한 수학인지 한 문장으로 말한다. 작은 수로 예측과 손계산 실행 전에 결과의 Shape·부호·대략적인 크기를 예측하고 직접 계산한다. 코드와 비교 NumPy 또는 PyTorch 결과와 일치하는지 확인하고 오차가 있다면 원인을 구분한다. 조건 변경과 복귀 입력이나 차원을 하나 바꿔 결과를 설명한 뒤 원래 모델 코드에 그 의미를 적용한다.

1 · 벡터·Tensor·행렬

Scalar·Vector·Matrix·Tensor, Shape, Norm, Unit Vector, Dot Product, Transpose, Hadamard Product, Reduction, Matrix Multiplication을 실제 연산으로 확인한다. Basis·Orthogonal·Orthonormal은 Embedding·Projection·유사도 또는 차원 축소에서 필요할 때 연결한다.

예정

2 · 미분·Gradient·Autodiff

변화율과 도함수, Product·Quotient·Chain Rule, Partial Derivative, 다변수 Chain Rule, Gradient를 다룬다. 손계산·유한차분·PyTorch Autograd가 같은 방향을 가리키는지 비교한다.

예정

3 · 확률·통계

평균·분산·표준편차·기댓값에서 시작해 결합·조건부확률, Bayes Rule, 분포, Likelihood를 모델 평가와 Loss에 연결한다. Calibration과 불확실성은 실제 예측 확률을 평가할 때 확장한다.

예정

4 · 최적화·수치 안정성

Gradient Descent, Learning Rate, 최소점과 곡률의 직관, 초기화, Floating-point 오차, 안정적인 Softmax와 LogSumExp를 학습 실패와 NaN 디버깅에 연결한다.

예정

5 · 고유값·SVD·Low Rank

Eigenvector·Eigenvalue, Eigendecomposition, SVD와 PCA를 차원 축소 실습에서 확인한다. Low-rank 근사는 LoRA의 ΔW = BA 와 모델 압축을 설명할 때 다시 사용한다.

예정

6 · 적분과 평가 면적

적분 과정을 별도로 완주하지 않는다. ROC-AUC가 Threshold에 따른 곡선 아래 면적이라는 뜻을 이해하고, 작은 좌표의 사다리꼴 수치 적분을 라이브러리 결과와 비교할 만큼만 다룬다.
