목표 문맥별 선택 이유

AI 모델 이해·추론·단일 GPU Serving 문맥

Machine Learning의 문제 정의와 평가에서 시작해 PyTorch 학습 구조, Transformer 내부 계산과 사전학습 Causal LM 추론을 이해한다. 하나의 물리 GPU에서 실행할 모델·입력·생성·측정 계약을 독립적으로 정의하고, vLLM API Serving·Scheduler·Continuous Batching·KV Cache·SLO·Capacity·Observability를 검증해 병목을 측정 근거로 설명한다.

선택된 하위 로드맵

LLM 추론 기초

LayerNorm·RMSNorm·현대 Decoder 구성요소·KV Cache·Prefill·Decode를 PyTorch Causal LM에서 계산과 Tensor Shape으로 검증하고, 재현 가능한 추론 Benchmark와 출력 검증 계약을 정의한다.

일부 완료 직접 학습 단원 완료 3 / 4

현재 목표에서 선택한 하위 학습 단원 (3)
  1. LayerNorm과 RMSNorm 비교 실습 · 같은 Hidden State에서 LayerNorm과 RMSNorm을 직접 계산하고 비교해 현대 Decoder의 정규화 차이를 이해한다.
  2. Cache·Batch·GPU 성능 측정 · 정규화 이해를 장치 이동·KV Cache·Batch·GPU 측정 조건과 연결해 PyTorch 추론 성능 기준선을 확인한다.
  3. 벤치마크 테스트 기초와 측정 기준 · PyTorch 기준선의 모델·입력·장치와 Timing 경계를 비교 계약으로 고정해 다음 vLLM 결과를 공정하게 비교한다.

단일 GPU LLM Serving·최적화

하나의 물리 GPU와 단일 vLLM Runtime에서 API Serving·Scheduler·Continuous Batching·KV Cache·Benchmark·SLO·Capacity·Observability를 독립적으로 검증한다. Multi-GPU Replica·Tensor Parallel·Data Parallel·NCCL·Cross-node Runtime·Kubernetes는 완료 범위에 포함하지 않는다.

완료 직접 학습 단원 완료 4 / 4

현재 목표에서 선택한 하위 학습 단원 (4)
  1. 단일 GPU vLLM Serving Baseline · 고정한 계약으로 하나의 물리 GPU에서 vLLM API Serving·출력 검증·재시작 재현성을 확인한다.
  2. 단일 GPU Scheduler·Continuous Batching·KV Cache · 단일 GPU Serving 기준선에서 Request Lifecycle·Continuous Batching·KV Cache 할당과 회수·Overload 경계를 검증한다.
  3. 단일 GPU Serving Benchmark·SLO·Capacity · Scheduler와 Cache 동작을 확인한 뒤 Workload·부하·설정을 통제해 SLO를 만족하는 Goodput과 Capacity Envelope를 산출한다.
  4. 단일 GPU Observability·병목 분석 · Benchmark 결과를 Serving·Queue·Cache·GPU Metric과 같은 시간축에 연결해 병목 가설을 통제된 실험으로 검증한다.

쿠버네티스 GPU 클러스터와 Multi-GPU Serving 학습 문맥

Fake GPU 환경에서 쿠버네티스의 GPU 자원 등록·할당·Node 및 그룹 배치와 LLM Serving 운영을 먼저 익힌다. 이후 실제 Multi-GPU 환경에서 분산 추론의 계산·통신·메모리·성능을 검증하고 Kubernetes의 자원 관리와 Runtime의 GPU 사용·통신 책임을 구분한다.

선택된 하위 로드맵

분산 LLM Runtime 핵심

단일 GPU 기준선과 Routing·TP·NCCL·P/D·KV Transfer를 바탕으로 GPU Interconnect·실제 Data Movement → Cross-node Network Transport·NCCL·KV·PP → End-to-End 설계·진단 종합 실습 순서로 확장한다. 이미 배운 측정법은 각 단원에서 필요한 만큼 재사용한다. Benchmark·Capacity 재측정, 실제 GPU의 Gateway·EPP 정책 검증, 광범위한 Replica·TP·P/D Scaling 비교는 별도 선택 심화이며 필수 선수나 완료 조건이 아니다.

일부 완료 직접 학습 단원 완료 6 / 7

현재 목표에서 선택한 하위 학습 단원 (7)
  1. 단일 GPU vLLM Serving 기준선 · 쿠버네티스를 마친 뒤 실제 Multi-GPU 비교 실험 직전에 단일 A40 기준선을 확보한다. 기존 증거를 검토해 재사용 가능한 학습은 보존하고 다른 하드웨어·측정 조건과 미확인 항목만 보완한다.
  2. Routing·Queue·Admission 원리 · 단일 GPU 비교 기준을 실제 Endpoint Routing·Queue·Admission 실험으로 확장하고 쿠버네티스에서 관찰한 요청 제어와 연결한다.
  3. Tensor Parallel과 NCCL Collective · 요청 제어와 비교 기준을 갖춘 뒤 GPU 여러 장에서 Tensor 분할·NCCL 통신·메모리·성능 변화를 검증한다.
  4. Prefill·Decode Disaggregation과 KV Transfer · TP·Collective를 이해한 다음 Prefill과 Decode를 분리하고 KV Transfer의 비용과 병목을 측정한다.
  5. High-bandwidth GPU Interconnect와 Data Movement · TP·P/D의 추상화 아래에서 NCCL·NIXL이 사용하는 실제 GPU 연결 경로와 통신 비용을 먼저 배운다. Benchmark·EPP 재실습은 선수로 요구하지 않는다.
  6. Cross-node NCCL·KV Transfer와 Network Transport · 서버 내부의 Data Path 이해를 서로 다른 물리 서버의 Network Transport·Collective·KV·Activation 전달 및 장애로 확장한다.
  7. 분산 LLM Runtime End-to-End 설계·진단 종합 실습 · 계산·요청 제어·KV 전달·GPU 연결·서버 간 통신을 모두 배운 뒤 하나의 시스템을 선택·구성하고 병목과 장애를 독립적으로 진단한다.
