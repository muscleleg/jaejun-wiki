    제공한 아티클을 한국어로 옮겨 [외부 아티클 05](wiki/external-articles/llm_finetuning_12_techniques_source.html)에 저장하고, LoRA부터 Federated Fine-Tuning까지 12가지 기법을 이후 하나씩 설명하고 참조할 항목으로 식별했다. 이번 기록은 원문 보존 단계이며 아직 내용 검증이나 이해도 완료 증거는 없다. 기존 Weight `W`와 파인튜닝으로 새로 배울 `ΔW`를 구분하고, `4096 × 4096`의 16,777,216개 값 대신 `4096 × 8 + 8 × 4096`의 65,536개 값을 학습하는 계산을 설명했다. Rank 1·2의 독립 방향 예제와 `A → 8개 계수 → B`, `rank(BA) ≤ 8`을 연결해 [LoRA와 Low-Rank 변화량](wiki/llm-systems/lora_low_rank_adaptation_learning.html)에 기록했다. 표준 `α/r`, 초기화, 작은 구현 확인은 다음 검증 항목으로 남겼다. `x=[0,1,2]`, `y=[2,5,8]` Tensor를 `TensorDataset`으로 입력·정답 한 쌍씩 묶고 `DataLoader(batch_size=2)`에서 2개와 남은 1개 Batch가 나오는 것을 확인했다. Batch는 GPU 사용 여부가 아니라 데이터를 묶어 전달하는 단위이고, 실제 계산은 선택한 device에서 수행된다고 구분했다. 각 Batch의 `zero_grad → prediction → loss → backward → step`을 100 Epoch 반복해 학습 전 전체 Loss `38.047859`가 `1.64 × 10⁻¹⁰`까지 줄고 예측이 `[2,5,8]`에 가까워짐을 확인했다. 한 Epoch를 마친 뒤 출력하면서 `epoch: 0`이라고 쓰던 로그는 실제 1회 학습 뒤 값이므로 `epoch + 1`로 고쳤다. 공개 회원 이탈 표 `(7043,21)`에서 `customerID`와 `Churn`을 분리하고 `No=0`, `Yes=1`로 정했다. `TotalCharges`를 숫자로 바꾸고 공백 결측을 0으로 처리한 뒤, `stratify=y`로 Train `(5634,19)`·Validation `(1409,19)`를 나눴다. 숫자형 4개·범주형 15개를 같은 `ColumnTransformer`로 처리해 Train에서만 `fit_transform`하고 Validation에는 `transform`만 적용했으며, NumPy `(5634,45)`·`(1409,45)`를 `float32` Tensor로 옮겼다. 정답은 `reshape(-1,1)`에서 행 수를 자동 계산해 `[5634,1]`·`[1409,1]`로 맞췄다. TensorDataset으로 고객별 Feature 45개와 정답 1개를 짝짓고, Train은 `batch_size=64, shuffle=True`, Validation은 `shuffle=False`로 만들었다. 첫 Batch `[64,45]`·`[64,1]`, Train 89개·Validation 23개 Batch를 확인했다. Validation Dataset에 NumPy 배열을 잘못 넣었을 때 `TypeError: 'int' object is not callable`가 발생했으며, NumPy의 정수 속성 `.size`와 Tensor의 `.size(0)` 메서드 차이를 확인하고 `X_valid_tensor`로 수정했다. `ChurnMLP`를 `[batch,45] → Linear(45,16) → ReLU → Linear(16,1) → [batch,1]`로 만들었다. `64`는 바뀔 수 있는 Batch 고객 수이고 45는 고정 입력 Feature 수이며, 16은 고객 한 명의 45개 값을 학습 가능한 중간 조합 16개로 바꾼 개수라고 설명했다. ReLU는 음수를 정확히 0으로 만들지만 양수를 1 이하로 제한하지 않고, 마지막 Linear의 Logit은 음수·1보다 큰 수를 포함한 임의의 실수가 될 수 있음을 구분했다. Sigmoid가 제한 없는 Logit을 `0~1` 사이로 압축하며, 현재 학습 전 값은 과하게 해석하지 않고 **학습 전 sigmoid 출력값**이라고 부르기로 했다. 첫 고객의 `z=-0.2608`에서 `p=0.4352`, 정답 `y=0`이므로 개별 BCE가 `-log(1-p)=-log(0.5648)≈0.571`임을 따라 계산했다. 고객별 Loss 64개를 기본 `reduction="mean"`으로 평균내 초기 Batch Loss `0.6564000844955444`가 되는 흐름을 확인했다. 출력값 `0.8`에서는 정답 0의 `-log(0.2)`가 정답 1의 `-log(0.8)`보다 크며, `e^(-x)`가 더 작은 값이 되려면 `x`가 더 커야 한다는 관계로 설명했다. 분산은 값에서 평균을, MSE는 예측에서 정답을 빼는 방식이며 BCE는 정답 쪽 sigmoid 출력값에 `-log`를 적용하는 별도 Loss임을 구분했다. 전체 BCE 계산을 자료 없이 다시 구성하는 확인은 남아 있다. 자세한 내용은 [회원 이탈 MLP와 BCE 문서](wiki/pytorch/pytorch_churn_mlp_learning.html)에 정리했다. `SGD(model.parameters(),lr=0.1)`를 연결하고 한 Batch에서 `zero_grad → forward → BCE → backward → step`을 한 번 실행했다. 같은 Batch를 `no_grad()`에서 다시 계산했을 때 Loss가 `0.6564000844955444 → 0.6511512994766235`로 내려갔다. `optimizer.step()` 한 번마다 Gradient와 learning rate를 기준으로 weight·bias가 조금 조정되고, 이번 한 번의 수정에서는 Loss가 소폭 감소한 것이라고 자기 말로 설명했다. SGD 한 Step의 원리는 확인했지만 한 Batch 과적합이나 전체 Train·Validation 루프 완료로 표시하지 않는다. `Linear(45,16)`의 weight `[16,45]` 720개와 bias 16개, `Linear(16,1)`의 weight 16개와 bias 1개로 전체 학습 파라미터가 753개라는 계산을 설명 중이다. Linear weight는 `[out,in]`인 2차원 행렬이지만 입력 Tensor는 3차원 이상일 수 있고 마지막 Feature 축만 바뀐다는 점도 현재 질문으로 남아 있다. `nn.Linear(45,33,16)`의 세 번째 값은 새 출력 차원이 아니라 `bias` 위치 인자이며, `45 → 33 → 16`에는 Linear 두 계층이 필요하다. 이 내용은 아직 자료 없이 Shape·파라미터 수를 다시 설명한 증거가 없어 완료로 기록하지 않는다.

    `print(model)`은 `Linear(in_features=1,out_features=1,bias=True)`라는 구조를, `model.parameters()`는 실제 학습 대상인 weight·bias Tensor를, `model(x)`는 입력으로 만든 실제 예측값을 보여 준다는 차이를 확인했다. weight는 기울기, bias는 절편이며 무작위 초기값에서 학습을 시작한다. MSE는 분산의 `value−mean`이 아니라 `prediction−target`을 제곱해 평균내며 음수가 될 수 없다는 점을 구분했다. `loss.backward()`는 weight를 조금 움직였을 때의 Loss 순간변화율과 bias를 조금 움직였을 때의 순간변화율을 각각 계산한다는 흐름을 작은 숫자로 다시 연결했다. 한 Step에서 `∂L/∂weight`는 현재 bias를 고정한 관점으로, `∂L/∂bias`는 현재 weight를 고정한 관점으로 계산하지만 한쪽을 먼저 수정한 값으로 다른 쪽을 계산하지 않는다는 점을 확인했다. 두 Gradient는 같은 수정 전 `(weight,bias)` 상태에서 만들어지고 `optimizer.step()`이 함께 적용하며, 새 값의 상호 영향은 다음 Epoch부터 반영된다. `SGD(model.parameters(),lr=0.1)`은 수정 대상과 규칙을 등록할 뿐 즉시 값을 바꾸지 않으며, 학습률 0.1은 고정 0.1이 아니라 각 Gradient 크기의 10%를 적용한다는 뜻이다. Loss를 계산하는 Forward에서는 Gradient가 쌓이지 않고 `backward()`에서 기존 `.grad`에 누적되므로, 매 Step의 현재 Gradient만 쓰려면 `zero_grad()`가 필요하다는 점을 구분했다. `x=3,y=11` 하나만으로는 `3×weight+bias=11`을 만족하는 조합이 여러 개라 두 파라미터를 유일하게 정할 수 없고, 서로 다른 입력 데이터가 추가 조건을 제공해야 한다는 점을 확인했다. `no_grad()`는 기존 Gradient를 지우는 기능이 아니라 추론 시 backward에 필요할 연산 경로와 중간값을 저장하지 않아 큰 모델의 메모리 부담을 줄이는 기능으로 정리했다. `y=3x+2`를 101 Epoch 학습해 Loss를 `9.36×10⁻⁸`까지 줄였다. 최종 weight `2.9996803`, bias `2.0004435`, 새 입력 `x=3`의 예측 `10.999484`와 정답 11을 검증했다. Epoch 20부터 절대 오차가 이미 작았고, 실제 학습에서는 Validation 개선이 멈추는 시점을 Early Stopping 기준으로 삼는다는 점도 연결했다. 다음 챕터는 `Dataset·DataLoader`와 Batch 학습이다. 같은 활동에 관해 기존 복습 기록에 남아 있던 검증 요약 (새 활동·추가 시간 아님) nn.Module·MSELoss·SGD의 역할을 구분하고 weight·bias Gradient와 Parameter 수정을 실행했습니다.

BCE 식을 샘플 단위로 추적해 보며, MSE와 BCE의 차이를 구분했고(둘 다 평균이지만 계산 항이 다름), 현재는 이진 분류의 기본 관점(임계값 0.5 기준)으로 `Yes/No` 판정을 다루었다. `SGD(model.parameters(), lr=0.1)` 루프에서 `zero_grad → forward → BCE → backward → step` 순서를 직접 확인했고, 한 번의 step 후 loss가 내려가는 모습을 봤다. `loss.backward()`는 현재 배치 기준 기울기(.grad)를 쌓고, `step()`에서만 weight·bias가 실제 이동한다는 연결을 유지했다. 또한 `valid`에서 손실/accuracy를 함께 보고 과적합 가능성 판단을 준비했다. 학습된 모델 파라미터는 `state_dict`로 저장·복원 가능하고, 로드 후 동일 입력에 대해 `torch.allclose`로 출력 일치 체크를 해서 복원 신뢰성을 점검했다. 단일 고객 추론 시에도 동일 전처리 기준을 `transform` 후 텐서화해 `sigmoid`까지 확인하면서 배치 학습/단일 예측 경로의 일관성을 맞췄다.

Dropout은 훈련 중 일부 원소를 확률적으로 0으로 만들고 살아남은 값을 보정하지만 Shape은 유지하며, `eval()`에서는 무작위 제거가 꺼져 같은 입력에 같은 결과가 나오는 것을 확인했다.
