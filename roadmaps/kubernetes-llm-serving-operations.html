Kubernetes GPU 클러스터 운영

[Minikube 멀티노드·Fake GPU] GPU 자원 등록·할당·Node 배치에서 시작해 DRA, Multi-node 워크로드 그룹과 토폴로지 기반 배치, LLM Serving 배포·Routing·확장·장애 복구를 검증한다. GPU 장치는 가상으로 구성하고 Kubernetes API·Scheduler·Controller와 CPU용 Mock Server는 실제 실행한다. Device Plugin과 DRA는 호환 버전과 설정을 고정해 분리 검증하며 Fake 장치·Synthetic Metric을 실제 GPU 연산·통신·하드웨어 격리의 증거로 사용하지 않는다. 실제 Multi-GPU Runtime 학습과 독립된 로드맵이다. 학습은 GPU 등록·배치 → 기본 관측 → DRA 비교 → Serving 배포·복구·그룹 → 요청 경로·Routing·과부하·Streaming → 확장·장애·업데이트 → 통합 부하·재현 순서의 개념+실습 묶음으로 진행한다. 이 권장 순서와 필수 선수 관계는 구분하며 DRA 전체 완료로 기본 Serving 배포를 막지 않는다. Apple Silicon에서는 ARM64 이미지와 호환 API 버전을 고정한 별도 Minikube Docker 프로필을 사용한다. 메모리가 제한되면 필요한 구성부터 단계적으로 실행하되 Control Plane 1개·Worker 2개 이상 조건과 최종 통합 검증은 축소하지 않는다. 단일 노드는 예비 실습으로만 사용한다. 한 실험의 관측을 여러 달성 기준에 재사용하되 각 원문 요구를 별도로 판정한다.

목표 문맥별 선택 이유

쿠버네티스 GPU 클러스터와 Multi-GPU Serving 학습 문맥

Fake GPU 환경에서 쿠버네티스의 GPU 자원 등록·할당·Node 및 그룹 배치와 LLM Serving 운영을 먼저 익힌다. 이후 실제 Multi-GPU 환경에서 분산 추론의 계산·통신·메모리·성능을 검증하고 Kubernetes의 자원 관리와 Runtime의 GPU 사용·통신 책임을 구분한다.

GPU 자원 등록과 Pod 할당

GPU 등록·Pod 할당

핵심 질문: GPU는 어떻게 Kubernetes 자원이 되어 Pod에 할당되는가? 개념·실습 흐름 구성요소의 역할을 먼저 배우고 멀티노드 Minikube·Fake GPU Node Pool을 만든다. GPU 게시 → Capacity/Allocatable → Pod 요청 → 배치 → 자원 소진 시 Pending을 추적한다. Fake GPU Metric과 실제 하드웨어 관측의 차이를 설명한다. Allocatable이 예약 후 남은 GPU 수처럼 자동 감소한다고 해석하지 않는다. 실험과 달성 기준 연결 구성요소 설명과 Fake/실제 경계는 달성 기준 10~11, 멀티노드·Pool 구성은 1~6, GPU 게시·요청·소진 실험은 7~9와 연결한다. 실행 조건과 검증 경계 Apple Silicon에서는 Docker Driver와 ARM64 이미지를 사용하고 기존 프로필과 분리한 학습용 프로필을 선택한다. 단일 노드는 예비 실습일 뿐이며 이 학습 단원의 완료에는 Control Plane 1개와 Worker 2개 이상, 서로 다른 Fake GPU Pool이 필요하다. CUDA 연산 대신 CPU 컨테이너를 실행한다. Allocatable 총량을 예약 후 남은 수량으로 해석하지 않는다.

KServe 배포와 GPU 요청 전달

KServe 배포·GPU 요청

핵심 질문: Serving 설정은 어떻게 GPU를 요청하는 Pod와 응답하는 API가 되는가? 개념·실습 흐름 KServe·CRD·Controller의 최소 역할부터 설명하고 Mock API와 Synthetic Metric 노출·수집을 준비한다. Deployment와 LLMInferenceService를 비교해 배포하고, HTTP 응답·Request Rate·Status와 상위 CRD부터 Pod까지 관계를 확인한다. 여러 GPU 요청과 Node 선택 조건이 상위 리소스에서 Pod로 전달되는지 추적하고 Pending·조건 수정·복구를 재현한다. 핵심 질문: 저장된 자료만으로 전체 환경과 장애·복구를 재현할 수 있는가? 개념·실습 흐름 Model Server 장애·Endpoint 제외/복구와 Drain → Rolling Update → Rollback을 통합 실행한다.
