세션 재개와 학습 컨텍스트

  • focusedSessionId가 가리키는 세션이 있으면 그 세션의 첫 pending 단계부터 재개한다.
  • 로드맵·백로그에 소속된 여러 세션을 열어 둘 수 있지만 한 번에 하나만 active로 두며, 사용자의 선택이나 명시적인 session.focus 작업 없이 다른 세션으로 초점을 바꾸지 않는다.
  • 대화 중 한 번 다룬 독립 주제는 날짜별 학습 기록에만 남길 수 있다. 다음 대화에서도 이어갈 필요가 생기면 먼저 백로그 항목으로 승격한 뒤 backlog 세션으로 연다.
  • 학습을 시작하거나 재개할 때는 responseBrief를 사용해 현재까지 확인된 기록, 로드맵 또는 백로그에서의 위치, 현재 학습 단위와 목적, 왜 지금 필요한지, 지금 할 가장 작은 단계와 관찰·완료 근거, 다음에 열리는 결과 순서로 설명한다.
  • Notebook·소스 코드·테스트·CLI·화면·대화 등 현재 매체에서 실행 결과와 사용자 이해를 확인한 뒤, 파일 위치가 아니라 이해·검증·남은 질문·다음 행동을 Markdown 학습 컨텍스트로 기록한다.
  • 학습 컨텍스트는 특정 파일의 현재 존재 여부에 의존하지 않으며, 직접 확인하지 않은 내용은 완료 근거로 기록하지 않는다.
  • 모든 필수 단계의 학습 컨텍스트가 확인되기 전에는 현재 학습 단위를 완료하지 않는다.
  • 모든 단계의 완료와 각 단계의 검증된 학습 컨텍스트가 확인되면 LLM이 해당 sessionId의 범위와 현재 progressionMode·관문 관계를 근거로 다음 작은 학습 단위를 만들고 session.advance-current-unit으로 전환한다. 관문이나 백로그 단계도 끝났다면 같은 Plan에 해당 진행 상태 변경을 별도 작업으로 기록한다.
  • 학습 세션을 마감할 때 LLM은 대화의 실제 학습 구간을 근거로 그날의 하루 총 학습시간을 분 단위로 판정하고 history.set-study-time에 절대값과 추정 여부만 전달한다. 근거가 부족하면 시간을 꾸며내지 않는다.

대화형 손코딩 학습

  • 사용자가 코드를 직접 입력한다.
  • 개념과 필요성을 설명한 뒤 독립 실행 가능한 작은 코드 셀과 예상 Shape·값을 제공하고 저장된 실행 결과를 검증한다.
  • 한 번에 새로운 핵심 개념 하나를 다루며 완료되지 않은 단계를 건너뛰지 않는다.
  • 새로운 클래스·메서드·API·모델 객체는 사용 전에 역할과 입력·출력을 먼저 설명한다.
  • 추상적인 용어보다 현재 코드의 실제 숫자와 Shape을 우선한다.
  • 연습 셀은 필요한 작은 입력·Target·상수를 다시 선언해 독립 실행 가능하게 만들고, 상태를 재사용해야 할 때는 이유를 설명한다.
  • 사용자가 자료 없는 재구현을 선택한 검증 단계가 아니라면 과제 순서만 주고 샘플 코드를 생략하지 않는다.
  • 외부 강의·교재는 출처로 사용하되 학습 단위를 개념 설명·예측·손코딩·실행 증거·자기 말 설명 순서로 재구성한다.

이해도와 완료 판정

  • 설명을 듣거나 코드를 따라 입력한 사실만으로 완료 처리하지 않는다.
  • 자기 말 설명·조건 변경 결과 예측·자료 없는 재구현·의도적 변경 설명 중 하나 이상의 증거를 확인한다.
  • 대표 실습은 입력과 정답 설명·핵심 Shape 예상·Metric 평가·조건 변경 설명·핵심 코드 재구현을 확인한다.
  • 완료 기준을 충족하면 선택 심화보다 먼저 완료 사실과 남은 필수 단계 수를 명확히 알린다.
  • 캐시된 출력만 믿지 않고 필요한 import·변수·모델·입력이 포함된 상태에서 커널 재시작 후 재현되는지 확인한다.

학습 설명과 피드백

  • 처음 소개하거나 다시 묻는 영문 약어와 모델명은 한국어 뜻을 함께 설명한다.
  • 질문한 대상과 코드 줄을 먼저 특정하고 질문을 다른 개념으로 바꾸어 답하지 않는다.
  • 막힘을 수학·Python 문법·PyTorch 객체 모델·Tensor Shape 등 실제 원인으로 분류한다.
  • 진도는 나이·전공·감정이 아니라 실행 결과·설명 능력·재구현 증거로 판단한다.

로드맵 안내

  • 현재 학습과의 경계: 최우선 방향 학습 기록의 Road to LLM inference 가 이 프로젝트 후보보다 항상 우선한다. 사전학습 Causal LM → PyTorch 추론 Baseline → vLLM Benchmark·관측 → Multi-GPU 분산 추론의 현재·예정 순서를 이 문서가 바꿀 수 없다. 기존 로드맵과의 차이 AI·ML 통합 로드맵 과 분야별 로드맵은 무엇을 이해하고 다시 구현할 수 있어야 하는지 관리한다. 이 문서는 그 역량 여러 개를 한 데이터와 하나의 결과물 안에서 연결하는 프로젝트만 관리한다. 15개 대표 실습과의 차이 대표 실습 풀 은 Shape·평가·누수 같은 개념 하나를 작게 검증하는 곳이다. 프로젝트는 그 실습을 필요한 순간에 가져와 문제 정의부터 추론까지 연결한다. 활성화 원칙 후보를 모두 순서대로 수행하지 않는다. 핵심 여정을 완료한 뒤 또는 사용자가 핵심 방향을 바꾸거나 별도 프로젝트 세션을 시작하겠다고 명시했을 때만 하나를 활성화하며, 실제 실행 증거가 생기기 전에는 진행 중이나 완료로 표시하지 않는다.
  • 모든 프로젝트가 통과할 공통 관문: 데이터와 모델이 달라도 아래 질문에 답할 수 있어야 하나의 프로젝트를 끝냈다고 본다. 1 · 문제와 평가 계약 누가 어떤 결정을 위해 예측을 사용하는지, 입력 Feature와 Target은 무엇인지, 어떤 Metric과 단순 Baseline을 기준으로 삼을지 먼저 적는다. 2 · 데이터 계약과 분할 한 행의 의미·자료형·결측·중복·Label 분포와 출처·사용 조건을 확인한다. 예측 시점을 기준으로 Train·Validation·Test를 나누고 미래 정보와 Target 누수를 차단한다. 3 · 가장 단순한 Baseline Dummy, 규칙, 평균값 또는 TF-IDF + 선형 모델처럼 빠르게 재현되는 기준을 먼저 만든다. 복잡한 모델은 이 기준과 같은 Split·Metric에서 비교한다. 4 · 모델 비교와 학습 검증 한 번에 변화 하나만 적용하고 Train·Validation Metric, Loss 곡선, Shape·dtype·device, Gradient와 finite 여부를 확인한다. 신경망은 작은 Batch를 의도적으로 과적합할 수 있어야 한다. 5 · 오류 분석 평균 점수만 보고 끝내지 않는다. 틀린 사례를 원본 입력과 연결해 어떤 집단·길이·범위에서 실패하는지 분류하고 다음 변경 가설을 세운다. 6 · 저장·복원·추론 전처리기 또는 Tokenizer, Config, Label mapping과 Weight를 함께 저장한다. 새 프로세스에서 복원해 단일 입력과 Batch 입력을 같은 의미로 추론한다. 7 · 결과 문서화 실행 방법, 데이터와 모델 선택 이유, Baseline 비교표, 대표 오류, 재현 조건, 한계와 다음 실험을 남긴다. 점수가 낮아도 실패 원인을 설명하고 재실행할 수 있으면 학습 증거가 된다.
  • 나중에 의논해서 고르는 프로젝트 후보: 아래는 난이도 순서나 예정된 다음 행동이 아닌 장기 참고 풀이다. 핵심 여정이 진행되는 동안 어떤 후보도 자동으로 선택하거나 추천 순서로 승격하지 않는다. 검증 완료 · 표 데이터 분류 회원 이탈 예측 Dummy·Logistic Regression·Decision Tree·PyTorch MLP를 같은 Split에서 비교하고, Threshold·오류 비용·저장·복원·원본 고객 추론까지 연결했다. 남긴 증거: Logistic Accuracy 80.55% , MLP 78.99% , 놓친 이탈자 분석과 복원 추론. 완료 근거 보기 → 보관 후보 · 텍스트 분류 IMDb 영화 리뷰 감성 분류 TF-IDF + Logistic Regression을 Baseline으로 두고 사전학습 Transformer 분류 모델과 Accuracy·F1·오류 유형·학습 및 추론 비용을 비교한다. 새로 연결할 역량: Tokenizer, Padding·Truncation, 전이학습, 길이별 오류 분석, Batch 추론. 공식 데이터 설명 · Hugging Face 공식 가이드 후보 · 회귀와 시간 검증 자전거 대여 수요 예측 평균 또는 직전 값 Baseline에서 시작해 선형 모델과 Tree 계열을 MAE·RMSE로 비교한다. 무작위 분할과 시간순 분할의 차이, Lag·Rolling Feature의 미래 정보 누수를 검증한다. 새로 연결할 역량: 회귀 Metric, 시간순 Split, 계절성, 잔차와 기간별 오류 분석. UCI 공식 데이터 설명 → 후보 · 이미지 분류 FashionMNIST 의류 이미지 분류 MLP를 기준으로 작은 CNN을 비교하고, Confusion Matrix에서 서로 자주 혼동되는 의류를 원본 이미지와 함께 분석한다. 새로 연결할 역량: 이미지 Tensor Shape, 정규화, CNN, 증강 전후 일반화와 클래스별 오류.   • 다음 프로젝트를 고르는 기준: 학습 공백을 메우는가 이미 끝낸 회원 이탈 분류를 이름만 바꿔 반복하지 않고, 텍스트·시간·이미지·추천 중 새로운 데이터 계약과 오류를 경험한다. Baseline과 비교가 가능한가 복잡한 AI 모델 없이도 먼저 만들 수 있는 단순 기준과 같은 Split·Metric을 정의할 수 있다. 끝까지 완주 가능한가 데이터 크기·학습 비용·License를 확인하고 문제 정의부터 복원 추론과 문서화까지 한 결과물로 닫을 수 있다. 현재 코어와 연결되는가 현재 배우는 Tokenizer·DataLoader·평가·Checkpoint 같은 개념을 프로젝트에서 다시 사용해 이해를 검증한다. 보관 기준 후보의 존재나 현재 학습과의 개념적 연결은 시작 근거가 아니다. 핵심 LLM 추론 여정이 진행되는 동안에는 프로젝트를 추천 다음 단계로 제시하지 않으며, 사용자가 나중에 프로젝트 세션을 선택하면 그때 당시의 역량 공백을 기준으로 다시 고른다.

학습 관문

1 · 문제와 평가 계약

누가 어떤 결정을 위해 예측을 사용하는지, 입력 Feature와 Target은 무엇인지, 어떤 Metric과 단순 Baseline을 기준으로 삼을지 먼저 적는다.

예정

2 · 데이터 계약과 분할

한 행의 의미·자료형·결측·중복·Label 분포와 출처·사용 조건을 확인한다. 예측 시점을 기준으로 Train·Validation·Test를 나누고 미래 정보와 Target 누수를 차단한다.

예정

3 · 가장 단순한 Baseline

Dummy, 규칙, 평균값 또는 TF-IDF + 선형 모델처럼 빠르게 재현되는 기준을 먼저 만든다. 복잡한 모델은 이 기준과 같은 Split·Metric에서 비교한다.

예정

4 · 모델 비교와 학습 검증

한 번에 변화 하나만 적용하고 Train·Validation Metric, Loss 곡선, Shape·dtype·device, Gradient와 finite 여부를 확인한다. 신경망은 작은 Batch를 의도적으로 과적합할 수 있어야 한다.

예정

5 · 오류 분석

평균 점수만 보고 끝내지 않는다. 틀린 사례를 원본 입력과 연결해 어떤 집단·길이·범위에서 실패하는지 분류하고 다음 변경 가설을 세운다.

예정

6 · 저장·복원·추론

전처리기 또는 Tokenizer, Config, Label mapping과 Weight를 함께 저장한다. 새 프로세스에서 복원해 단일 입력과 Batch 입력을 같은 의미로 추론한다.

예정

7 · 결과 문서화

실행 방법, 데이터와 모델 선택 이유, Baseline 비교표, 대표 오류, 재현 조건, 한계와 다음 실험을 남긴다. 점수가 낮아도 실패 원인을 설명하고 재실행할 수 있으면 학습 증거가 된다.
