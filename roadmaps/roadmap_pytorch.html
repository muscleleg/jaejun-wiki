현재 위치

완료nn.Linear(1,1)의 weight·bias, MSELoss, zero_grad → backward → step을 연결해 y=3x+2를 학습했다. 이어 TensorDataset·DataLoader(batch_size=2)로 2개와 1개 Batch를 공급받아 학습 전 전체 Loss 38.047859를 Epoch 100 뒤 1.64 × 10⁻¹⁰까지 줄였다.
현재 진전회원 이탈 데이터의 Train·Validation 전처리를 같은 기준으로 재현하고 NumPy → float32 Tensor → TensorDataset → batch_size=64 DataLoader를 연결했다. [64,45] → [64,16] → [64,1] MLP Forward와 초기 BCEWithLogitsLoss=0.6564000844955444를 확인하고, SGD 한 Step 뒤 같은 Batch Loss가 0.6511512994766235로 내려가는 실행까지 확인했다.
현재 질문Linear(45,16)·Linear(16,1)의 파라미터 수와 다차원 입력 Shape을 어떻게 읽고, 한 Step을 반복한 Train 루프와 가중치를 바꾸지 않는 Validation 루프를 어떻게 분리하는가?
다음 행동먼저 Linear 파라미터·Shape와 고객별 BCE·Batch 평균을 재확인한 뒤, 이미 실행한 SGD 한 Step을 반복해 한 Batch 과적합과 전체 Train·Validation 루프를 구현한다.

교차 트랙에서 이어질 순서

현재 활성 상태Machine Learning 회원 이탈 Baseline 뒤 nn.Module·Optimizer 학습 흐름까지 완료하고, 실제 회원 이탈 데이터의 전처리·DataLoader·MLP Forward와 SGD 한 Step까지 연결했다.
완료한 연결수동 w·b 업데이트를 nn.Linear, MSELoss, Optimizer.zero_grad(), backward(), step()으로 재구현했다. 실제 데이터에서는 Pandas → NumPy → Tensor의 Shape·dtype과 [batch,45] → [batch,16] → [batch,1]을 설명했다. 다차원 Linear의 파라미터·Shape는 아직 이해 확인 중이다.
다음 연결과 복귀회원 이탈 MLP의 Train·Validation Metric, 저장·복원·한 건 추론까지 확인한다. 이 결과물을 닫은 뒤 Tiny Decoder LM으로 돌아간다.

현재 1차 순환 · 회원 이탈 MLP와 전달

현재 MLP에 바로 적용BCEWithLogitsLoss와 Logit·Sigmoid의 관계, Train/Validation 루프 분리, 한 Batch 과적합, Validation 기준 Best checkpoint를 회원 이탈 데이터 한 흐름에서 검증한다. 여러 Activation과 Optimizer를 모두 비교하지 않고 ReLU와 AdamW 또는 SGD 한 기준만 사용한다.
테스트와 재현성입력 [batch,45]·출력 Logit·정답 Shape, Loss finite 여부, Gradient 존재, train()·eval() 차이를 확인한다. 저장 전후 동일 입력의 예측 일치와 한 건 추론을 재현하면 현재 PyTorch 전달 관문을 닫는다.

2차 깊이 선택 · 딥러닝·PyTorch 실습 후보

현재 회원 이탈 MLP와 Tiny Decoder LM·사전학습 모델 적용까지의 1차 순환이 우선이다. 아래 항목은 그 뒤 실제 약점이나 선택 프로젝트에 맞춰 하나씩 꺼내며 현재 완료 조건에 포함하지 않는다.

운영 원칙처음하는 딥러닝과 파이토치 부트캠프, 딥러닝 CNN 완벽 가이드, 딥러닝의 모든 것을 순서대로 완주하지 않는다. 이미 검증한 Tensor·선형회귀·Gradient Descent·Autograd·Linear·Optimizer·Mini-batch는 다시 듣지 않고 현재 코드의 완료 증거를 사용한다. TensorFlow·Keras로 같은 모델을 반복 구현하지 않고 Python·PyTorch 결과물 하나로 압축한다.
코어 뒤 선택할 이미지 실습이미지 파일과 Label 메타데이터 → Custom Dataset·DataLoader → Train 전용 Augmentation과 공통 Normalize → 사전학습 Backbone 고정·Head 학습 → 일부 Layer Fine-tuning → Validation 기준 Best checkpoint → 오답 이미지와 클래스별 Metric 분석 → 저장·Batch 추론을 하나의 프로젝트로 연결한다. Convolution·Padding·Stride·Pooling과 출력 Feature Map Shape은 이 실습을 막는 범위만 작은 Tensor로 계산하며, 마지막 Logit·Softmax·Cross Entropy는 MLP와 Tiny LM에서 확인한 원리를 재사용한다. torchvision·timm 또는 동등한 모델 라이브러리를 사용한다.
이미지 실습 완료 증거Augmentation이 Validation·Test에 섞이지 않는지, 채널 순서와 입력 크기·정규화가 Pretrained 모델 계약과 맞는지, 고정한 파라미터에는 Gradient가 없는지, Fine-tuning 전후 동일 Metric이 어떻게 변했는지 확인한다. 최고 점수만 남기지 않고 틀린 이미지의 공통 특성과 모델·데이터 한계를 기록한다.
Tiny LM 뒤 선택 비교 · RNN/LSTM주가 예측 강의를 따라가지 않고 짧은 합성 Sequence의 다음 값 또는 복사 문제 하나에서 작은 nn.RNN이나 nn.LSTM을 학습한다. Hidden State가 시간축으로 전달되는 Shape, Backpropagation Through Time, 긴 Sequence에서의 Gradient 감소·증가를 확인하고, 순차 계산·장거리 의존성·병렬화 관점에서 이미 구현한 Causal Self-Attention과 비교한다. RNN 계열을 별도 전문 트랙으로 확장하지 않는다.
AutoEncoder는 이상탐지 조건부 선택정상 데이터의 입력을 복원하는 작은 AutoEncoder에서 Reconstruction Error 분포와 Threshold를 확인할 수 있다. 다만 규칙·Logistic·Tree·Isolation Forest 같은 단순 Baseline의 한계와 충분한 정상 Train 데이터가 먼저 확인될 때만 사용하며, Stacked AutoEncoder 구조 자체를 목표로 삼지 않는다.
현재 제외Momentum·NAG·AdaGrad·RMSProp의 개별 장시간 전개, AlexNet·VGG·GoogLeNet·ResNet·EfficientNet을 모두 처음부터 재구현하는 반복, 모든 Augmentation과 Scheduler 조합 탐색, CutMix 직접 구현, RNN·LSTM 주가·전력량 예측은 현재 코어 완료 조건이 아니다. SOM과 Boltzmann Machine 추천 실습도 현재 결과물 관문보다 우선하지 않는다. Residual Block은 Transformer Residual과 비교할 때, 고급 증강과 특정 CNN 구조는 실제 오답 분석이 필요성을 보일 때만 꺼낸다.
