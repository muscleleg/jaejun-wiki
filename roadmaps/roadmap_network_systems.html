네트워크 시스템 심화

계층 이름과 장비 기능을 따로 외우지 않는다. Client의 요청 한 건이 Link·IP·Transport·TLS·Application 계층과 Linux·Container·Kubernetes 경계를 지나 목적지에 도착하고 돌아오는 경로를 예측하고 Packet 증거로 검증한다.

활성화 경계

현재 학습을 대체하지 않는다네트워크를 깊게 공부하고 싶은 방향은 장기 계획에 보존한다. 페이지를 만들었다는 이유로 현재 AI·ML이나 코딩 테스트 진행률에 포함하지 않는다.
언제 시작하는가CS 네트워크 기반을 검증한 뒤 Packet 수준으로 깊게 들어가고 싶을 때, 또는 Kubernetes·OpenStack·LLM Serving의 연결 실패와 지연을 실제 경로로 진단해야 할 때 시작 준비 상태로 올린다.

심화 경로

1 · Link와 Local NetworkFrame, MAC, ARP, Switch, VLAN과 MTU를 같은 Broadcast Domain 안의 전달로 연결한다. 목적지 IP가 같은 Subnet인지에 따라 ARP 대상이 목적지 Host와 Gateway 중 무엇인지 예측한다.
2 · IP와 RoutingSubnet, Prefix, Routing Table, Next Hop, ICMP와 NAT를 연결한다. 출발지와 목적지 주소가 각 Hop에서 어떻게 유지되거나 변하는지 경로별로 표시한다.
3 · TCP·UDP와 SocketPort와 Socket, TCP 연결·Sequence·ACK·재전송·Flow Control·Congestion Control, UDP의 전달 경계를 구분한다. Packet Loss와 느린 Receiver가 Latency와 Throughput에 미치는 차이를 설명한다.
4 · DNS·TLS·HTTPName Resolution, TCP 연결, TLS 인증·키 합의, HTTP 요청·응답을 시간 순서로 추적한다. DNS, Connect, TLS, Server Processing, Response Read Timeout을 서로 다른 실패로 진단한다.
5 · Linux 가상 네트워크Network Namespace, veth pair, Bridge, Routing과 NAT를 Packet 이동으로 검증한다. Container 내부 주소와 Host 외부 NIC 사이에서 L2 전달과 L3 Routing의 경계를 표시한다.
6 · Kubernetes·Cloud NetworkingPod·Service·Endpoint·Ingress 또는 Gateway, CNI와 Network Policy를 한 요청 경로로 연결한다. OpenStack의 Tenant·Provider Network, Router와 Floating IP는 같은 L2·L3 원리의 다른 구현으로 비교한다.
7 · 패킷 기반 장애 진단DNS 실패, Route 누락, MTU 문제, Port 미수신, TLS 오류 또는 Network Policy 차단 중 하나를 의도적으로 만든다. 요청 로그와 Packet Capture에서 마지막으로 성공한 계층을 찾아 수정 전후를 비교한다.

완료 조건

End-to-End 경로 예측
Client에서 Server까지 Source·Destination MAC/IP/Port가 경계마다 어떻게 달라지는지 먼저 표시한다.
계층별 실패 구분
DNS, Route, TCP, TLS와 HTTP 오류를 같은 연결 실패로 부르지 않고 증거로 분리한다.
가상 네트워크 재구성
Namespace·veth·Bridge·Route·NAT로 작은 경로를 만들고 Packet이 예상 인터페이스를 지나는지 확인한다.
실제 시스템 전이
Kubernetes 또는 OpenStack 요청 한 건에서 같은 원리를 사용해 실패 위치와 수정 근거를 설명한다.
