현재 위치

완료 · TransformerBlockTransformerBlock.forward()의 Attention → Residual·LayerNorm → FFN → Residual·LayerNorm을 구현하고 Shape·Token 통계를 검증했으며, Causal Mask를 포함한 최소 Block도 같은 순서로 다시 실행했다.
완료 · Target shift·Token Loss2-Batch Tensor에서 [:, :-1]·[:, 1:]을 다시 구성하고, [B,T,V] → [B×T,V] Logit과 [B,T] → [B×T] Target index를 Cross Entropy의 좌우 입력으로 연결했다.
완료 · TinyDecoderLM 학습·생성저장 실행에서 d_model=2 Loss 0.462389 정체와 예측 [9,2,9]를 관찰하고, 새 d_model=4 모델에서 Loss 0.00000258까지 과적합했다. Seed가 없어 세부 수치는 달라질 수 있지만 새 커널에서도 같은 정체 경향과 [3] → [3,7] → [3,7,2] → [3,7,2,9] 생성을 재현했다.
완료 · Prefix 병렬 학습 설명Causal Mask와 shifted Target이 한 Forward에서 [3]→7·[3,7]→2·[3,7,2]→9를 병렬 채점하고, 생성에서는 같은 관계를 순차적으로 사용한다고 자기 말로 설명했다.
현재 관문 · 사전학습 Causal LMHugging Face Tokenizer·Dataset·동적 Padding으로 첫 Batch를 만들고, 실제 모델의 [B,S,V] Forward와 generate() 없는 수동 생성을 연결한다.

교차 트랙 전환 실행

완료한 교차 트랙회원 이탈 Baseline과 PyTorch MLP의 학습·평가·저장·복원·원본 고객 한 명 추론까지 연결해 예약했던 ML·PyTorch 기반 관문을 닫았다.
완료한 활성 트랙TinyDecoderLM의 Forward·shifted Target Cross Entropy·작은 데이터 과적합·마지막 위치 기반 반복 생성을 모두 실행해 Tiny Decoder LM 관문을 닫았다.
다음 행동Hugging Face Tokenizer에서 input_ids와 attention_mask를 만들고, 길이가 다른 예제를 동적 Padding한 첫 Batch의 Shape과 PAD Mask를 확인한다.

보강 상태

완료 · Tensor 축 변환[1,2,3,1] Tensor에서 transpose(1,2) 전후 값을 먼저 주석으로 예측하고, Head별 묶음이 Token별 묶음으로 바뀌어 [1,3,2,1]이 되는 결과와 일치함을 확인했다.
후속 보강Tiny Decoder LM으로 복귀할 때 view·transpose·reshape의 반대 방향 변환을 자료 없이 다시 설명해 장기 기억을 확인한다. 이 보강은 완료한 Transformer Block 관문을 되돌리지 않는다.
완료 · Softmax에서 Token Loss까지수동 Logit의 Softmax에서 Target이 각 행의 채점 열을 고른다는 실제 연산을 확인하고 -log 위치별 Loss [0.7966,1.4612,0.3702]와 평균 0.8760을 검산했다. Cross Entropy의 기본 mean과 reduction="none"도 구분했다.
예정 · MLE·Entropy·KL 연결여러 예제의 Log-Likelihood 최대화와 평균 NLL 최소화의 관계, Entropy·Cross Entropy·KL Divergence의 차이는 Tiny LM 코어 학습 뒤 같은 분포로 별도 검산한다.

Tiny LM 다음의 실제 적용 관문

목적손코딩으로 이해한 Decoder-only 구조를 라이브러리 모델 사용과 분리하지 않는다. Tiny Decoder LM을 만든 뒤 사전학습 Causal LM의 Forward와 수동 생성으로 옮겨 추론 시스템 학습의 다리를 놓는다.
라이브러리 입력 파이프라인작은 공개 데이터셋을 고정 Split·Seed로 준비하고, 해당되는 경우 Dataset revision과 License를 기록한다. 이어서 Hugging Face Dataset.map(batched=True) → AutoTokenizer의 Special token·Padding·Truncation 확인 → 길이가 서로 다른 예제 유지 → DataCollatorWithPadding의 Batch별 동적 Padding → DataLoader 첫 Batch 확인을 연결한다. input_ids·attention_mask의 dtype과 Shape을 예측·검사하고 PAD 위치의 Mask가 0인지 확인한다. Causal LM 학습용 labels를 만들 때는 PAD 위치를 -100 또는 동일한 ignore_index 값으로 바꾸며, 일반 동적 Padding용 DataCollatorWithPadding과 Causal LM label까지 만드는 collator의 역할을 구분한다.
Forward·수동 생성AutoModelForCausalLM에 input_ids와 attention_mask를 전달해 Logit [B,S,V]를 확인한다. generate()를 사용하기 전에 마지막 위치 Logit [:, -1, :]에서 다음 Token을 선택하고 입력 뒤에 붙이는 과정을 반복해 수동 생성 루프를 완성한다.
평가·Artifact고정 Prompt·Text 집합에서 NLL·Perplexity 또는 과제에 맞는 품질 지표와 오류 사례를 기록하고 단순 텍스트 Baseline 원칙을 재사용한다. Tokenizer·Config·Weights와 필요한 전처리 설정을 저장한 뒤 새 프로세스에서 불러 동일한 Forward Logit과 수동 생성 결과를 재현한다.
완료 증거첫 Batch의 ID·Mask Shape과 [B,S,V]를 예측하고, 마지막 위치 Logit이 다음 Token 선택에 사용되는 과정을 설명한다. 조건 하나를 바꿔 생성·NLL 또는 품질·오류 변화를 확인하고 저장·복원 결과까지 비교한다.
선택 · 첫 순환 뒤 모델 계열 비교이 분기는 현재 Decoder-only 추론 코어보다 앞서지 않으며 진행률 완료 조건에도 포함하지 않는다. 필요할 때 BERT(양방향 인코더 모델)의 한 Batch 분류에서 [B,S] → [B,S,H] → [B,C]를 확인하고, Marian 계열 Encoder-Decoder의 한 Batch에서 Source·Target shift와 Cross-Attention [B,h,S_tgt,S_src]를 확인한다. 이후 선택적으로 Greedy와 Beam Search를 비교하고 Encoder 출력을 한 번만 계산해 재사용하되, 이것이 Decoder KV Cache와는 다른 최적화임을 구분한다.
