적용 학습 정책

세션 재개와 학습 컨텍스트

  • focusedSessionId가 가리키는 세션이 있으면 그 세션의 첫 pending 단계부터 재개한다.
  • 로드맵·백로그에 소속된 여러 세션을 열어 둘 수 있지만 한 번에 하나만 active로 두며, 사용자의 선택이나 명시적인 session.focus 작업 없이 다른 세션으로 초점을 바꾸지 않는다.
  • 대화 중 한 번 다룬 독립 주제는 날짜별 학습 기록에만 남길 수 있다. 다음 대화에서도 이어갈 필요가 생기면 먼저 백로그 항목으로 승격한 뒤 backlog 세션으로 연다.
  • 학습을 시작하거나 재개할 때는 responseBrief를 사용해 현재까지 확인된 기록, 로드맵 또는 백로그에서의 위치, 현재 학습 단위와 목적, 왜 지금 필요한지, 지금 할 가장 작은 단계와 관찰·완료 근거, 다음에 열리는 결과 순서로 설명한다.
  • Notebook·소스 코드·테스트·CLI·화면·대화 등 현재 매체에서 실행 결과와 사용자 이해를 확인한 뒤, 파일 위치가 아니라 이해·검증·남은 질문·다음 행동을 Markdown 학습 컨텍스트로 기록한다.
  • 학습 컨텍스트는 특정 파일의 현재 존재 여부에 의존하지 않으며, 직접 확인하지 않은 내용은 완료 근거로 기록하지 않는다.
  • 모든 필수 단계의 학습 컨텍스트가 확인되기 전에는 현재 학습 단위를 완료하지 않는다.
  • 모든 단계의 완료와 각 단계의 검증된 학습 컨텍스트가 확인되면 LLM이 해당 sessionId의 범위와 현재 progressionMode·관문 관계를 근거로 다음 작은 학습 단위를 만들고 session.advance-current-unit으로 전환한다. 관문이나 백로그 단계도 끝났다면 같은 Plan에 해당 진행 상태 변경을 별도 작업으로 기록한다.
  • 학습 세션을 마감할 때 LLM은 대화의 실제 학습 구간을 근거로 그날의 하루 총 학습시간을 분 단위로 판정하고 history.set-study-time에 절대값과 추정 여부만 전달한다. 근거가 부족하면 시간을 꾸며내지 않는다.

대화형 손코딩 학습

  • 사용자가 코드를 직접 입력한다.
  • 개념과 필요성을 설명한 뒤 독립 실행 가능한 작은 코드 셀과 예상 Shape·값을 제공하고 저장된 실행 결과를 검증한다.
  • 한 번에 새로운 핵심 개념 하나를 다루며 완료되지 않은 단계를 건너뛰지 않는다.
  • 새로운 클래스·메서드·API·모델 객체는 사용 전에 역할과 입력·출력을 먼저 설명한다.
  • 추상적인 용어보다 현재 코드의 실제 숫자와 Shape을 우선한다.
  • 연습 셀은 필요한 작은 입력·Target·상수를 다시 선언해 독립 실행 가능하게 만들고, 상태를 재사용해야 할 때는 이유를 설명한다.
  • 사용자가 자료 없는 재구현을 선택한 검증 단계가 아니라면 과제 순서만 주고 샘플 코드를 생략하지 않는다.
  • 외부 강의·교재는 출처로 사용하되 학습 단위를 개념 설명·예측·손코딩·실행 증거·자기 말 설명 순서로 재구성한다.

이해도와 완료 판정

  • 설명을 듣거나 코드를 따라 입력한 사실만으로 완료 처리하지 않는다.
  • 자기 말 설명·조건 변경 결과 예측·자료 없는 재구현·의도적 변경 설명 중 하나 이상의 증거를 확인한다.
  • 대표 실습은 입력과 정답 설명·핵심 Shape 예상·Metric 평가·조건 변경 설명·핵심 코드 재구현을 확인한다.
  • 완료 기준을 충족하면 선택 심화보다 먼저 완료 사실과 남은 필수 단계 수를 명확히 알린다.
  • 캐시된 출력만 믿지 않고 필요한 import·변수·모델·입력이 포함된 상태에서 커널 재시작 후 재현되는지 확인한다.

학습 설명과 피드백

  • 처음 소개하거나 다시 묻는 영문 약어와 모델명은 한국어 뜻을 함께 설명한다.
  • 질문한 대상과 코드 줄을 먼저 특정하고 질문을 다른 개념으로 바꾸어 답하지 않는다.
  • 막힘을 수학·Python 문법·PyTorch 객체 모델·Tensor Shape 등 실제 원인으로 분류한다.
  • 진도는 나이·전공·감정이 아니라 실행 결과·설명 능력·재구현 증거로 판단한다.

PyTorch Tensor 타입과 Shape 표기

  • 모델·Tokenizer·Batch와 의미가 바로 드러나지 않는 주요 Tensor 변수에는 타입 힌트를 명시한다.
  • 함수 입력·반환과 input_ids·Hidden State·Logit·Q·K·V·KV Cache처럼 Shape 의미가 핵심인 Tensor에는 jaxtyping으로 dtype과 축 이름을 인라인 표기한다.
  • reshape·transpose·Head Split·Merge처럼 축이 바뀌는 경계의 타입과 Shape을 우선 표시한다.
  • jaxtyping은 문서화에 사용하고 Shape 예측·실제 출력 검증이나 런타임 검사를 대신하지 않는다.

Transformer 구현 검증

  • 직접 구현한 Attention과 공식 SDPA 결과를 같은 입력에서 비교한다.
  • Padding Mask와 Causal Mask의 Shape과 적용 위치를 확인한다.
  • Target shift·Token loss·작은 생성 루프를 연결하고 각 경계의 Tensor Shape을 검증한다.
  • 근삿값·평균변화율·순간변화율·정확한 미분값을 구분하고, 단순화한 예제가 실제 구현과 다른 가정을 쓰면 먼저 밝힌다.

로드맵 안내

  • 교차 트랙 전환 실행: 완료한 교차 트랙 회원 이탈 Baseline과 PyTorch MLP의 학습·평가·저장·복원·원본 고객 한 명 추론까지 연결해 예약했던 ML·PyTorch 기반 관문을 닫았다. 완료한 활성 트랙 TinyDecoderLM 에 이어 사전학습 Causal LM의 Tokenizer·Forward·수동 생성·평가·Artifact 복원까지 실행해 Transformer 1차 순환을 닫았다. 다음 행동 같은 tiny GPT-2·Prompt·출력 길이에서 먼저 Cache 없는 반복 생성의 기준선을 측정하고, 이어 past_key_values 를 재사용하는 KV Cache 생성과 비교한다.
  • 보강 상태: 완료 · Tensor 축 변환 [1,2,3,1] Tensor에서 transpose(1,2) 전후 값을 먼저 주석으로 예측하고, Head별 묶음이 Token별 묶음으로 바뀌어 [1,3,2,1] 이 되는 결과와 일치함을 확인했다. 후속 보강 Tiny Decoder LM으로 복귀할 때 view · transpose · reshape 의 반대 방향 변환을 자료 없이 다시 설명해 장기 기억을 확인한다. 이 보강은 완료한 Transformer Block 관문을 되돌리지 않는다. 완료 · Softmax에서 Token Loss까지 수동 Logit의 Softmax에서 Target이 각 행의 채점 열을 고른다는 실제 연산을 확인하고 -log 위치별 Loss [0.7966,1.4612,0.3702] 와 평균 0.8760 을 검산했다. Cross Entropy의 기본 mean과 reduction="none" 도 구분했다. 예정 · MLE·Entropy·KL 연결 여러 예제의 Log-Likelihood 최대화와 평균 NLL 최소화의 관계, Entropy·Cross Entropy·KL Divergence의 차이는 Tiny LM 코어 학습 뒤 같은 분포로 별도 검산한다.
  • Tiny LM 다음의 실제 적용 관문: 목적 손코딩으로 이해한 Decoder-only 구조를 라이브러리 모델 사용과 분리하지 않는다. Tiny Decoder LM을 만든 뒤 사전학습 Causal LM의 Forward와 수동 생성으로 옮겨 추론 시스템 학습의 다리를 놓는다. 라이브러리 입력 파이프라인 작은 공개 데이터셋을 고정 Split·Seed로 준비하고, 해당되는 경우 Dataset revision과 License를 기록한다. 이어서 Hugging Face Dataset.map(batched=True) → AutoTokenizer 의 Special token·Padding·Truncation 확인 → 길이가 서로 다른 예제 유지 → DataCollatorWithPadding 의 Batch별 동적 Padding → DataLoader 첫 Batch 확인을 연결한다. input_ids · attention_mask 의 dtype과 Shape을 예측·검사하고 PAD 위치의 Mask가 0인지 확인한다. Causal LM 학습용 labels 를 만들 때는 PAD 위치를 -100 또는 동일한 ignore_index 값으로 바꾸며, 일반 동적 Padding용 DataCollatorWithPadding 과 Causal LM label까지 만드는 collator의 역할을 구분한다. Forward·수동 생성 AutoModelForCausalLM 에 input_ids 와 attention_mask 를 전달해 Logit [B,S,V] 를 확인한다. generate() 를 사용하기 전에 마지막 위치 Logit [:, -1, :] 에서 다음 Token을 선택하고 입력 뒤에 붙이는 과정을 반복해 수동 생성 루프를 완성한다. 평가·Artifact 고정 Prompt·Text 집합에서 NLL·Perplexity 또는 과제에 맞는 품질 지표와 오류 사례를 기록하고 단순 텍스트 Baseline 원칙을 재사용한다. Tokenizer·Config·Weights와 필요한 전처리 설정을 저장한 뒤 새 프로세스에서 불러 동일한 Forward Logit과 수동 생성 결과를 재현한다. 완료 증거 첫 Batch의 ID·Mask Shape과 [B,S,V] 를 예측하고, 마지막 위치 Logit이 다음 Token 선택에 사용되는 과정을 설명한다. 조건 하나를 바꿔 생성·NLL 또는 품질·오류 변화를 확인하고 저장·복원 결과까지 비교한다. 선택 · 첫 순환 뒤 모델 계열 비교 이 분기는 현재 Decoder-only 추론 코어보다 앞서지 않으며 진행률 완료 조건에도 포함하지 않는다. 필요할 때 BERT(양방향 인코더 모델)의 한 Batch 분류에서 [B,S] → [B,S,H] → [B,C] 를 확인하고, Marian 계열 Encoder-Decoder의 한 Batch에서 Source·Target shift와 Cross-Attention [B,h,S_tgt,S_src] 를 확인한다. 이후 선택적으로 Greedy와 Beam Search를 비교하고 Encoder 출력을 한 번만 계산해 재사용하되, 이것이 Decoder KV Cache와는 다른 최적화임을 구분한다.
