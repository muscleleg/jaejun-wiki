활성화 경계

완전한 초보 로드맵이 아니다Control Plane·Workload·RBAC·Network·Storage·Helm·GitOps 관련 문서와 Kubernetes 운영 관측 AI, Function Calling 개인 프로젝트가 이미 있다. 다만 과거 메모와 프로젝트 범위를 Kubernetes 플랫폼 전체 이해로 자동 환산하지 않는다.
관심은 보존하고 현재 집중은 유지한다Kubernetes를 더 깊게 파고 싶은 방향은 보존하지만 Road to LLM inference의 현재 관문, PyTorch 추론 Baseline → vLLM → Multi-GPU 순서나 AI 코어 진행률을 바꾸지 않는다.
언제 시작하는가핵심 여정을 완료했거나 사용자가 별도 Kubernetes 세션을 명시적으로 선택했을 때 시작한다. 핵심 여정의 LLM Serving·GPU Workload에서 Scheduling·Network·Storage 문제가 실제 blocker가 되면 필요한 진단만 수행하고 즉시 원래 관문으로 돌아간다.

완료 조건

Control Loop 설명
Manifest 적용부터 실제 Pod가 Running·Ready가 될 때까지 참여 구성 요소와 상태 변화를 자료 없이 설명한다.
요청과 데이터 경로 추적
외부 요청이 Service를 거쳐 Pod에 도달하는 경로와 Stateful Pod의 I/O가 Storage Backend에 도달하는 경로를 각각 추적한다.
안전한 변경과 복구
배포 변경 전후의 객체·Metric을 비교하고 실패 조건에서 Rollback 또는 원상 복구를 실제로 검증한다.
계층적 장애 진단
Application, Kubernetes Object, Container Runtime, Linux, Network·Storage 중 어느 계층의 실패인지 증거로 좁힌다.
새 Workload로 전이
처음 보는 API 또는 AI Workload의 요구에서 Resource·Network·Storage·Security·관측 구성을 도출하고 선택 이유를 설명한다.
