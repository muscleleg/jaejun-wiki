Knowledge Graph·GraphRAG·Agent Harness

문서를 단순 Vector 검색하는 Baseline에서 출발해 Entity·Relation·Ontology를 명시하고, 필요한 도구를 선택하며 실패를 검증할 수 있는 지식 Agent 결과물로 확장한다.

선택 경계

언제 시작하는가Tiny Decoder LM과 사전학습 텍스트 모델 적용을 완료하고, 문서 검색 문제에서 단순 Keyword 또는 Vector RAG의 한계가 실제 평가로 확인됐을 때 선택한다.
Graph를 목적처럼 만들지 않는다Entity 관계를 여러 단계 따라가야 하거나 Schema·권한·규칙 검증이 답의 핵심일 때 Knowledge Graph를 사용한다. 단순 문서 유사도 검색으로 충분하면 Vector RAG를 유지한다.
프로젝트 범위공개 문서 묶음 하나를 사용해 Baseline과 Graph 확장을 같은 질문 세트로 비교한다. 여러 도메인 Agent를 동시에 만들지 않는다.

결과물 중심 학습 경로

1 · 문서 계약과 검색 Baseline문서 ID·출처·제목·Section·Tag·갱신 시각 같은 Metadata를 정하고 Parsing 결과를 JSONL 등 확인 가능한 형식으로 저장한다. Keyword 또는 Vector RAG로 질문·근거·응답 Baseline을 먼저 측정한다.
2 · Knowledge Graph Schema현재 질문에 필요한 Entity Type, Relation Type, Triple과 고유 식별 규칙을 먼저 설계한다. 원문 근거와 연결되지 않는 추출 정보는 Graph에 넣지 않는다.
3 · 정보 추출과 정규화Entity·Relation을 추출하고 표기 차이를 정규화하며 중복 Entity를 병합한다. 자동 병합의 Threshold와 보류·거절 이유를 남겨 잘못된 관계가 조용히 퍼지지 않게 한다.
4 · Graph 저장과 QueryGraph Database에 Node·Edge와 출처를 적재하고 Cypher 같은 Query로 한 단계·다단계 관계를 직접 조회한다. Text-to-Query를 붙이기 전에 고정 Query의 정답과 실행 비용을 검증한다.
5 · GraphRAG 비교질문에서 필요한 Entity와 관계 경로를 찾아 Graph Context를 구성한다. 같은 질문 세트에서 Vector RAG와 GraphRAG의 검색 성공, 근거 적합성, 다단계 질문 성공과 지연·비용을 비교한다.
6 · Ontology와 Semantic Validation허용하는 Entity·Relation·Vocabulary와 Constraint를 명시한다. Schema 위반, 의미적으로 금지된 관계, 권한 없는 요청을 구분해 통과·보류·거절과 구체적인 Reject reason을 만든다.
7 · Agent Tool과 Routingdocs_search, graph_query, ontology_check처럼 역할과 입력·출력이 분리된 도구를 만들고, 어떤 질문에서 어떤 도구를 호출할지 Router의 규칙과 실패 조건을 시험한다.
8 · Agent Harness 안정성Structured output Schema, Timeout, Retry 가능 오류, Fallback, 최대 반복 횟수와 Human review 조건을 둔다. Retry가 같은 잘못을 무한 반복하지 않도록 Evidence와 실패 이유를 다음 시도에 전달한다.
9 · 평가와 증분 갱신검색 성공·근거 충실성·최종 답·도구 선택·Schema 준수·latency·비용을 분리해 평가한다. 문서가 바뀌면 영향받은 Chunk·Entity·Relation만 갱신하고 삭제·충돌·버전 변경을 재평가한다.

하나의 프로젝트로 묶는 방법

권장 문제공개 기술 문서처럼 출처와 구조를 확인할 수 있는 작은 Corpus에서 단일 문서 질문 → 여러 문서 관계 질문 → 규칙 위반 질문 세 종류를 만든다.
비교 순서검색 없는 LLM → Vector RAG → Graph Query를 포함한 GraphRAG → Ontology 검증과 Tool Router를 포함한 Agent Harness 순서로 한 기능씩 추가한다. 각 단계는 이전 Baseline 대비 무엇이 좋아지고 어떤 비용과 실패가 생겼는지 기록한다.
현재 프로젝트와의 연결기존 RAG 지식 비서의 문서 수집·검색·근거 응답 흐름은 Vector RAG Baseline으로 재사용할 수 있다. Graph와 Ontology는 기존 평가에서 관계 탐색 또는 규칙 검증의 부족이 확인된 뒤에만 추가한다.

완료 조건

재현 가능한 Corpus와 Baseline
문서 출처·Parser·Chunk·Metadata와 고정 질문 세트를 재생성하고 Vector RAG 결과를 보존한다.
근거가 있는 Graph
Entity·Relation·Triple의 원문 근거와 Schema를 확인하고 중복·오류 사례를 설명한다.
Vector RAG와 GraphRAG 비교
다단계 질문에서 좋아진 사례와 오히려 복잡도·지연만 늘어난 사례를 같은 평가표로 분석한다.
Ontology 검증
허용·보류·거절 예제를 만들고 각 판단의 Constraint와 Reject reason을 재현한다.
Tool Router와 실패 복구
도구 선택, Structured output, Timeout·Retry·Fallback과 최대 반복 제한을 테스트한다.
End-to-End 평가
검색·근거·답·도구·안전·지연·비용을 분리한 실패 분석과 증분 갱신 결과를 문서화한다.
