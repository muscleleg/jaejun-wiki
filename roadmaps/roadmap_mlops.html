MLOps·모델 운영

모델을 한 번 배포하는 데서 끝내지 않고, 어떤 데이터·코드·설정으로 만든 모델인지 재현하고 안전하게 교체하며 운영 중 품질 변화를 발견하는 결과물로 확장한다.

선택 경계

언제 시작하는가회원 이탈 MLP의 학습·평가·저장·복원·단일 고객 추론은 첫 순환에서 완료했다. 현재는 Tiny Decoder LM의 클래스 조립 → Cross Entropy Loss → 작은 데이터 학습·생성을 마친 뒤 사전학습 Causal LM 적용까지 연결하는 것이 먼저다. 그 결과물을 반복 배포하고 관찰해야 하는 실제 필요가 생겼을 때 이 확장을 선택한다.
당시 우선순위와 현재 우선순위이 로드맵을 추가할 당시에는 회원 이탈 MLP의 한 Batch 과적합과 Train·Validation Metric이 우선이었다. 그 관문을 완료한 현재의 다음 행동은 TinyDecoderLM 클래스 → Cross Entropy Loss → 작은 데이터 Loss 감소 → Autoregressive Generation이다. Feature Store, Streaming, Canary 같은 용어를 먼저 학습해 이 활성 구현을 지연시키지 않는다.
도구보다 운영 계약특정 플랫폼 사용법보다 어떤 Artifact를 배포했는가 → 어떤 입력을 받는가 → 무엇을 측정하는가 → 언제 되돌리거나 재학습하는가를 먼저 명시한다.

결과물 중심 학습 경로

1 · 재현 가능한 학습과 Artifact데이터 버전·코드 커밋·의존성·seed·config·Metric을 한 실행 기록으로 묶고, 전처리기·Label mapping·모델 Weight·평가 결과를 함께 저장한다. 새 프로세스에서 같은 입력의 예측이 일치해야 한다.
2 · 모델 버전과 서빙 계약모델 버전, 입력 Schema, 출력 의미, Threshold와 실패 응답을 명시한다. Batch 추론과 API 추론이 같은 전처리·모델 경로를 사용하고, latency·throughput·error rate를 측정한다.
3 · 안전한 배포와 Rollback이전 버전과 새 버전을 동시에 식별하고 작은 Traffic부터 새 버전으로 보내는 Canary 흐름을 만든다. 기술 오류와 모델 Metric의 중단 기준을 정하고 이전 버전으로 되돌리는 절차를 실제로 시험한다.
4 · 운영 모니터링과 Drift서비스 오류·지연뿐 아니라 입력 결측·범주 변화·Feature 분포와 예측 분포를 관찰한다. Data Drift, Label을 나중에 확인할 수 있을 때의 성능 저하, 단순 계절 변화를 구분하고 경고 Threshold의 근거를 기록한다.
5 · 재학습과 승인 관문새 데이터 수집 → 품질 검사 → 학습 → 고정 평가 세트 비교 → 승인 → 배포를 분리한다. 자동 재학습이 곧 자동 배포가 되지 않게 품질·안전·비용 관문과 Rollback 가능한 Artifact를 둔다.
6 · 온라인 실험서비스에 충분한 Traffic과 명확한 제품 지표가 있을 때만 A/B Test를 연다. 모델 Metric과 CTR 같은 제품 Metric, latency·오류 같은 Guardrail을 함께 보고 실험 단위·기간·중단 조건을 정한다.

하나의 프로젝트로 묶는 방법

기본 후보1차 순환에서 완료한 표 데이터 모델을 재사용한다. 같은 전처리와 모델을 API로 제공하고, 두 모델 버전을 Canary로 교체하며 입력·예측 분포 변화와 지연을 관찰한 뒤 승인된 재학습까지 연결한다.
조건부 확장실시간 이상탐지, 추천 Feature Store, OCR 자동 재학습은 각각 독립 프로젝트로 모두 만들지 않는다. 선택한 문제에서 Streaming·Entity Feature·Auto Labeling이 실제 요구사항일 때만 기본 운영 계약 위에 하나를 추가한다.
안전·권리·데이터 관리데이터 출처와 사용 권한, 개인정보 최소화, Label 생성 방식, 모델·라이브러리 License, 예상 가능한 오용과 실패 시 대응을 배포 체크리스트에 포함한다.

완료 조건

재현 가능한 Artifact
새 환경에서 버전이 고정된 전처리기와 모델을 불러 동일 입력의 예측을 재현한다.
관찰 가능한 서빙
입력 검증, 오류율, latency·throughput과 모델 버전을 한 요청 흐름에서 확인한다.
Canary와 Rollback
새 버전의 Traffic 비율을 조절하고 정한 실패 조건에서 이전 버전으로 실제 복귀한다.
Drift 판단
분포 변화와 성능 저하를 구분하고 경고 하나의 오탐·미탐 비용을 설명한다.
안전한 재학습
새 데이터가 평가·승인·배포 관문을 통과하고 기존 모델과 비교된 뒤에만 교체된다.
운영 회고
품질·비용·지연·안전과 실패 사례를 함께 기록하고 다음 변경의 근거를 남긴다.
