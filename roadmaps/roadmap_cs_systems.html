세션 재개와 학습 컨텍스트

  • focusedSessionId가 가리키는 세션이 있으면 그 세션의 첫 pending 단계부터 재개한다.
  • 로드맵·백로그에 소속된 여러 세션을 열어 둘 수 있지만 한 번에 하나만 active로 두며, 사용자의 선택이나 명시적인 session.focus 작업 없이 다른 세션으로 초점을 바꾸지 않는다.
  • 대화 중 한 번 다룬 독립 주제는 날짜별 학습 기록에만 남길 수 있다. 다음 대화에서도 이어갈 필요가 생기면 먼저 백로그 항목으로 승격한 뒤 backlog 세션으로 연다.
  • 학습을 시작하거나 재개할 때는 responseBrief를 사용해 현재까지 확인된 기록, 로드맵 또는 백로그에서의 위치, 현재 학습 단위와 목적, 왜 지금 필요한지, 지금 할 가장 작은 단계와 관찰·완료 근거, 다음에 열리는 결과 순서로 설명한다.
  • Notebook·소스 코드·테스트·CLI·화면·대화 등 현재 매체에서 실행 결과와 사용자 이해를 확인한 뒤, 파일 위치가 아니라 이해·검증·남은 질문·다음 행동을 Markdown 학습 컨텍스트로 기록한다.
  • 학습 컨텍스트는 특정 파일의 현재 존재 여부에 의존하지 않으며, 직접 확인하지 않은 내용은 완료 근거로 기록하지 않는다.
  • 모든 필수 단계의 학습 컨텍스트가 확인되기 전에는 현재 학습 단위를 완료하지 않는다.
  • 모든 단계의 완료와 각 단계의 검증된 학습 컨텍스트가 확인되면 LLM이 해당 sessionId의 범위와 현재 progressionMode·관문 관계를 근거로 다음 작은 학습 단위를 만들고 session.advance-current-unit으로 전환한다. 관문이나 백로그 단계도 끝났다면 같은 Plan에 해당 진행 상태 변경을 별도 작업으로 기록한다.
  • 학습 세션을 마감할 때 LLM은 대화의 실제 학습 구간을 근거로 그날의 하루 총 학습시간을 분 단위로 판정하고 history.set-study-time에 절대값과 추정 여부만 전달한다. 근거가 부족하면 시간을 꾸며내지 않는다.

대화형 손코딩 학습

  • 사용자가 코드를 직접 입력한다.
  • 개념과 필요성을 설명한 뒤 독립 실행 가능한 작은 코드 셀과 예상 Shape·값을 제공하고 저장된 실행 결과를 검증한다.
  • 한 번에 새로운 핵심 개념 하나를 다루며 완료되지 않은 단계를 건너뛰지 않는다.
  • 새로운 클래스·메서드·API·모델 객체는 사용 전에 역할과 입력·출력을 먼저 설명한다.
  • 추상적인 용어보다 현재 코드의 실제 숫자와 Shape을 우선한다.
  • 연습 셀은 필요한 작은 입력·Target·상수를 다시 선언해 독립 실행 가능하게 만들고, 상태를 재사용해야 할 때는 이유를 설명한다.
  • 사용자가 자료 없는 재구현을 선택한 검증 단계가 아니라면 과제 순서만 주고 샘플 코드를 생략하지 않는다.
  • 외부 강의·교재는 출처로 사용하되 학습 단위를 개념 설명·예측·손코딩·실행 증거·자기 말 설명 순서로 재구성한다.

이해도와 완료 판정

  • 설명을 듣거나 코드를 따라 입력한 사실만으로 완료 처리하지 않는다.
  • 자기 말 설명·조건 변경 결과 예측·자료 없는 재구현·의도적 변경 설명 중 하나 이상의 증거를 확인한다.
  • 대표 실습은 입력과 정답 설명·핵심 Shape 예상·Metric 평가·조건 변경 설명·핵심 코드 재구현을 확인한다.
  • 완료 기준을 충족하면 선택 심화보다 먼저 완료 사실과 남은 필수 단계 수를 명확히 알린다.
  • 캐시된 출력만 믿지 않고 필요한 import·변수·모델·입력이 포함된 상태에서 커널 재시작 후 재현되는지 확인한다.

학습 설명과 피드백

  • 처음 소개하거나 다시 묻는 영문 약어와 모델명은 한국어 뜻을 함께 설명한다.
  • 질문한 대상과 코드 줄을 먼저 특정하고 질문을 다른 개념으로 바꾸어 답하지 않는다.
  • 막힘을 수학·Python 문법·PyTorch 객체 모델·Tensor Shape 등 실제 원인으로 분류한다.
  • 진도는 나이·전공·감정이 아니라 실행 결과·설명 능력·재구현 증거로 판단한다.

로드맵 안내

  • 학습 원칙과 활성화 경계: 기본 CS가 먼저다 각 관문에서 AI 사례부터 외우지 않는다. 일반 프로그램과 시스템에서 개념을 설명하고 작은 코드·관찰 실험으로 검증한 뒤, 같은 원리를 AI 학습·추론·서빙에 옮긴다. 현재 핵심 여정을 바꾸지 않는다 사전학습 Causal LM 적용까지 완료했고 현재는 같은 모델·Prompt에서 No-cache와 KV Cache, Batch 1과 Batch N을 비교하는 PyTorch 추론 Baseline을 진행한다. 이 로드맵은 보관 상태를 유지하며 현재 다음 행동을 대체하지 않는다. 언제 시작하는가 현재 AI 관문을 실제로 막는 CS 개념이 생기면 해당 개념만 짧게 꺼내고 즉시 복귀한다. 독립 트랙으로는 Road to LLM inference를 완료하거나 사용자가 CS 학습 세션을 명시적으로 선택했을 때 첫 미완료 관문부터 시작한다. 기존 지식을 다시 세지 않는다 이미 작성된 Linux·운영체제·네트워크·Database 문서는 출발 증거로 사용한다. 문서를 읽거나 영상을 시청한 사실만으로 완료하지 않고, 자료 없이 설명·예측하고 작은 실험과 AI 전이를 검증한 관문만 닫는다.

Transaction, Isolation Level, Lock, MVCC와 WAL이 해결하는 동시성·복구 문제를 설명하고 Index 전후 실행 계획을 비교한다. AI 전이: 모델 Artifact·Checkpoint·평가 결과·Embedding 저장에서 일관성, 검색 비용과 복구 요구를 구분한다. 7 · 분산 시스템의 실패와 신뢰성 기본 CS: Network·Partial Failure를 전제로 Timeout·Retry·Backoff·Idempotency·Queue·Cache·Backpressure를 선택한다. Consistent Hashing, 복제와 Raft의 책임을 구분하고 중복 요청·느린 Consumer를 재현한다. AI 전이: 분산 추론 요청 Routing, Batch Queue, Cache 배치와 Worker 장애에서 처리 횟수·지연·최종 상태를 관찰한다. 8 · AI 추론 시스템 통합 Client 요청 → API → Queue → Batch → Model Worker → GPU Memory·KV Cache → Streaming 응답을 하나의 흐름으로 그린다. 앞선 관문의 숫자 표현·자료구조·CPU·메모리·운영체제·Network·Storage·분산 실패 원리를 사용해 TTFT, Token 생성 속도, Throughput, Peak VRAM과 실패 원인을 고정 조건의 측정 근거로 설명한다.
  • 짧은 외부 자료를 사용하는 기준: 필수와 선택 심화로 분류 짧은 영상에서 발견한 Floating Point, Virtual Memory, CPU Cache, Context Switching, Trie, LRU, DNS, TLS, WAL, Raft 같은 개념은 범용성과 AI 시스템 재사용성을 따져 분류한다. 필수는 가장 가까운 기존 관문과 완료 조건에 흡수하고, 선택 심화만 활성화 조건을 붙여 백로그에 둔다. 학습 순서의 원본으로 사용하지 않음 영상의 업로드 순서나 조회 수가 로드맵 순서를 정하지 않는다. 특정 CVE·공격 사례는 Memory Safety·권한·입력 검증 같은 기본 원리를 설명하는 사례로만 사용하고 개별 관문으로 늘리지 않는다. 시청은 완료 증거가 아님 짧은 설명을 본 뒤 자료 없이 원리를 말하고, 조건을 바꾸기 전 결과를 예측하며, 작은 일반 CS 실험과 AI 시스템 적용을 모두 확인해야 완료 근거로 인정한다.
  • 선택 심화의 보관 경계: 표현·압축·오류 복구 Huffman Coding, LZ77, JPEG, CRC와 Reed–Solomon은 기본 숫자·Byte 표현을 검증한 뒤 선택하는 심화다. 확률·내용 주소 자료구조 Bloom Filter와 Merkle Tree는 Hash Table·Tree·Hash의 기본 동작을 이해한 뒤 오탐률, 공간 절약 또는 무결성 검증이 실제로 필요할 때 비교한다. CPU·Runtime·디버거·브라우저 내부 Branch Prediction, JIT Compilation, Breakpoint의 명령어 치환과 Critical Rendering Path는 실행·메모리 기본 관문 뒤 CPU·언어·브라우저의 성능 또는 디버깅 원인을 더 깊게 설명할 때 꺼낸다. 메모리 공격과 방어 Buffer Overflow, Return Address Overwrite, Stack Canary, Use-After-Free, Rowhammer와 Meltdown은 Stack·Heap·가상 메모리·CPU Cache의 기본 검증 뒤 공격 조건과 방어 경계를 학습한다. 인증·애플리케이션 보안 TOTP, OAuth PKCE, Prototype Pollution, Insecure Deserialization, Unicode Normalization 우회와 SQL Injection은 기본 암호·웹·Database 경계 뒤 작은 취약 예제와 안전한 처리의 차이를 검증한다. 프로토콜·저장·보안 사례 HLS·DASH, File Recovery, Git Internals와 개별 CVE·공급망·악성코드 사례는 관련 기본 관문을 완료한 뒤 한 사례의 원인·영향·완화책을 공식 원자료로 재검증한다.
  • 검증 방식: 기본 원리 설명 AI 용어에 기대지 않고 작은 값·자료구조·프로그램 또는 요청 하나의 상태 변화를 자료 없이 설명한다. 조건 변경 결과 예측 dtype, 입력 크기, 자료구조, Thread 수, Memory 크기, Index, Timeout 또는 Queue 크기 하나를 바꾸기 전에 시간·공간·정확성 변화를 예측한다. 일반 CS 실험 Overflow, 자료구조 연산, Cache Miss, Race, Query Plan 또는 Retry 중 하나를 작은 코드나 시스템 관찰 도구로 재현하고 예상과 결과를 비교한다. AI 시스템 전이 같은 원리를 Tensor·PyTorch·GPU, 추론 API, Cache·Batch Scheduler 또는 Multi-GPU 흐름에 적용하고 무엇이 같고 다른지 설명한다.
