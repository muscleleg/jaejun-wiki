전산학 용어를 넓게 암기하지 않는다. 프로그램 한 개와 요청 한 건이 CPU·메모리·운영체제·네트워크·데이터베이스·분산 시스템을 통과하는 과정을 예측하고 관찰한 뒤, AI 추론 시스템의 병목과 실패를 설명하는 기반을 만든다.

활성화 경계

지금 바로 병행하지 않는다Tiny Decoder LM의 Loss 감소와 Autoregressive Generation은 완료했다. 현재 가까운 관문은 Tokenizer·동적 Padding과 사전학습 Causal LM의 Forward·수동 생성이며, 이 로드맵을 만들었다는 이유로 현재 다음 행동을 바꾸지 않는다.
언제 시작하는가현재 AI 관문을 닫고 다음 장기 트랙을 선택하거나, 메모리·동시성·네트워크·저장·분산 실패가 실제 구현을 막을 때 이 로드맵을 진행 중 상태로 올린다.
기존 지식을 다시 세지 않는다이미 작성된 Linux·운영체제·네트워크·Database 문서는 출발 증거로 사용한다. 읽었다는 이유로 완료하지 않고, 자료 없이 설명·예측하거나 작은 실험으로 다시 검증한 관문만 닫는다.

6개 성취 관문

1 · 컴퓨터 실행과 메모리Source Code가 Process로 실행되고 CPU가 명령을 처리하며 Register·Cache·RAM·Storage를 오가는 흐름을 구분한다. 함수 호출의 Stack, 동적 객체의 Heap, 가상 주소와 Page를 작은 프로그램의 상태 변화로 설명하고 Locality와 Cache Miss가 성능에 미치는 영향을 예측한다.
2 · 운영체제와 동시성Process·Thread·Coroutine, User Mode·Kernel Mode, System Call, Scheduling과 Context Switching을 연결한다. 공유 상태가 있는 작은 코드에서 Race Condition을 재현하고 Lock 적용 전후, Deadlock의 네 조건, Process·Thread·Async 선택 근거를 설명한다.
3 · 네트워크와 웹 요청한 요청을 DNS → IP Routing → TCP → TLS → HTTP → Server 순서로 추적한다. 연결·전송·응답 Timeout을 구분하고 Packet 또는 요청 로그에서 문제가 생긴 계층을 좁힌다.
4 · 데이터베이스와 저장Page·Heap·B-Tree Index·Query Plan을 실제 조회 비용과 연결한다. Transaction, Isolation Level, Lock, MVCC와 WAL이 어떤 동시성 문제와 복구 요구를 해결하는지 설명하고 Index 전후의 실행 계획을 비교한다.
5 · 분산 시스템의 실패와 신뢰성Network Failure와 Partial Failure를 전제로 Timeout·Retry·Backoff·Idempotency·Queue·Cache·Backpressure를 선택한다. 중복 요청과 느린 Consumer를 의도적으로 만들고 처리 횟수·지연·최종 상태를 관찰한다.
6 · AI 추론 시스템으로 전이Client 요청 → API → Queue → Batch → Model Worker → GPU Memory·KV Cache → 응답 흐름을 그린다. CPU·메모리·Network·Storage·GPU 중 어느 자원이 TTFT, Token 생성 속도, Throughput과 실패에 영향을 주는지 고정 조건의 측정 근거로 설명한다.

검증 방식

자료 없이 흐름 설명
개별 정의를 나열하지 않고 프로그램 또는 요청 하나의 상태 변화를 처음부터 끝까지 설명한다.
조건 변경 결과 예측
Thread 수, Memory 크기, Index 유무, Timeout 또는 Queue 크기 하나를 바꾸기 전에 결과를 예측한다.
작은 재현 실험
Race, Cache Miss, Query Plan, Retry 중 하나를 코드나 시스템 관찰 도구로 재현하고 예상과 결과를 비교한다.
실제 시스템 전이
같은 원리를 Python API, Container·Kubernetes 또는 LLM 추론 흐름의 실제 병목과 연결한다.
