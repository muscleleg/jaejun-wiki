데이터 엔지니어링·
데이터 시스템

도구 이름을 넓게 수집하지 않는다. 여러 원천의 데이터를 명확한 Grain과 Schema로 정의하고, 품질을 검증하며, 실패 뒤 안전하게 다시 실행할 수 있는 파이프라인을 만든다. 마지막에는 같은 데이터가 Machine Learning 학습과 LLM 평가에서 어떤 Version과 Lineage로 사용되었는지 추적한다.

활성화 경계

기존 기초에서 시작한다SQL, Database Index, Pandas 조작, CSV 품질 점검과 ML Dataset 분리 경험은 출발 증거로 사용한다. 다만 개별 문서와 실습을 End-to-End 데이터 파이프라인 역량으로 자동 환산하지 않는다.
현재 학습 흐름을 바꾸지 않는다이 로드맵은 장기 방향으로 보관하며 Road to LLM inference의 현재 사전학습 Causal LM 관문과 PyTorch 추론 Baseline → vLLM → Multi-GPU 순서, 코어 진행률과 다음 행동을 바꾸지 않는다.
언제 시작하는가핵심 여정을 완료했거나 사용자가 별도 데이터 엔지니어링 세션을 명시적으로 선택했을 때 시작한다. 현재 관문을 데이터 품질·Version·Lineage 문제가 실제로 막는 경우에는 필요한 최소 검증만 수행하고 즉시 핵심 여정으로 돌아간다.
첫 검증은 작게 시작한다CSV와 SQL 두 원천을 하나의 분석용 Table로 만드는 작은 Batch Pipeline을 첫 결과물로 삼는다. 같은 입력을 다시 처리해도 중복되지 않고, 잘못된 Schema를 거절하며, 중간 실패 뒤 이어서 실행되는지 확인한다.

6개 성취 관문

1 · SQL과 데이터 모델링업무 질문에서 Entity, Event, Grain, Primary Key·Foreign Key와 1:N 관계를 정의한다. 정규화와 비정규화, Fact·Dimension 구조의 선택 이유를 설명하고 Join·Aggregation·Window Function으로 기대 Row 수와 중복 위험을 먼저 예측한다.
2 · Batch ETL 파이프라인File·Database·API 중 둘 이상의 원천을 Extract하고, 명시적 Schema로 Transform한 뒤 분석용 저장소에 Load한다. Full Load와 Incremental Load, Watermark와 Upsert의 경계를 정하고 동일 입력 재실행이 같은 결과를 만드는 Idempotency를 검증한다.
3 · 데이터 품질과 계약Schema, Null, Unique, Range, Referential Integrity, Freshness와 Row Count 기준을 코드로 검사한다. 생산자와 소비자 사이의 데이터 계약, Schema Evolution과 Backward Compatibility를 정의하고 잘못된 입력을 격리해 원인을 추적한다.
4 · 저장 형식과 성능CSV·JSON 같은 Row 중심 교환 형식과 Parquet 같은 Columnar 형식의 차이를 Query 패턴과 비용으로 설명한다. Partition·Compression·File Size·Predicate Pushdown을 바꾸기 전 Scan 양과 실행 시간을 예측하고 실제 Query Profile로 비교한다.
5 · 오케스트레이션과 복구Task Dependency, Schedule, Retry, Timeout, Backfill, Catchup과 SLA를 DAG로 표현한다. 한 Task를 의도적으로 실패시킨 뒤 중복 쓰기 없이 재시작하고, 어느 Partition까지 완료되었는지 관측 가능하게 남긴다.
6 · ML·LLM 데이터 Version과 LineageRaw → Validated → Feature·Prompt → Train·Validation·Test 또는 Evaluation Dataset의 변환 계보를 추적한다. Code·Config·Schema·Source Snapshot과 Dataset Version을 연결해 특정 모델과 평가 결과가 어떤 데이터에서 나왔는지 재현한다.

완료 조건

데이터 모델과 계약 설명
대표 질문 하나에서 Grain·Key·관계·Schema와 품질 기준을 도출하고, 잘못된 Join이나 중복 Row가 생기는 조건을 자료 없이 설명한다.
두 원천의 종단 간 처리
서로 다른 두 원천을 수집해 검증·변환·적재하고, 결과 Table 또는 Dataset을 소비자가 다시 사용할 수 있게 만든다.
재실행과 실패 복구
동일 Batch 재실행, 중간 Task 실패, 늦게 도착한 데이터와 Backfill에서 중복·누락 없이 최종 상태가 수렴함을 검증한다.
성능 근거 제시
저장 형식·Partition·Query 하나를 바꾸기 전 결과를 예측하고 Scan 양·실행 계획·시간을 비교해 선택 이유를 설명한다.
Dataset 재현과 계보 추적
모델 학습 또는 LLM 평가 결과 하나에서 사용한 Dataset Version을 찾아 Raw Source와 변환 Code까지 거슬러 올라가고 같은 산출물을 다시 만든다.

첫 통합 결과물

입력날짜가 포함된 CSV Event와 SQL의 Entity Master를 사용한다. 원천의 Schema와 Key, 예상 Row 수를 먼저 문서화한다.
처리Incremental Extract → Schema·품질 검사 → Join·집계 → Partitioned Parquet 또는 분석용 Table 적재를 하나의 DAG로 연결한다.
실패 실험Schema 변경, 중복 Event, 중간 Task 실패, 늦게 도착한 Partition 중 두 가지 이상을 주입하고 재시도·격리·Backfill 결과를 확인한다.
최종 증거입력 Snapshot, 실행 Run, 품질 Report, Dataset Version과 소비 결과를 연결해 다른 날에도 같은 데이터 산출물을 재현한다.
