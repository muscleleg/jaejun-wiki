완료 · Logistic Baseline 평가Logistic Regression은 Validation Accuracy 80.55%로 Dummy Baseline 73.46%보다 7.10%p 높았다. Confusion Matrix에서 Yes Recall 55.88%·Precision 65.72%·F1 60.40%을 직접 계산하고, classification_report()의 macro·weighted 평균도 실제 인원수와 연결해 읽었다.
완료 · Threshold와 sigmoid 확인기본 0.5 기준은 Yes 318명, No 1,091명을 예측했고 predict()와 직접 Threshold 예측이 같음을 확인했다. 완료 · DecisionTree 첫 Baseline 실행같은 preprocessor_scaled를 포함한 Pipeline으로 DecisionTree를 Train에 학습하고 Validation 1,409개를 예측했다. Accuracy는 Dummy 73.456%, Logistic 80.554%, 기본 Tree 72.889%였다.
복습 참조 · StandardScaler 수학(x − μ) / σ가 평균 0·표준편차 1이 되는 분산 전개는 작은 숫자 예제로 확인했지만, 아직 자기 말로 완전히 설명해 완료 처리하지 않았다. 모델 학습과 병렬로 복습한다.
복습 방향 · 모델과 전처리기 구분LogisticRegression은 모델이고 fit()이 X_train과 y_train의 관계에 맞게 가중치를 학습한다. OneHotEncoder·StandardScaler·ColumnTransformer는 전처리기이고 fit_transform()은 입력 X의 표현을 바꾼다. 완료 확인: 각 객체에서 fit·transform·fit_transform이 무엇을 저장하고 어떤 결과물을 내는지 구분해 설명한다.
복습 방향 · Pandas 결과표 읽기모델 평가에서 NumPy 행렬을 pd.DataFrame(..., index=..., columns=...)로 읽기 좋은 표로 바꾸는 흐름을 보강한다. 완료 확인: confusion matrix에서 labels가 No·Yes의 행·열 순서를 정하고, index·columns가 행·열 제목을 붙인다는 것을 설명한다.
복습 방향 · Recall과 Precision 축 읽기혼동 행렬은 실제 행과 예측 열을 바꿔 읽기 쉬우므로 반복 확인한다. 완료 확인: 네 칸 표를 보고 메모 없이 Recall을 실제 Yes → 예측 Yes / 실제 Yes 전체, Precision을 예측 Yes → 실제 Yes / 예측 Yes 전체로 설명한다.
완료 · Tree 과적합과 복잡도 제한기본 Tree의 깊이 22·잎 1,106개와 Train 99.8048%·Validation 72.8886%를 확인했다. max_depth=3·5·7과 min_samples_leaf=10을 비교했고, 시험한 Tree 중 깊이 5가 Validation 79.8439%로 가장 높았지만 Logistic 80.5536%보다 낮았다.
완료 · PyTorch MLP 비교같은 Split에서 MLP를 20 Epoch·1,780번 수정하고 Validation Accuracy 78.99%·Yes Recall 35.56%를 계산했다. Logistic의 80.55%·55.88%보다 모두 낮고 실제 이탈자 241명을 놓친다는 한계를 확인했다.
완료 · 저장·복원·원본 추론state_dict 복원 뒤 원본 고객 DataFrame (1,19)를 Train 전처리로 Tensor [1,45]로 바꾸고 sigmoid 출력 0.06814424·예측 Label 0·실제 Label 0을 확인했다.

현재 계획을 유지하며 보강할 자료 조작

Pandas·NumPy 보강현재 프로젝트의 데이터 품질 확인·분할·전처리·평가 흐름은 이어가되, 배열·표 조작을 자료 없이 다시 만드는 증거는 아직 적다. MLP 진행을 바꾸지 않고 실제 데이터 단계마다 짧게 확인한다.
완료 확인작은 표에서 Pandas 열 선택·Boolean 필터·loc·drop·groupby·merge, NumPy indexing·Boolean mask·reshape·axis를 직접 사용하고, Pandas → NumPy → Tensor 변환 전후 Shape을 실행 전에 예측한다.

핵심 여정 이후 보관 · 머신러닝 실습 후보

아래 항목은 Road to LLM inference를 완료했거나 사용자가 별도 ML 심화 세션을 명시적으로 선택했을 때만 검토하는 후보다. 모두 완료해야 하는 순서표가 아니며 현재 관문과 다음 행동을 바꾸지 않는다.

운영 원칙파이썬 머신러닝 완벽 가이드, 처음하는 파이썬 머신러닝 부트캠프, 실전 금융 머신러닝, 머신러닝·딥러닝 이상거래 탐지, 캐글 Advanced 머신러닝 실전, 머신러닝의 모든 것을 강의 순서로 완주하지 않는다. R 강의와 R 코드는 제외하고 재사용할 가치가 있는 개념만 Python·Pandas·scikit-learn·PyTorch 실습으로 옮긴다. 이미 회원 이탈 프로젝트에서 검증한 전처리·분류 평가·Logistic·DecisionTree는 다시 수강하지 않는다.
확률을 현재 숫자와 연결별도 확률 이론 과정을 길게 듣지 않고 현재 Confusion Matrix로 주변확률·결합확률·조건부확률을 계산한다. Recall을 P(예측 Yes | 실제 Yes), Precision을 P(실제 Yes | 예측 Yes)로 읽고 두 조건의 방향이 왜 다른지 설명한 뒤, 작은 표에서 Bayes 규칙으로 서로 변환해 검산한다. 우도와 Naive Bayes는 텍스트 Baseline에서 실제로 사용할 때 확장한다.
보관 후보 중 하나사용자가 이 세션을 선택하면 같은 회원 이탈 데이터에서 Stratified K-Fold·Cross-validation, RandomForest 또는 Gradient Boosting 한 모델, 간단한 하이퍼파라미터 탐색, ROC-AUC와 PR-AUC, Permutation Importance를 하나의 비교표로 검증한다. RandomForest를 선택하면 OOB Score가 어떤 샘플로 계산되는지도 확인한다. 강의의 분류 파트를 알고리즘별로 반복하지 않는다.
Feature Engineering 판정도메인 가설이 있는 파생 Feature 하나만 만들고, Train에서만 학습되는 Pipeline 안에 넣어 누수를 막는다. 고정 Split과 교차검증에서 Baseline 대비 Metric 변화가 일관적인지 확인하며, 좋아진 이유를 설명하지 못하거나 검증 변동 범위보다 효과가 작으면 버린다. 여러 Feature를 한꺼번에 추가하거나 Kaggle 점수만 보고 남기지 않는다.
여러 테이블의 Grain과 Join메인 엔터티와 각 테이블의 행 의미·Primary/Foreign Key·1:1 또는 1:N 관계를 먼저 적는다. 이력 테이블은 엔터티별 count·mean·max·조건부 count 같은 집계 Feature로 한 행에 축약한 뒤 조인하고, 조인 전후 행 수·Key 중복·결측 증가·Label 분포를 확인해 행 증식과 잘못된 집계를 막는다.
다중 테이블 완료 증거작은 두 테이블에서 1:N 조인이 원본 엔터티를 왜 중복시키는지 직접 예측하고, groupby·조건부 집계·merge 뒤 한 엔터티당 한 행이 유지되는지 검증한다. 예측 시점 이후의 이력과 Target을 암시하는 컬럼은 집계 전에 차단하고, 각 파생 Feature의 원본 테이블·기간·집계식을 기록한다.
OOF Prediction교차검증 각 Fold에서 해당 Fold를 학습에 쓰지 않은 예측만 모아 전체 Train의 OOF Prediction을 만든다. 이를 일반 Train 예측과 비교해 과적합을 확인하고, Threshold·Calibration·Stacking용 입력이 왜 학습 내 예측보다 안전한지 설명한다. 단일 Holdout을 대체하는 마법 점수나 리더보드 최적화 도구로 사용하지 않는다.
시계열 미니 실습금융상품 이론이나 종목 추천 대신 일반 시계열 관문만 취한다. 예측 시점과 Target 시점을 먼저 정의하고 시간순 Train/Validation, 과거 값만 사용하는 Lag·Rolling Feature, Naive 또는 Seasonal Baseline, TimeSeriesSplit이나 Walk-forward 평가를 연결한다. Random split과 전체 기간 통계로 생기는 미래 정보 누수를 의도적으로 만들어 올바른 결과와 비교한다.
시계열 완료 증거각 Feature가 예측 시점에 실제로 알 수 있는 값인지 설명하고, Lag 계산 뒤 생긴 결측 처리와 Shape을 확인한다. 모델은 단순 Baseline보다 같은 기간·Metric에서 좋아야 하며, 금융 Backtest를 선택할 때는 거래비용·Look-ahead bias·생존자 편향을 명시한다. LSTM은 선형·트리 Baseline을 이길 근거가 생긴 뒤에만 비교한다.
이상탐지 미니 실습먼저 이상 Label의 존재와 신뢰도를 확인해 지도 이진 분류와 비지도 탐지를 구분한다. 규칙 또는 빈도 Baseline → Class weight를 적용한 Logistic·Tree 계열 → Isolation Forest 같은 비지도 모델 하나를 같은 검증 구간에서 비교한다. Autoencoder는 단순 모델의 한계와 충분한 정상 데이터가 확인된 뒤 재구성 오류 Threshold를 검증할 때만 추가한다.
불균형 Sampling과 평가 계약Random over/under-sampling·SMOTE·ADASYN은 Validation·Test가 아니라 각 Train fold 안에서만 적용해 누수를 막고, 무샘플링·Class weight·Threshold 조정과 같은 조건에서 비교한다. Accuracy 대신 PR-AUC, Recall at fixed Precision, Precision@K와 검토 가능한 Alert 수를 사용하며, Threshold는 운영 비용과 탐지 예산으로 정한다.
회귀 예측과 추론 구분작은 실제 데이터에서 Dummy → Linear/Ridge → Tree 계열을 Python으로 같은 Split과 MAE·RMSE에서 비교한다. 예측 성능이 목적이면 교차검증과 Holdout 오류를 기준으로 고르고, 계수 해석이 목적이면 선형성·잔차 패턴·등분산성·이상치·다중공선성 가정을 별도로 점검한다. P-value와 계수 유의성은 인과관계 증명이 아니며 예측 모델 선택 점수로 사용하지 않는다.
회귀 완료 증거예측값 대비 잔차 그래프에서 비선형 패턴과 분산 변화를 읽고, 큰 잔차 사례를 원본 행과 연결한다. 다항 Feature는 검증 성능과 잔차 패턴이 근거를 줄 때만 추가하며, P-value 기반 Backward Elimination으로 Feature를 자동 삭제하는 과정을 기본 전략으로 사용하지 않는다.
별도 미니 실습차원 축소·군집화는 PCA → K-Means 고객 세그먼테이션 한 번으로, 텍스트 분석은 TF-IDF + Logistic Baseline → 사전학습 Transformer 비교로 압축한다.
필요할 때만 선택KNN·SVM·SVR·Naive Bayes·AdaBoost·Voting·Blending을 모두 같은 데이터에 반복 적용하거나, Association Rule·UCB·Thompson Sampling·LDA·SVD·NMF·MeanShift·GMM·DBSCAN·Surprise·HyperOpt 사용법을 각각 완주하는 것은 현재 코어가 아니다. 포트폴리오 최적화·채권·파생상품, LSTM 주가 예측, LOF·Isolation Forest·Autoencoder·VAE를 모두 나열해 구현하는 과정도 실제 문제의 Label과 오류 비용이 선택 근거를 줄 때만 확장한다. Bayesian Optimization과 Public Leaderboard 반복 튜닝도 코어가 아니다.
시각화 연결Matplotlib·Seaborn은 독립 강의로 몰아서 듣지 않고 각 실습에서 분포·클래스 비율·Confusion Matrix·ROC/PR Curve·잔차·Train/Validation 곡선·시계열 구간별 오차와 이상 점수 분포를 그리는 완료 조건으로 넣는다.

완료한 데이터 관문과 다음 연결

시작 근거TransformerBlock.forward() 구현·Shape·전체 흐름 설명을 완료해 예약했던 데이터 기반 트랙으로 전환했다.
완료한 데이터 관문원본 구조·자료형·결측·중복·Label 분포를 확인하고, Train/Validation 분할과 전처리 뒤 Dummy·Logistic·Tree·PyTorch MLP를 같은 Split과 Metric으로 비교했다.
완료 증거MLP를 20 Epoch·1,780번 수정한 뒤 Validation Accuracy 78.99%·Yes Recall 35.56%를 계산했다. Logistic의 80.55%·55.88%보다 모두 낮고 실제 이탈자 374명 중 241명을 놓친다는 한계를 확인했다.
현재 이동회원 이탈 데이터를 문제 정의·Baseline·MLP 평가·한계 분석·저장·복원·원본 한 명 추론까지 연결해 ML 관문을 닫았고 Tiny Decoder LM도 완료했다. 현재는 사전학습 Causal LM 적용을 이어가며, 이 문서의 심화 후보는 다음 행동을 만들지 않는다.
