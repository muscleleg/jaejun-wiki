현재 위치

완료 · 데이터 이해와 분할원본 품질과 Label 분포를 확인하고 X (7043,19)·y (7043,)를 Train 5,634명·Validation 1,409명으로 나눴다. stratify=y가 두 Split의 No·Yes 비율을 유지하는 것도 검증했다.
완료 · Dummy 챕터most_frequent가 y_train의 다수 클래스 No를 선택해 Validation 1,409개를 모두 No로 예측했고, 실제 No 비율과 같은 Accuracy 73.456%가 나오는 과정을 직접 계산했다.
완료 · 전처리 통합 검증One-Hot의 고정 출력 칸과 ColumnTransformer의 작업 명세를 이해했다. 범주형 41열과 StandardScaler 숫자형 4열을 합쳐 Train (5634,45)·Validation (1409,45)를 만들었고, 마지막 숫자형 부분 (5634,4)의 평균이 사실상 0, 표준편차가 모두 1인 것도 확인했다.
완료 · Logistic Baseline 평가Logistic Regression은 Validation Accuracy 80.55%로 Dummy Baseline 73.46%보다 7.10%p 높았다. Confusion Matrix에서 Yes Recall 55.88%·Precision 65.72%·F1 60.40%을 직접 계산하고, classification_report()의 macro·weighted 평균도 실제 인원수와 연결해 읽었다.
완료 · Threshold와 sigmoid 확인기본 0.5 기준은 Yes 318명, No 1,091명을 예측했고 predict()와 직접 Threshold 예측이 같음을 확인했다. Threshold를 0.3으로 낮추면 Yes 예측은 543명으로 늘고, Yes Recall은 55.88% → 75.40%, Precision은 65.72% → 51.93%, F1은 60.40% → 61.50%으로 바뀌었다. decision_function() 점수에 직접 sigmoid를 적용한 Yes 확률도 predict_proba()의 Yes 열과 같았다.
완료 · DecisionTree 첫 Baseline 실행같은 preprocessor_scaled를 포함한 Pipeline으로 DecisionTree를 Train에 학습하고 Validation 1,409개를 예측했다. Accuracy는 Dummy 73.456%, Logistic 80.554%, 기본 Tree 72.889%였다.
복습 참조 · StandardScaler 수학(x − μ) / σ가 평균 0·표준편차 1이 되는 분산 전개는 작은 숫자 예제로 확인했지만, 아직 자기 말로 완전히 설명해 완료 처리하지 않았다. 모델 학습과 병렬로 복습한다.
복습 방향 · 모델과 전처리기 구분LogisticRegression은 모델이고 fit()이 X_train과 y_train의 관계에 맞게 가중치를 학습한다. OneHotEncoder·StandardScaler·ColumnTransformer는 전처리기이고 fit_transform()은 입력 X의 표현을 바꾼다. 완료 확인: 각 객체에서 fit·transform·fit_transform이 무엇을 저장하고 어떤 결과물을 내는지 구분해 설명한다.
복습 방향 · Pandas 결과표 읽기모델 평가에서 NumPy 행렬을 pd.DataFrame(..., index=..., columns=...)로 읽기 좋은 표로 바꾸는 흐름을 보강한다. 완료 확인: confusion matrix에서 labels가 No·Yes의 행·열 순서를 정하고, index·columns가 행·열 제목을 붙인다는 것을 설명한다.
복습 방향 · Recall과 Precision 축 읽기혼동 행렬은 실제 행과 예측 열을 바꿔 읽기 쉬우므로 반복 확인한다. 완료 확인: 네 칸 표를 보고 메모 없이 Recall을 실제 Yes → 예측 Yes / 실제 Yes 전체, Precision을 예측 Yes → 실제 Yes / 예측 Yes 전체로 설명한다.
완료 · Tree 과적합과 복잡도 제한기본 Tree의 깊이 22·잎 1,106개와 Train 99.8048%·Validation 72.8886%를 확인했다. max_depth=3·5·7과 min_samples_leaf=10을 비교했고, 시험한 Tree 중 깊이 5가 Validation 79.8439%로 가장 높았지만 Logistic 80.5536%보다 낮았다.
다음 행동PyTorch nn.Module과 Optimizer로 y=3x+2 학습 루프를 직접 구현해 scikit-learn의 fit()과 연결한다.

완료한 데이터 관문과 다음 연결

시작 근거TransformerBlock.forward() 구현·Shape·전체 흐름 설명을 완료해 예약했던 데이터 기반 트랙으로 전환했다.
완료한 데이터 관문원본 구조·자료형·결측·중복·Label 분포를 확인하고, Train/Validation 분할과 전처리 뒤 Dummy·Logistic·Tree를 같은 Metric으로 비교했다.
완료 증거Threshold 변화에서 Precision·Recall trade-off를 설명했고, Tree의 Train·Validation 차이와 깊이 제한 결과로 과적합·일반화를 비교했다.
현재 이동PyTorch nn.Module·Optimizer 학습으로 이동했다. 학습 루프를 검증한 뒤 같은 회원 이탈 Split의 MLP를 Logistic·Tree와 비교하고, 저장·복원·간단한 추론 API까지 닫은 다음 Tiny Decoder LM으로 복귀한다.
