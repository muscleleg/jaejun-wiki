적용 학습 정책

세션 재개와 학습 컨텍스트

  • focusedSessionId가 가리키는 세션이 있으면 그 세션의 첫 pending 단계부터 재개한다.
  • 로드맵·백로그에 소속된 여러 세션을 열어 둘 수 있지만 한 번에 하나만 active로 두며, 사용자의 선택이나 명시적인 session.focus 작업 없이 다른 세션으로 초점을 바꾸지 않는다.
  • 대화 중 한 번 다룬 독립 주제는 날짜별 학습 기록에만 남길 수 있다. 다음 대화에서도 이어갈 필요가 생기면 먼저 백로그 항목으로 승격한 뒤 backlog 세션으로 연다.
  • 학습을 시작하거나 재개할 때는 responseBrief를 사용해 현재까지 확인된 기록, 로드맵 또는 백로그에서의 위치, 현재 학습 단위와 목적, 왜 지금 필요한지, 지금 할 가장 작은 단계와 관찰·완료 근거, 다음에 열리는 결과 순서로 설명한다.
  • Notebook·소스 코드·테스트·CLI·화면·대화 등 현재 매체에서 실행 결과와 사용자 이해를 확인한 뒤, 파일 위치가 아니라 이해·검증·남은 질문·다음 행동을 Markdown 학습 컨텍스트로 기록한다.
  • 학습 컨텍스트는 특정 파일의 현재 존재 여부에 의존하지 않으며, 직접 확인하지 않은 내용은 완료 근거로 기록하지 않는다.
  • 모든 필수 단계의 학습 컨텍스트가 확인되기 전에는 현재 학습 단위를 완료하지 않는다.
  • 모든 단계의 완료와 각 단계의 검증된 학습 컨텍스트가 확인되면 LLM이 해당 sessionId의 범위와 현재 progressionMode·관문 관계를 근거로 다음 작은 학습 단위를 만들고 session.advance-current-unit으로 전환한다. 관문이나 백로그 단계도 끝났다면 같은 Plan에 해당 진행 상태 변경을 별도 작업으로 기록한다.
  • 학습 세션을 마감할 때 LLM은 대화의 실제 학습 구간을 근거로 그날의 하루 총 학습시간을 분 단위로 판정하고 history.set-study-time에 절대값과 추정 여부만 전달한다. 근거가 부족하면 시간을 꾸며내지 않는다.

대화형 손코딩 학습

  • 사용자가 코드를 직접 입력한다.
  • 개념과 필요성을 설명한 뒤 독립 실행 가능한 작은 코드 셀과 예상 Shape·값을 제공하고 저장된 실행 결과를 검증한다.
  • 한 번에 새로운 핵심 개념 하나를 다루며 완료되지 않은 단계를 건너뛰지 않는다.
  • 새로운 클래스·메서드·API·모델 객체는 사용 전에 역할과 입력·출력을 먼저 설명한다.
  • 추상적인 용어보다 현재 코드의 실제 숫자와 Shape을 우선한다.
  • 연습 셀은 필요한 작은 입력·Target·상수를 다시 선언해 독립 실행 가능하게 만들고, 상태를 재사용해야 할 때는 이유를 설명한다.
  • 사용자가 자료 없는 재구현을 선택한 검증 단계가 아니라면 과제 순서만 주고 샘플 코드를 생략하지 않는다.
  • 외부 강의·교재는 출처로 사용하되 학습 단위를 개념 설명·예측·손코딩·실행 증거·자기 말 설명 순서로 재구성한다.

이해도와 완료 판정

  • 설명을 듣거나 코드를 따라 입력한 사실만으로 완료 처리하지 않는다.
  • 자기 말 설명·조건 변경 결과 예측·자료 없는 재구현·의도적 변경 설명 중 하나 이상의 증거를 확인한다.
  • 대표 실습은 입력과 정답 설명·핵심 Shape 예상·Metric 평가·조건 변경 설명·핵심 코드 재구현을 확인한다.
  • 완료 기준을 충족하면 선택 심화보다 먼저 완료 사실과 남은 필수 단계 수를 명확히 알린다.
  • 캐시된 출력만 믿지 않고 필요한 import·변수·모델·입력이 포함된 상태에서 커널 재시작 후 재현되는지 확인한다.

학습 설명과 피드백

  • 처음 소개하거나 다시 묻는 영문 약어와 모델명은 한국어 뜻을 함께 설명한다.
  • 질문한 대상과 코드 줄을 먼저 특정하고 질문을 다른 개념으로 바꾸어 답하지 않는다.
  • 막힘을 수학·Python 문법·PyTorch 객체 모델·Tensor Shape 등 실제 원인으로 분류한다.
  • 진도는 나이·전공·감정이 아니라 실행 결과·설명 능력·재구현 증거로 판단한다.

Machine Learning 실습 검증

  • 문제 정의·Feature·Label·데이터 분할·Baseline·Loss·Metric·과적합·일반화·데이터 누수를 하나의 판단 흐름으로 연결한다.
  • 실제 데이터는 원본 구조·자료형·결측치·중복·Label 분포를 확인한 뒤 NumPy·Tensor·Dataset으로 넘긴다.
  • 가능한 경우 한 Batch 과적합과 Shape·dtype·device·Gradient finite 여부를 먼저 검사한다.
  • 모델 선택은 Accuracy 하나가 아니라 문제에 맞는 Metric과 Baseline 대비 일반화 근거로 설명한다.

로드맵 안내

  • 현재 계획을 유지하며 보강할 자료 조작: Pandas·NumPy 보강 현재 프로젝트의 데이터 품질 확인·분할·전처리·평가 흐름은 이어가되, 배열·표 조작을 자료 없이 다시 만드는 증거는 아직 적다. MLP 진행을 바꾸지 않고 실제 데이터 단계마다 짧게 확인한다. 완료 확인 작은 표에서 Pandas 열 선택·Boolean 필터· loc · drop · groupby · merge , NumPy indexing·Boolean mask· reshape · axis 를 직접 사용하고, Pandas → NumPy → Tensor 변환 전후 Shape을 실행 전에 예측한다.
  • 핵심 여정 이후 보관 · 머신러닝 실습 후보: 아래 항목은 Road to LLM inference 를 완료했거나 사용자가 별도 ML 심화 세션을 명시적으로 선택했을 때만 검토하는 후보다. 모두 완료해야 하는 순서표가 아니며 현재 관문과 다음 행동을 바꾸지 않는다. 운영 원칙 파이썬 머신러닝 완벽 가이드 , 처음하는 파이썬 머신러닝 부트캠프 , 실전 금융 머신러닝 , 머신러닝·딥러닝 이상거래 탐지 , 캐글 Advanced 머신러닝 실전 , 머신러닝의 모든 것 을 강의 순서로 완주하지 않는다. R 강의와 R 코드는 제외하고 재사용할 가치가 있는 개념만 Python·Pandas·scikit-learn·PyTorch 실습으로 옮긴다. 이미 회원 이탈 프로젝트에서 검증한 전처리·분류 평가·Logistic·DecisionTree는 다시 수강하지 않는다. 확률을 현재 숫자와 연결 별도 확률 이론 과정을 길게 듣지 않고 현재 Confusion Matrix로 주변확률·결합확률·조건부확률을 계산한다. Recall을 P(예측 Yes | 실제 Yes) , Precision을 P(실제 Yes | 예측 Yes) 로 읽고 두 조건의 방향이 왜 다른지 설명한 뒤, 작은 표에서 Bayes 규칙으로 서로 변환해 검산한다. 우도와 Naive Bayes는 텍스트 Baseline에서 실제로 사용할 때 확장한다. 보관 후보 중 하나 사용자가 이 세션을 선택하면 같은 회원 이탈 데이터에서 Stratified K-Fold·Cross-validation, RandomForest 또는 Gradient Boosting 한 모델, 간단한 하이퍼파라미터 탐색, ROC-AUC와 PR-AUC, Permutation Importance를 하나의 비교표로 검증한다. RandomForest를 선택하면 OOB Score가 어떤 샘플로 계산되는지도 확인한다. 강의의 분류 파트를 알고리즘별로 반복하지 않는다. Feature Engineering 판정 도메인 가설이 있는 파생 Feature 하나만 만들고, Train에서만 학습되는 Pipeline 안에 넣어 누수를 막는다. 고정 Split과 교차검증에서 Baseline 대비 Metric 변화가 일관적인지 확인하며, 좋아진 이유를 설명하지 못하거나 검증 변동 범위보다 효과가 작으면 버린다. 여러 Feature를 한꺼번에 추가하거나 Kaggle 점수만 보고 남기지 않는다. 여러 테이블의 Grain과 Join 메인 엔터티와 각 테이블의 행 의미·Primary/Foreign Key·1:1 또는 1:N 관계를 먼저 적는다. 이력 테이블은 엔터티별 count·mean·max·조건부 count 같은 집계 Feature로 한 행에 축약한 뒤 조인하고, 조인 전후 행 수·Key 중복·결측 증가·Label 분포를 확인해 행 증식과 잘못된 집계를 막는다. 다중 테이블 완료 증거 작은 두 테이블에서 1:N 조인이 원본 엔터티를 왜 중복시키는지 직접 예측하고, groupby ·조건부 집계· merge 뒤 한 엔터티당 한 행이 유지되는지 검증한다. 예측 시점 이후의 이력과 Target을 암시하는 컬럼은 집계 전에 차단하고, 각 파생 Feature의 원본 테이블·기간·집계식을 기록한다. OOF Prediction 교차검증 각 Fold에서 해당 Fold를 학습에 쓰지 않은 예측만 모아 전체 Train의 OOF Prediction을 만든다. 이를 일반 Train 예측과 비교해 과적합을 확인하고, Threshold·Calibration·Stacking용 입력이 왜 학습 내 예측보다 안전한지 설명한다. 단일 Holdout을 대체하는 마법 점수나 리더보드 최적화 도구로 사용하지 않는다. 시계열 미니 실습 금융상품 이론이나 종목 추천 대신 일반 시계열 관문만 취한다. 예측 시점과 Target 시점을 먼저 정의하고 시간순 Train/Validation, 과거 값만 사용하는 Lag·Rolling Feature, Naive 또는 Seasonal Baseline, TimeSeriesSplit 이나 Walk-forward 평가를 연결한다. Random split과 전체 기간 통계로 생기는 미래 정보 누수를 의도적으로 만들어 올바른 결과와 비교한다. 시계열 완료 증거 각 Feature가 예측 시점에 실제로 알 수 있는 값인지 설명하고, Lag 계산 뒤 생긴 결측 처리와 Shape을 확인한다. 모델은 단순 Baseline보다 같은 기간·Metric에서 좋아야 하며, 금융 Backtest를 선택할 때는 거래비용·Look-ahead bias·생존자 편향을 명시한다. LSTM은 선형·트리 Baseline을 이길 근거가 생긴 뒤에만 비교한다. 이상탐지 미니 실습 먼저 이상 Label의 존재와 신뢰도를 확인해 지도 이진 분류와 비지도 탐지를 구분한다. 규칙 또는 빈도 Baseline → Class weight를 적용한 Logistic·Tree 계열 → Isolation Forest 같은 비지도 모델 하나를 같은 검증 구간에서 비교한다. Autoencoder는 단순 모델의 한계와 충분한 정상 데이터가 확인된 뒤 재구성 오류 Threshold를 검증할 때만 추가한다. 불균형 Sampling과 평가 계약 Random over/under-sampling·SMOTE·ADASYN은 Validation·Test가 아니라 각 Train fold 안에서만 적용해 누수를 막고, 무샘플링·Class weight·Threshold 조정과 같은 조건에서 비교한다. Accuracy 대신 PR-AUC, Recall at fixed Precision, Precision@K와 검토 가능한 Alert 수를 사용하며, Threshold는 운영 비용과 탐지 예산으로 정한다. 회귀 예측과 추론 구분 작은 실제 데이터에서 Dummy → Linear/Ridge → Tree 계열을 Python으로 같은 Split과 MAE·RMSE에서 비교한다. 예측 성능이 목적이면 교차검증과 Holdout 오류를 기준으로 고르고, 계수 해석이 목적이면 선형성·잔차 패턴·등분산성·이상치·다중공선성 가정을 별도로 점검한다. P-value와 계수 유의성은 인과관계 증명이 아니며 예측 모델 선택 점수로 사용하지 않는다. 회귀 완료 증거 예측값 대비 잔차 그래프에서 비선형 패턴과 분산 변화를 읽고, 큰 잔차 사례를 원본 행과 연결한다. 다항 Feature는 검증 성능과 잔차 패턴이 근거를 줄 때만 추가하며, P-value 기반 Backward Elimination으로 Feature를 자동 삭제하는 과정을 기본 전략으로 사용하지 않는다. 별도 미니 실습 차원 축소·군집화는 PCA → K-Means 고객 세그먼테이션 한 번으로, 텍스트 분석은 TF-IDF + Logistic Baseline → 사전학습 Transformer 비교로 압축한다. 필요할 때만 선택 KNN·SVM·SVR·Naive Bayes·AdaBoost·Voting·Blending을 모두 같은 데이터에 반복 적용하거나, Association Rule·UCB·Thompson Sampling·LDA·SVD·NMF·MeanShift·GMM·DBSCAN·Surprise·HyperOpt 사용법을 각각 완주하는 것은 현재 코어가 아니다. 포트폴리오 최적화·채권·파생상품, LSTM 주가 예측, LOF·Isolation Forest·Autoencoder·VAE를 모두 나열해 구현하는 과정도 실제 문제의 Label과 오류 비용이 선택 근거를 줄 때만 확장한다. Bayesian Optimization과 Public Leaderboard 반복 튜닝도 코어가 아니다. 시각화 연결 Matplotlib·Seaborn은 독립 강의로 몰아서 듣지 않고 각 실습에서 분포·클래스 비율·Confusion Matrix·ROC/PR Curve·잔차·Train/Validation 곡선·시계열 구간별 오차와 이상 점수 분포를 그리는 완료 조건으로 넣는다.
  • 완료한 데이터 관문과 다음 연결: 시작 근거 TransformerBlock.forward() 구현·Shape·전체 흐름 설명을 완료해 예약했던 데이터 기반 트랙으로 전환했다. 완료한 데이터 관문 원본 구조·자료형·결측·중복·Label 분포를 확인하고, Train/Validation 분할과 전처리 뒤 Dummy·Logistic·Tree·PyTorch MLP를 같은 Split과 Metric으로 비교했다. 완료 증거 MLP를 20 Epoch·1,780번 수정한 뒤 Validation Accuracy 78.99% ·Yes Recall 35.56% 를 계산했다. Logistic의 80.55% · 55.88% 보다 모두 낮고 실제 이탈자 374명 중 241명을 놓친다는 한계를 확인했다. 현재 이동 회원 이탈 데이터를 문제 정의·Baseline·MLP 평가·한계 분석·저장·복원·원본 한 명 추론까지 연결해 ML 관문을 닫았고 Tiny Decoder LM도 완료했다. 현재는 사전학습 Causal LM 적용을 이어가며, 이 문서의 심화 후보는 다음 행동을 만들지 않는다.
