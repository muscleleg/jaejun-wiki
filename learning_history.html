기존 Multi-Head Attention에 길이 3의 하삼각 Boolean Mask를 넣고 미래 Score를 -inf로 바꾼 뒤 Softmax했다. 입력과 Attention 출력은 [1,3,2], Attention weight는 [batch,head,query,key]=[1,2,3,3]이었으며 첫 Head에서 미래 칸이 모두 0인 결과를 확인했다. Causal Mask는 참고 가능한 값을 제한할 뿐 Tensor 차원을 바꾸지 않는다고 예측했다.

Head 병합과 Projection 오타 수정

Head 출력 [1,3,2,1]을 reshape(batch_size,token_count,d_model)로 [1,3,2]에 합치며, 이는 num_heads × head_dim = d_model이기 때문에 가능하다고 설명했다. 이어 output_projection이 이어 붙인 Head 정보를 학습 가능한 Weight로 다시 섞는다. 최초 셀에서 Key를 Query Projection으로 잘못 계산한 key=self.query_projections(x)를 찾아 key=self.key_projection(x)로 고치고 재실행해 서로 다른 Q·K Projection을 사용하도록 수정했다.

Causal TransformerBlock 최소 연결

Causal Multi-Head Attention → x+Attention Residual → LayerNorm → FFN(Linear 2→8 → GELU → Linear 8→2) → 첫 LayerNorm 결과+FFN Residual → LayerNorm 순서로 최소 Block을 연결했다. 입력과 출력 Shape이 모두 [1,3,2], Attention weight가 [1,2,3,3]임을 확인했으며 Block 출력은 [[[1,-1],[-1,1],[1,-1]]]이었다. 두 번째 Residual에는 처음의 x가 아니라 첫 Residual과 LayerNorm까지 마친 표현을 더한다는 점을 자기 말로 설명했다. 이번 최소 연결에서는 Dropout을 생략했다.

위치별 Vocabulary Logit의 Shape과 수동 점수 확인

torch.zeros(1,3,10)을 Batch 1개·예측 위치 3개·Vocabulary Token 10개의 Logit Tensor로 해석했다. logits[0,0,7]=2.0, logits[0,1,2]=1.0, logits[0,2,9]=3.0은 모델이 계산한 값이 아니라 각 위치의 특정 Token 칸에 직접 넣은 연습용 점수임을 구분했다. 따라서 이 단계는 학습된 예측의 성능 확인이 아니라 Logit 축과 이후 Loss 계산을 이해하기 위한 수동 예제다.

dim=-1 Softmax와 선택된 Token 값

logits[0,0]은 첫 Batch의 첫 위치에서 Token 10개에 준 점수 벡터이고, softmax(...,dim=-1)의 -1은 현재 Tensor의 마지막 축인 Vocabulary 축을 뜻한다. 따라서 [1,3,10]에서는 세 위치마다 Token 10개를 각각 Softmax하며, 점수 2를 넣은 7번 칸은 약 0.4509, 나머지 칸은 약 0.0610이 되었다. 선택된 값 하나에도 분모를 만드는 나머지 아홉 Token 점수가 모두 반영된다는 점을 확인했다.

first_target=7은 값을 더하거나 정답에 보너스를 주는 수가 아니라, 첫 위치의 Softmax 벡터에서 채점할 7번 열을 고르는 인덱스다. 선택값 first_position_values[7]≈0.4509에 -log를 적용해 Loss 약 0.7966을 얻었다. 선택값이 1에 가까우면 Loss가 0에 가까워지고, 0에 가까우면 Loss가 크게 증가한다는 방향도 설명했다.

세 위치 Cross Entropy와 평균 Loss

[3,10] Logit의 각 행에서 Target [7,2,9]가 지정한 열을 하나씩 채점했다. CrossEntropyLoss(reduction="none")으로 위치별 Loss [0.7966,1.4612,0.3702]를 확인하고, 그 평균이 0.8760임을 계산했다. 기본 CrossEntropyLoss()가 위치별 결과를 평균내 Scalar 하나를 돌려준다는 점과, 이 계산이 분산의 (값-평균)²이나 MSE의 (예측-정답)²와 다른 방식임을 구분했다.

수동 Hidden State [1,3,2]에 Linear(in_features=2,out_features=10)을 적용해 Logit [1,3,10]이 되는 결과를 실행했다. Embedding(num_embeddings=10,embedding_dim=2)에 Token ID [[3,7,2]]을 넣어 [1,3,2] Hidden State를 얻었다. vocab_size=10은 반환 Shape에 10을 붙이는 값이 아니라 ID 0~9에 대응하는 [10,2] Embedding 표의 행 수이며, 입력 ID 3·7·2가 그 표의 해당 행을 조회한다. 학습 전 같은 Embedding 표에서는 어느 Sequence에 있든 같은 Token ID가 같은 벡터를 가져오고, 이후 위치 정보와 Attention 문맥이 더해지면 표현이 달라진다는 점까지 연결했다.

TransformerBlock 전체 흐름 복습

분산·Scaling·LayerNorm 오해 교정

LayerNorm은 값을 0~1로 제한하거나 튀는 값을 제거하는 연산이 아니라, Token별 평균을 빼고 표준편차로 나누어 전체 이동과 배율을 정돈하면서 상대적 모양을 남기는 연산으로 바로잡았다.

회원 이탈 MLP의 SGD 한 Step 실행

SGD(model.parameters(),lr=0.1)를 연결하고 한 Batch에서 zero_grad → forward → BCE → backward → step을 한 번 실행했다. 같은 Batch를 no_grad()에서 다시 계산했을 때 Loss가 0.6564000844955444 → 0.6511512994766235로 내려갔다. 사용자는 optimizer.step() 한 번마다 Gradient와 learning rate를 기준으로 weight·bias가 조금 조정되고, 이번 한 번의 수정에서는 Loss가 소폭 감소한 것이라고 자기 말로 설명했다. MSE는 분산의 value−mean이 아니라 prediction−target을 제곱해 평균내며 음수가 될 수 없다는 점을 구분했다. loss.backward()는 weight를 조금 움직였을 때의 Loss 순간변화율과 bias를 조금 움직였을 때의 순간변화율을 각각 계산한다는 흐름을 작은 숫자로 다시 연결했다.

동일한 수정 전 상태에서 두 Gradient 계산

한 Step에서 ∂L/∂weight는 현재 bias를 고정한 관점으로, ∂L/∂bias는 현재 weight를 고정한 관점으로 계산하지만 한쪽을 먼저 수정한 값으로 다른 쪽을 계산하지 않는다는 점을 확인했다. 두 Gradient는 같은 수정 전 (weight,bias) 상태에서 만들어지고 optimizer.step()이 함께 적용하며, 새 값의 상호 영향은 다음 Epoch부터 반영된다.

SGD·학습률·Gradient 누적

SGD(model.parameters(),lr=0.1)은 수정 대상과 규칙을 등록할 뿐 즉시 값을 바꾸지 않으며, 학습률 0.1은 고정 0.1이 아니라 각 Gradient 크기의 10%를 적용한다는 뜻이다. Loss를 계산하는 Forward에서는 Gradient가 쌓이지 않고 backward()에서 기존 .grad에 누적되므로, 매 Step의 현재 Gradient만 쓰려면 zero_grad()가 필요하다는 점을 구분했다.

첫 Residual 결과의 Token별 평균을 빼고 표준편차로 나누면 각 Token의 마지막 특징 차원이 평균 0, 분산 1에 가까워진다는 흐름을 확인했다. 2.9802e-08은 정확한 0을 Float로 계산하면서 생긴 매우 작은 오차이므로 사실상 0으로 해석했다. 두 번째 Residual 뒤에도 같은 이유로 별도의 nn.LayerNorm(d_model)이 필요하다고 먼저 예측하고 실행 결과로 검증했다.

nn.Linear(2,4)는 층을 만드는 것이고, expanded_output = ffn_expand(normalized_output)은 그 층에 실제 Tensor를 넣어 실행하는 것임을 구분했다. 첫 Linear는 Token마다 더 넓은 중간 특징 공간을 만들고, GELU는 음수를 곧바로 노이즈로 판정하는 것이 아니라 학습된 중간 반응의 전달 정도를 부드럽게 조절하며, 두 번째 Linear는 4 → 2로 돌아오면서 현재 표현에 더할 수정값을 만든다고 이해했다.
